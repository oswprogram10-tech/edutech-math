### 1. 공통
- **과제 설정**
  - 과제마다 `engine:"E12"`, `mode:"surface-volume"`, `submit:"button"`
  - 일반 규칙의 `when`은 `{"kind":"equals","path":"mode","value":"surface-volume"}`
- **오개념 코드 4개**는 레지스트리에 없다. 그래서 응답 경로와 predicate로 건다.
  - MC-SURFACE-3-FACES
  - MC-VOLUME-SURFACE-CONFUSION
  - MC-VOLUME-UNIT-CONVERT-100
  - MC-PERIMETER-AREA-SAME
- **응답 칸:** 실행기에는 식 입력 칸이 없다. 그래서 식 과제(A1.T2)는 면 넓이 칸 3개와 '몇 배' 칸으로 바꾼다. 수 응답은 `forms:["integer"]`다.
- **③ 역추적**
  - 오개념 규칙의 ③은 명세 표의 ③ 열이다.
  - 일반 규칙의 ③은 그 과제 개념의 선수 개념이다.
    | 개념 | 선수(③) |
    | --- | --- |
    | surface-area | `g5s2u5.nets` |
    | volume-unit-cube | `g5s2u5.cuboid-parts` |
    | volume-formula | `g6s1u6.volume-unit-cube` |
    | volume-units | `g6s1u6.volume-formula` |
    | surface-vs-volume | `g6s1u6.surface-area` |
- **정답 노출 금지:** 발문, 힌트, 라벨에 52·24·150·125·1000000·"×2" 같은 답이나 공식을 쓰지 않는다. 치수(4cm 등)는 주어진 재료라 써도 된다.
- **오버레이 문구:** 오버레이가 그 상태에서 아무것도 그리지 않을 수 있다. 예를 들어 `unpainted-blink`는 6면을 다 칠했으면 그릴 것이 없다. 그래서 ② `say`에 "보여 줬어요"를 쓰지 않고, 그림이 없어도 맞는 문장을 쓴다. 실제로 그려지는 상태는 E2E로 확인한다.
- **두 칸 배치:** 실행기에서 엔진 판과 응답 칸이 나란히 놓이는 크롬북 폭을 확인한다(T145 메모 '검수자가 꼭 볼 곳' 2).
  - 대상: fixed-volume 무대, 가로·세로 단추, 기록표 첫 줄, 응답 칸, '확인하기'
  - 첫 화면에 들어오지 않으면 `expectContentPanelsReachable` 기준으로 하고 측정값을 메모에 적는다.
  - 무대가 너무 작아 상자가 거의 안 보이면(무대 높이 150px 미만) 멈추고 보고한다.

### A1 `g6s1u6.A1` "펼쳐 칠하고 채워 보기" (5과제)
**공통 입체 S:** `{"w":4,"d":3,"h":2}`

2. **A1.T1 칠하고 겉넓이 (C).** concepts `["g6s1u6.surface-area"]`
   - 발문: "상자를 돌려 보고 펼쳐서 모든 면을 칠해 보세요. 칠한 넓이는 모두 몇 cm²인가요?"
   - config: `{"mode":"surface-volume","solid":S,"steps":["rotate","unfold","paint"]}`
   - 응답: 수 `area` "겉넓이(cm²)"
   - 판정: `all`(`allFacesPainted`, `area`="52")
   - **MC-SURFACE-3-FACES**
     - when: `area`="26"
     - ①: "전개도에 면이 몇 개였을까요?"
     - ②: `show {"engine":"E12","overlay":"unpainted-blink"}` + "전개도의 면을 하나씩 짚으며 모두 셌는지 확인해 봐요."
     - ③: `g5s2u5.nets`
   - **상태 규칙**(일반 앞)
     - when: `paintedFacesIs {count:0}`
     - ①: "펼친 전개도의 면을 눌러 칠해 볼까요?"
     - ②: `say`만 "'펼치기' 단계로 가서 면을 하나씩 눌러 봐요."
     - ③: `g5s2u5.nets`
   - 일반: ① "칠한 면마다 칸이 몇 개인지 세어 더해 볼까요?" / ② `say`만 "마주 보는 두 면은 칸 수가 같은지 살펴봐요." / ③ `g5s2u5.nets`
   - E2E
     - 3면만 칠하고 26 → MC ①
     - 다시 → MC ②와 `unpainted-blink`. 그려지는지, 정렬이 1px 이내인지 본다(**이 단원의 정렬 테스트**).
     - 6면 칠하고 52 → 통과
3. **A1.T2 합동인 면 쌍으로 겉넓이 (P).** concepts `["g6s1u6.surface-area"]`
   - 발문: "서로 다른 면 세 개의 넓이를 구하고, 겉넓이를 구하려면 그 합을 몇 배 해야 하는지 적어요."
   - config: `{"mode":"surface-volume","solid":S,"steps":["rotate","unfold","paint"]}`
   - 응답: 수 `top` "윗면 넓이(cm²)", `front` "앞면 넓이(cm²)", `side` "옆면 넓이(cm²)", `times` "몇 배"
   - 판정: `all`(`top`="12", `front`="8", `side`="6", `times`="2")
   - **MC-SURFACE-3-FACES**: when `times`="1" / ① "보이지 않는 쪽에도 같은 면이 있을까요?" / ② `show unpainted-blink` + "펼친 전개도에서 마주 보는 면을 짝지어 봐요." / ③ `g5s2u5.nets`
   - 일반: ① "윗면은 가로와 세로가 각각 몇 cm인가요?" / ② `say`만 "펼친 전개도에서 같은 무늬 면끼리 짝지어 봐요." / ③ `g5s2u5.nets`
   - E2E
     - 12·8·6·1 → MC ①
     - 12·8·5·2 → 일반 ①
     - 12·8·6·2 → 통과
4. **A1.T3 쌓기나무로 부피 (C).** concepts `["g6s1u6.volume-unit-cube","g6s1u6.volume-formula"]`
   - 발문: "빈 상자에 1cm³ 쌓기나무를 아래층부터 채워 보세요. 상자의 부피는 몇 cm³인가요?"
   - config: `{"mode":"surface-volume","solid":S,"steps":["fill-voxels"]}`
   - 응답: 수 `vol` "부피(cm³)"
   - 판정: `all`(`voxelsComplete`, `vol`="24")
   - **MC-VOLUME-SURFACE-CONFUSION**: when `vol`="52" / ① "상자를 감싸는 양을 구했나요, 채우는 양을 구했나요?" / ② `show wrap-vs-fill` + "겉을 감싸는 것과 속을 채우는 것을 나란히 놓고 비교해 봐요." / ③ `g6s1u6.volume-unit-cube`
   - 일반: ① "한 층에 쌓기나무가 몇 개 들어가나요?" / ② `say`만 "'한 층 채우기'로 한 층씩 채우며 층 수를 세어 봐요." / ③ `g6s1u6.volume-unit-cube`
   - E2E
     - 한 층만 채우고 24 → 일반 ①
     - 다 채우고 52 → MC ①
     - 다 채우고 24 → 통과
5. **A1.T4 정육면체 겉넓이와 부피 (A).** concepts `["g6s1u6.surface-area","g6s1u6.volume-formula"]`
   - 발문: "한 모서리가 5cm인 정육면체의 겉넓이와 부피를 구해요."
   - config: `{"mode":"surface-volume","solid":{"w":5,"d":5,"h":5},"steps":["rotate"]}`
   - 응답: 수 `area` "겉넓이(cm²)", `vol` "부피(cm³)"
   - 판정: `all`(`area`="150", `vol`="125")
   - **MC-VOLUME-SURFACE-CONFUSION**: when `all`(`area`="125", `vol`="150") / ① "어느 쪽이 감싸는 양이고 어느 쪽이 채우는 양일까요?" / ② `show wrap-vs-fill` + "겉을 감싸는 것과 속을 채우는 것을 비교해 봐요." / ③ `g6s1u6.volume-unit-cube`
   - **MC-SURFACE-3-FACES**: when `area`="75" / ① "정육면체에는 면이 몇 개 있을까요?" / ② `say`만 "보이지 않는 쪽 면도 세었는지 상자를 돌려 확인해 봐요." / ③ `g5s2u5.nets`
     - 이 과제는 rotate 단계만 있어 `unpainted-blink`가 그릴 전개도가 없을 수 있다. 그래서 `say`만 쓴다.
   - 일반: ① "한 면의 넓이는 얼마이고, 쌓기나무는 한 층에 몇 개일까요?" / ② `say`만 "한 면의 넓이와 한 층의 개수부터 구해 봐요." / ③ `g6s1u6.volume-unit-cube`
   - E2E: 125·150 → MC-VOLUME ①, 75·125 → MC-SURFACE ①, 150·100 → 일반 ①, 150·125 → 통과
6. **A1.T5 1m³는 몇 cm³ (A).** concepts `["g6s1u6.volume-units"]`
   - 발문: "한 모서리가 1m인 정육면체에 1cm³ 쌓기나무를 빈틈없이 채우려고 해요. 1m³는 몇 cm³인가요?"
   - config: `{"mode":"surface-volume","solid":{"w":1,"d":1,"h":1},"steps":["rotate"]}`
     - 화면의 상자는 1cm³ 쌓기나무 한 개를 보여 주는 재료다.
     - `unit-zoom`이 이 상태에서 그려지는지 E2E로 확인한다. 그려지지 않으면 멈추고 보고한다.
   - 응답: 수 `cm3` "1m³는 몇 cm³"
   - 판정: `cm3`="1000000"
   - **MC-VOLUME-UNIT-CONVERT-100**: when `any`(`cm3`="100", `cm3`="10000") / ① "1m 한 줄에 1cm³ 쌓기나무가 몇 개 들어갈까요? 한 층에는요?" / ② `show unit-zoom` + "한 줄, 한 층, 전체로 차례로 늘려 생각해 봐요." / ③ `g6s1u6.volume-formula`
   - 일반: ① "1m는 몇 cm인지 떠올려 볼까요?" / ② `say`만 "가로, 세로, 높이에 각각 몇 개씩 놓이는지 생각해 봐요." / ③ `g6s1u6.volume-formula`
   - E2E
     - 100 → MC ①
     - 10000을 두 번 → MC ②와 `unit-zoom` 보임
     - 1000000 → 통과

### A2 `g6s1u6.A2` "포장지를 아끼는 상자" (3과제)
**공통 config F:** `{"mode":"surface-volume","variant":"fixed-volume","volume":24,"log":true}`

7. **A2.T1 부피 24인 상자 4가지 (P).** concepts `["g6s1u6.volume-formula"]`
   - 발문: "쌓기나무 24개로 만들 수 있는 상자를 가로와 세로를 바꿔 가며 4가지 기록해요."
   - 판정: `logDistinctAtLeast {count:4}`
   - 응답 칸이 없는 과제다. 실행기가 응답 칸 없이 엔진 판정만 하는지 확인한다(T111 공통 6).
   - 일반: ① "가로나 세로를 바꾸면 높이는 어떻게 달라지나요?" / ② `say`만 "가로 단추와 세로 단추를 바꿀 때마다 '기록하기'를 눌러요." / ③ `g6s1u6.volume-unit-cube`
   - E2E: 3가지 기록 → 일반 ①, 4가지 → 통과
8. **A2.T2 포장지가 가장 적게 드는 상자 (A).** concepts `["g6s1u6.surface-vs-volume"]`
   - 발문: "기록한 상자의 겉넓이를 표에 적고, 포장지가 가장 적게 드는 상자를 찾아요. 그 상자의 겉넓이는 몇 cm²인가요?"
   - 응답: 수 `least` "가장 작은 겉넓이(cm²)"
   - 판정: `all`(`logHasMinSurface`, `least`="52")
   - **MC-SURFACE-3-FACES**: when `logSurfaceIs {w:2,d:3,h:4,value:26}` / ① "상자의 면은 모두 몇 개였을까요?" / ② `say`만 "기록한 상자의 면 6개를 모두 더했는지 확인해 봐요." / ③ `g5s2u5.nets`
     - `unpainted-blink`는 fixed-volume에 전개도가 없어 쓰지 않는다.
   - 일반: ① "기록한 상자들 가운데 겉넓이가 가장 작은 것은 어떤 모양인가요?" / ② `say`만 "가로, 세로, 높이가 서로 비슷한 상자도 기록해 봐요." / ③ `g6s1u6.surface-area`
   - E2E
     - 2×3×4에 26을 적고 확인 → MC ①
     - 1×1×24(98)와 1×2×12(76)만 기록하고 76 → 일반 ①
     - 2×3×4에 52를 기록하고 52 → 통과
     - 정답 상자가 `minSurfaceBox(24)`인지 관찰로 확인한다.
9. **A2.T3 부피가 같으면 겉넓이도 같을까 (A).** concepts `["g6s1u6.surface-vs-volume"]`
   - 발문: "'부피가 같으면 겉넓이도 같다'는 말이 맞을까요? 상자 두 개 이상을 기록하고 겉넓이를 적은 뒤 골라요."
   - 응답: 고르기 `claim`(한 개) — `yes` "맞아요" / `no` "맞지 않아요"
   - 판정: `all`(`claim`=["no"], `logDistinctAtLeast {count:2}`, `logAllCorrect`)
   - **MC-PERIMETER-AREA-SAME**: when `claim`=["yes"] / ① "기록표에서 겉넓이가 모두 같았나요?" / ② `show wraps-compare` + "두 상자의 포장지를 칸으로 비교해 봐요." / ③ `g5s1u6.perimeter-vs-area`
     - ③의 개념 ID가 `data/concepts.json`에 있는지 확인하고, 없으면 멈추고 보고한다.
   - 일반: ① "기록한 상자들의 겉넓이를 다시 계산해 볼까요?" / ② `say`만 "상자마다 면 6개의 넓이를 더했는지 확인해 봐요." / ③ `g6s1u6.surface-area`
   - E2E
     - 맞아요 → MC ①
     - 다시 → MC ②와 `wraps-compare`
     - 상자 두 개를 맞게 적고 맞지 않아요 → 통과
