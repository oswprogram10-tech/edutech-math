## 목표
E15에 `calc-pattern` 모드를 더한다. g4s1u6.A2 "블록 피라미드와 계산식 1:1 뷰어"에 쓴다.
- 단계별 블록 배열(1, 1+2+1, 1+2+3+2+1 …)과 계산식 배열(1 = 1 × 1, 1+2+1 = 2 × 2 …)을 나란히 보여 준다. 블록 한 줄(열)과 식의 수를 서로 강조한다.
- 학생은 다음 단계를 블록으로 쌓고 식을 쓴다.
- 계산식 배열(11 × 11 = 121 …)도 같은 화면 틀로 보여 준다.

**범위 밖:**
- 예측 값(5단계 블록 수, 1111 × 1111)과 규칙 문장 카드는 엔진이 아니라 실행기 `response`(`number`, `choice`)로 콘텐츠 카드에서 받는다.
- g2s2u6의 덧셈표·곱셈표 돋보기(`table`, `magnifierUses`)는 나중 카드에서 다룬다.

### 2. 설정
```ts
interface CalcPatternConfig {
  mode: 'calc-pattern';
  pattern: 'symmetric-sum-square' | 'repunit-square';
  stepsShown?: number;   // 보여 줄 단계 수(기본 3), 1~8
  workStep?: number;     // 학생이 쌓고 식을 쓸 단계(기본 stepsShown + 1), 1~9
  build?: boolean;       // 블록 쌓기 칸(기본: symmetric은 true, repunit은 false — repunit에서 true면 무시)
  expression?: boolean;  // 식 쓰기 칸(기본 true)
  linkHighlight?: boolean; // 기본 true (symmetric만)
  look?: 'blocks' | 'picture' | 'none'; // CPA: 쌓기(C) / 그림만(P, build 꺼짐) / 식만(A, 블록 그림 없음)
}
```
- **`symmetric-sum-square` n단계**
  - 열 높이는 1, 2, …, n, …, 2, 1이다(2n−1열). 블록 수는 n × n이다.
  - 식은 `1 + 2 + … + n + … + 2 + 1 = n × n`이다.
- **`repunit-square` n단계**
  - 식은 `1…1 × 1…1 = 12…n…21`이다(1이 n개).
  - 블록 그림은 없다. n ≤ 9다.
- 값은 모두 `Rational`(BigInt)로 계산한다. `111111111²`도 정확해야 한다.
- 범위 밖이나 모르는 `pattern`이면 T170 규칙대로 설정 오류 판을 그린다.

### 3. 상태와 Action
- **상태:**
  ```ts
  { mode: 'calc-pattern', settings, heights: number[], cursor: { col: number; h: number }, exprText: string, focus: 'build' | 'expr', link: { step: number; col: number } | null }
  ```
  - `heights`는 학생이 쌓은 열 높이다. 길이는 `2 × workStep + 1`(한 열 여유)이고 처음엔 모두 0이다.
  - 쌓기 칸 높이는 `workStep + 1`이다(한 칸 여유). 정답 모양이 칸 수로 드러나지 않게 한다.
- **Action**
  - `tap-cell {col, h}`: 열 높이를 h로 둔다(h는 1부터). 이미 높이가 h면 h−1로 둔다.
  - `clear-build`
  - `move-cursor {dx, dy}`, `toggle-at-cursor`
  - `type {key}`: `0-9 + × =`
  - `backspace`, `clear-expr`
  - `set-focus`
  - `link {step, col} | null`: 강조만 하고 판정에는 쓰지 않는다.

### 4. 계산 (`calc.ts`)
- `stepColumns(n)`, `stepTotal(pattern, n)`, `stepExpression(pattern, n)`(표시 문자열)
- `isPyramid(heights, n)`: 앞뒤 0을 뺀 열 높이가 1…n…1과 같은지 본다.
- `readExpression(text)`: `parseRelation`으로 읽는다(○·□가 있으면 무효). 아래를 돌려준다.
  - `valid`
  - `holds`: 양변 값이 같다.
  - `left`, `right`: 값(Rational 문자열)
  - `addends`: 한 변이 수의 덧셈만이면 그 수 목록(왼쪽 우선), 아니면 null
  - `factors`: 한 변이 `a × b` 하나이면 [a, b], 아니면 null

### 5. 화면 (`CalcView.tsx`)
- **보기 판 SVG** `data-testid="calc-canvas"`
  - 1~stepsShown 단계를 위에서 아래로 그린다. 각 줄은 블록 그림(symmetric, look ≠ 'none')과 그 단계의 식이다.
  - 블록 한 칸은 화면 24px 이상이다. 넘치면 줄이지 말고 판 스크롤한다(T170 원칙).
  - 블록 열은 `data-step`·`data-col`, 식의 수는 `data-term`이다.
  - **linkHighlight:** 열을 누르면(또는 포커스 후 Enter) 같은 단계 식의 k번째 수가 굵게 + 밑줄로 강조된다. 식의 수를 누르면 그 열이 테두리 강조된다. 색만으로 구분하지 않는다.
- **쌓기 칸** `data-testid="calc-build"` (build일 때)
  - 2·workStep+1열 × workStep+1행 격자다. 칸은 targetSize 이상이고 `data-col`·`data-h`다.
  - 블록이 있는 칸은 채운 사각형 + 윤곽으로 그린다. 키보드 커서는 굵은 테두리다.
  - 쌓은 블록 수를 "블록 ○개"처럼 숫자로 보여 준다. 이것은 학생이 쌓은 수이므로 정답 노출이 아니다.
- **식 칸**
  - 입력 칸에는 `formatRelation` 스타일로 띄어 쓴 텍스트를 보여 준다. 읽을 수 없으면 오류 위치에 밑줄을 긋는다.
  - 키패드 단추 `0-9 + × =`, 지우기, 모두 지우기는 targetSize 이상이다.
- **판정 표시 없음:** ✓/✕를 엔진이 그리지 않는다(실행기 피드백을 쓴다).
- **레이아웃:** 보기 판은 `.boardArea`, 쌓기·식·키패드는 `.sideStack`이다. 판 맞춤 원칙은 T170과 같다.
- **문구**는 `strings.ko.ts`에 둔다. 학년 표시는 하지 않는다.

### 6. Observation과 predicate
- **Observation 키**
  - `pattern`, `workStep`
  - `heights`: 앞뒤 0 제거
  - `builtTotal`, `builtIsPyramid`
  - `exprText`, `exprValid`, `exprHolds`, `exprLeft`, `exprRight`, `exprAddends`, `exprFactors`
  - `misconceptions`
- **Predicate**
  - `builtIsPyramid {}`
  - `builtTotalIs {n}`
  - `exprHolds {}`
  - `exprAddendsAre {terms: number[]}`
  - `exprFactorsAre {a, b}`: 순서 무관
  - `exprValueIs {n}`: `holds`이고 값이 n
  - `hasMisconception {code}`
- **오개념 `MC-PATTERN-RECURSIVE-ONLY`**
  - 쌓은 모양이 `workStep−1` 단계 피라미드에 한 열만 붙인 모양이면 건다(앞 단계에 덧붙이기만 함). 예: 4단계에서 1,2,3,2,1,4
  - 식이 성립하지만 덧셈 항이 앞 단계 합 + 증가분 두 수뿐인 경우에도 건다(예: `9 + 7 = 16`).
  - 둘 다 판정 함수로 단위 테스트한다.

### 7. 오버레이
- **`step-table`** (`calc-canvas` 기준, RECURSIVE-ONLY ②)
  - 판 아래 띠에 "단계 | 1 2 3 …", "블록 수 | 1 4 9 …"를 표로 그린다. 보여 준 단계(stepsShown)까지만이다.
  - workStep 값은 쓰지 않는다(정답 노출 금지).
- **`column-link`** (`calc-canvas` 기준)
  - `args.step` 단계의 열마다 그 열 높이 숫자를 열 위에 쓰고, 식의 같은 수와 점선으로 잇는다.
  - 기본은 stepsShown 단계다.

### 8. 테스트
- **단위**
  - `calc.ts`: n = 1·4·9의 열·합·식, `isPyramid`(앞뒤 0, 비대칭, 높이 초과), `readExpression`
    - `1+2+3+4+3+2+1=4×4` → addends·factors·holds
    - `16=4×4`
    - `4×4=16` (factors가 왼쪽에 있는 경우)
    - `1=1`
    - ○ 포함 무효
    - 빈 문자열
  - repunit 9단계 = 12345678987654321
  - 오개념 두 경우와 아닌 경우
  - reduce 불변·직렬화, `tap-cell` 토글
- **View:** build=false나 look='none'이면 쌓기 칸·블록이 없음. 쌓기 칸 크기가 workStep 모양을 드러내지 않음(열 2n+1, 행 n+1).

  - 식 `1+2+3+4+3+2+1=4×4` 입력: `exprHolds`, `exprAddends`
  - 키보드만으로 쌓기·식
  - 열을 눌러 식 수 강조, 식 수를 눌러 열 강조
  - repunit 화면
  - `step-table`·`column-link` 오버레이가 1px 안에서 맞는다
  - 크롬북·아이패드 판 전체 스냅샷
  - 키패드 맨 아래 단추가 스크롤로 닿는다
  - `fit-canvas.spec.ts`의 E15 `modes`에 `'calc-pattern'`을 더한다
