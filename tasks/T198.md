### 1. 공통
- **과제 기본값:** `submit:"button"`(6학년 48px). config는 타입에 있는 키만 쓴다.
- **힌트 규칙 순서:** 오개념 → 일반. 각 규칙에 level 1·2·3을 둔다.
- **오개념**

  | 코드 | 감지 | ① | ② | ③ |
  | --- | --- | --- | --- | --- |
  | MC-RATIO-ADDITIVE | E06 `hasMisconception`, 응답 과제는 '차 보존' 값 equals | "5가 20이 되려면 몇 배가 되었지?"(과제 수에 맞게 바꾼다) | `big-tilt`(E06) / 응답만이면 `say` | `g6s1u4.ratio-value` |
  | MC-PROPORTION-CROSS-WRONG | E06 pairSelect `hasMisconception` | "바깥쪽 두 수, 안쪽 두 수는 어느 것이었지?" | `cross-brackets` | `g6s2u4.extremes-means` |
  | MC-PROPORTION-DIVIDE-BY-RATIO-TERM | E20 `hasMisconception` | "형과 동생 몫을 합치면 35가 될까?"(과제 수에 맞게 바꾼다) | `unit-count` | `g6s2u4.proportional-distribution` |

- **일반 ③:** 그 과제 개념의 선수 개념이다.
- **정답 노출 금지**
  - 발문·힌트에 답(12, 1 : 3, 3 : 2, 9, 5, 15, 20, 30, 18, 64 등)을 쓰지 않는다. 문제의 수는 쓴다.
  - 고르기 선택지 식은 예외다.
- **힌트 문구:** 학생에게 하는 말로만 쓴다. 화면이 무엇을 그리는 조건을 설명하지 않는다.

### 2. A1 (C→P→A, E06 `proportion`)
| 과제 | 개념 | 설정 | 응답·판정 |
| --- | --- | --- | --- |
| T1 (C) | `proportion` | cards `["2 : 3 = 4 : 6", "2 : 3 = 3 : 4", "4 : 5 = 8 : 9"]` | "카드를 하나씩 저울에 올려 보고 비례식인 것을 골라요. 가: 2 : 3 = 4 : 6 나: 2 : 3 = 3 : 4 다: 4 : 5 = 8 : 9" / choice `prop` → `["ga"]` |
| T2 (C) | `extremes-means` | equation `"3 : 5 = □ : 20"`, slider 1~20 | "저울이 수평이 되도록 □를 찾아요." / `all [balanced, boxValueIs "12"]`. 18 → ADDITIVE |
| T3 (P) | `extremes-means` | equation `"2 : 3 = 4 : 6"`, `pairSelect true`, look `grid` | "넓이가 같은 두 직사각형이 되도록 곱할 두 수를 골라요." / `all [pairingCorrect, balanced]`. 짝 오류 → CROSS-WRONG |
| T4 (A) | `ratio-property` | 응답만(또는 E06 symbols `"2 : 3 = 4 : 6"`) | "0.4 : 1.2를 간단한 자연수의 비로 나타내요." / number `a`·`b`(integer) → 1, 3 |
| T5 (A) | `ratio-property` | T4와 같은 화면 | "1/2 : 1/3을 간단한 자연수의 비로 나타내요." / `a`·`b` → 3, 2. 2·3 → `say` "전항과 후항에 같은 수를 곱했나요?"(오개념 코드 없음, 일반 규칙 ①로 둔다) |
| T6 (A) | `extremes-means` | E06 equation `"7 : □ = 21 : 27"`, look `symbols`, slider 1~30 | "□에 알맞은 수를 찾아요." / `all [balanced, boxValueIs "9"]`. '차 보존' 값(13) → ADDITIVE |

- T2·T6 일반 ②는 `area-diff`다.
- T4·T5 응답 비교는 T192 방식을 따른다(1 : 3과 2 : 6 중 기약만 정답).
- 완료 기준의 "A 단계 2문제"는 T5·T6이다. 명세 과제 번호와 대응을 명세에 적는다.

### 구현 메모 (Sonnet, 2026-11-20)
- 구현 결정 그대로 만들었다. 해석한 곳만 적는다.
- **A1.T1:** 오개념 코드 없이 나(2 : 3 = 3 : 4)·다(4 : 5 = 8 : 9) 선택(둘 다 차를 지킨 카드)을 `response.prop.selected` equals로 묶어 ① "앞의 수가 몇 배가 되었는지…"·② say·③ `g6s1u4.ratio-value`. 그 밖(가를 안 고른 경우)은 일반 규칙(`mode equals proportion`), ③ `g6s2u4.ratio-property`.
- **A1.T4·T5(응답만):** `showEngine:false` + 숨은 E06 `proportion` `equation:"2 : 3 = 4 : 6"`, look `symbols`(T192 방식). 응답은 number 칸 `a`(전항)·`b`(후항), `forms:["integer"]`, 비교는 기약분수 문자열 `"1"`·`"3"`(T4), `"3"`·`"2"`(T5)이라 4 : 12 같은 안 줄인 답은 오답이다. 일반 힌트는 숨은 엔진 Observation `mode equals proportion`으로 맞는다. T5 일반 ①은 카드대로 "전항과 후항에 같은 수를 곱했나요?"(2·3 답 전용 규칙 대신 일반 ①로 뒀다).
- **A1.T6:** `look:"symbols"`라 `area-diff`·`big-tilt`가 그려지지 않아 ADDITIVE ②·일반 ②는 `say`만 있다(`show` 없음). A1.T2는 ADDITIVE ② `big-tilt`·일반 ② `area-diff`, A1.T3은 CROSS ② `cross-brackets`, 일반 ②는 `say`만.
- **A2.T6:** 카드는 "T1 문제, look symbols"라고만 해서 형광펜은 `highlight:null`(없음)로 했다. 형광펜이 있으면 symbols에서 막대는 안 보이지만 형광펜 단계가 남을 수 있어서다(T6 판정은 식·몫만 본다). 형광펜은 T1·T4에서 이미 한다.
- **A2.T5:** 거꾸로 문제(형 24 고정, 전체 입력). 오개념 DIVIDE는 몫의 합이 어긋날 때 잡히므로 ①은 "형 몫과 동생 몫이 비 3 : 5에 맞는지 확인해 봐요."로 썼다. 일반 ①은 "알려 준 형의 몫 24개는 막대 몇 칸일까요?".
- **A2 형광펜 오답 규칙:** T4는 `highlightCorrect equals false`로 DIVIDE 다음, 일반 앞에 둔다. T1은 일반 규칙 하나가 형광펜 ①·②·③을 겸한다. 형광펜 ③은 `g6s1u4.ratio-notation`(비 표기 읽기).
- **③ 역추적 선택:** ADDITIVE → `g6s1u4.ratio-value`, CROSS → `g6s2u4.extremes-means`, DIVIDE → `g6s2u4.proportional-distribution`(카드 표). 일반은 선수 개념: extremes-means 과제 → `proportion`, proportion·ratio-property 과제 → `ratio-property`·`g6s1u4.ratio-value`, 비례배분 → `ratio-property`.
