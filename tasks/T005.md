## 목표
`data/content/<unitId>.json`을 읽어 과제를 순서대로 보여 주고 채점·기록하는 실행기를 만든다.

## 먼저 읽을 문서
- docs/02-architecture.md §3
- docs/04-units/_template.md

## 할 일
- [ ] 콘텐츠 JSON 스키마(zod 등으로 검증) 정의: unit → activities → tasks(engine, mode, cpa, config, goal, hints, concepts, submit)
- [ ] GoalSpec 평가기(equals, equivalent-expr, predicate, all, any) — predicate는 엔진이 이름으로 등록
- [ ] 과제 진행: 시작/조작/제출/통과/실패 이벤트 기록, submit 'auto'|'button'
- [ ] 엔진 이벤트 연결(core/runner에서 엔진 A의 이벤트 → 엔진 B의 Action) 메커니즘 — 같은 화면에 두 엔진(예: E01+E07) 배치 지원. `linkedViews`(같은 수를 여러 엔진으로 나란히 동기화, docs/03 부록) 포함
- [ ] 예제 콘텐츠 `data/content/demo.json`(E00-demo 과제 3개)
- [ ] 콘텐츠 검증 스크립트를 `check:specs`에 연결(콘텐츠의 unit/engine/concept ID가 실제로 있는지)

## 건드리지 말 것
