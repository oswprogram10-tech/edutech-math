## 구현 결정 (2026-11-03 Claude 작성 — 여기 적힌 대로 하고, 바꿔야 하면 메모에 이유를 적고 질문한다)
**공통(T020 g3s1u6을 본보기로 삼는다)**
1. **파일·형식:** `data/content/g3s2u4.json` 하나. 콘텐츠 스키마를 따르고 `views`/`links`, `response`, `showEngine`, `hints`, `hintVars`, `diagnose`를 쓴다. 과제 ID는 `<활동ID>.T<n>`, `concepts`는 명세의 개념 노드 ID(과제마다 1~2개).
2. **CPA:** 활동 안에서 C → P → A 순서. A 과제는 `showEngine:false` + 응답 위젯이 기본. 학생 화면 문구에 학년·단원 ID를 쓰지 않는다.
3. **정답 노출 금지:** E05는 `showValue`를 켜지 않는다(기본 `none` — 명세 A1의 "12의 3/4 = 9" 표시는 과제 2의 답이므로 켜지 않는다). E03에서 점 찍기·카드 꽂기가 판정인 과제는 `"labels": "partial"`. 발문·힌트·선택지 이름에 그 과제의 정답 값을 쓰지 않는다.
4. **힌트:** 과제마다 ①(발문)·②(`show` 오버레이)·③(`backtrack`, 명세 오개념 표의 ③ 열). 발문은 docs/05 §4(학생이 만든 것을 언급, "어떻게/왜/몇" 질문, 정답 수치 금지)를 따르고, 풀이 절차를 그대로 지시하는 문장과 오개념을 부추기는 문장을 쓰지 않는다. 오개념 규칙(`when`)을 일반 규칙보다 앞에 둔다. 오버레이는 이미 있는 것만 쓴다.
5. **오개념 감지:** `src/core/math/diagnose.ts`에 감지기가 있는 코드(`MC-FRAC-MIXED-CONVERT`, `MC-FRAC-BIGGER-DENOM`)는 `diagnose`로, 없는 코드는 그 과제의 **대표 오답을 GoalSpec `when`으로 직접 적어** 힌트 규칙에 건다(예: 12의 1/3에 "3" → `{ "kind":"equals", "path":"response.ans.value", "value":"3" }` = `MC-FRAC-DISCRETE-COUNT`). 명세 표의 코드 6개마다 감지 테스트를 하나씩 둔다. 이 단원 과제로 감지 규칙을 만들 수 없는 코드는 메모에 적는다.
6. **엔진·core 수정 금지:** 아래 과제별 결정은 지금 엔진·실행기 기능만으로 만들 수 있게 정했다. 그래도 엔진 추가가 필요하면 **진행을 멈추고 메모로 묻는다**(같은 묶음의 T024와 같은 E05 파일을 동시에 고치면 병합 충돌이 난다).
7. **E2E·화면:** `tests/e2e/units/g3s2u4.spec.ts`(3개 뷰포트) — 과제마다 정답 조작 → 통과, 대표 오답 → 힌트 ①(정답 값은 DOM에 없음), 활동마다 첫 화면 스크린샷, 크롬북·전자칠판에서 응답 칸과 '확인하기'가 첫 화면 안에 있는지, 오프라인에서 첫 활동이 열리는지.
8. **상태:** `data/units.json`의 `status`는 바꾸지 않는다.

**과제별**
9. **A1(E05 `discrete`):** 과제 1 = 12개를 3개씩(엔진 `groupSize` 3, `groups` 4) + 응답 분수 1/4. 과제 2 = 4묶음 중 3묶음 선택(`selectedGroups` 3개) + 응답 9. 과제 3 "사탕 4개는 12의 얼마? 두 가지로"는 **응답 분수 필드 2개**(라벨 '4개씩 묶으면', '2개씩 묶으면')로 하고, 판정은 `raw`가 각각 `"1/3"`, `"2/6"`이다(필드 순서를 고정해 '서로 다른 두 표현'을 GoalSpec으로 판정). `MC-FRAC-GROUP-AS-UNIT`는 `raw`가 `"4/12"`인 경우를 `when`으로 건다. 과제 4 = items 18, 18의 2/3 → 12. 과제 5(A) = `showEngine:false`, 20의 3/5 → 12.
10. **A2(E05 `mixed`):** 과제 1(진분수·가분수·대분수 분류)은 `sort` 위젯(카드 3/5, 7/5, 1 2/5, 5/5, 상자 3개), `showEngine:false`. `MC-FRAC-IMPROPER-INVALID`는 상자에 '분수가 아니에요'를 하나 더 두고 가분수를 그곳에 넣은 경우를 `when`으로 건다. 과제 2 = 11/4을 융합 2회(`eventAtLeast` fused 2) + 응답 대분수 `raw` `"2 3/4"`. 과제 3 = 2 1/3 풀기(break-whole 2회) + 응답 가분수 7/3, `diagnose` `MC-FRAC-MIXED-CONVERT`. 과제 4(A) = 응답 필드 2개(13/5 → 대분수, 3 2/7 → 가분수), `showEngine:false`. 명세의 `conveyorSpeed`는 엔진에 없는 키이므로 넣지 않는다.
11. **A3(E03 `fraction` 0~3):** 과제 1 = `cards` 6장 꽂기, `cardsCorrect`, `labels:"partial"`. 과제 2 "같은 수 짝"은 카드를 꽂은 상태에서 `choice` 필드 2개('5/4와 같은 점의 카드', '11/4와 같은 점의 카드')로 판정한다. 과제 3 = 7/3과 2 2/3 비교(이 과제만 `subdivisions: 3`), `compare` 위젯 `<`. 과제 4(A) = 9/5와 12/5 `compare`, `showEngine:false`. 과제 5(A) = "1 3/8과 12/8 중 큰 수"는 `choice`(단일) — `MC-FRAC-WHOLE-COMPARE-ONLY`는 1 3/8을 고른 경우를 `when`으로 건다.

## 메모
- **`data/units.json` 상태:** g3s2u4 `status`는 `spec` 그대로 두었다. 운영자가 수업에 써 보고 확인한 뒤 올린다.
- **힌트 ②(시각적 반례) 대체:** 이 단원 과제 중 E05 `discrete`/`mixed`(A1 전체, A2 T2~T4), `sort` 위젯(A2 T1), E03 카드 꽂기(A3 T1·T2), `showEngine:false`인 A3 T4·T5에는 지금 있는 오버레이(E05 `grid-reveal`, `size-compare` / E03 `distance-from-zero`, `same-point`)를 그대로 쓸 수 없다. 이 과제들은 ② 단계를 레벨 2 `say` 질문으로 두었다. 오버레이는 A3 T3(7/3과 2 2/3 비교, E03 `same-point`)에만 썼다. 새 오버레이를 만들려면 엔진 수정이 필요하므로 카드 규칙에 따라 손대지 않았다.
- **`MC-FRAC-BIGGER-DENOM` 한계:** 이 단원의 비교 과제는 분모가 같은 짝(9/5와 12/5, 7/3과 2 2/3)이라 "분모가 클수록 크다" 오개념이 성립할 수 없다. 감지기를 억지로 만들지 않고, A3 T3의 대표 오답 `>`를 GoalSpec `when`(`response.cmp.symbol == ">"`)으로 걸어 힌트만 연결했다. 이 단원 과제만으로는 이 코드를 실제로 진단할 수 없다.
- **나머지 오개념 코드:** `MC-FRAC-MIXED-CONVERT`는 `src/core/math/diagnose.ts` 감지기를 `diagnose`로 썼다(A2 T3·T4). 감지기가 없는 `MC-FRAC-DISCRETE-COUNT`(A1 T2·T4·T5의 대표 숫자 오답), `MC-FRAC-GROUP-AS-UNIT`(A1 T3 `raw` `4/12`), `MC-FRAC-IMPROPER-INVALID`(A2 T1 '분수가 아니에요' 상자), `MC-FRAC-WHOLE-COMPARE-ONLY`(A3 T5 `1 3/8` 선택)는 카드 지시대로 대표 오답을 GoalSpec `when`에 직접 적었다. 코드 6개 모두 E2E에서 대표 오답 → 힌트 ①로 확인한다.
- **E05 묶음 탭:** E05 `discrete`에서 사탕 아이콘이 묶음 사각형 위에 그려져, 아이콘을 직접 누르면 사각형의 `onClick`이 아니라 아이콘에서 이벤트가 끝난다. 사각형 여백을 누르거나 키보드 Enter로는 고를 수 있어 E2E는 Enter를 썼다. 학생이 사탕을 눌러도 묶음이 선택되게 하려면 E05 View 수정이 필요하다(이 카드에서는 엔진 수정 금지라 손대지 않음, 후속 카드 제안).
- **E2E 카드 선택:** E03 카드 `<g>`는 Playwright 포인터 클릭이 선택으로 이어지지 않아 카드에 `Enter`를 보낸 뒤 수직선을 눌렀다. 엔진의 키보드 대체 조작 경로를 그대로 쓴 것이다.
- **다른 카드 E2E 영향:** g3s2u4 콘텐츠가 켜지면서 `tests/e2e/star-map.spec.ts`의 처음 보기 배율(400% → 375%)과 켜진 별 수(5 → 9)가 달라졌다. 값을 박지 않고 처음 배율을 잡아 되돌아오는지, 켜진 별을 모두 지도 안에서 확인하도록 고쳤다. `tests/e2e/response.spec.ts`의 demo.A3 ③ 부스터는 `MC-FRAC-ADD-DENOM` → `g4s2u1.unit-fraction-count`의 선수인 `g3s2u4.improper-mixed`가 콘텐츠를 갖게 되면서 `g3s2u4.A2`(가분수·대분수)로 바뀌었다. 부스터 활동을 알아보고 두 경우 모두 통과시키도록 고쳤다. `src/core/`는 바꾸지 않았다.
