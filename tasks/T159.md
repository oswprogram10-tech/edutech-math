### 1. 공통
- **과제 기본값:** `engine:"E18"`, `submit:"button"`이다. 일반 규칙의 `when`은 그 과제의 `mode`를 equals로 본다.
- **자료:** 마을별 사과 수확 `{"가":32,"나":25,"다":41,"라":18}`, 단위 "상자"(`valueLabel`), 아이콘 `apple`
- **3학년 문구:** 교과서 말 "그림그래프", "큰 그림", "작은 그림"을 쓴다.
- **정답 노출 금지:**
  - 발문·힌트·라벨에 행 값, "다 마을이 가장 많아요" 같은 결론을 쓰지 않는다.
  - 그림그래프를 읽는 A2에서는 표를 보이지 않는다(`views:["pictograph"]`). 말풍선은 `tooltips:"hide"`다. 표가 보이면 읽을 것이 없어지기 때문이다.
  - 명세의 "P: 아이콘 위 값 툴팁"은 쓰지 않는다. 이 결정을 메모에 적는다.
- **그림그래프를 만드는 A1:** 표가 출처이므로 `table:"given"`이다.
- **오개념**(T154 레지스트리, `diagnose`):
  - `MC-GRAPH-ICON-VALUE`: 수 감지, args `icons`
  - `MC-GRAPH-ICON-COUNT-COMPARE`: 고르기, trapChoice
- **③:** 오개념 규칙은 레지스트리 backtrack이고, 일반 규칙은 그 과제의 첫 concept다.

### A1 `g3s2u6.A1` "아이콘 압축 그림그래프 만들기" (C→P→A, 4과제)
2. **A1.T1 그림그래프 완성 (C).** concepts `["g3s2u6.pictograph-units"]`
   - 발문: "표를 보고 그림그래프를 완성해요. 작은 그림 10개는 큰 그림 1개로 묶어요."
   - config: `{"mode":"pictograph","data":{…},"icon":"apple","legend":{"big":10,"small":1},"build":"student","table":"given","valueLabel":"상자"}`
   - 응답 칸 없음. 판정: `all`(`rowsMatchData`, `allRowsCompressed`)
   - **상태 규칙**(일반 앞)
     - when: `rowsMatchData`(값은 맞지만 묶지 않은 행이 있음)
     - ①: "작은 그림이 10개 넘게 있는 줄이 있나요?"
     - ②: `say`만 "올가미로 작은 그림 10개를 묶거나 '묶기' 단추를 눌러 봐요."
     - ③: 공통
   - 일반: ① "줄마다 큰 그림과 작은 그림이 몇 상자인지 세어 볼까요?" / ② `say`만 "큰 그림 1개는 10상자, 작은 그림 1개는 1상자예요." / ③ 공통
   - E2E
     - 가 줄을 작은 그림 32개로만 채우고 나머지도 작은 그림으로 → 상태 ①
     - 묶어서 정답 → 통과
     - 나 줄 하나 틀림 → 일반 ①
3. **A1.T2 줄어든 그림 수 (P).** concepts `["g3s2u6.pictograph-units"]`
   - 발문: "가 마을 줄에서 작은 그림만으로 나타낼 때와 묶어서 나타낼 때, 그림은 몇 개 줄었나요?"
   - config: A1.T1과 같고 `"data":{"가":32}`(한 줄)이다.
   - 응답: 수 칸 `fewer`
   - 판정: `all`(`rowValueIs {cat:"가",value:32}`, `allRowsCompressed`, `fewer`=27)
   - 일반: ① "묶기 전 그림 수와 묶은 뒤 그림 수를 각각 세어 볼까요?" / ② `say`만 "묶기 전 그림 수에서 묶은 뒤 그림 수를 빼 봐요." / ③ 공통
   - E2E
     - 묶기 전 32 그대로 답 → 일반 ①
     - 묶은 뒤 27 → 통과
4. **A1.T3 큰 그림 = 5 (P).** concepts `["g3s2u6.pictograph-units"]`
   - 발문: "범례를 큰 그림 = 5상자로 바꾸고, 그림그래프를 다시 나타내요."
   - config: A1.T1 + `"legendEditable":true,"legendOptions":[10,5],"legendChange":"keep-icons"`
     - 처음 그림은 비어 있다(학생이 처음부터 다시 만든다).
   - 판정: `all`(`legendIs {big:5}`, `rowsMatchData`, `allRowsCompressed`)
   - **상태 규칙**(일반 앞)
     - when: `rowsMatchData`이고 legend가 10
     - ①: "범례를 바꿨나요?"
     - ②: `say`만 "범례에서 큰 그림 = 5를 골라 봐요."
     - ③: 공통
   - 일반: ① "큰 그림 1개가 이제 몇 상자인지 범례를 볼까요?" / ② `say`만 "작은 그림 5개를 큰 그림 1개로 묶어 봐요." / ③ 공통
   - E2E
     - 범례 10인 채 정답 그래프 → 상태 ①
     - 범례 5로 바꾸고 다시 만들기 → 통과
     - 범례 5에서 10개씩 묶은 모양(값 틀림) → 일반 ①
5. **A1.T4 학급 자료 (A).** concepts `["g3s2u6.collect-organize","g3s2u6.pictograph-units"]`
   - 발문: "우리 반이 좋아하는 계절을 그림그래프로 나타내요."
   - config: `{"mode":"pictograph","data":{"봄":12,"여름":15,"가을":9,"겨울":6},"icon":"person","legend":{"big":10,"small":1},"build":"student","table":"given","valueLabel":"명"}`
     - 명세의 "교사가 입력한 자료"는 1단계에서는 콘텐츠에 넣은 예시 자료로 한다. 교사 입력 화면은 후순위다.
     - `docs/04-units/g3s2.md` g3s2u6 후순위·선택에 이 한 줄을 더한다. 다른 문장은 바꾸지 않는다.
   - 판정·일반: A1.T1과 같다(문구의 "상자"는 "명"으로 바꾼다).

### A2 `g3s2u6.A2` "그림그래프 읽기와 해석" (P→A, 3과제)
6. **공통 설정:** `{"mode":"table-to-graph","data":{…사과 자료},"views":["pictograph"],"legend":{"big":10,"small":1},"icon":"apple","tooltips":"hide","valueLabel":"상자","title":"마을별 사과 수확량"}`
   - 응답 칸이 있다(두 칸 배치). 그림그래프가 given이라 누르는 그림이 없다.
7. **A2.T1 다 마을 값 (P).** concepts `["g3s2u6.read-pictograph"]`
   - 발문: "다 마을에서 수확한 사과는 몇 상자인가요?"
   - 응답: 수 칸 `value`. 판정: `value` = 41
   - **MC-GRAPH-ICON-VALUE**
     - diagnose: `{"code":"MC-GRAPH-ICON-VALUE","args":{"icons":"5","expected":"41"},"path":"response.value.value"}`(path 모양은 g2s2u5·기존 단원과 같게)
     - ①: "큰 사과 하나는 몇 상자였지? 범례를 볼까?"
     - ②: `show {"engine":"E18","overlay":"expand-icons","args":{"cat":"다"}}` + "큰 그림 하나를 작은 그림으로 펼쳐 봐요."
     - ③: 레지스트리 값
   - 일반: ① "큰 그림과 작은 그림을 따로 세어 볼까요?" / ② `say`만 "큰 그림은 10상자, 작은 그림은 1상자씩 더해 봐요." / ③ 공통
   - E2E
     - 5 → MC ①
     - 다시 → ②와 `expand-icons`, 정렬 1px
     - 40 → 일반 ①
     - 41 → 통과
8. **A2.T2 가장 많은 곳과 가장 적은 곳의 차 (A).** concepts `["g3s2u6.read-pictograph"]`
   - 발문: "사과를 가장 많이 수확한 마을과 가장 적게 수확한 마을의 차는 몇 상자인가요?"
   - 응답: 수 칸 `diff`. 판정: `diff` = 23
   - 일반: ① "가장 많은 마을과 가장 적은 마을의 값을 먼저 읽어 볼까요?" / ② `say`만 "두 값을 읽은 뒤 큰 값에서 작은 값을 빼 봐요." / ③ 공통
9. **A2.T3 그림 개수와 값 (P).** concepts `["g3s2u6.read-pictograph"]`
   - 발문: "그림 개수가 가장 많은 마을은 라 마을이에요. 라 마을이 사과를 가장 많이 수확했을까요?"
     - 라는 그림 9개(큰 1 + 작은 8)로 가장 많지만 값은 가장 작다. 명세의 "반례 그래프"를 이 자료로 대신한다.
   - 응답: 고르기 `most`: `yes` "네, 가장 많아요" / `no` "아니요, 아니에요"
   - 판정: `most`=["no"]
   - **MC-GRAPH-ICON-COUNT-COMPARE**
     - diagnose trapChoice `{"trap":"yes"}`, path `response.most.selected.0`
     - ①: "큰 그림 1개와 작은 그림 9개 중 무엇이 더 많을까?"
     - ②: `show {"engine":"E18","overlay":"expand-compare","args":{"cats":["라","다"]}}` + "두 줄을 모두 작은 그림으로 펼쳐 길이를 비교해 봐요."
     - ③: 레지스트리 값
   - E2E
     - yes → MC ①, 다시 → ②와 `expand-compare`, 정렬 1px
     - no → 통과
10. **완료 기준:** 명세(A1 과제 1·3 통과, A2 3개 통과)를 활동 메모에 적는다. T157처럼 스키마에 키가 없으면 JSON에 넣지 않는다.
