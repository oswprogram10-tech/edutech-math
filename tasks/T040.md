## 구현 결정 (2026-11-04 Claude 작성 — 여기 적힌 대로 하고, 바꿔야 하면 메모에 이유를 적고 질문한다)
1. **폴더:** `src/engines/E02-counters/`, E05·E07과 같은 구조(`index.ts`, `types.ts`, `reduce.ts`, `observe.ts`, `events.ts`, `View.tsx`, `View.module.css`, `strings.ko.ts`, `icons.tsx`, `overlays/`, `__tests__/`). 엔진 ID `E02`, 이름 "셈돌", modes 순서 `summon`, `ten-frame`, `part-whole`, `flash`. 확장 모드(`rekenrek`, `pairing`, `share`, `measure-out`)와 part-whole 변형(`bubble-pairs`, `bridge`)은 T041 몫이므로 만들지 않는다. 다만 `PartWholeConfig`에 `variant?: 'plates'` 자리를 두어 T041이 넓힐 수 있게 한다.
2. **좌표·수:** 논리 캔버스 1000×600 SVG(`preserveAspectRatio` 기본 meet), 누른 위치는 SDK `pointerToLogical`로 바꾼다(직접 계산 금지). 셈돌 위치는 논리 좌표 정수로 상태에 둔다. 개수는 0 이상의 정수(number)다. 소수·분수가 없으므로 `Rational`은 쓰지 않는다.
3. **셈돌 모양(icons.tsx):** 외부 이미지 없이 인라인 SVG 아이콘 8종: `apple`, `fish`, `bird`, `balloon`, `candy`, `strawberry`, `star`, `dot`(단색 원). 설정 `icon`(기본 `dot`). CPA: C는 아이콘 + 낙하 연출(CSS transform, `prefers-reduced-motion`이면 끔), P는 `dot`, A는 엔진이 그림 없이 상자만 그린다(A 과제는 대개 콘텐츠가 `showEngine:false`). 색 두 가지(`red`/`blue`)는 색과 함께 **무늬(속 찬 원 / 가운데 점 원)**로 구분한다(색만으로 정보 전달 금지).
4. **summon:** 설정 `max`(기본 10), `shelf`(기본 true), `input`(`["multitouch","tap","buttons"]` 중 부분집합, 기본 전부), `icon`, `start`(처음 셈돌 수, 기본 0), `showNumeral`(`"never"` 기본 / `"always"`). 선반 영역을 여러 손가락으로 동시에 누르면 SDK `useMultiTouchCount`의 활성 pointer 수만큼 한 번에 생긴다(Action `summon {count}` 하나). `tap`은 누를 때마다 1개(`summon {count:1}`). `buttons`는 숫자 버튼 1~9가 그 수만큼 더한다. `max`를 넘는 만큼은 생기지 않는다. 셈돌은 선반에 왼쪽부터 줄 선다(위치는 reduce가 정한다). 셈돌을 끌어 휴지통으로 → `remove {id}`. `"after-submit"`은 실행기가 제출 결과를 엔진에 알리지 않으므로 지원하지 않는다(`never`로 취급하고 메모에 core 요청으로 남긴다).
5. **ten-frame:** 설정 `frames`(1|2), `prefill`(첫 프레임에 미리 놓인 빨간 셈돌 수) 또는 `left`/`right`(이중 프레임 각각의 개수), `fillColor`(학생이 놓는 셈돌 색, 기본 `blue`), `trayCount`(끌어 쓸 셈돌 상자 개수, 기본 10), `swipeFill`(boolean), `showBond`(`"never"` / `"after-move"`), `removable`(기본 true). 칸은 2×5. 셈돌을 칸 근처에 놓으면 가장 가까운 빈칸에 붙는다(SDK `snapToPoints`). 프레임 밖으로 끌어 내면 빠진다(`take-out`). `swipeFill`: 오른쪽 프레임에서 왼쪽 프레임 쪽으로 쓸면(끌기 거리 ≥ 칸 2개, 방향 왼쪽) **왼쪽 빈칸 수만큼만** 넘어간다(`swipe-fill {from, to}`). 키보드 대체: 프레임에 포커스 + `←`로 같은 Action. 넘긴 뒤 `showBond: "after-move"`면 넘긴 쪽 수의 가르기 나무(예: 5 → 2, 3)를 그린다.
6. **part-whole(plates):** 설정 `total`(셈돌 전체 수) 또는 `groups`(접시별 처음 개수 배열, 예 `[3,2]`), `parts`(접시 수, 기본 2), `gesture`(`["pinch","drag","divider-button"]`), `showBond`(boolean, 기본 true), `icon`, `scene`(선택, 아래 7번). 셈돌을 끌어 접시 사이로 옮긴다(`move {id, plate}`). 두 손가락으로 두 접시를 모으면(SDK `usePinch`의 축소 제스처, 두 포인터가 각각 다른 접시 위에서 시작) 한 접시로 합친다(`merge {from, to}`). `divider-button`은 한 접시의 셈돌을 반으로 가르는 대신 **칸막이 위치를 학생이 고르게** 한다(접시 아래 −/+ 버튼으로 왼쪽 몫을 1개씩 바꾸는 `set-split {plate, left}`). 가르기 나무: 위 동그라미 = 전체 수, 아래 = 접시별 수(학생이 만든 상태 그대로 보여 주므로 정답 노출이 아니다). **"기록하기" 버튼**(`record-split`)이 지금 두 접시 수를 순서쌍으로 `recorded`에 쌓는다(같은 쌍은 다시 쌓지 않는다) — "다르게 가르는 방법 3가지" 판정용.
7. **scene(이야기 그림):** `scene: { icon, kind: "join" | "remove" | "compare", numbers: [a, b] }`. 엔진이 위쪽에 정지 그림(아이콘 a개 + b개, remove는 b개에 × 표시, compare는 두 줄)을 그린다. 학생은 아래 접시에서 셈돌로 다시 만든다. compare는 두 줄 셈돌을 하나씩 짝짓는 `pair {a, b}` Action이 있고, 짝 지은 선을 그린다. 식 카드·수 입력은 응답 위젯(T016) 몫이다. 음성(STT)은 만들지 않는다.
8. **flash:** 설정 `count`(보여 줄 수, 1~10) 또는 `range`+`seed`, `layout`(`"dice"` / `"ten-frame"` / `"fingers"` / `"random"`), `displayMs`(기본 1500, 500~3000으로 자른다), `seed`(정수, `random` 배치·`range`에서 고른 수를 정한다). **무작위는 createInitialState에서 seed로 한 번 정하고 reduce에서 쓰지 않는다**(되감기·미러링에서 같은 그림). 상태 `phase`: `ready` → (보기 버튼 `show`) → `showing` → (View가 `displayMs` 뒤 `hide` dispatch) → `hidden`. `hidden`에서 "다시 보기" 버튼은 없다(한눈에 세기 과제의 뜻을 지킨다). 반응 시간은 엔진이 재지 않는다(이벤트 로그의 시각으로 나중에 계산, 메모에 남김). `afterReveal`(정답 뒤 여러 표상)은 제출 결과 신호가 없으므로 이번에 만들지 않고 메모에 core 요청으로 남긴다.
9. **Observation(모드 공통 + 모드별):** `mode`, `total`(놓인 셈돌 수). summon: `total`. ten-frame: `frameFill: number[]`(프레임별), `total`, `full: boolean[]`, `moves`(swipe 횟수), `bond: [whole, a, b] | null`, `madeTenFirst`(처음 가득 찬 프레임이 생긴 Action이 다른 프레임을 비우기 전에 있었는지), `subtractStrategy`(`"from-ten"` / `"sequential"` / `null` — 13−5처럼 셈돌을 뺄 때 처음 뺀 프레임이 가득 찬 프레임이면 from-ten). part-whole: `plates: number[]`, `total`, `recorded: [number, number][]`(정렬된 쌍), `distinctSplits`(순서 무시 개수), `pairs`(compare 짝 수), `unpaired`(짝 없는 셈돌 수). flash: `phase`, `shown`(보여 준 수 — `phase`가 `showing` 이후에만 값, 화면 문구에 쓰지 않는다), `layout`.
10. **Predicates:** `totalIs {value}`, `frameFillIs {frame, value}`, `platesAre {values, ordered?}`, `distinctSplitsAtLeast {count, total}`, `allPlatesAtLeast {min}`, `unpairedIs {value}`.
11. **이벤트:** `value-changed {value}`(total이 바뀔 때, E05·E07과 같은 모양), `frame-filled {frame}`, `split-recorded {a, b}`.
12. **정답 노출 금지:** 수 카드·셈돌 개수 숫자는 `showNumeral:"always"`일 때만 보인다(기본 숨김). flash는 숨긴 뒤 그 수를 어디에도 쓰지 않는다. 가득 찬 프레임의 반짝임은 상태 표시라 괜찮지만 "10!" 같은 숫자 문구는 `showNumeral:"always"`일 때만.
13. **입력·접근성:** Pointer Events만. 셈돌·칸·버튼 터치 타깃은 `targetSize` 이상(저학년 64px — 1학년 단원이 대부분이므로 E2E는 64로도 한 번 돈다). 키보드: Tab으로 셈돌·칸·접시 이동, Space/Enter로 집기·놓기, 방향키로 옮길 접시·칸 고르기, `Delete`로 빼기. 멀티터치가 안 되는 기기(크롬북·전자칠판)는 tap·buttons로 같은 과제를 끝낼 수 있어야 한다.
14. **오버레이(힌트 ②):** `count-ones`(셈돌마다 1, 2, 3 … 순서 번호를 잠깐 붙인다 — 학생이 놓은 것을 세어 보이는 것이지 목표 수가 아니다), `frame-gaps`(빈칸에 점선 동그라미), `bond-tree`(지금 접시 수로 가르기 나무), `pair-lines`(compare에서 짝 없는 셈돌 강조).
15. **물리:** Matter.js 등 물리 엔진은 쓰지 않는다(번들). 낙하는 CSS 연출만.
16. **테스트:** reduce·observe 단위(summon max·0개, swipe가 빈칸만큼만 넘어감, 13−5 전략 두 가지, 기록한 가르기 중복 제거·순서 무시, flash seed 결정성·`hide` 뒤 shown 유지, `assertSerializable`), View 테스트(기본 상태에서 개수 숫자가 DOM에 없음), `#/sandbox/E02` E2E 3개 뷰포트: tap으로 7개 만들기, 이중 프레임 8+5 swipe → `frameFill [10,3]`, 키보드만으로 part-whole 6을 (2,4)로 가르고 기록.
