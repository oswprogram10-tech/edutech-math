# 08. 코딩 에이전트와 일하는 방법

Claude(Claude Code), Codex, OpenCode 세 에이전트를 함께 쓰는 운영 규칙이다. 핵심은 **한 번에 한 작업 카드, 서로 다른 폴더, 다른 에이전트가 리뷰**다.

## 1. 처음 한 번 준비 (Windows)
1. Node.js LTS, Git, VS Code 설치. GitHub 계정에 **공개** 저장소 생성(실제: `oswprogram10-tech/edutech-math`). 무료 계정은 비공개 저장소에서 GitHub Pages를 쓸 수 없어서 공개로 정했다(2026-11-02). 공개이므로 학생 정보·API 키·개인 이메일은 절대 커밋하지 않는다. 커밋 작성자 이메일은 GitHub noreply 주소를 쓴다.
2. **저장소 위치:** 경로에 한글·공백이 있으면 일부 개발 도구가 오작동할 수 있다. 가능하면 `C:\dev\MathExplorer`처럼 영문 경로에 두고, 바탕화면의 `수학 에듀테크` 폴더에는 바로가기를 둔다. (지금 문서는 `수학 에듀테크\MathExplorer`에 있으니 그대로 옮기면 된다.)
3. 이 폴더를 저장소 첫 커밋으로 올린다.
4. 첫 작업: 에이전트에게 `tasks/T001.md를 수행해 줘`.

## 2. 세 에이전트가 읽는 파일
- **Codex, OpenCode:** 저장소 루트의 `AGENTS.md`를 자동으로 읽는다.
- **Claude Code:** `CLAUDE.md`를 읽는다. 이 저장소의 `CLAUDE.md`는 `AGENTS.md`를 따르라고만 적혀 있다 → 규칙은 `AGENTS.md` 한 곳에서만 고친다.

## 3. 작업 흐름

```
작업 카드 고르기 (tasks/Txxx.md, 상태 todo)
   ↓
에이전트 A에게 맡김: 새 브랜치 task/Txxx 에서 작업
   ↓
에이전트 A가 끝나면: 테스트 통과 + 카드의 '완료 확인' 체크 + PR(또는 브랜치) 
   ↓
에이전트 B에게 리뷰 요청 (A와 다른 에이전트)
   ↓
선생님이 직접 실행해서 확인 (npm run dev → 태블릿으로 접속)
   ↓
main에 합치기, 카드 상태 done
```

### 동시에 여러 에이전트를 돌릴 때
- **서로 다른 엔진 폴더**를 맡기면 동시에 돌려도 충돌이 거의 없다. 예: Codex는 `E05`, OpenCode는 `E03`.
- `src/core/`와 `data/units.json`은 **한 번에 한 에이전트만** 고친다. 엔진 작업 중 core 변경이 필요하면 에이전트가 직접 고치지 말고 작업 카드에 "core 변경 요청"을 적게 한다 → 선생님이 별도 카드로 처리.
- 각 에이전트는 별도 브랜치(가능하면 git worktree)에서 작업한다.

### 역할 나누기 (제안 — 써 보면서 바꿔도 된다)
| 작업 종류 | 맡길 에이전트 | 리뷰 |
| --- | --- | --- |
| core(수학 코어, SDK, 실행기, 지식 그래프) | 가장 신뢰하는 에이전트 하나로 고정 | 다른 에이전트 |
| 엔진 구현 | 세 에이전트가 나눠서 병렬 | 다른 에이전트 |
| 단원 콘텐츠 JSON(과제·힌트) | 아무나 — 명세를 옮기는 작업 | 선생님이 수학적으로 확인 |
| 테스트 보강·버그 수정 | 아무나 | — |

## 4. 에이전트에게 줄 말 (복사해서 사용)

**작업 시작**
```
tasks/T0xx.md 작업 카드를 수행해 줘.
AGENTS.md 규칙을 지키고, 카드의 '건드리지 말 것'에 있는 파일은 수정하지 마.
끝나면 npm test와 npm run test:e2e를 돌려서 통과한 결과를 보여 주고,
카드의 '완료 확인' 항목을 하나씩 체크한 결과를 알려 줘.
```

**리뷰 요청 (다른 에이전트에게)**
```
브랜치 task/T0xx 의 변경을 리뷰해 줘. 기준:
1) 작업 카드 tasks/T0xx 의 요구사항을 모두 만족하는가
2) AGENTS.md 규칙(엔진 간 import 금지, 부동소수 금지, 정답 노출 금지 등) 위반이 있는가
3) 테스트가 실제로 동작을 검증하는가(항상 통과하는 테스트는 아닌가)
4) 아이패드 Safari에서 문제가 될 API를 썼는가
수정은 하지 말고 문제 목록만 심각도 순으로 알려 줘.
```

**단원 콘텐츠 만들기**
```
docs/04-units/g5s1.md 의 g5s1u4 명세를 보고 data/content/g5s1u4.json 을 만들어 줘.
과제마다 E2E 테스트(정답 조작 통과, 대표 오답 → 힌트 ①)도 tests/e2e/units/g5s1u4.spec.ts 에 추가해 줘.
```

**명세가 이상할 때**
에이전트가 "명세대로는 구현이 어렵다"고 하면, 억지로 진행시키지 말고 이유를 들은 뒤 `docs/`를 먼저 고치게 한다. 명세와 코드가 어긋나기 시작하면 다음 에이전트가 헷갈린다.

## 4-1. Claude Code의 두 가지 개발 방식 (2026-11-04)
Claude Code 세션(Opus)에서 아래 명령으로 쓴다. 명령 정의는 저장소가 아니라 선생님 계정의 Claude Code 사용자 설정(`~/.claude/skills/`, `~/.claude/agents/`)에 있어 모든 프로젝트에서 같이 쓴다. 이 저장소에만 해당하는 규칙은 아래 '이 저장소의 정해진 값'에 둔다.

| 방식 | 명령 | 기획·검수 | 구현 |
| --- | --- | --- | --- |
| A | `/plan-sonnet T0xx` | Opus | 소넷 서브에이전트 `card-implementer`(브랜치 `task/Txxx-sonnet`) |
| B | `/plan-handoff T0xx` | Opus | 선생님이 프롬프트를 붙여 넣은 다른 LLM(브랜치 `task/Txxx-<agent>`, 기본 OpenCode) |
| 공통 검수 | `/review-task` | Opus | — |

두 방식 모두 Opus가 카드의 '구현 결정'을 먼저 채우고, 구현 쪽은 푸시·main 병합을 하지 않는다. 병합·푸시는 선생님 승인 뒤 Opus가 한다.

### 이 저장소의 정해진 값
- **작업 카드:** `tasks/Txxx.md`(`tasks/_TEMPLATE.md` 형식). 선행 관계는 `tasks/README.md`, 진행 상황은 `docs/00-handoff.md`. 다음 웨이브 카드가 없으면 `docs/07-roadmap.md`에서 만든다.
- **작업 폴더:** `수학 에듀테크\MathExplorer-Txxx-<agent>`(저장소 폴더 옆), 브랜치 `task/Txxx-<agent>`.
- **검사:** `npm test`, `npm run test:e2e`, `npm run lint`, `npm run check:specs`, `npm run build`. 화면 비교는 허용 오차(0.02)가 있어 낡은 기준 이미지로도 통과할 수 있으니, 기준 이미지가 바뀐 카드는 실제 이미지를 본다.
- **검수 기기 크기:** 아이패드 768×1024, 크롬북 1366×768, 전자칠판 1920×1080. 브라우저 확인은 `.claude/launch.json`의 `dev` 서버로 한다.
- **규칙 대조:** `AGENTS.md` 절대 규칙 1~11과 카드의 '건드리지 말 것'(특히 `src/core/`, `data/units.json`).
- **단원 콘텐츠 카드 추가 검수:** 명세(`docs/04-units/`)의 활동·과제·힌트가 모두 있는가, goal이 정답 조작에서만 통과하는가, 대표 오답이 의도한 오개념 코드로 진단되는가, 힌트가 정답을 말하지 않는가, 선택지 정답 위치 편향, 오탈자.
- **커밋 이메일:** noreply 주소(`252700324+oswprogram10-tech@users.noreply.github.com`)만. 공개 저장소이므로 개인 이메일을 커밋하지 않는다.
- **병합 뒤:** 병합한 main에서 검사를 다시 모두 돌리고, 카드 상태를 `done`으로, `docs/00-handoff.md` 진행 상황을 갱신한다.
- **CI 확인(gh CLI 없음):** `curl -s "https://api.github.com/repos/oswprogram10-tech/edutech-math/actions/runs?head_sha=<sha>"`
- **프롬프트에 넣지 않을 것:** 학생 실명·실데이터, API 키. DeepSeek는 중계 사이트를 거친다.

## 5. 선생님만 할 수 있는 일
- 수학적으로 맞는지, 발문이 아이 눈높이인지 확인
- 실제 태블릿에서 손으로 조작해 보기(특히 1~2학년 터치)
- 웨이브 안의 단원 순서 결정
- 제공자로서의 처리방침·약관(`09-privacy-safety.md` §2, §5)
- 출판사별 단원 대응 자료 모으기(T090)

## 6. 비용
- 세 에이전트의 구독·사용 요금은 앱 운영 예산(무료)과 별개다. 앱 자체는 정적 호스팅 + (2단계) Supabase 무료 플랜으로 운영비 0원을 목표로 한다.
