### 2. `rate`
```ts
interface RateConfig {
  mode: 'rate';
  racers: { id: string; name: string; distance: number | null; time: number | null; editable?: boolean }[]; // 2명
  predictFirst?: boolean;   // 기본 false
  maxDistance?: number;     // 기본 400 (m)
  maxTime?: number;         // 기본 120 (초)
  look?: 'race' | 'table';  // C 경주 트랙 / P 표(이름·거리·시간), 기본 'race'
}
```
- `editable`의 기본값은 처음 값이 null인 칸만 편집할 수 있는 것이다. 이름은 학생 화면에 그대로 보인다(동물 이름 등, 사람 이름 쓰지 않음은 콘텐츠 몫).
- **Action**
  - `set {racerId, field:'distance'|'time', value}`: 편집할 수 있는 칸만, 1~max 정수다.
  - `predict {value: racerId | 'same'}`: 잠그기 전 한 번만이다.
  - `run`: 두 캐릭터의 거리·시간이 모두 있어야 한다.
  - `reset`: 처음 값으로 돌린다. 예측·실행 기록은 남긴다.
- **예측 잠금:** `predictFirst`이면 예측 전에 `run`을 거절한다. 예측은 값을 다 넣은 뒤에만 받는다.
- **경주 그림**
  - 같은 트랙 두 줄에 캐릭터(간단한 SVG 도형 + 이름표)를 놓는다.
  - `run` 뒤 화면 시간 0~T(=두 시간 중 큰 값)를 3초 연출로 재생한다. 각자 자기 시간에 자기 거리에 닿는다.
  - 위치는 결정적이다. 재생 상태는 화면 상태이고 reducer 상태가 아니다.
  - `prefers-reduced-motion`이면 끝 장면만 보인다.
  - 트랙 축척은 `maxDistance`다. 결승선은 각자의 거리에 그린다.
  - 끝나면 "○○이 1초에 더 멀리 갔어요"같이 비교만 쓰는 결과 글은 넣지 않는다. 결과는 그림(같은 시각 위치)과 표로만 보인다.
  - 표 look에서는 "1초에 간 거리" 열을 두지 않는다. 그 값을 구하는 것이 과제이기 때문이다.
- **Observation**
  - `mode`
  - `racers: {id, distance, time, speed: string|null}[]`(speed = 거리/시간 기약분수 문자열)
  - `fastestId: string|null`(같으면 null), `sameSpeed: boolean`
  - `prediction`, `predictionLocked`, `ran: boolean`, `runs: number`
  - `misconceptions`
- **MC-RATE-DISTANCE-ONLY:** 예측이 거리가 더 긴 쪽(또는 시간이 더 긴 쪽)이고 그 캐릭터가 더 빠르지 않으면 기록한다.
- **Predicates:** `predictionIs {value}`, `predictionCorrect`(예측 = fastestId, 같으면 'same'), `ran`, `sameSpeed`, `racerIs {id, distance, time}`, `racersDiffer`(두 캐릭터의 거리·시간 쌍이 다름), `hasMisconception {code}`
- **오버레이**
  - `footprints`(MC ②): 두 트랙에 1초마다 발자국 표시를 찍은 정지 그림이다. 처음 3초만 그린다. 거리 글은 쓰지 않는다.
  - `same-time`(일반 ②): 짧은 쪽 시간 t에서 두 캐릭터가 있을 위치에 세로 점선과 "같은 시간" 글을 그린다.

### 3. `percent`
```ts
interface PercentConfig {
  mode: 'percent';
  layout?: 'strip' | 'grid';     // 1×100 띠(10칸마다 굵은 선) / 10×10 판, 기본 'grid'
  shaded?: number;               // 미리 칠한 칸 수(0~100), 기본 0
  editable?: boolean;            // 기본 true
  showCount?: boolean;           // 기본 true: "칠한 칸 n / 100"
}
```
- **Action:** `toggle {index}`, `fill-to {count}`(앞에서부터 count칸, 끌기나 키보드로), `clear`
- **입력:** 칸을 누르면 하나씩 바뀐다. 누른 채 끌면 지나간 칸을 처음 누른 칸의 새 상태로 맞춘다(Pointer Events). 키보드는 방향키로 칸을 옮기고 Space로 바꾼다.
- **Observation:** `shaded: number`, `cells: number[]`(칠한 칸 번호), `percent: string`(= shaded), `fraction: string`(shaded/100 기약분수), `misconceptions: []`
- **Predicates:** `shadedIs {n}`, `fractionIs {value}`(Rational 비교)
- **오버레이 `tens-brackets`**(②): 다 칠해진 10칸 줄마다 괄호와 "10"을 붙인다. 남은 칸은 점선으로 묶는다. 학생이 칠한 것을 세어 주는 그림이라 정답 노출이 아니다.

### 4. 등록과 테스트
- `index.ts`의 `modes`에 `rate`, `percent`를 더한다. fit-canvas ENGINES의 E20 modes에도 더한다. 샌드박스 기본값은 다음과 같다.
  - rate: 토끼 120m·20초, 거북 200m·40초, predictFirst
  - percent: grid, 0칸
- **단위**
  - rate
    - speed 6과 5 → fastest 토끼
    - 같은 속력(60·10 vs 120·20) → sameSpeed
    - 예측 잠금, 거리만 큰 쪽 예측 → MC
    - set 거절(편집 불가·범위 밖)
  - percent
    - toggle·fill-to 0/100
    - fraction "1/4"(25칸)
    - 경계 0·100
  - JSON 왕복, predicates
- **E2E**(`tests/e2e/ratio-lab.spec.ts`에 추가, 3 뷰포트)
  - rate: 값 넣기 → 예측 → 실행, reduced-motion 끝 장면, 키보드만으로 한 번
  - percent: 끌어 칠하기, 키보드
  - 오버레이 셋 1px 정렬
  - 첫 화면 스냅샷(rate race·table, percent grid·strip)
- **E2E 범위:** `npx playwright test ratio-lab fit-canvas overlay-alignment --workers=3 --reporter=line`

### 구현 메모 (Sonnet, 2026-11-20)
- 구현 결정 그대로. 해석을 정한 곳:
  - `racers` 생략 = 토끼 120m·20초 / 거북 200m·40초(샌드박스 기본)이고 이때만 `predictFirst` 기본이 true다(카드 기본 false는 racers를 준 경우). `id`를 생략한 racer는 `racer-1`·`racer-2`로 채운다(g6s1u4 설정 예시에 id가 없어서).
  - 오개념 MC-RATE-DISTANCE-ONLY는 예측을 받는 순간 계산해 상태에 남긴다(기록). 이후 값을 바꾸거나 `reset`해도 지워지지 않는다.
  - `set`은 예측·실행 뒤에도 편집할 수 있는 칸이면 받는다(g6s1u4 과제 4 "같은 속력이 되는 다른 거리·시간 입력"). 경주 뒤 값을 바꾸면 화면 재생은 시작 장면으로 돌아간다(`ran`·`runs` 기록은 그대로).
  - 경주 재생: 진행도 0~1000(천분율)을 3초 동안 올리는 화면 상태(`usePlayback.ts`). 위치는 Rational로 계산한 진행도의 순수 함수. `prefers-reduced-motion`·rAF 없음이면 끝 장면. 캔버스 `data-step`·`data-playing`으로 E2E가 본다.
  - rate 입력은 글자 입력 칸(편집 가능한 칸만, 아닌 칸은 값 글자만). 잘못된 글(숫자 아님·범위 밖)은 이유를 글로 알리고 칸에 남긴다. 입력 칸에 쓰는 동안에는 단축키(숫자·R·G)가 꺼진다. 예측하면 예측 단추가 사라지므로 포커스를 [경주 시작]으로 옮긴다(키보드 단축키가 계속 듣게).
  - rate 단축키: 1·2 캐릭터 예측, 3 같아요, G 경주, R 처음으로. percent: C 모두 지우기, R 처음으로. percent 판 안에서 방향키 이동·Space 바꾸기·Enter "여기까지 칠하기"(= fill-to 커서+1).
  - percent 끌기는 처음 누른 칸의 반대 상태로 지나간 칸을 맞춘다(칸마다 toggle을 보내되 이번 끌기에서 이미 보낸 칸은 건너뜀). 두 점 사이를 4논리px 간격으로 살펴 빨리 끌어도 칸을 빼먹지 않는다. 띠(strip)는 칸 폭이 9논리px라 한 칸씩 누르기는 어려워 끌기·키보드가 주 입력이다.
  - 오버레이 footprints: 1·2·3초 발자국(시간이 3초 미만이면 도착 뒤는 안 찍음), 세로 점선 + 발 모양, 글 없음. same-time: 짧은 시간 t에서 두 캐릭터 위치에 점선 둘 + "같은 시간"(값 글 없음). tens-brackets: 다 찬 10칸 줄(띠는 10칸 묶음)마다 괄호 + "10", 못 채운 줄은 점선 상자. table look에서도 작은 트랙이 있어 오버레이가 그대로 정렬된다.
  - 관찰 결과(샌드박스 개발자 패널)에는 fastestId·speed가 보이지만 학생 화면(DOM·aria·data-*)에는 쓰지 않는다. 단위 테스트가 이를 확인한다.
  - iPad 세로(`?stage=fit`)에서 rate 조작 칸이 안쪽 스크롤(mix·resize와 같음).
- 기준 이미지 8장 신규: rate race·table, percent grid·strip × 크롬북·아이패드.
- **요청(Opus 결정 필요):** 샌드박스 모드 선택(`<select>`) 너비가 가장 긴 모드 이름(`percent`)에 맞춰 넓어져서, 기존 mix·resize 첫 화면 기준 이미지 10장이 도구 줄(툴바)의 단추 위치 몇 px 이동으로 달라졌다.
