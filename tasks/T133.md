## 목표
T132(g2s1u2.A2) 검수 ㉘에서 E12 화면 문제가 나왔다. 엔진 안에서 고친다.
1. 응답 칸이 있는 과제(실행기 두 칸 배치)에서 E12 판이 좁아지면 과제 보기(`reference`·`referenceViews`)가 조작 묶음 맨 아래, 판 안 스크롤 밑으로 밀린다. 그림자 그림도 52×70px로 작다(크롬북·아이패드 T3).
2. 쌓기나무를 모두 고정해 보여 주기만 하는 과제(T3·T4)에서도 쌓기·빼기·모두 빼기 단추가 보이고, 시작하자마자 "더 쌓을 수 없어요"가 뜬다.
3. 3D 무대의 '앞' 표시는 바닥에 눕힌 텍스처라, 크롬북에서 글자가 10px 정도로 기울어져 읽을 수 없다. T2·T4 발문은 "'앞' 쪽에서 보아요"로 시작한다.
4. `rotationLocked:true`여도 안내 문구에 "Q/E: 돌리기", "손가락 두 개로 돌려 보세요 · 마우스는 오른쪽 버튼으로 끌어요"가 그대로 나온다.

## 구현 결정 (2026-11-14 Claude 작성 — 여기 적힌 대로 하고, 바꿔야 하면 메모에 이유를 적고 멈춰서 묻는다)
1. **과제 보기 자리:** `CubesView`에서 과제 보기 블록(`settings.reference` 그림 + `referenceViews` 투영)을 `sideStack`의 **첫 자식**으로 옮긴다(지금은 실시간 투영 블록 다음, 키보드 안내 바로 앞).
   - 좁은 판(세로·`stageRow display: contents`)에서는 무대 바로 아래, 넓은 판에서는 오른쪽 칸 맨 위에 온다.
   - 블록 순서: 과제 보기 → 도구 막대 → 3D 시점 단추 → 실시간 투영 → 키보드 안내.
   - test id·`aria-label`·제목 문구는 그대로 둔다.
2. **과제 보기 투영 칸 크기:** `ProjectionGrid`에 `cellSize?: number` prop을 더한다(기본 20 = 지금 값, 실시간 투영은 그대로).
   - 과제 보기 투영(`cubes-reference-top/front/side`)은 `cellSize` 32로 그린다.
   - `PAD`·"앞" 글자 자리 등 칸 크기에 묶인 값은 비율을 맞춘다. 2×2 그림자가 대략 80×100px이 된다.
   - 과제 보기 모양 그림(`ReferenceShapeSvg`, 지금 최대 180px)은 그대로 둔다.
3. **보기 전용 모드:** `CubesConfig`에 `editable?: boolean`(기본 `true`)을 더하고 `CubesSettings.editable: boolean`으로 정규화한다. `false`면:
   - `reduce`: `add`·`remove`·`clear`·`select-tool`·`move-cursor` Action을 무시한다(같은 state 반환). `turn`·`set-translucent`·`focus-cell`은 그대로 둔다.
   - 화면: 쌓기·빼기·모두 빼기 단추를 그리지 않는다. 바닥 커서 테두리(등각·3D)와 칸 누르기를 그리지 않거나 무시한다. 상태 줄에 "더 쌓을 수 없어요"를 띄우지 않는다(`maxReached`·`blockedAdd` 문구 숨김).
   - 왼쪽·오른쪽으로 돌리기, 반투명, 평면/입체 전환, 3D 시점 단추는 남긴다.
   - 키보드: 방향키·Enter·Backspace를 무시하고 Q/E·T는 둔다. `cubes-stage`는 계속 포커스를 받는다(Q/E로 돌려 보기).
   - 첫 줄 안내(`S.instructions` "칸을 눌러 쌓기나무를 쌓거나…")는 보기 전용 문구로 바꾼다: `S.instructionsView` "쌓기나무를 돌려 보며 살펴보아요."(회전 잠금이면 `S.instructionsViewLocked` "쌓기나무를 살펴보아요.").
   - Observation은 지금과 같다(`maxReached` 값도 그대로 계산). `editable`은 Observation에 넣지 않는다.
   - 단위 테스트: reduce 무시 Action 5종, settings 기본값·정규화, View에서 단추 숨김·상태 문구 없음.
4. **3D '앞' 표시를 화면 글자로:** 3D 무대에 HTML 이름표 `<span data-testid="cubes-front-label">앞</span>`을 겹친다(`aria-hidden`, 포인터 없음).
   - 위치: 바닥 앞 가장자리 가운데 바로 바깥점(지금 텍스처 자리, `[0, 0, rows/2 + 0.34]`를 무대 좌표로 바꾼 점)을 카메라로 투영(`Vector3.project`)한 화면 좌표.
   - 카메라·크기가 바뀔 때마다 다시 계산한다(`frameloop="demand"`이므로 controls `change`·resize·preset 이벤트에서).
   - 글자는 늘 바로 선 상태로, 굵게, 18px 이상, 배경 칩(흰 바탕 + 파란 테두리)과 함께 그린다. 점이 무대 밖이면 무대 안쪽 가장자리로 붙인다.
   - 바닥 텍스처 화살표는 남기되 글자는 지운다(두 번 쓰지 않게). `frontMarker:false`면 이름표도 없다.
   - 등각 2D 무대의 "앞" 글자는 실행기 아이패드 기준 화면 16px 이상인지 재서 메모에 적는다. 작으면 글자 크기만 키운다.
5. **회전 잠금 안내:** `strings.ko.ts`에 회전 잠금용 문구를 더한다.
   - `keyHintLocked` "방향키: 칸 옮기기 · Enter: 쌓기 · Backspace: 빼기 · T: 반투명"
   - `keyHintView` "Q/E: 돌리기 · T: 반투명", `keyHintViewLocked` "T: 반투명"
   - `rotationLocked`면 `keyHint3d`를 붙이지 않는다(3D 궤도 회전·확대가 이미 꺼져 있다 — T131).
   - 보기 전용이면 `keyHintView` 계열을 쓴다.
6. **스타일·레이아웃:** T122·T131의 판 높이 규칙(`stageRow`·`sideStack`·`boardArea` 줄어드는 순서)은 바꾸지 않는다. 블록 순서와 투영 칸 크기만 바꾼다. 터치 타깃 규칙(48/64px)은 그대로다.
7. **E2E**(`tests/e2e/solid-3d.spec.ts`에 더함, 세 뷰포트):
   - **샌드박스 T3 설정**(`?stage=fit&config=` + T132 결정 13의 A2.T3 config + `"editable":false`, `stage:"isometric"`):
     - `cubes-reference-top`이 `toBeInViewport({ratio:1})`이고 상자가 70×70px 이상인지
     - 쌓기·빼기·모두 빼기 단추가 없고 돌리기 단추는 있는지
     - `cubes-status`가 비어 있는지
     - Enter로 쌓기나무 수가 그대로인지
     - Q로 돌아가는지
   - **보기 블록 순서:** `reference`가 있는 설정에서 과제 보기 블록이 도구 막대보다 DOM 앞에 있는지.
   - **3D 이름표**(`solid-3d-webgl.spec.ts` 방식, WebGL이 없으면 건너뜀):
     - `cubes-front-label`이 보이고 무대 상자 안에 있는지
     - 계산된 `font-size`가 18px 이상인지
     - 시점 단추 '위에서' → '비스듬히' 뒤에도 무대 안에 있는지
   - **회전 잠금 안내:** `rotationLocked:true`에서 키보드 안내에 "돌리기"·"손가락 두 개"가 없는지(등각·3D).
   - 기존 E12 E2E와 스냅샷이 바뀌면 `--update-snapshots=all`로 다시 만들고 이미지를 직접 열어 본다.
8. **범위:** E12 엔진 폴더와 E12 E2E만 고친다. `src/core/`, 다른 엔진, `data/`는 고치지 않는다. 실행기 두 칸 배치에서의 확인은 T132 수정(이 카드 병합 뒤)에서 한다.
