# 01. 제품 요구사항 (PRD)

## 1. 한 줄 정의
초등 1~6학년 학생이 **디지털 교구를 직접 조작하며 수학 원리를 발견**하고, 교사가 그 과정을 보고 **수업 토론을 이끌 수 있게** 하는 웹 앱. 설치 없이 학급의 모든 기기에서 돌아간다.

## 2. 설계 원칙 (원 계획서 유지, 실행 규칙으로 바꿈)

| 원칙 | 실행 규칙 (코드 리뷰에서 확인) |
| --- | --- |
| 무연필 구체물 조작·CPA 전이 | 모든 활동은 `cpa` 단계를 가진다. 같은 엔진이 C→P→A로 표현을 바꾼다. 공식·세로셈을 첫 화면에 보여 주지 않는다 |
| 과정 중심 피드백 | 정답 문자열 비교 금지. 판정은 엔진의 `Observation`에 대한 조건식으로만 한다. 오답에는 *왜 안 되는지*를 보여 준다 |
| 무학년 역추적 | 막히면 선수 개념 마이크로 활동으로 보낸다. 화면 어디에도 "○학년" 표시를 하지 않는다 |
| 보편적 학습 설계(UDL) | 자석 스냅, TTS, 64px 터치 타깃(저학년), 키보드 대체 조작, 색만으로 정보 전달 금지 |
| 내재적 게임화 | 점수·랭킹·꾸미기 보상 없음. 성공 조건 자체가 수학적 원리여야 한다(예: 레이저가 모든 보석을 맞히는 것 = 관계식이 모든 쌍에서 성립) |
| 정답 노출 금지 | 힌트 사다리(발문 → 시각적 반례 → 역추적)만 있고 "정답 보기" 버튼은 없다. 교사 모드에서만 예시 풀이를 볼 수 있다 |

## 3. 사용자와 상황

| 사용자 | 기기 | 주 사용 상황 |
| --- | --- | --- |
| 학생 (1~6학년) | 크롬북, 아이패드, 갤럭시탭 | 수업 중 개별·짝 활동 10~20분, 보충 활동 |
| 교사 (앱을 쓰는 학교의 교사) | 전자칠판, 교사 PC | 도입 시연, 학생 전략 비교 토론, 진도 확인 |
| 운영자 (콘텐츠 제공자) | PC | 단원 콘텐츠 제작·검수, 배포, 시범 운영 학교 지원 |
| 학부모 | (3단계) 스마트폰 | 주간 대화 카드 — 후순위 |

### 대표 수업 시나리오 (5학년 「약분과 통분」 1차시)
1. **도입(5분):** 교사가 전자칠판에서 *교사 시연 모드*로 E05를 열고 1/2과 1/3 막대를 보여 주며 "어느 쪽이 얼마나 더 클까?"를 묻는다.
2. **탐구(15분):** 학생은 태블릿에서 `g5s1u4.A1`(투명 타일 겹치기)을 한다. 막힌 학생은 힌트 ①→②를 받고, 계속 막히면 '같은 크기 조각' 부스터(g3s1u6 개념)를 2분 하고 돌아온다.
3. **토론(10분):** 교사는 두 학생의 화면(1단계: 학생이 '보여 주기' 버튼으로 공유 코드 생성 / 2단계: 실시간 미러링)을 나란히 띄워 "6등분과 12등분 둘 다 맞을까?"를 토론한다.
4. **정리(5분):** A 단계 과제 2개(기호만)로 마무리. 교사는 오개념 코드별 학생 수를 본다(2단계).

## 4. 범위

### 1단계: 서버 없이 어느 학급에서나 바로 쓰는 앱
- 앱 셸, 단원 지도(별자리), 활동 실행기, 힌트 사다리, 역추적 부스터
- 웨이브 순서대로 엔진과 단원 콘텐츠(`07-roadmap.md`)
- 교사 시연 모드(전자칠판)
- 기기 내 기록 + 교사에게 내보내기(파일/QR)
- 오프라인 동작(PWA)

### 2단계: 학급 연결 (Supabase 무료)
- 학급 코드 입장, 교사 대시보드(진도·오개념 히트맵), 실시간 썸네일 미러링, 일시정지, 익명 전략 비교, 학급 투표(E18), 도형 스무고개 대전(g4s2u4)
- 수업 끝 모둠 자동 편성 제안(보충/유창성/심화)과 출구 과제 배포

### 3단계: 선택 기능
- 풀이 영상(Thinklet) 녹화·공유와 피어 리뷰, 학부모 대화 카드, 관심사 기반 문장제 바꾸기(템플릿 → 예산 생기면 LLM), AR(안드로이드), 몸동작 인식, 음성 인식, 손글씨 숫자 인식

### 하지 않는 것
- 점수 경쟁, 랭킹, 아바타 꾸미기, 광고
- 실명·사진·생년월일 수집
- 생성형 AI가 계산하거나 채점하는 것

## 5. 성공 지표 (측정 방법까지 정한 버전)

원 계획서의 "흥미도 +30%, 성취도 +25%"는 측정 도구가 정해지지 않았다. 협력 교사·학교의 시범 운영에서 측정할 수 있게 바꾼다.

| 지표 | 측정 | 목표(제안) |
| --- | --- | --- |
| 개념 이해 | 단원별 사전·사후 진단(같은 5문항, 교과서 단원평가에서 개념형 문항 선택) | 사후 정답률이 사전 대비 의미 있게 상승. 앱 활용 단원과 비활용 단원 비교 가능하면 함께 비교 |
| 수학 흥미·자신감 | 5문항 리커트 설문(사전·사후), 학생 인터뷰 3~5명 | 하락하지 않을 것 + 질적 사례 수집 |
| 과정 지표(앱 로그) | 힌트 ② 이후 자기 수정 비율, 부스터 후 원래 과제 성공률, 오개념 코드 재발률 | 단원 진행에 따라 재발률 감소 |
| 사용성 | 저학년 스냅 조작 성공률, 조작 중 프레임 저하 | 성공률 95% 이상, 60fps(저가 크롬북 30fps 이상) |
| 수업 운영 | 교사가 활동 시작까지 걸린 시간 | 1분 이내 |

> 연구로 발표할 계획이라면 학교·교육청의 연구 윤리 절차(학생·보호자 동의 등)를 먼저 확인한다.

## 6. 콘텐츠 기준
- 단원명은 원 계획서 기준이다. **3~6학년은 검정 교과서라 출판사마다 단원 이름·순서가 다를 수 있다.** 앱은 단원을 `unitId`로 관리하고, 교사 관리 화면에서 단원 표시 이름과 순서를 바꿀 수 있게 한다(`units.json`의 `textbookAlias`).
- 성취기준 코드는 2022 개정 수학과 교육과정 원문에서 확인해 `units.json`의 `standards`에 채운다(작업 카드 `T090`).
- 초등 수학 성취기준은 **학년군(1~2, 3~4, 5~6)** 단위다. 그래서 출판사마다 같은 내용을 다른 학년·학기·단원에 둘 수 있다. 교구·개념·과제는 공통으로 만들고, 출판사별 학년·학기·단원명은 대응표(`textbookAlias`)로만 맞춘다. 단원 ID는 바꾸지 않는다.
