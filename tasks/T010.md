## 구현 결정 (2026-11-02 Claude 추가 — 여기 적힌 대로 하고, 바꿔야 하면 메모에 이유를 적고 질문한다)
1. **폴더:** `src/engines/E05-fraction-model/`, AGENTS.md 엔진 폴더 구조와 E00-demo 본보기를 따른다. 엔진 ID `E05`, modes 순서: `partition`, `shade`, `compare`, `overlay-slicer`, `discrete`, `mixed`, `add-sub`, `decimal-grid`.
2. **수의 값은 Rational, 도형 기하는 number:** 분수값·색칠 비율·합·차는 모두 `src/core/math`의 `Rational`. 상태·Observation·Action에는 `toJSON()` 문자열(`"3/4"`)로 넣는다(BigInt는 JSON이 안 된다). **예외:** 자유 절단 조각의 넓이 비교는 화면 기하라 논리 좌표(number)로 계산하고 `areaTolerance`(기본 0.02)로 판정한다. 등분으로 판정된 뒤의 분수값은 `k/n` Rational로 기록한다. 이 예외를 types.ts 주석에 적는다.
3. **절단 도구(`partition`):** `cutTool`은 두 가지 — `line`(도형을 가로지르는 직선, 오목 다각형이면 여러 조각으로 나뉠 수 있음)과 `radial`(원의 중심에서 가장자리까지의 반지름 선, 원은 부채꼴 각도로 넓이를 정확히 계산). 명세의 `"free-line"`은 `line`의 별칭으로 받는다. 손가락으로 2% 안에 맞추기 어려우므로 **절단 끝점을 자석 스냅**한다: 변을 2·3·4·5·6·8등분하는 점, 꼭짓점, 중심. 도형: `rect`, `square`, `bar`, `circle`(정다각형 근사 아님 — 부채꼴 계산), `triangle`, `polygon`(config에 꼭짓점 목록, 오목 허용). `fixedParts`가 있으면 미리 n등분된 막대를 보여 준다.
4. **명세의 설정 키:** W1 단원 명세(카드 '먼저 읽을 문서')의 E05 설정 키를 모두 받는다 — partition(`shape`, `targetParts`, `cutTool`, `equalityCheck`, `areaTolerance`, `fixedParts`, `label`, `fraction`, `groupChoices`, `showGcdShortcut`), shade(`whole`, `target`, `refine`, `coarsen`), compare(`bars`, `align`), overlay-slicer(`a`, `b`, `shape`, `orientation`, `challenge`), discrete(`items`, `itemIcon`, `groupSizeOptions`, `grouping`, `showFractionOf`), mixed(`direction`, `value`, `wholeShape`, `op`, `a`, `b`, `breakWhole`, `commonGrid`), add-sub(`op`, `a`, `b`, `shape`, `fuseWhole`, `allowBreakWhole`, `strategyChoice`, `requireCommonGrid`), decimal-grid(`size`, `layers`, `overlayAlpha`). 키마다 types.ts에 타입과 한 줄 설명. 명세의 `numberLine`·`linkedNumberLine`·`then` 같은 **다른 엔진·다음 단계 설정은 무시**한다(러너의 views·links와 과제 순서로 표현한다 — T020에서).
5. **Observation(모드 공통 + 모드별):** `mode`, `wholes: [{ parts, equal, shaded, value }]`(value는 색칠 비율 Rational 문자열, 약분 전 표기 `raw`와 기약 `reduced` 둘 다), `cutSignature`(절단 방식 비교용 정규화 문자열 — "다른 방법으로 4등분" 판정용), `commonGrid`(overlay-slicer 공통 격자 칸 수), 모드별 이벤트 횟수(`fused`, `brokeWhole`, `overlaid`, `refined`, `coarsened`), discrete는 `groupSize`, `groups`, `selectedGroups`, `selectedCount`, decimal-grid는 층별 `cells`·`value`.
6. **Predicates:** `isEqualPartition`(args `{ parts }`), `shadedEquals`(args `{ value }`, 동치 비교), `shadedRawIs`(표기까지 같은지), `isIrreducible`, `commonGridIs`(args `{ size }`), `differentCutFrom`(args `{ signature }`), `eventAtLeast`(args `{ name, count }`). 명세 판정을 이것으로 표현할 수 없으면 추가하고 메모에 적는다.
7. **이벤트(`emit`/`receive`, T005 계약):** `events`: `partitioned`, `shaded`, `value-changed`, `fused`, `broke-whole`, `overlaid`. **`value-changed` payload는 `{ value: "<Rational 문자열>" }`** — E03도 같은 이름·모양을 받는다(엔진끼리 import 없이 이름 약속으로 연결). `receive`는 `value-changed`를 받으면 compare/shade의 표시 값을 맞춘다(필요한 모드만).
8. **오버레이(힌트 ②):** `size-compare`(학생이 만든 조각들을 한 줄로 겹쳐 크기 차이를 보여 줌), `grid-reveal`(공통 격자 선만 보여 주고 **정답 칸은 칠하지 않음**). 둘 다 정답 상태로 바꾸지 않는다.
9. **CPA:** C는 SVG 패턴 질감(케이크·피자·리본 — 이미지 파일 없이), P는 단색, A는 숫자·분수 표기만. 같은 상태를 세 방식으로 그린다.
10. **입력 범위:** 이 엔진은 조작만 다룬다. "분수를 써 넣기", "부등호 고르기", "카드 분류" 같은 **답 입력은 이 카드 범위 밖**이다(별도 응답 위젯 카드 T016에서). 엔진 안에 키패드를 만들지 않는다.
11. **문구·크기:** 문구는 `strings.ko.ts`. 조작 요소는 T003 `minTouchRadius`로 `targetSize` 이상. 선택·색칠 상태는 색 외에 무늬·테두리로도 구분.
12. **테스트:** reduce·observe 단위 테스트(경계값: 1등분, 분수값 0과 1, 가분수, 큰 분모), `assertSerializable`, `#/sandbox/E05`에서 3개 뷰포트 E2E(직사각형 4등분 절단 → 등분 판정, 크기 다른 4조각 → 등분 아님, 1/2과 1/3 겹치기 → `commonGrid` 6).
