## 목표
W3 단원 콘텐츠(T110~T121) 검수 ㉕에서, E09·E10·E11·E17 판이 실행기 슬롯 높이에 맞춰 줄어들지 않아 크롬북(1366×768)과 일부 아이패드·전자칠판에서 교구 본체가 첫 화면 밖으로 나가거나 판 아래 조작 패널·안내 글이 캔버스 위에 겹쳐 그려지는 것을 찾았다(예: g5s2u3 크롬북에서 움직이는 도형이 밀기·뒤집기 패널 밑에 깔림, g4s2u6 카드 아랫줄이 판 안 스크롤 아래, g4s1u2 각이 첫 화면 밖). 단원 E2E의 첫 화면 검사(`expectNoPanelInnerScroll`)는 `data-layout="content"` 판만 보므로 이 문제를 잡지 못했다. 네 엔진의 캔버스가 슬롯에 맞춰 줄어들게 고치고, fit 판도 보는 E2E 검사를 만든다. 같은 카드에서 E10 predict의 '확인'이 정답 그림을 보여 주는 문제도 고친다.

## 구현 결정 (2026-11-11 Claude 작성 — 여기 적힌 대로 하고, 바꿔야 하면 메모에 이유를 적고 질문한다)
1. **원인:** 네 엔진 모두 `.canvas`가 `width: 100%; max-width: 720px; aspect-ratio: 1 / 1`(E17은 엔진 비율)이라 너비로 높이가 정해진다. `.canvasArea`는 `flex: 1 1 auto`로 줄어들지만 안의 svg는 줄지 않아 넘치고, 넘친 부분 위에 다음 형제(조작 패널·안내 글)가 그려진다. 넘침은 실행기 `.viewport`(`overflow: auto`) 안 스크롤이 된다.
2. **고치는 방향(엔진 CSS, 네 엔진 같은 방식):**
   - `.canvasArea`: `flex: 1 1 0`, `min-height: 200px`(저학년 64px 모드도 같음), `align-items: center`(가운데), `overflow: hidden`.
   - `.canvas`: 높이 기준으로 맞춘다 — `height: 100%; max-height: 100%; width: auto; max-width: 100%; aspect-ratio`는 그대로. 그래서 가로·세로 중 좁은 쪽에 맞춰 줄어든다. `max-width: 720px` 상한은 지금처럼 둔다(전자칠판에서 너무 커지지 않게).
   - 캔버스 아래 조작 패널(E10 MovePanel·E09 기록표·E11 슬라이더 등)과 안내 글은 캔버스와 같은 흐름에 두어 겹치지 않게 한다. 슬롯이 아주 낮아 `min-height`를 지킬 수 없을 때만 판 안 스크롤이 생긴다.
   - 좁은 화면 가로 배치(E09 기록표가 옆에 오는 경우 등)는 지금 구조를 유지한다.
   - svg `viewBox`·`preserveAspectRatio`와 포인터 좌표 변환(`pointerToLogical`)은 바꾸지 않는다(화면 크기만 바뀐다). `minTouchRadius`가 렌더 크기로 터치 반지름을 늘리는지 확인한다.
3. **E2E 검사 `expectFitCanvasVisible(page)` 추가(`tests/e2e/panel-layout.ts`):**
   - 모든 `[data-testid^="runner-slot-"]` 판(fit 포함)에서 엔진 캔버스(`svg[data-testid$="-canvas"]` 또는 엔진별 캔버스 testid)가 (a) 판 viewport 안에 완전히 보이고(판 안 스크롤 없이), (b) 같은 판 안의 다른 보이는 요소(버튼·안내 글·패널)와 상자가 겹치지 않는지 본다(겹침 허용 1px).
   - 엔진 E2E(`geo-board*`, `transform*`, `cut-rearrange*`, `sorter*`)에 모드마다 세 뷰포트로 이 검사를 더한다. 크롬북에서 캔버스 짧은 변이 200px 이상인지도 본다.
   - 기존 단원 E2E 스냅샷은 이 카드에서 다시 만들지 않는다(단원 카드 수정 때 다시 만든다). 다만 이 카드 브랜치에서 `npm run test:e2e` 전체를 돌려 깨지는 단원 스냅샷 목록을 메모에 적는다.
4. **E10 predict 결과 숨김:** 지금 predict는 엔진 '확인'을 누르면 결과 도형과 '못 칠한 칸'이 보이고, '다시 해 보기'로 그대로 베껴 칠하면 실행기 '확인하기'를 통과한다(정답 노출, AGENTS 3).
   - `PredictConfig`에 `selfCheck?: boolean`(기본 `true` — 지금 동작)을 더한다. `false`이면 엔진 '확인'·'다시 해 보기' 단추와 결과 그림·못 칠한 칸 표시를 그리지 않는다. 칠하기·지우기는 그대로.
   - `selfCheck:false`일 때 Observation·predicate(`predictionMatches` 등)는 칠한 칸만으로 판정되게 한다(`confirmed` 없이). 힌트 오버레이(`point-track`·`clock-hand`·`pin-arcs`)는 지금처럼 그려진다.
   - 단위 테스트: `selfCheck:false`에서 확인 단추가 없고 결과 그림이 없으며, 맞게 칠하면 `predictionMatches`가 참.
5. **검사:** `npm test`, `npm run lint`, `npm run check:specs`, `npm run build`, `npm run test:e2e` 전체(단원 스냅샷 차이는 위 3번대로 목록만).
