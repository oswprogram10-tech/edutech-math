## 구현 결정 (2026-11-19 Claude 작성 — 여기 적힌 대로 하고, 바꿔야 하면 메모에 이유를 적고 멈춰서 묻는다)
**공통:** T111 공통 1~9와 T140 구현 결정 1번을 따른다.

### 1. 공통
- **과제 기본값:** `engine:"E18"`, `mode:"line-graph"`, `submit:"button"`. 일반 규칙의 `when`은 `mode`를 equals로 본다.
- **수 값:** 설정의 세로 값은 소수 문자열("0.5", "36.4")로 쓴다. GoalSpec의 equals 값은 응답 칸이 내는 모양(Rational JSON, 예 37.1 → "371/10")에 맞춘다. 기존 소수 응답 콘텐츠에서 모양을 확인한다.
- **4학년 문구:** "꺾은선그래프", "선분", "물결선", "눈금 한 칸"을 쓴다.
- **정답 노출 금지:**
  - 발문·힌트·라벨에 값, 기간, "5일에서 7일 사이에 가장 많이 자랐어요" 같은 결론을 쓰지 않는다.
  - 학생이 그리는 과제는 `graph:"student"`라 말풍선이 없다.
  - 주어진 그래프를 읽는 과제는 `table:"hidden"`, `tooltips:"hide"`다.
- **오개념**(T154 레지스트리, `diagnose`):
  - `MC-GRAPH-HEIGHT-NOT-CHANGE`: trapChoice
  - `MC-GRAPH-NO-INTERPOLATE`: trapChoice
  - `MC-GRAPH-WAVY-LINE`: trapValue
  - `MC-GRAPH-SCALE-ONE`은 이 단원에 맞는 감지 자리가 없어 쓰지 않는다. 메모에 적는다.
- **③:** 오개념 규칙은 레지스트리 backtrack, 일반 규칙은 그 과제의 첫 concept다.

### A1 `g4s2u5.A1` "강낭콩 키 자료로 꺾은선그래프 그리기" (P→A, 4과제)
2. **자료(꾸민 예시):**
   - points `1일 0.5`, `3일 2`, `5일 5.5`, `7일 9.5`, `9일 11`(명세 값 그대로)
   - `yStep:"1"`, `plotStep:"0.5"`, `yMax:"12"`, `valueLabel:"cm"`, `categoryAxisTitle:"날짜"`, `valueAxisTitle:"키(cm)"`, `title:"강낭콩 키"`
   - 구간 증가량은 1.5, 3.5, 4, 1.5이다. 가장 많이 자란 때는 5일~7일, 가장 높은 점은 9일이다.
3. **장면 범위:** 명세의 장면 슬라이더와 자 재기(C)는 후순위다(T163). A1은 표 자료로 점을 찍는다(P). 활동 메모와 명세 후순위에 적는다.
4. **A1.T1 표를 보고 점 찍기 (P).** concepts `["g4s2u5.line-graph-make"]`
   - 발문: "표를 보고 날짜마다 강낭콩 키를 점으로 찍어요. 세로 눈금 한 칸은 1cm예요."
   - config: 자료 + `graph:"student"`, `connect:"auto"`, `table:"given"`
   - 응답 칸 없음. 판정: `pointsMatch {source:"data"}`
   - 일반: ① "점마다 표의 키와 같은 높이에 찍었나요?" / ② `say`만 "날짜 줄을 누른 채 위아래로 움직여 표의 키에 맞춰 봐요. 한 칸의 절반은 0.5cm예요." / ③ 공통
   - E2E: 한 점 틀림 → 일반 ①, 다 맞춤(끌기 1개 + 키보드 ↑ 나머지) → 통과
5. **A1.T2 점을 이어 꺾은선그래프 완성 (P).** concepts `["g4s2u5.line-graph-make"]`
   - 발문: "점을 찍고, 날짜 순서대로 점과 점을 선분으로 이어 꺾은선그래프를 완성해요."
   - config: A1.T1과 같고 `connect:"student"`
   - 판정: `all`(`pointsMatch {source:"data"}`, `segmentsInOrder`)
   - **상태 규칙**(일반 앞): when `pointsMatchData` true이고 `segmentsInOrder` false → ① "날짜 순서대로 바로 옆 점끼리 이었나요?" / ② `say`만 "1일 점부터 차례로 옆 날짜 점과 이어 봐요. 건너뛴 선분은 눌러서 끊을 수 있어요." / ③ 공통
   - 일반: A1.T1과 같다.
   - E2E: 점 다 맞춤 + 1일–5일을 이음 → 상태 ①, 그 선분을 끊고 순서대로 이음 → 통과
6. **A1.T3 가장 많이 자란 기간 (A).** concepts `["g4s2u5.read-change"]`
   - 발문: "강낭콩이 가장 많이 자란 기간은 언제인가요?"
   - config: 자료 + `graph:"given"`, `table:"hidden"`, `tooltips:"hide"`
   - 응답: 고르기 `period` — `p13` "1일~3일", `p35` "3일~5일", `p57` "5일~7일"(정답), `p79` "7일~9일"
   - 판정: `period`=["p57"]
   - **MC-GRAPH-HEIGHT-NOT-CHANGE**
     - diagnose trapChoice, trap `p79`, path `response.period.selected.0`
     - ①: "키가 '가장 큰 날'과 '가장 많이 자란 기간'은 같은 질문일까?"
     - ②: `show {"engine":"E18","overlay":"change-bars"}` + "기간마다 얼마나 자랐는지 그래프 아래에 작은 막대로 보여 줘요. 가장 긴 막대를 찾아봐요."
     - ③: 레지스트리 값
   - 일반: ① "선분이 가장 가파르게 올라간 곳을 찾아볼까요?" / ② `say`만 "기간마다 선분이 얼마나 기울었는지 비교해 봐요." / ③ 공통
   - E2E: p79 → MC ①, 다시 → ②와 `change-bars`(정렬 1px), p13 → 일반 ①, p57 → 통과
7. **A1.T4 예측 선과 실제 선 비교 (P, 성찰).** concepts `["g4s2u5.read-change"]`
   - 발문: "강낭콩 키가 어떻게 변할지 먼저 예측 점을 찍어 보고, '실제 자료 보기'를 눌러 비교해요. 어디가 가장 많이 달랐나요?"
   - config: 자료 + `graph:"given"`, `predict:true`, `table:"given"`, `tooltips:"hide"`
   - 응답: 고르기 `diff` — `early` "처음 며칠", `middle` "가운데 날들", `late` "마지막 며칠", `close` "거의 비슷했어요"
   - 판정: `all`(`predictionDone`, `any`(diff가 네 선택지 중 하나)). 정오가 없는 성찰 과제다.
   - 일반: ① "예측 점을 찍고 '실제 자료 보기'를 눌렀나요?" / ② `say`만 "날짜 줄을 눌러 예측 점을 찍은 뒤 '실제 자료 보기'를 눌러 두 선을 비교해 봐요." / ③ 공통
   - E2E: 예측 전 고르고 확인 → 일반 ①, 예측 점 2개 + 실제 자료 보기 + 고르기 → 통과. 예측 단계에서 표가 없고, 실제 단계에서 범례 "예측"·"실제"가 보이는지 단언한다.

### A2 `g4s2u5.A2` "물결선 아코디언과 예측기" (P→A, 4과제)
8. **자료(꾸민 예시):**
   - points `9시 36.4`, `10시 36.8`, `11시 37.2`, `12시 37`, `13시 36.6`(명세 값 그대로)
   - `yStep:"0.2"`, `plotStep:"0.1"`, `yMax:"37.6"`, `valueLabel:"℃"`, `categoryAxisTitle:"시각"`, `valueAxisTitle:"체온(℃)"`, `title:"하루 체온"`
9. **A2.T1 물결선 넣기 (P).** concepts `["g4s2u5.wavy-line"]`
   - 발문: "체온이 어떻게 변하는지 잘 보이도록 물결선으로 세로축을 줄여요."
   - config: 자료 + `graph:"given"`, `yFrom:"0"`, `yFromOptions:["0","35","36"]`, `table:"given"`, `tooltips:"hide"`
   - 판정: `all`(`yFromAtLeast {value:"35"}`, `wavyShown`)
   - 일반: ① "0부터 그린 그래프에서 체온 변화가 잘 보이나요?" / ② `say`만 "'물결선' 줄에서 더 큰 시작값을 골라 그래프가 어떻게 바뀌는지 봐요." / ③ 공통
   - E2E: 그대로 확인 → 일반 ①, "36부터" → `data-y-from`·`data-wavy` 확인 후 통과
10. **A2.T2 11시 30분 체온 어림 (A).** concepts `["g4s2u5.interpolate-predict","g4s2u5.wavy-line"]`
    - 발문: "11시 30분에는 체온을 재지 않았어요. 그때 체온을 알 수 있을까요? 알 수 있다면 어림해 써요."
    - config: 자료 + `graph:"given"`, `yFrom:"36"`, `table:"hidden"`, `tooltips:"hide"`(물결선 단추 없음)
    - 응답: 고르기 `can` — `yes` "선분을 보고 어림할 수 있어요", `no` "재지 않아서 알 수 없어요" / 수 칸 `temp`(`forms:["decimal"]`, 라벨 "11시 30분 체온(℃)")
    - 판정: `all`(`can`=["yes"], `any`(`temp` = 37, 37.1, 37.2)). 명세의 "37.0~37.2 사이"를 0.1 단위 세 값으로 둔다.
    - **MC-GRAPH-NO-INTERPOLATE**(먼저)
      - diagnose trapChoice, trap `no`, path `response.can.selected.0`
      - ①: "선분 위에서 11시 30분은 어디쯤일까?"
      - ②: `show {"engine":"E18","overlay":"interp-guide","args":{"a":2,"t":0.5}}` + "11시와 12시 가운데에 세로선을 그었어요. 선분과 만나는 곳을 봐요."
    - **MC-GRAPH-WAVY-LINE**
      - diagnose trapValue, args `{"trap":["1","1.1","1.2"],"expected":"37.1"}`, path `response.temp.value`(물결선 위 시작 줄을 0으로 읽은 값)
      - ①: "물결선이 무엇을 줄여 놓은 표시였지?"
      - ②: `show {"engine":"E18","overlay":"unfold-axis"}` + "줄여 놓은 세로축을 0부터 다시 펼쳐 보여 줘요."
    - 일반: ① "11시 점과 12시 점을 잇는 선분의 가운데를 볼까요?" / ② `say`만 "선분 가운데 높이에서 옆으로 가서 세로 눈금을 읽어 봐요." / ③ 공통
    - E2E: no → NO-INTERPOLATE ①, 다시 → ②와 `interp-guide`(정렬 1px). 새로 열고 yes + 1.1 → WAVY ①, 다시 → ②와 `unfold-axis`. 새로 열고 yes + 36.5 → 일반 ①, yes + 37.1 → 통과
11. **A2.T3 체온이 가장 많이 오른 때 (A).** concepts `["g4s2u5.read-change"]`
    - 발문: "체온이 가장 많이 오른 때는 언제인가요? 맞는 것을 하나 골라요."
    - config: A2.T2와 같다.
    - 응답: 고르기 `rise` — `h9` "9시~10시", `h10` "10시~11시", `h11` "11시~12시", `h12` "12시~13시"
    - 판정: `any`(`rise`=["h9"], `rise`=["h10"]). 두 구간 모두 0.4℃ 올랐다.
    - 일반: ① "선분이 오른쪽 위로 올라간 곳 중 가장 가파른 곳을 찾아볼까요?" / ② `say`만 "올라간 선분마다 눈금 몇 칸만큼 올랐는지 세어 봐요." / ③ 공통
    - E2E: h11 → 일반 ①, h10 → 통과(새로 열고 h9 → 통과)
12. **A2.T4 14시 체온 예측과 근거 (A).** concepts `["g4s2u5.interpolate-predict"]`
    - 발문: "14시 체온은 어떻게 될까요? 근거를 고르고, 그 근거에 맞게 체온을 예측해 써요."
    - config: A2.T2와 같다.
    - 응답: 고르기 `reason` — `down` "11시부터 계속 내려가고 있어서", `up` "다시 올라갈 것 같아서", `same` "13시와 비슷할 것 같아서" / 수 칸 `next`(`forms:["decimal"]`, 라벨 "14시 체온(℃)")
    - 판정: `any`
      - `all`(`reason`=["down"], `responseCompare {field:"next", op:"lt", value:"36.6"}`)
      - `all`(`reason`=["up"], `responseCompare {field:"next", op:"gt", value:"36.6"}`)
      - `all`(`reason`=["same"], `responseCompare {field:"next", op:"eq", value:"36.6"}`)
    - 일반: ① "고른 근거와 예측한 체온이 서로 맞나요?" / ② `say`만 "13시 체온보다 낮을지, 높을지, 같을지 근거에 맞춰 생각해 봐요." / ③ 공통
    - E2E: down + 36.8 → 일반 ①, down + 36.4 → 통과
    - 명세의 "다음 시각에 점 찍기(extrapolate)"는 엔진에 가로축을 늘리는 기능이 없어 고르기 + 수 칸으로 대신한다. 메모와 명세 후순위에 적는다.
13. **완료 기준:** 명세(A1 과제 1~3, A2 과제 1~3)를 활동 메모에 적는다. 스키마에 키가 없으면 JSON에 넣지 않는다(T162와 같다).

### 14. 문서
- `docs/04-units/g4s2.md` g4s2u5에서 다음 곳만 고친다. 다른 문장은 바꾸지 않는다.
  - A1 설정 예시: T163 모양(`points`, `yStep`, `plotStep`, `graph`, `connect`, `predict` …)으로 바꾼다.
  - A2 설정 예시: `data`·`wavyLineTool`·`interpolate`·`extrapolate` 대신 `points`, `yStep`, `yFrom`, `yFromOptions`로 바꾼다.
  - 후순위·선택:
    - `scene`·`frames` 줄 끝에 "→ 1단계 A1은 표 자료로 점을 찍는다(P, T163·T164)"를 더한다.
    - 새 줄: "A2 다음 시각 점 찍기(가로축 늘리기)와 근거 카드는 1단계에서 근거 고르기 + 수 칸으로 대신한다(T164)."
- `data/units.json`은 건드리지 않는다.

### 15. E2E와 화면
