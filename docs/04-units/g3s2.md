### 활동
#### g3s2u1.A1 4분할 넓이 퍼즐 — E04 `area-model` · C→P→A
- **원 계획서:** (20+a)×(10+b) 4분할 넓이 퍼즐 조립기
- **화면과 조작:** 23 × 14 모눈 직사각형에 가로 분할선(20|3), 세로 분할선(10|4)을 끌어 놓으면 4조각(200, 30, 80, 12)이 각기 다른 색으로 나뉜다. 조각을 떼어 "부분곱 판"에 끌어 놓고 넓이를 입력, 합을 구한다. 퍼즐 모드에서는 조각들이 섞여 주어지고, 학생이 원래 직사각형으로 조립한 뒤 곱셈식을 쓴다.
- **설정 예시:**
  ```json
  { "mode": "area-model", "a": 23, "b": 14, "splitA": "free", "splitB": "free", "puzzle": false, "showGrid": "C-only" }
  ```
- **과제:**
  1. 20 × 30을 10 × 10 블록으로 / 판정: 블록 6개, 넓이 600
  2. 23 × 14를 4조각으로 / 판정: 분할 20|3, 10|4 + 부분곱 {200, 30, 80, 12} + 합 322
  3. 퍼즐: 섞인 조각 {600, 40, 90, 6}을 직사각형으로 조립해 원래 곱셈식 찾기 / 판정: 식 32 × 23 또는 23 × 32, 값 736
  4. 37 × 26 / 판정: 합 962
- **CPA 페이딩:** C: 모눈 칸 보임 / P: 칸 없는 직사각형, 변에 수만 / A: 넓이 모델 없이 부분곱 4개 목록만

#### g3s2u1.A2 자릿값 누락 터치 교정기 — E07 `mul` · P→A
- **원 계획서:** 세로셈 자릿값 누락 터치 교정기
- **화면과 조작:** 두 자리 × 두 자리 세로셈 격자. 둘째 부분곱 줄의 일의 자리 칸은 회색 "0 자리"로 표시된다(P). A 단계에서는 표시가 사라진다. `debug` 과제에서는 틀린 세로셈(둘째 줄을 한 칸 안 밀어 씀)을 보여 주고 학생이 잘못된 칸을 터치한다. 터치하면 그 줄이 넓이 모델의 어느 조각인지 색으로 연결된다.
- **설정 예시:**
  ```json
  { "mode": "mul", "a": 46, "b": 27, "style": "two-rows", "showZeroPlaceholder": "P-only", "debugSample": { "rows": [322, 92], "sum": 414 } }
  ```
- **과제:**
  1. 46 × 27 세로셈 / 판정: 칸 값 일치(322, 920, 1242)
  2. 틀린 풀이 46 × 27 = 414 에서 잘못된 칸 찾기 / 판정: 둘째 줄 일의 자리 칸 터치
  3. 58 × 34 / 판정: 1972
  4. 어림 확인: 46 × 27은 약 50 × 30 = 1500 근처인가? / 판정: 예
- **CPA 페이딩:** P: 0 자리 표시 + 넓이 조각 색 / A: 표시 없이

### 활동
#### g3s2u2.A1 십모형 해체 분배 — E01 `divide` + E07 `div` · C→P→A
- **원 계획서:** 십모형 해체 분배 세로셈 연동기
- **화면과 조작:** 52를 십 블록 5개 + 일 블록 2개로 놓고 접시 4개에 똑같이 나눈다. 십 블록을 하나씩 접시에 놓으면 4개는 나눠지고 1개가 남는다. 남은 십 블록은 망치로 풀어 일 블록 10개로 바꾼 뒤(12개) 다시 나눈다. 각 동작이 세로셈 격자의 한 단계(몫 쓰기 → 곱 → 빼기 → 내리기)를 자동으로 강조한다(C). P 단계부터 학생이 세로셈 칸을 직접 입력하면 블록이 그대로 따라 움직인다.
- **설정 예시:**
  ```json
  { "mode": "divide", "dividend": 52, "divisor": 4, "linkColumnCalc": { "engine": "E07", "mode": "div" }, "autoHighlightSteps": "C-only" }
  ```
- **과제:**
  1. 52 ÷ 4 / 판정: 접시별 13, 남은 블록 0 + E07 칸 일치
  2. 75 ÷ 3 / 판정: 25
  3. 47 ÷ 3 / 판정: 몫 15, 나머지 2
  4. 312 ÷ 6 (백 블록 풀기부터) / 판정: 몫 52
  5. 408 ÷ 4 (몫 가운데 0) / 판정: 몫 102, 몫 십의 자리 칸 0
- **CPA 페이딩:** C: 블록 + 접시 / P: 블록은 작게, 세로셈 직접 입력 / A: 세로셈만

#### g3s2u2.A2 나머지 경고등과 되감기 검산 — E07 `div` + E01 `regroup` · P→A
- **원 계획서:** 나머지 크기 경고등 및 역재생(Rewind) 검산 조립기
- **화면과 조작:** 학생이 몫과 나머지를 쓰면, 나머지가 나누는 수와 같거나 크면 경고등이 빨갛게 켜진다("한 번 더 나눌 수 있어"). 다 풀면 "되감기" 버튼으로 나눗셈 동작을 거꾸로 재생: 접시의 블록(몫 × 나누는 수)과 나머지 블록이 다시 한 무더기로 합쳐지며 검산식 `몫 × 나누는 수 + 나머지 = ?`가 채워진다.
- **설정 예시:**
  ```json
  { "mode": "div", "dividend": 83, "divisor": 6, "remainderAlarm": true, "rewindCheck": { "engine": "E01", "mode": "regroup" } }
  ```
- **과제:**
  1. 83 ÷ 6 몫과 나머지 / 판정: 13, 5; 경고등 꺼짐
  2. 틀린 답 "83 ÷ 6 = 12 … 11" 판단 / 판정: 경고 이유 카드 "나머지가 6보다 크다" 선택
  3. 되감기 검산식 완성 / 판정: 13 × 6 + 5 = 83
  4. 나머지가 될 수 있는 수 모두(÷ 7) / 판정: {0~6} 또는 {1~6}(교과서 확인: 나머지 0 포함 여부)
- **CPA 페이딩:** P: 되감기 애니메이션 / A: 검산식만

### 활동
#### g3s2u3.A1 말뚝과 밧줄 — E09 `circle` · C→P
- **원 계획서:** 말뚝·밧줄 원 생성 시뮬레이터
- **화면과 조작:** 운동장에 말뚝을 박고 밧줄 끝을 잡아 한 바퀴 끌면 지나간 자리에 점이 찍힌다. 밧줄은 늘어나지 않으므로 손가락이 너무 멀리 가면 밧줄이 팽팽하게 멈춘다. 점이 다 이어지면 원이 된다. 이어서 원 위 아무 점을 잡아 중심까지 선분을 그어 길이를 재면 항상 같다(반지름).
- **설정 예시:**
  ```json
  { "mode": "circle", "scene": "playground", "stake": [0, 0], "ropeLength": 4, "traceDots": true, "measureTool": true }
  ```
- **과제:**
  1. 밧줄로 원 그리기 / 판정: 궤적 각도 커버리지 ≥ 95%
  2. 반지름 3개를 그어 길이 비교 / 판정: 서로 다른 반지름 3개 + 길이 모두 같음 확인 버튼
  3. "밧줄 길이를 바꾸면 무엇이 달라질까?" 예측 후 실험 / 판정: 밧줄 6으로 원 그리기 + 선택지 "원의 크기"
- **CPA 페이딩:** C: 운동장·밧줄 / P: 점과 선분 / A: 반지름 값 문항

#### g3s2u3.A2 가장 긴 선분 찾기와 컴퍼스 무늬 — E09 `circle` + `construct` · P→A
- **원 계획서:** 가상 컴퍼스 무늬 작도 및 중심 통과 최대 현(지름) 스냅 탐색기
- **화면과 조작:** 원 위 두 점을 잡고 움직이면 그 선분 길이가 막대로 표시된다. 가장 길어질 때 선분이 중심을 지나며 "딸깍" 스냅, 지름 이름표가 붙는다. 가상 컴퍼스(침 위치·벌린 폭 조절)로 반지름을 바꿔 가며 원을 그려 무늬를 만든다. 제시된 무늬를 똑같이 그리는 과제는 중심과 반지름을 찾아야 한다.
- **설정 예시:**
  ```json
  { "mode": "circle", "radius": 3, "chordExplorer": true, "snapDiameter": true, "compass": { "enabled": true, "gridSnap": 0.5 }, "targetPattern": "three-circles-in-row" }
  ```

### 활동
#### g3s2u4.A1 사탕 묶음 스튜디오 — E05 `discrete` · C→P→A
- **원 계획서:** 이산량(사탕) 묶음 기준 변화 스튜디오
- **화면과 조작:** 사탕 12개가 흩어져 있다. 학생이 "몇 개씩 묶기" 다이얼(2, 3, 4, 6)을 돌리면 사탕이 자동으로 그만큼씩 묶음 상자에 들어간다(또는 올가미로 직접 묶기). 묶음 하나를 누르면 "12의 1/4", 세 개를 누르면 "12의 3/4 = 9"가 표시된다. 같은 사탕 4개가 묶음 기준에 따라 1/3도, 2/6도 되는 것을 비교한다.
- **설정 예시:**
  ```json
  { "mode": "discrete", "items": 12, "itemIcon": "candy", "groupSizeOptions": [2, 3, 4, 6], "grouping": "dial-or-lasso", "showFractionOf": true }
  ```
- **과제:**
  1. 사탕 12개를 3개씩 묶으면 3개는 12의 얼마? / 판정: 묶음 수 4 + 답 1/4
  2. 12의 3/4은 몇 개? / 판정: 4묶음 중 3묶음 선택 + 9
  3. 사탕 4개는 12의 얼마? 묶는 방법 두 가지로 / 판정: 1/3(4개씩)과 2/6(2개씩) 두 표현 모두
  4. 18의 2/3 / 판정: 12
  5. A 단계: "20의 3/5은 □" / 판정: 12
- **CPA 페이딩:** C: 사탕 그림과 묶음 상자 / P: 점과 동그라미 묶음 / A: 식과 답만(막히면 점 묶음 힌트)

#### g3s2u4.A2 가분수·대분수 컨베이어 — E05 `mixed` · C→P→A
- **원 계획서:** 가분수-대분수 자연수 융합 컨베이어
- **화면과 조작:** 컨베이어 벨트 위로 1/4 조각들이 하나씩 실려 온다. 학생이 조각을 원판에 채워 넣다가 4조각이 가득 차면 원판이 "1" 자연수 상자로 융합되어 옆으로 빠진다. 11/4을 다 실으면 자연수 상자 2개와 3/4 조각이 남아 "2와 3/4"이 된다. 거꾸로 대분수를 넣으면 자연수 상자가 조각으로 분해되어 가분수가 된다.
- **설정 예시:**
  ```json
  { "mode": "mixed", "direction": "improper-to-mixed", "value": "11/4", "wholeShape": "circle", "conveyorSpeed": "student-controlled" }
  ```
- **과제:**
  1. 진분수·가분수·대분수 카드 분류(3/5, 7/5, 1 2/5, 5/5) / 판정: 분류 정오(5/5는 가분수)
  2. 11/4을 대분수로 / 판정: 융합 2회 + 답 2 3/4
  3. 2 1/3을 가분수로 / 판정: 분해 결과 7/3

### 활동
#### g3s2u6.A1 아이콘 압축 그림그래프 만들기 — E18 `pictograph` · C→P→A
- **원 계획서:** 낱개 아이콘 10개 드래그 압축(큰 아이콘 변환) 픽토그래프 빌더
- **화면과 조작:** 마을별 사과 수확 표(예: 32, 25, 41, 18 상자)를 보고 처음엔 작은 사과 아이콘을 하나씩 놓는다. 너무 길어지면 "압축" 도구로 작은 아이콘 10개를 올가미로 묶어 큰 아이콘 1개로 바꾼다. 범례(큰 그림 = 10, 작은 그림 = 1)가 자동으로 생기고, 학생이 범례 값을 바꾸면(예: 큰 그림 = 5) 그래프가 다시 계산된다.
- **설정 예시:**
  ```json
  { "mode": "pictograph", "data": { "가": 32, "나": 25, "다": 41, "라": 18 }, "icon": "apple", "compressGroup": 10, "legendEditable": true }
  ```
- **과제:**
  1. 표를 보고 그림그래프 완성 / 판정: 각 행 값 = 큰 아이콘×10 + 작은 아이콘×1
  2. 압축 전·후 아이콘 수 비교("몇 개 줄었나") / 판정: 정답 수
  3. 큰 그림 = 5로 바꿔 다시 나타내기 / 판정: 각 행 값 일치
  4. 학급 자료(교사가 입력한 좋아하는 계절)로 그림그래프 만들기 / 판정: 자료와 일치
- **CPA 페이딩:** C: 아이콘 끌기·묶기 / P: 아이콘 수 입력 / A: 그래프만 보고 읽기

#### g3s2u6.A2 그림그래프 읽기와 해석 — E18 `table-to-graph` · P→A
- **원 계획서:** (픽토그래프 빌더의 읽기 단계)
- **화면과 조작:** 완성된 그림그래프를 보고 값 읽기, 가장 많은/적은 곳, 차이 구하기. 같은 자료를 표·그림그래프로 번갈아 보여 주고 어느 쪽이 무엇을 알기에 편한지 고른다.
- **설정 예시:**
  ```json
  { "mode": "table-to-graph", "data": { "가": 32, "나": 25, "다": 41, "라": 18 }, "views": ["table", "pictograph"], "legend": { "big": 10, "small": 1 } }
  ```
- **과제:**
  1. 다 마을 값 읽기 / 판정: 41
  2. 가장 많은 마을과 가장 적은 마을의 차 / 판정: 23
  3. "그림 개수가 가장 많은 행 = 가장 큰 값일까?" 반례 고르기 / 판정: 반례 그래프 선택
- **CPA 페이딩:** P: 아이콘 위에 값 툴팁 / A: 툴팁 없이
