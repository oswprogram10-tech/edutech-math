# T199 E06·E19·E20: 좁은 실행기 판에서 조작 칸이 눌려 사라지는 문제

| 항목 | 내용 |
| --- | --- |
| 상태 | review |
| 웨이브 | W5 |
| 선행 카드 | T192 |
| 담당 | 소넷 서브에이전트 |

## 목표
g6s1u4.A2.T3(T192)에서 오른쪽에 응답 칸이 있으면 E20 `rate` 판이 좁아진다. 이때 문제가 생긴다.
- 판 폭이 820px 컨테이너 기준 아래로 내려가면 세로 배치가 된다.
- 세로 배치에서 `.sideStack`(조작 칸)이 `flex: 0 1 auto`라 높이 32px 안팎으로 눌린다.
- 크롬북 1366×768에서 거리·시간 입력·예측·경주 시작 단추가 첫 화면에서 보이지 않고, 마우스로 누를 수 없다(단축키만 된다).
- 아이패드 세로에서는 한 줄만 보인다.
- 전자칠판에서는 판 그림이 8% 가려진다.

E06(T187)·E19(T193)도 같은 구조(`boardArea` + `sideStack`, 820px 컨테이너 기준)라 같은 문제가 날 수 있다. 세 엔진을 함께 고친다.

## 먼저 읽을 문서

- 앞서 같은 문제를 푼 엔진 참고(import 금지): `src/engines/E15-pattern/`의 `.sideStack[data-table]` 처리(T179)

## 구현 결정 (2026-11-20 Claude 작성 — 여기 적힌 대로 하고, 바꿔야 하면 메모에 이유를 적고 멈춰서 묻는다)
1. **세로 배치 원칙**(판 폭 < 820px 컨테이너)
   - 조작 칸은 눌리지 않는다(`flex-shrink: 0`, 내용 높이 그대로).
   - 판 그림은 남는 높이에 맞춰 줄되, 최소 배율 0.6 아래로는 줄지 않는다.
   - 둘을 합쳐 슬롯보다 길면 엔진 바깥 상자(`.wrap`)가 세로로 스크롤한다. 판 안 스크롤(`data-scroll`)과 바깥 세로 스크롤이 겹치지 않게 한다. 바깥은 세로만, 판 안은 가로만 쓴다.
2. **첫 화면 기준:** 크롬북 1366×768, 응답 칸이 있는 g6s1u4.A2.T3에서 조작 칸 첫 줄(입력 칸 또는 첫 단추)이 스크롤 없이 보인다.
   - 이를 위해 세로 배치에서 판 그림의 최대 높이를 `min(60%, 판 논리 높이 × 배율)`처럼 제한해도 된다.
   - 그래도 안 되면 그 이유와 수치를 메모에 적고 멈춰서 묻는다.
3. **가로 배치**(≥ 820px): 지금 동작을 유지한다. 단, 전자칠판에서 판 그림이 조작 칸에 가리지 않게 한다. 판 상자 폭 안에서 그림이 다 보여야 한다.
4. **세 엔진 모두 같은 원칙**
   - 엔진마다 자기 CSS만 고친다(엔진끼리 import 금지).
   - E06·E19에서 같은 문제가 재현되지 않으면 그 엔진은 고치지 않고 메모에 "재현 안 됨"과 확인 방법을 적는다.
   - 재현 확인에는 응답 칸이 있는 과제를 쓴다(E06은 g2s1u3.A2 T5 symbols 또는 응답 판이 있는 과제, 없으면 샌드박스 좁은 폭).
5. **E2E**
   - `g6s1u4.spec.ts`
     - `expectReachable` ratio 0.9 완화를 풀어 1로 되돌린다.
     - A2.T3의 예측·경주를 단축키가 아니라 단추 클릭으로 바꾼다.
   - 크롬북·아이패드에서 조작 칸 첫 단추의 화면 높이 ≥ 44px와 클릭 가능을 확인하는 검사를 g6s1u4 A2.T3에 더한다.
   - 바뀐 기준 이미지는 다시 찍고 직접 확인한다. g6s1u4·ratio-lab·chance-lab·balance·g2s1u3·g5s2u6(있으면)이 대상이다.
   - 도구 줄만 밀린 것과 그림·배치가 달라진 것을 메모에 나눠 적는다.
6. **E2E 범위:** `npx playwright test ratio-lab chance-lab balance fit-canvas overlay-alignment g6s1u4 g2s1u3 --workers=3 --reporter=line`

## 메모

### 구현 메모 (Sonnet, 2026-11-20)
- **재현(수정 전)**: g6s1u4.A2.T3 크롬북 1366×768에서 슬롯 454px, 판 360px, `.sideStack`(rate 조작 칸) 높이 32px(내용 322px가 눌림). 아이패드 세로는 70px, 전자칠판(1920)은 가로 배치에서 판 상자 551px < 그림 600px라 그림이 49px(8%) 잘림. E06·E19는 응답 칸이 있는 실제 과제가 없거나(E19는 어떤 콘텐츠에도 아직 없음) 구조가 똑같아서, 샌드박스 `?stage=fit` 아이패드(판 520px)에서 확인했다. E06 `balance-scale-tilt-ipad` 기준 이미지가 조작 칸이 ~150px로 눌려 안쪽 스크롤되던 모습이었다. 세 엔진 CSS가 글자 단위로 같아 같은 수정을 넣었다.
- **고친 것(세 엔진 `View.module.css`만)**
  - 세로 배치: `.wrap`이 세로 스크롤(`overflow-y: auto`, 가로는 hidden). `.sideStack`은 `flex: 0 0 auto`, `overflow: visible`로 눌리지 않는다. 판은 `min-height: 360px`(=논리 600 × 0.6)로 최소 배율 0.6 아래로 줄지 않는다. 판 안 스크롤(`data-scroll`)은 `overflow-x: auto; overflow-y: hidden`(가로만).
  - 가로 배치: 컨테이너 조건을 820px → 900px로 올리고 판에 `min-width: 600px`를 줘서 조작 칸이 그림을 가리지 않는다(600 + 간격 16 + 조작 칸 최소 280 = 896px). 조작 칸 스크롤은 가로 배치에서만 `.sideStack`이 맡는다. 820~900px 구간은 세로 배치가 된다(구현 결정 3의 820 기준에서 벗어남, 이유는 위).
- **구현 결정 2(크롬북 첫 화면)를 만족하지 못했다 — 질문**: 크롬북 반쪽 판은 슬롯 454px이고 판이 최소 0.6배 = 360px라서 조작 칸에 남는 높이는 약 44px뿐이다(안내 글 한 줄 정도). 입력 칸·첫 단추(48px)는 바깥 상자를 스크롤해야 보인다. 이제 단추는 48px 그대로이고 마우스로 눌린다(Playwright 클릭 통과). 판 배율 0.6 하한을 지키는 한 더 줄일 방법이 없다. 하한을 낮추거나 슬롯을 키우는 결정이 필요하면 알려 달라.
- **E2E**: `g6s1u4.spec.ts` — `expectReachable` 0.9 완화 제거, 예측·경주를 단추 클릭으로 바꿈, `expectControlsUsable`(첫 단추 ≥44px·뷰포트 안·눌림 없음·판 높이 ≥360·클릭 가능)을 A2.T3 첫 화면에 추가. `panel-layout.ts`·`fit-canvas.spec.ts` — 샌드박스 아이패드에서 E06·E19·E20은 바깥 상자의 세로 스크롤을 허용(`outerScrollY`). `ratio-lab`·`chance-lab`·`balance` 스냅샷 도우미 — 바깥 상자 스크롤도 맨 위로 되돌린 뒤 찍는다.
- **기준 이미지**: 다시 찍은 것은 `balance-scale-tilt-ipad-win32.png` 하나. 직접 열어 보니 판 그림은 그대로이고 조작 칸 줄만 달라졌다(**도구 줄만 밀림**: 예전에는 조작 칸 안쪽 스크롤이 아래로 가 있던 화면, 지금은 맨 위 안내·입력 칸). **배치 달라짐**은 없다. ratio-lab 아이패드 4장은 스크롤 위치 보정 뒤 기존 기준과 같다. g5s2u6 콘텐츠는 이 저장소에 아직 없다.
- 범위 밖 요청: 없음.
