# T169 E18 distortion 배치: 두 칸 판에서 그래프가 기사 제목 줄에 덮이지 않게

## 목표
T168 검수에서 크롬북 g6s1u5.A2.T1(응답 칸이 있는 두 칸 판)의 문제가 나왔다.
- distortion 막대그래프 영역이 최소 높이 200px로 눌린다.
- 그 아래 "기사 제목" 줄이 그래프 아래쪽을 덮어, 세로축 0 눈금과 가로축 이름(1반·2반)이 가려진다(스냅샷 `g6s1u5-a2-chromebook`).
- 이 과제는 "세로축 맨 아래 숫자"를 읽는 것이 핵심이라, 가려지면 학습이 안 된다.
- 아이패드(한 칸 판)와 전자칠판은 괜찮다.

## 구현 결정 (2026-11-19 Claude 작성 — 여기 적힌 대로 하고, 바꿔야 하면 메모에 이유를 적고 멈춰서 묻는다)
1. **원인부터 잰다.**
   - 크롬북 g6s1u5.A2.T1에서 `.wrap`, `.distControls`, `.distBody`, `.distBoard`, `.boardArea`, SVG, `.headline`의 크기·위치를 재어 메모에 적는다.
   - 겹침이 어디서 생기는지 찾는다. 짐작: `.distBody`·`.distBoard`가 `min-height: 0`이라 `.boardArea`(min-height 200)보다 작게 줄고, 넘친 그래프 위에 다음 형제인 `.headline`이 그려진다.
2. **겹치지 않게 한다.**
   - 어떤 판 크기에서도 형제 상자(조작 줄·그래프·제목 줄·체크리스트)가 서로 겹치지 않는다.
   - 공간이 모자라면 `.wrap`(이미 `overflow-y: auto`)이 세로로 스크롤한다.
   - 그래프 영역은 남는 높이를 받되, 그래프가 줄어드는 하한은 200px다.
3. **그래프를 덜 누른다.**
   - 크롬북 두 칸 판에서 그래프 높이가 200px보다 커질 수 있으면 키운다.
   - 방법은 둘 중 하나다:
     - 조작 줄을 한 줄로 촘촘히 한다(이미 쓰는 `.scaleRow` 간격 안에서).
     - 제목 카드 줄을 가로로 흘린다.
   - 단추 크기는 48px(저학년 64px) 아래로 줄이지 않는다.
   - 결과 높이를 메모에 적는다.
4. **바꾸지 않는 것:** Action·State·Observation·predicate의 뜻, 다른 모드(band-circle·line·bar 등)의 배치, 체크리스트 동작.
5. **테스트:**
   - graph-studio.spec.ts에 distortion 배치 E2E를 더한다. 3 뷰포트와, 응답 칸이 있는 두 칸 판을 흉내 낸 좁은 stage(폭 640 안팎, 높이 420)에서 확인한다.
     - 그래프 SVG 상자와 `.headline` 상자가 겹치지 않는다.
     - 세로축 0 눈금 글자와 가로축 범주 이름이 화면 안에서 보인다. 다른 요소에 덮이지 않았는지 `elementFromPoint`로 확인한다.
   - g6s1u5.spec.ts: 크롬북 A2.T1에서 같은 단언을 더한다.
   - 바뀐 스냅샷은 다시 찍고 직접 연다. 대상은 g6s1u5 `a2-*`, graph-studio distortion 관련이다. E18·g6s1u5 밖 스냅샷이 바뀌면 멈춘다.

## 메모

### 구현 메모 (소넷, 2026-11-19)
- **원인 측정(크롬북 660x420 두 칸 판, g6s1u5.A2.T1 흉내)**: `.wrap` 높이 424(y70-494), 탭 줄 ~58, 조작 줄 102(y128-230), `.distBody`·`.distBoard` 142(y240-382), `.boardArea`·SVG 200(y240-440), `.headline` 102(y392-494). 짐작대로 `.distBody`/`.distBoard`가 `min-height: 0`이라 142로 줄었고 `.boardArea`(min 200, overflow hidden)가 그 밖으로 58px 넘쳐 다음 형제 `.headline`(y392~)이 그래프 아래 48px(y392-440)를 덮었다. `.wrap`은 내용이 안 넘친다고 보아 스크롤도 없었다(scrollHeight 424 = clientHeight).
- **고침**: `View.module.css`의 `.distBody`, `.distBoard`를 `min-height: 0` → `min-height: 200px`(그래프 하한과 같게). 이제 같은 판에서 distBody 200(y240-440), headline y449-552, `.wrap` scrollHeight 482 > 424라 58px 세로 스크롤. 다른 모드·Action·Observation은 그대로. 큰 판(전자칠판 672, 아이패드 515)은 높이 변화 없음.
- **그래프 높이는 키우지 못함(200 유지)**: 조작 줄은 이미 2줄(단추 48px), 제목 줄은 글 칸 48 + 카드 한 줄 48이라 더 줄일 곳이 없고, 단추 48px 아래로는 안 줄인다. 두 칸 폭에서는 .wrap 스크롤을 받아들였다. 0 눈금·1반·2반 이름은 첫 화면에서 보이고, 제목 카드 단추는 스크롤해서 닿는다(스냅샷 확인).
- **테스트**: graph-studio.spec.ts에 T169 배치 테스트(3 뷰포트 기본 판 + 크롬북 660x420 `?stage=fit`: 조작 줄·그래프·제목 줄 상자 비겹침, 그래프 >= 200, 단추 >= 48, 0·1반·2반을 elementFromPoint로 확인), g6s1u5.spec.ts A2.T1에 같은 단언. 스냅샷은 `g6s1u5-a2-chromebook` 하나만 바뀜(maxDiffPixelRatio 2% 안이라 자동 갱신이 안 되어 파일을 지우고 다시 찍고 직접 열어 확인). graph-studio 스냅샷은 변경 없음.
- **E2E 범위**: 지시에 따라 전체 대신 E18 spec만 실행(graph-studio, g2s2u5, g3s2u6, g4s1u5, g4s2u5, g6s1u5; 513개 중 494 통과·17 skip·2 실패). 실패 2건은 부하 중 타임아웃(g4s1u5.A1 ipad의 click 20초, graph-studio length-only chromebook 오버레이 정렬 3.4px)으로, 단독 재실행에서 통과.
- **의심스러운 곳**: ① 체크리스트(예시 탭)가 있는 두 칸 판도 `.distBody` 최소 200px 규칙을 받는다(예시 탭 한 줄 배치는 컨테이너 560px 이상일 때만). ② `.distBoard`의 min-height 200이 distNote가 있을 때 노트 높이를 포함하지 않음(그래프는 안 겹치지만 노트가 아래로 넘칠 수 있음; .wrap 스크롤로 닿음).
