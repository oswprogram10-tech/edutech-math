## 구현 결정 (2026-11-02 Claude 추가 — 여기 적힌 대로 하고, 바꿔야 하면 메모에 이유를 적고 질문한다)
1. **폴더:** `src/engines/E03-number-line/`, E00-demo 본보기를 따른다. 엔진 ID `E03`, modes 순서: `integer`, `fraction`, `decimal`. 확장 모드는 W1 명세에 쓰인 것이 없으므로 만들지 않는다(`range`·`double` 등은 해당 웨이브에서).
2. **위치는 Rational, 눈금 인덱스로 스냅:** 화면(논리) 좌표 → **가장 가까운 눈금의 정수 인덱스 k** → 값 = `min + k × tick`(Rational). 값을 number로 계산했다가 반올림하지 않는다. 상태·Observation에는 Rational 문자열로 넣는다. `3/4`와 `0.75`는 같은 Rational이므로 같은 점이다.
3. **눈금(`tick`):** integer는 `1/subdivisions`가 아니라 1(또는 `unit`), fraction은 `1/subdivisions`. `subdivisions`가 배열(`[3, 5]`)이면 두 눈금 줄을 위아래로 그린다(학생이 점을 찍을 때는 가까운 줄의 눈금에 스냅). decimal은 줌 단계마다 `1 → 1/10 → 1/100 → 1/1000`, `zoom.from`/`zoom.to`로 허용 범위를 정한다.
4. **줌:** 두 손가락 핀치(T003 `usePinch`), Ctrl+휠, 화면 `+`/`−` 버튼, 키보드 `+`/`-` 네 가지 모두. 줌은 보기 상태라 **Action으로 기록**한다(`{type:'zoom', level}` — 되감기에서 학생이 어디까지 확대했는지 보이게).
5. **명세의 설정 키:** `mode`, `min`, `max`(Rational 문자열 허용), `subdivisions`(수 또는 배열), `unit`, `zoom`(`from`, `to`), `cards`(끌어서 꽂는 카드 값 목록 — 대분수 `"1 1/4"` 포함), `snap`(`"tick"`), `laser`(두 점이 같은 위치인지 세로 레이저로 보여 주는 표시, 정답 표시 아님), `showJumps`. 다른 엔진 설정은 무시한다.
6. **조작:** 빈 곳 탭 → 점 찍기(스냅), 점 끌기 → 옮기기(놓을 때 Action 한 번), 점 두 개 사이 끌기 → 점프 화살표, 카드 끌어 꽂기(`cards`가 있을 때). 키보드: 점 선택 후 ←/→ 한 눈금, Shift+←/→ 큰 눈금, Enter 점 찍기, Delete 점 지우기.
7. **Observation:** `mode`, `points: [{ value, label? }]`(값 오름차순), `cards: { [card]: value | null }`(카드가 꽂힌 위치의 값), `jumps: [{ from, to, size }]`, `jumpTotal`, `zoomLevel`, `tick`. 값은 모두 Rational 문자열.
8. **Predicates:** `hasPointAt`(args `{ value }`, 동치), `cardsCorrect`(꽂힌 위치 값 = 카드 값, 모두), `samePoint`(args `{ a, b }`), `jumpTotalIs`(args `{ value }`).
9. **이벤트:** `events`: `point-placed`, `point-moved`, `jumped`, `card-placed`, `zoomed`, `value-changed`. **`value-changed` payload는 E05와 같은 `{ value: "<Rational 문자열>" }`**. `receive`로 `value-changed`를 받으면 그 값에 '연결 점'(학생 점과 구분되는 모양)을 표시한다 — 학생이 찍은 점으로 세지 않는다.
10. **오버레이(힌트 ②):** `distance-from-zero`(학생이 찍은 점까지 0에서의 거리를 막대로 표시), `same-point`(두 값이 같은 점인지 세로선으로 보여 줌). 정답 위치에 점을 찍어 주지 않는다.
11. **핀치 E2E:** Playwright는 WebKit(아이패드 프로젝트)에서 두 손가락 터치를 만들 수 없다. **아이패드 프로젝트 E2E는 `+`/`−` 버튼과 휠로 줌을 확인**하고, 핀치 계산은 단위 테스트로 확인한다. 실기기 핀치는 운영자가 확인한다.
12. **입력 범위·문구·크기:** 답 입력(부등호, 분수 쓰기)은 범위 밖(T016). 문구는 `strings.ko.ts`, 조작 요소는 `targetSize` 이상, 연결 점·학생 점·카드는 색 외에 모양으로도 구분.
13. **테스트:** 단위(스냅 경계: min, max, 눈금 사이 정중앙, 대분수 카드, 줌 단계 경계), `assertSerializable`, `#/sandbox/E03`에서 3개 뷰포트 E2E(3/4 점 찍기 → 0.75와 같은 점, decimal 줌 버튼으로 0.01 눈금까지).

## 메모

- 엔진 폴더: `src/engines/E03-number-line/` — `types.ts`, `ticks.ts`, `reduce.ts`, `observe.ts`, `events.ts`, `strings.ko.ts`, `View.tsx`, `View.module.css`, `overlays/distance-from-zero.tsx`, `overlays/same-point.tsx`, `index.ts`.
- `ticks.ts`: 화면 x → 수 값(`Rational`) → 가장 가까운 눈금 인덱스 `k` → `min + k×tick`. 눈금 사이 정중앙은 큰 쪽 눈금으로 보낸다(단위 테스트로 고정). `integer`는 `unit`, `fraction`은 `unit/subdivisions`, `decimal`은 `unit/10^level`. `subdivisions` 배열이면 줄을 위아래로 그린다.
- `3/4`과 `0.75`은 같은 `Rational`이라 같은 점이다. 카드 `"1 1/4"`은 `5/4`으로 파싱한다. 상태·Observation·Action에는 모두 정규 문자열(`"3/4"`, `"5/4"`)로 넣는다.
- `decimal` 줌: `zoom.from`/`zoom.to`를 10의 거듭제곱 지수로 바꿔 `zoomMin`/`zoomMax`를 정한다. 기본 `1 → 1/1000`(0~3단계). `zoom` Action은 절대 단계 `{type:'zoom', level}`이다.
- 핀치: `usePinch`(scale 0.25~4, step 0.25)의 `onChange`를 `zoomDeltaForPinch(baseScale, next, 0.25)`로 단계 변화로 바꾼다. Ctrl+휠은 React 합성 wheel이 passive라 SVG에 non-passive 리스너를 직접 붙였고, 연속 휠에서 최신 단계를 읽도록 SVG의 `data-zoom-*` 속성을 쓴다. `+`/`−` 버튼과 키보드 `+`/`-`도 같은 Action을 보낸다.
- 조작: 빈 곳 탭 → 점 찍기, 점 끌기 → 옮기기(놓을 때 Action 한 번), 점을 다른 점 위에 놓으면 점프 화살표, 카드는 탭으로 고른 뒤 수직선 탭 또는 끌어서 꽂기. 키보드: 점 선택 후 ←/→(Shift 5눈금), Enter 점 찍기, Delete/Backspace 점 지우기, Escape 선택 해제. 터치 타깃은 `minTouchRadius`로 계산하고 점은 원, 연결 점은 마름모, 카드는 둥근 사각형으로 모양도 구분한다.
