# T174 E16 `rule-shooter`: 관계식 레이저로 보석 맞히기

## 목표
E16에 네 번째 모드 `rule-shooter`를 더한다. g5s1u3.A2 "관계식 레이저로 보석 모으기"에 쓴다.
- 좌표 격자(가로 ○, 세로 □)에 보석이 있다.
- 학생이 `□ = ○ × 3 + 1` 같은 관계식을 쓰고 발사하면, 식에 맞는 점에 레이저 점이 떨어진다.
- 맞힌 보석과 빗나간 보석이 드러나고, 빗나간 보석에는 설명 패널이 붙는다(명세 부록의 '빗나간 보석 설명 패널').
- 명세의 "전함" 변형(블랙박스 3번 이내)은 T173 `black-box`의 `maxTrials`로 하므로 이 카드에서 만들지 않는다.

## 구현 결정 (2026-11-20 Claude 작성 — 여기 적힌 대로 하고, 바꿔야 하면 메모에 이유를 적고 멈춰서 묻는다)

### 1. 범위
- `modes`에 `'rule-shooter'`를 더한다. 새 파일은 `ShooterView.tsx`, `shooter.ts`(순수 계산)와 `overlays/laser-miss.tsx`다. 키패드·식 입력·`relation-check`는 T173 것을 그대로 쓴다.
- 다른 모드의 동작과 상태 모양은 바꾸지 않는다.
- `src/core/`, 다른 엔진, `data/`, `docs/`, `package.json`은 고치지 않는다.

### 2. 설정
```ts
interface ShooterConfig extends CommonConfig { // rule은 받지 않아도 된다(아래)
  mode: 'rule-shooter';
  gems: [string | number, string | number][]; // [○, □], 2~8개, 정수 또는 Rational 문자열
  grid?: { xMax: number; yMax: number };     // 기본: 보석 최댓값 + 여유(○ +2, □ +3), 정수
  allowedOps?: ('+' | '-' | '×' | '÷')[];    // 식 키패드에 보일 연산 단추(기본 넷 다)
  look?: 'grid' | 'table';                   // A 단계: 'table'이면 격자 없이 보석 표만
  missPanel?: boolean;                       // 기본 true
  avoidForm?: string;                        // ruleFormDiffers용(화면에 보이지 않음)
}
```
- `rule`은 선택이다. 판정은 "보석을 모두 맞혔는가"로 하기 때문이다.
  - `rule`이 있으면 `matchesHidden`을 계산한다.
  - 없으면 `matchesHidden`은 `allHit`과 같게 둔다.
- 보석이 2개 미만이거나 좌표가 읽히지 않으면 설정 오류 판을 그린다(T173 규칙).
- 모르는 키(`symbols` 등)는 무시한다.

### 3. 상태와 Action
- **상태:** `{ mode: 'rule-shooter', settings, ruleText, tested, ruleHistory, target: 'rule', shots: { text: string; hits: number[] }[] }`
  - `shots`는 발사 기록(파싱된 식만, 최근 10개)이다. `hits`는 맞힌 보석 번호다.
- **Action:** T173 식 입력 Action(`type`, `backspace`, `clear`)과 `fire`.
  - `fire`는 `test-rule`과 같이 식을 시험하고 `shots`에 더한다.
  - 파싱되지 않으면 `tested`만 바뀌고 `shots`는 그대로다.

### 4. 계산 (`shooter.ts`, 순수, Rational)
- `laserPoints(rel, grid)`: ○ = 0, 1, …, xMax 정수마다 `solveBox(rel, ○)`를 구한다.
  - 0 ≤ □ ≤ yMax인 점만 남긴다(분수 □도 남긴다).
  - NONLINEAR나 null인 ○는 건너뛴다.
- `gemHits(rel, gems)`: 보석마다 `relationHolds(rel, ○, □)`를 본다.
- `missInfo(rel, gem)`: `{ x, gemY, ruleY: solveBox(rel, x) | null }`

### 5. 화면 (`ShooterView.tsx`)
- **격자 SVG** `data-testid="shooter-canvas"`
  - 가로축 ○ 0~xMax, 세로축 □ 0~yMax, 눈금 숫자가 있다. 축 이름은 "○"·"□"다.
  - 보석은 보석 그림(다이아몬드 모양 + 윤곽)이고 `data-gem="<i>"`다.
  - 칸이 많아 한 칸이 화면 14px보다 작아지면 눈금 숫자를 건너뛰어 쓴다(E18 T165 규칙 참고, import는 하지 않는다).
  - 보석은 화면에서 지름 24px 이상이다.
- **발사**
  - "발사" 단추를 누른다(식 키패드의 "규칙 시험하기" 자리에 "발사"를 쓴다).
  - 레이저 점이 ○ 작은 쪽부터 차례로 떨어지는 짧은 애니메이션이 나온다. 전체 0.8초 이하이고, `prefers-reduced-motion`이면 바로 그린다.
  - 레이저 점은 작은 원 + 십자 표시다(색만으로 구분 금지).
- **결과 표시** (가장 최근 발사만)
  - 맞힌 보석: 보석 위에 ✓ 배지, 보석은 사라지지 않고 옅어진다.
  - 빗나간 보석: ✕ 배지
  - 학생 식이 바뀌면(입력 중) 결과 표시는 사라진다.
- **빗나간 보석 설명 패널** (`missPanel`)
  - 빗나간 보석마다 "이 보석의 ○는 4인데, 내 식에 넣으면 □는 13이에요."를 쓴다(`ruleY`가 null이면 "내 식으로는 □를 하나로 정할 수 없어요").
  - 보석 □(과제 자료)와 학생 식의 □(학생 자료)만 쓰므로 정답 노출이 아니다.
  - 패널은 격자 옆이나 아래의 목록이다(SVG 밖 HTML 가능). 보석 번호와 같은 그림 표시를 붙인다.
- **`look: 'table'`**: 격자 대신 보석 쌍을 T173 대응표(`relation-canvas`)로 그리고 ✓/✕를 표 아래에 쓴다. 레이저 그림은 없다.
- **판 맞춤:** 격자는 `.boardArea`, 식 입력·키패드·패널은 `.sideStack`이다. 판에 안 들어가면 줄이지 말고 스크롤한다(T170·T173 원칙). 키패드 단추는 targetSize 이상이다.

### 6. Observation과 predicate
- **Observation:** T173 공통 키 + 아래
  - `gems`(Rational 문자열 쌍)
  - `hits`: 최근 발사
  - `hitCount`, `allHit`
  - `shotCount`
  - `pairs`: 보석 쌍. T173 오개념 판정이 `pairs`로 보석을 본다.
- **오개념:** T173 `detectMisconceptions`를 그대로 쓴다(ONE-PAIR, SWAP-VARS, RECURSIVE-ONLY). ADD-ONLY는 숨은 `rule`이 있을 때만 걸린다.
- **Predicate:** T173 것 + 아래
  - `allHit {}`
  - `hitCountAtLeast {n}`
  - `shotsAtMost {n}`
  - `ruleFormDiffers {from}`: 이 모드에서는 `allHit`이고, `formatRelation(학생 식)`이 `formatRelation(parseRelation(from))`과 다르다.
- **이벤트:** `laser-fired {valid, hitCount, allHit}`

### 7. 오버레이
- **`laser-miss`** (ONE-PAIR, `shooter-canvas`에 맞춘다)
  - 빗나간 보석마다 그 ○에서 학생 식의 레이저 점(있으면)까지 세로 점선을 긋는다.
  - 두 점의 □ 값을 글자로 쓴다(보석 □, 내 식 □).
  - 맞힌 보석에는 ✓ 고리만 그린다.
- **`swap-check`·`long-chain`**: T173 것을 이 모드에서도 쓸 수 있게 한다. 기준 SVG가 `relation-canvas`이므로 `look: 'table'`에서만 그린다.
  - `look: 'grid'`에서는 `swap-check`가 `shooter-canvas` 위에 같은 내용을 그리게 기준 selector를 모드에 따라 고른다. 그게 어려우면 멈추고 묻는다.

### 8. 테스트
- **단위 (`shooter.ts`)**
  - `laserPoints`: 범위 밖 점 제외, 분수 □ 포함, ○=0, NONLINEAR 식에서 빈 목록
  - `gemHits`: 보석 [1,4],[2,7],[3,10],[5,16]에서 `□ = ○ × 3 + 1`은 모두 맞고 `□ = ○ + 3`은 첫 보석만 맞는다
  - `missInfo`
  - 오개념: SWAP `○ = □ × 3`(보석 [1,3],[2,6],[4,12])
  - `ruleFormDiffers`: `□ - 1 = ○ × 3` vs `□ = ○ × 3 + 1`
  - 직렬화, reduce 불변
- **View:** 숨은 `rule`·`avoidForm`이 DOM에 없음. 발사 전에는 ✓/✕와 패널이 없음.
- **E2E (`tests/e2e/function-machine.spec.ts`에 rule-shooter 묶음, 3 뷰포트)**
  - 보석 [1,3],[2,6],[4,12]에 `□ = ○ + 2` 발사: ✓ 1개, ✕ 2개, 패널 2줄, ONE-PAIR
  - 이어서 `□ = ○ × 3` 발사: `allHit`
  - 키보드만으로 같은 흐름
  - `laser-miss` 오버레이가 1px 안에서 맞는다
  - `look:'table'` 화면
  - 크롬북·아이패드 판 전체 스냅샷(발사 뒤)
  - 키패드 맨 아래 단추가 스크롤로 닿는다
  - `fit-canvas.spec.ts`의 E16 `modes`에 `'rule-shooter'`를 더한다
- **E2E 범위:** `npx playwright test function-machine fit-canvas overlay-alignment --workers=3 --reporter=line`

## 메모
- 구현 메모 (Sonnet):
  - `gems`를 아예 쓰지 않으면 샌드박스용 기본 보석 [1,4],[2,7],[3,10],[5,16]을 쓴다(fit-canvas가 설정 없이 모드를 열기 때문). `gems`가 있는데 2개 미만·9개 이상·음수·읽히지 않으면 설정 오류 판. 격자가 보석을 못 담으면 `grid` 오류.
  - `fire` Action을 더했고, shooter에서는 `test-rule`도 같은 뜻으로 처리한다(Enter가 어느 쪽이든 발사). Frame이 shooter에서는 `fire`를 보낸다. `ExprPad`에 `ops`·`testLabel` 선택 prop을 더했다(기존 모드 모양 그대로).
  - 상태 `target`은 늘 `'rule'`이고 수 입력 Action(`target:'input'`)·`focus input`·`insert-input`은 무시한다.
  - 결과 표시(✓/✕·패널·레이저)는 `tested`가 읽혔고 `tested.text === ruleText`일 때만 `tested`에서 바로 다시 계산한다. `shots`는 기록·Observation `shotCount`용이다.
  - Observation `hits/hitCount/allHit`은 지금 `tested` 식 기준이다(읽히지 않으면 `hits: []`, `allHit: false`). `rule`이 없으면 `matchesHidden = allHit`.
  - `ruleFormDiffers`는 `observation.mode === 'rule-shooter'`일 때만 `allHit` 기준이고 다른 모드는 `matchesHidden` 그대로다.
  - 격자 논리 크기는 `shooterLayout(grid)`(○ 칸 20~56, □ 칸 12~44, 표 바깥 여백 포함)로 뷰·오버레이가 같이 쓴다. 판 배율은 최소 0.9(보석 28→25px)이고 그 밑이면 판 안 스크롤. 눈금 숫자는 한 칸이 화면 14px보다 작으면 건너뛴다(□ 칸이 12~13이면 2칸씩).
  - swap-check 격자 판: 기준 selector를 `onGrid(state)`로 고른다(`shooter-canvas`). 첫 보석에 파란 테두리, 격자 윗부분에 같은 두 줄 설명. fail-cols·diff-arrows·long-chain은 격자 판에서 그리지 않는다(기준 svg가 없으므로).
  - 모드 선택에 `rule-shooter`가 들어가 샌드박스 모드 select 너비가 달라져, 기존 `function-machine-{black-box,covary,table}` 화면 기준 이미지 6장을 다시 만들었다(내용 변화는 모드 줄 단추 위치뿐). 엔진 단위 테스트의 모드·이벤트·오버레이 목록 기대값도 갱신했다.
