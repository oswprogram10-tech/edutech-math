## 목표
E08에 `order-tree` 모드를 더한다. g5s1u1.A1 "연산 순서 터치 트리"에 쓴다.
- 혼합 계산식의 연산 기호를 누르면, 지금 계산할 수 있는 부분이면 묶여서 값으로 바뀌고 아래에 트리 가지가 남는다.
- 약속에 맞지 않는 곳을 누르면 바뀌지 않고 흔들린다. 그 누름은 오개념으로 기록된다.

## 구현 결정 (2026-11-20 Claude 작성 — 여기 적힌 대로 하고, 바꿔야 하면 메모에 이유를 적고 멈춰서 묻는다)

### 1. 범위
- `StepMode`에 `'order-tree'`를 더한다.
- 새 파일: `order-tree.ts`(순수), `OrderTreeView.tsx`, `overlays/group-box.tsx`, `overlays/two-ways.tsx`
- 기존 세 모드의 동작·상태 모양은 바꾸지 않는다.
- `src/core/`, 다른 엔진, `data/`, `docs/`, `package.json`은 고치지 않는다. core의 `parse`·`evaluate`·`operationOrder`·`renderAst`는 import해서 쓴다.

### 2. 설정
```ts
interface OrderTreeConfig {
  mode: 'order-tree';
  expr: string;          // 기존 parse가 읽는 식(자연수, + − × ÷, 괄호). □·분수·비는 설정 오류
  showTree?: boolean;    // 기본 true(P). false면 트리 그림 없이 식만 줄어든다
}
```
- 명세의 `allowWrongTap`은 받지 않는다. 틀린 누름은 늘 기록만 하고 식은 바꾸지 않는다.
- 0으로 나누는 단계가 생기는 식은 설정 오류다. 연산이 하나도 없는 식도 설정 오류다.

### 3. 판정 규칙 (`order-tree.ts`)
- 식의 연산 기호마다 처음 식 기준 번호 `opIndex`(왼쪽부터 0, 1, …)를 매긴다. 번호는 줄어든 뒤에도 바뀌지 않는다.
- **누를 수 있는 연산:** 그 연산의 AST 이항 노드에서 두 자식이 모두 수(또는 이미 계산된 값)일 때만이다.
  - parse가 우선순위와 왼쪽 결합을 AST에 담으므로 이것이 곧 약속이다.
  - 예: `24 − 6 × 3 + 8 ÷ 2`에서는 `×`와 `÷` 둘 다 누를 수 있다.
  - 예: `48 ÷ 6 × 2`에서는 `÷`만 누를 수 있다.
  - 괄호 노드는 안이 수 하나가 되면 저절로 벗겨진다.
- **틀린 누름의 오개념**(위에서부터 처음 맞는 것 하나)
  1. 식에 아직 풀리지 않은 괄호가 있고, 누른 연산이 그 괄호 밖에 있으면 `MC-ORDER-PAREN-IGNORED`
  2. 누른 연산이 + 또는 −이고, 식에 아직 × 또는 ÷가 남아 있으면 `MC-ORDER-LEFT-TO-RIGHT`
  3. 누른 연산이 ×이고, 같은 덧셈 덩어리 안에서 그 왼쪽에 아직 ÷가 남아 있으면 `MC-ORDER-MUL-BEFORE-DIV`
  4. 그 밖(같은 단계 + − 에서 오른쪽을 먼저 누름 등)은 코드 없이 틀린 누름만 센다.
- **계산 기록:** `reductions: { opIndex, op, left, right, result }[]`. 값은 Rational 문자열이다.

### 4. 상태와 Action
- **상태:** `{ mode:'order-tree', settings, ast (JSON 직렬화 가능한 현재 AST), reductions, wrongTaps: { opIndex: number; code: string | null }[], shake: { opIndex: number; seq: number } | null }`
  - AST가 직렬화 가능한지 확인한다. 안 되면 처음 식 + reductions로 다시 만드는 방식으로 바꾸고 메모에 적는다.
- **Action:** `tap {opIndex}`, `undo`(마지막 계산 되돌리기, 틀린 누름 기록은 남김), `reset`

### 5. 화면 (`OrderTreeView.tsx`)
- **식 줄**: 큰 글씨로 쓴다. 연산 기호는 누를 수 있는 단추다(targetSize 이상, `data-op="<opIndex>"`). 수는 단추가 아니다.
  - 틀린 누름은 그 기호가 0.4초 흔들리고(reduced-motion이면 테두리만 깜빡임), 식 아래에 "여기를 먼저 계산할 수 있을까요? 다시 살펴봐요."를 짧게 쓴다(strings).
  - 정답 위치는 알려 주지 않는다.
- **트리 SVG** `data-testid="order-tree-canvas"` (showTree)
  - 계산할 때마다 한 단계씩 아래로 줄을 더한다. 각 줄은 그때의 식이다.
  - 방금 계산한 부분은 위 줄의 해당 범위에서 아래 줄의 값으로 가지 선을 긋고, 묶음 괄호 모양으로 표시한다.
  - 끝까지 계산하면 전체 트리가 남는다. 판이 넘치면 줄이지 말고 스크롤한다.
- **키보드:** ←/→로 연산 기호 사이를 이동하고, Enter·Space로 누르고, Backspace로 되돌린다.
- **단추:** "한 단계 되돌리기", "처음부터"
- 엔진은 ✓/✕를 그리지 않는다. 판 맞춤은 기존 E08 레이아웃을 따른다. 문구는 `strings.ko.ts`에 둔다.

### 6. Observation과 predicate
- **Observation**
  - `mode`, `expr`, `current`(현재 식 문자열)
  - `reductionOrder`: opIndex 목록
  - `reductions`
  - `done`
  - `finalValue`: done일 때만, 아니면 null
  - `wrongTapCount`, `wrongTaps`
  - `misconceptions`: 틀린 누름 코드의 중복 없는 목록. 기록은 지우지 않는다.
- **Predicate**
  - `firstReductionIs {opIndex}`
  - `reductionOrderIs {order: number[]}`
  - `done {}`
  - `finalValueIs {value}`: Rational 비교
  - `wrongTapsAtMost {n}`
  - `hasMisconception {code}`
- **이벤트:** `reduced {opIndex, result}`, `wrong-tap {opIndex, code}`

### 7. 오버레이
- **`group-box`** (PAREN-IGNORED ②, `order-tree-canvas`가 아니라 식 줄 기준이면 식 줄을 SVG로 그려 기준으로 삼는다)
  - 아직 풀리지 않은 괄호 덩어리를 굵은 상자 + 무늬로 감싼다.
- **`two-ways`** (LEFT-TO-RIGHT·MUL-BEFORE-DIV ②)
  - 마지막 틀린 누름을 기준으로 두 줄을 나란히 보여 준다.
    - "누른 곳부터 계산하면" 줄: 그 연산부터 계산하고 나머지는 왼쪽부터 계산한 끝값
    - "약속대로 계산하면" 줄: `operationOrder` 끝값
  - 명세 ②가 두 결과를 함께 보여 주라고 하므로 끝값 노출을 허용한다.
  - 질문 "어느 쪽이 약속일까요?"를 함께 쓴다.
- 오버레이 기준 SVG는 식 줄 SVG(`data-testid="order-expr"`)로 한다. 식 줄을 HTML 단추로 만들면 같은 위치에 SVG 틀을 겹쳐 둔다. 어렵다면 멈추고 묻는다.

### 8. 테스트
- **단위 (`order-tree.ts`)**
  - 누를 수 있는 연산: 명세 과제 네 식
  - 괄호 벗기기
  - 오개념 셋, 코드 없는 경우(`10 − 3 + 2`에서 +)
  - reductionOrder, finalValue(`7 + 3 × (12 − 8) ÷ 2` = 13, `(15 + 9) ÷ 4 − 2` = 4)
  - undo
  - 설정 오류(□, 0으로 나누기)
  - 큰 수
  - 직렬화
- **View:** 끝값이 시작 화면 DOM에 없음. showTree=false면 트리 없음.
- **E2E (`tests/e2e/step-solver.spec.ts`에 order-tree 묶음, 3 뷰포트)**
  - `36 − 4 × 5`에서 −를 누르면 LEFT-TO-RIGHT·흔들림, ×를 누르면 줄어듦
  - `48 ÷ 6 × 2` MUL-BEFORE-DIV, `two-ways` 1px 정렬
  - `(15 + 9) ÷ 4 − 2` PAREN-IGNORED, `group-box`
  - 끝까지 계산해 finalValue
  - 키보드만으로 같은 흐름
  - 크롬북·아이패드 스냅샷
  - `fit-canvas.spec.ts`의 E08 `modes`에 `'order-tree'`
- **E2E 범위:** `npx playwright test step-solver fit-canvas overlay-alignment --workers=3 --reporter=line`. E08을 쓰는 단원 spec이 있으면 함께 돌린다(`grep -l E08 tests/e2e/units`).
