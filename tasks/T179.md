## 목표
E15 `calc-pattern`에 표 변형을 더한다. g2s2u6.A2 "수 배열표·곱셈표 가려진 숫자 돋보기 탐정"에 쓴다.
- 덧셈표·곱셈표의 칸이 대부분 가려져 있다.
- 돋보기(횟수 제한)로 가려진 칸 몇 개를 볼 수 있다.
- 학생은 가려진 칸에 수를 쓴다.
- 규칙을 화살표(→ ↓ ↘ ↙)와 증가량으로 그린다.

## 구현 결정 (2026-11-20 Claude 작성 — 여기 적힌 대로 하고, 바꿔야 하면 메모에 이유를 적고 멈춰서 묻는다)

### 1. 범위
- **표 변형으로 갈라 쓰기:** `calc-pattern` 설정에 `table` 키가 있으면 표 변형이다.
  - 상태는 `{ mode:'calc-pattern', variant:'table', … }`이다.
  - 기존 피라미드 상태에는 `variant`가 없다. 없으면 피라미드로 본다. 기존 상태 모양은 바꾸지 않는다.
- **새 파일:** `calc-table.ts`(순수), `CalcTableView.tsx`, `overlays/cell-diff.tsx`
- `src/core/`, 다른 엔진, `data/`, `docs/`, `package.json`은 고치지 않는다.

### 2. 설정
```ts
interface CalcTableConfig {
  mode: 'calc-pattern';
  table: 'addition' | 'multiplication';
  size?: [number, number];        // 몸통 [행, 열](기본 [6,6]), 각 2~9
  start?: number;                 // 머리 첫 수(기본: 덧셈 1, 곱셈 1), 0~9, 머리는 start, start+1, …
  hidden?: 'most' | [number, number][]; // 가린 몸통 칸 [행, 열](0부터). 'most' = 첫 몸통 행·첫 몸통 열 말고 모두
  magnifierUses?: number;         // 0~5(기본 0 = 돋보기 없음)
  drawArrows?: boolean;           // 기본 false
}
```
- 칸 값은 정수다(덧셈은 행머리 + 열머리, 곱셈은 행머리 × 열머리). 격자 인덱스·정수라 number를 써도 된다.
- 범위 밖이면 설정 오류 판을 그린다.

### 3. 상태와 Action
- **상태:**
  ```ts
  { mode:'calc-pattern', variant:'table', settings, entries: Record<string,string>, revealed: string[], active: string | null, tool: 'write' | 'magnifier' | 'arrow', arrows: { from: string; dir: 'right' | 'down' | 'down-right' | 'down-left'; amount: string }[], draftArrow: … | null }
  ```
  - 칸 키는 `"r.c"`다.
- **Action:** `set-tool`, `activate {cell}`, `type`, `backspace`, `clear`, `move {dir}`, `peek {cell}`, `arrow-start {cell}`, `arrow-dir {dir}`, `arrow-type`/`arrow-backspace`, `arrow-commit`, `arrow-remove {index}`
- **`peek`:** 가린 칸만 열 수 있다. 남은 횟수가 0이면 무시한다. 연 칸은 값이 보이고 입력 칸이 아니다.
- **화살표:** 최대 6개다. 증가량은 정수 문자열이고, 음수는 받지 않는다(이 단원 범위).

### 4. 화면 (`CalcTableView.tsx`)
- **표 SVG** `data-testid="calc-table-canvas"`
  - 왼쪽 위 칸에 "+" 또는 "×"를 쓴다.
  - 머리 칸은 진한 배경 + 굵은 글씨다.
  - 몸통 칸은 targetSize 이상이고 `data-cell`이다.
  - 가린 칸은 무늬(빗금) + "?"로 그린다. 학생이 쓴 수는 다른 글꼴 굵기로 그린다.
  - 돋보기로 연 칸은 돋보기 아이콘 표시 + 값이다.
  - 판에 안 들어가면 줄이지 말고 스크롤한다.
- **도구 막대**: "수 쓰기" / "돋보기 (남은 n번)" / "화살표"
  - 돋보기는 `magnifierUses > 0`일 때만, 화살표는 `drawArrows`일 때만 보인다.
- **화살표 그리기**
  1. 화살표 도구에서 칸을 누른다.
  2. 방향 단추 넷(→ ↓ ↘ ↙, 글자와 그림을 함께 쓴다) 중 하나를 고른다.
  3. 숫자 패드로 증가량을 쓰고 "놓기"를 누른다.
  - 화살표는 그 칸에서 그 방향으로 두 칸 길이로 그리고, 끝에 "+n" 글자를 단다.
- 엔진은 ✓/✕를 그리지 않는다.
- **키보드**
  - 방향키로 칸을 이동하고 숫자로 입력한다.
  - `M`은 돋보기 도구로 바꾸고, Enter로 그 칸을 연다.
  - 화살표 도구에서는 1~4 키로 방향을 고른다.
- **레이아웃:** 판 맞춤 원칙은 T170·T175와 같다. 문구는 `strings.ko.ts`에 둔다.

### 5. Observation과 predicate
- **Observation**
  - `table`, `size`
  - `hidden`: 키 목록
  - `revealed`, `magnifierLeft`
  - `entries`
  - `arrows`: 각 화살표에 `{from, dir, amount, amountCorrect}`. `amountCorrect`는 from에서 dir로 한 칸 간 값의 차이가 amount와 같은지다. 학생 자료를 판정한 값이고 정답 수는 아니다.
  - `misconceptions`
  - 가린 칸의 정답 값은 넣지 않는다.
- **Predicate**
  - `tableEntriesCorrect {cells?: string[]}`: 지정한 칸(없으면 가린 칸 중 연 칸이 아닌 모든 칸)에 쓴 값이 맞다.
  - `tableEntryIs {cell, value}`
  - `arrowFound {dir, amount?}`: 그 방향의 `amountCorrect` 화살표가 있다. amount를 주면 그 값도 같아야 한다.
  - `peeksAtMost {n}`
  - `hasMisconception`
- **오개념 `MC-CHART-ROW-COL`**
  - 쓴 값이 틀렸고, 다음 둘 중 하나와 같으면 건다.
    - 왼쪽 이웃(보이거나 쓴 값) + 세로 한 칸 차이
    - 위 이웃 + 가로 한 칸 차이
  - 두 차이가 같으면 걸지 않는다.
  - 예: 곱셈표 5단 줄 (5×4)에 15 + 4 = 19

### 6. 오버레이 `cell-diff` (`calc-table-canvas` 기준, ROW-COL ②)
- `args.cell`(없으면 오개념이 걸린 첫 칸) 기준이다.
- 같은 행에서 보이는 이웃 두 칸 사이에 "→ +a"를, 같은 열에서 보이는 이웃 두 칸 사이에 "↓ +b"를 그린다.
- 보이는 칸만 쓴다. 머리 칸, 가리지 않은 칸, 연 칸, 학생이 쓴 칸은 쓰지 않는다.
- 가린 칸의 값은 쓰지 않는다.

### 7. 테스트
- **단위 (`calc-table.ts`)**
  - 덧셈·곱셈 값, `start` 0, 크기 경계
  - `'most'` 가림
  - peek 횟수, 연 칸 입력 불가
  - 화살표 `amountCorrect`(덧셈 ↘ = 2, 곱셈은 위치마다 다름)
  - ROW-COL(걸림, 차이가 같아 안 걸림)
  - 기존 피라미드 상태가 그대로 동작
  - 직렬화
- **View:** 가린 칸 값이 DOM에 없음. 돋보기·화살표 도구 표시 조건.
- **E2E (`tests/e2e/pattern.spec.ts`에 calc-table 묶음, 3 뷰포트)**
  - 덧셈표 가린 칸 3개 쓰기 → `tableEntriesCorrect`
  - 돋보기 3번 뒤 더 못 씀
  - ↘ +2 화살표 → `arrowFound`
  - 곱셈표 19 → ROW-COL, `cell-diff` 1px 정렬
  - 키보드만으로 같은 흐름 일부
  - 크롬북·아이패드 스냅샷
- **E2E 범위:** `npx playwright test pattern fit-canvas overlay-alignment --workers=3 --reporter=line`

### 구현 메모 (소넷, 2026-11-20)
- 파일: `calc-table.ts`(설정·reduce·판정 계산), `calc-table-layout.ts`(논리 좌표, 오버레이와 공유), `CalcTableView.tsx`, `overlays/cell-diff.tsx`. `reduce`·`observe`·`events`·`index`·`types`·`settings` 대신 `calc-table.ts`에 정규화를 두었다(설정은 `settings.ts` 변경 없음).
- 기존 `CalcState`에 타입만 `variant?: undefined`를 더했다(런타임 상태 모양은 그대로). 피라미드 헬퍼 `calcOf`는 표 상태를 제외하도록 좁혔고, 기존 `calc.test.ts` 도우미의 타입 가드 한 줄만 고쳤다.
- Observation에 `start`를 더했다(명세 목록 밖). predicate가 값을 다시 계산하려면 필요하다. 가린 칸의 정답은 넣지 않았다.
- `tableEntriesCorrect`는 판정할 칸이 하나도 없으면(가린 칸 없음, 전부 열었음) false이다.
- 쓰기·돋보기 도구의 `activate`·`move`는 가린 칸(열지 않은)만, 화살표 도구는 몸통 전체를 고른다. 연 칸이 있던 자리에서 방향키로 이어 갈 수 있게 `move`는 지금 칸이 후보가 아니어도 그 자리에서 센다.
- 키보드: 명세의 M·방향키·숫자·Enter·1~4에 더해 W(쓰기)·A(화살표) 도구 전환과, 화살표 초안에서 Escape(같은 칸에서 다시 시작)를 넣었다. 증가량은 방향을 고른 뒤 숫자로 쓴다.
- 판 안에 안 들어가면 줄이지 않고 스크롤(칸 ≥ targetSize). 세로 화면에서 9×9처럼 큰 표가 조작 묶음(도구·패드)을 0 높이로 눌러 못 닿던 문제를 `.sideStack[data-table]`(좁은 화면 줄어들지 않음) + 판 최소 높이 50dvh로 고쳤다.
- cell-diff 이웃 칸: 명세 문장("머리 칸, 가리지 않은 칸, 연 칸, 학생이 쓴 칸은 쓰지 않는다")이 "보이는 칸만 쓴다"와 부딪혀, 보이는 몸통 칸(처음부터 안 가린 칸 + 돋보기로 연 칸)만 쓰고 머리 칸·학생이 쓴 칸·가린 칸은 쓰지 않는 것으로 읽었다. 짝이 여러 개면 고른 칸에서 가장 가까운 짝(같으면 왼쪽·위쪽)이고, 보이는 짝이 없으면 그 방향 표시는 그리지 않는다('most'만 쓰면 같은 줄·같은 칸에 보이는 짝이 없을 수 있다).
- E2E: `pattern.spec.ts`에 calc-table 묶음 6개와 첫 화면 기준 이미지 2장(`pattern-calc-table-add|mul`, 크롬북·아이패드) 추가. 기존 스냅샷은 다시 만들지 않았다.
