## 구현 결정 (2026-11-06 Claude 작성 — 여기 적힌 대로 하고, 바꿔야 하면 메모에 이유를 적고 질문한다)
1. **범위:** `src/engines/E03-number-line/`만 고친다. 새 모드를 만들지 않고 `integer` 모드에 설정이 있을 때만 켜지는 기능으로 둔다. 설정이 없으면 지금 `integer`·다른 모드의 동작·Observation·이벤트가 그대로여야 한다(기존 테스트 전부 통과).
2. **설정:** `jumpButtons?: (number | string)[]`(점프 크기 목록, 부호 있는 정수, 예 `[10, 1, -1, -10]`), `jumpStart?: number | string`(개구리 처음 위치, 기본 `min`). `jumpButtons`가 있으면 개구리 기능이 켜진다. 명세 예시의 `jumps: { allowed, drawFreeArrow }`와 `character`는 받기만 하고 무시한다(콘텐츠는 `jumpButtons`를 쓴다 — 메모). 값은 모두 `Rational`(`parseValue`)로 읽고 상태에는 `toJSON()` 문자열로 둔다.
3. **상태:** `frog: { start: string, jumps: string[] } | null`(`jumps`는 누른 점프 크기를 차례로, 예 `["10","10","1"]`). 개구리 위치 = start + jumps 합. 기존 `jumps`(끌어 그린 점프) 배열과 섞지 않는다.
4. **Action:** `frog-jump { size: string }`(목록에 없는 크기이거나 결과가 `min`~`max` 밖이면 무시), `frog-undo`(마지막 점프 하나 되돌리기, 없으면 무시), `frog-reset`(모든 점프 지우기). reduce는 순수 함수.
5. **화면:**
   - 수직선 위 개구리 표시(SVG 그림 또는 🐸 글자, `aria-label`은 "개구리" — **위치 숫자를 쓰지 않는다**).
   - 수직선 아래 점프 버튼 줄: 크기마다 버튼 하나, 이름은 `+10`, `+1`, `−1`, `−10`(학생이 고르는 재료라 보여도 된다). 그 옆에 "되돌리기"·"처음부터" 버튼. 모든 버튼은 `targetSize` 이상(저학년 64px).
   - 점프마다 수직선 위에 호를 그리고 호 위에 그 점프 크기(`+10`)를 쓴다. 착지 값은 쓰지 않는다.
   - 점프 기록 띠: "출발 → +10 → +10 → +1"처럼 출발 수(주어진 재료)와 누른 크기만 쓴다. **도착 값·합계는 쓰지 않는다**(과제 답).
   - 눈금 이름표는 기존 `labels` 설정을 따른다.
   - 키보드: 버튼이 Tab으로 가고 Enter·Space로 눌린다. 버튼이 수직선의 기존 키 처리(←/→ 커서)와 겹치지 않게 한다.
6. **Observation(새 키, 개구리가 없으면 null):** `frogAt`(개구리 위치 Rational 문자열), `frogStart`, `frogJumps`(크기 문자열 목록), `frogJumpTotal`(합).
7. **Predicates(추가):** `frogAtIs {value}`(Rational 비교), `frogJumpCountIs {size, count}`(그 크기 점프를 정확히 count번), `frogJumpTotalIs {value}`.
8. **이벤트:** 점프마다 기존 `jumped`를 `{from, to, size}`로, 그리고 `value-changed {value: 도착 값}`을 낸다. `index.ts`의 events 목록은 그대로(새 이름 없음).
9. **오버레이 `hop-numbers`(힌트 ②, MC-JUMP-COUNT-START):** 개구리 점프마다 그 점프가 지나간 **눈금 칸 사이**마다 작은 호와 1, 2, 3… 번호를 그린다(+10 점프면 1~10, 칸 사이를 세는 것을 보여 줌). 도착 값은 쓰지 않는다. 개구리가 없으면 아무것도 그리지 않는다.
10. **정답 노출 금지:** 개구리 위치·점프 합·도착 값이 DOM(글자·aria-label·title)에 없어야 한다. 눈금 이름표(`labels`)는 설정대로.
11. **테스트:**
    - reduce 단위: 35에서 +10 +10 +1 +1 +1 → frogAt "58"; max 밖 점프 무시; 목록 밖 크기 무시; undo·reset; jumpStart 없으면 min; `assertSerializable`.
    - events·predicates: `frogAtIs`, `frogJumpCountIs {size:"10", count:3}`, `frogJumpTotalIs "-34"`.
    - View 테스트: 35 + 23 점프 뒤 DOM에 `58`이 없음(`labels:"partial"`에서 58은 눈금 이름표가 아님), 버튼 이름 `+10`·`−1`이 있음, 설정이 없으면 개구리·버튼이 없음.
    - `tests/e2e/number-line.spec.ts`에 sandbox E2E 3개 뷰포트: `?config=`로 `{ "mode":"integer","min":0,"max":100,"unit":1,"labels":"partial","jumpButtons":[10,1,-1,-10],"jumpStart":35 }`, 키보드만으로 +10 두 번·+1 세 번 → Observation `frogAt` 58(기존 sandbox 관찰 도구로 확인).
