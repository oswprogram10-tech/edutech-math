1. **폴더·모드:** `src/engines/E04-array-area/`만 고친다. `modes`는 기존 4개 뒤에 `tiling`, `decimal-area`, `fraction-area` 순서로 붙인다. `puzzle`은 모드가 아니라 **area-model의 설정 `puzzle`**, `scaler`는 **fraction-area의 `variant: "scaler"`**다. 기존 모드의 동작·Observation·이벤트는 바꾸지 않는다(아래 5번 dot-array `shelf`만 더한다). View.tsx가 이미 1500줄이므로 새 화면은 `views/TilingView.tsx`, `views/DecimalAreaView.tsx`, `views/FractionAreaView.tsx`, `views/ScalerView.tsx`, `views/PuzzleView.tsx`로 나누고 View.tsx는 고르기만 한다.
2. **수:** 행·열·칸 수·타일 크기는 정수(number). 소수·분수 값(인수·곱·곱하는 수·리본 길이)은 **`Rational`로만** 계산하고 상태에는 문자열(`Rational.toString()`, 소수 모드는 `toDecimalString()`)이나 정수 쌍으로 둔다. 넓이 계산은 `area.ts`에 모은다. 0.1을 number로 곱하지 않는다.
3. **tiling:** 설정 `width`, `height`(방 칸 수, 1~30), `tileSizes`(고를 수 있는 타일 한 변, 기본 1부터 min(width,height)까지), `compare?: { width, height }`(두 번째 방 — "두 방 비교", 같은 타일 크기를 두 방에 함께 깐다), `showGrid`(기존 `GridDisplay`). 상태 `tileSize: number | null`, `recordedSizes: number[]`(정렬·중복 제거). Action `set-tile {size}`(슬라이더 눈금 끌기·−/+ 버튼·방향키, `tileSizes` 밖 값은 무시), `record-tile`("기록하기"). 그림: 왼쪽 위부터 **온전한 타일만** 깐다. 오른쪽·아래에 남는 칸은 빨강 + 빗금(색만으로 구분 금지). 고른 타일 크기 숫자는 학생 입력이라 보여도 되지만 **타일 개수·남는 칸 수·덮이는지 여부 글자는 쓰지 않는다**(그림으로만 보인다).
4. **decimal-area:** 설정 `a`, `b`(처음 값, 소수 문자열, 기본 `"0"`), `maxA`(기본 `"1"`, `"4"`까지), `maxB`(기본 `"1"`, `"2"`까지), `grid`(10 고정), `locked`(boolean — P 단계 그림 고정, 슬라이더 숨김), `showUnitLabel`(기본 true — "1칸 = 0.01" 단위 이름표), `showCounts`(기본 false). 1×1 정사각형(10×10 모눈)을 가로 `ceil(maxA)`개 × 세로 `ceil(maxB)`개 붙여 그린다. 가로 슬라이더로 a, 세로 슬라이더로 b를 0.1 단위로 정한다(Action `set-factor {side: 'a' | 'b', value}`, value는 0.1 배수 소수 문자열, max 넘으면 자름). a 띠(세로줄)와 b 띠(가로줄)는 서로 다른 색 + 빗금 방향, 겹친 칸은 진한 색 + 격자 무늬. `showCounts`일 때만 "겹친 칸 ○개"(학생이 만든 칸 수)를 쓴다. **곱(0.18)은 어디에도 쓰지 않는다.**
5. **dot-array `shelf`(g5s1u2용 추가):** dot-array 설정에 `shelf: boolean`(기본 false)을 더한다. true면 오른쪽에 "약수 선반"을 그리고 기존 `record-arrangement`로 기록한 배열을 작은 그림 + "행×열"(학생이 만든 배열의 크기)로 쌓는다. Observation에 `factorsFound: number[]`(기록한 배열의 행·열에 나온 서로 다른 수, 정렬)를 더한다. 기존 `recorded`·`distinctArrangements`는 그대로.
6. **fraction-area:** 설정 `a`, `b`(처음 분수, 문자열, 기본 `"0"`), `maxDenominator`(기본 12), `locked`, `showCounts`(기본 false), `layout`(기본 `{ a: "vertical", b: "horizontal" }`). 1×1 정사각형 하나. 상태는 변마다 `{ n, k }` 정수(분모·칠한 조각 수). Action `set-parts {side, n}`(조각 수 −/+, 1~maxDenominator — 바꾸면 그 변의 k를 n 이하로 자른다), `set-shaded {side, k}`(조각을 누르거나 끌어 칠함, 0~n). a는 세로 칼로 나눠 노랑 + 빗금, b는 가로 칼로 나눠 파랑 + 반대 빗금, 겹친 칸은 초록 + 격자 무늬(반투명 겹침 — E05 `multiply`와 같은 색 순서. E05를 import하지 않고 색 값만 `types.ts`에 둔다). `showCounts`일 때만 "전체 ○칸 중 ○칸"(학생이 만든 칸 수). **곱 분수는 쓰지 않는다.** 대분수 곱(정사각형 여러 개)은 이번에 하지 않는다(메모).
7. **fraction-area `scaler`:** 설정 `variant: "scaler"`, `base`(정수, 리본 길이 m), `multipliers`(분수·정수 문자열 목록 — 슬라이더 눈금 순서), `predictFirst`(기본 true), `showResult`(기본 false). 상태 `prediction: 'smaller' | 'same' | 'larger' | null`, `index: number | null`(고른 눈금), `tried: string[]`(고른 곱하는 수, 처음 순서, 중복 없음). Action `predict {value}`, `set-multiplier {index}`. `predictFirst`면 예측 세 버튼("짧아질까 / 같을까 / 길어질까" — 문구는 `strings.ko.ts`)을 먼저 눌러야 슬라이더가 열린다(그 전 `set-multiplier`는 무시). 그림: 원래 리본(base 길이)은 흐린 윤곽으로 늘 보이고, 결과 리본은 base × 곱하는 수 길이(`Rational`로 계산해 화면 좌표로만 number 변환). 리본 아래 1m 눈금 자. 곱하는 수가 1보다 작음/같음/큼에 따라 리본 색 + 무늬가 바뀐다. 슬라이더 눈금 이름표(곱하는 수)는 학생이 고르는 재료라 보인다. **결과 길이 숫자는 `showResult: true`일 때만**(과제 답이다). 크로스 약분 슬라이더는 E08 몫이라 만들지 않는다(메모).
8. **area-model `puzzle`:** 설정 `puzzle: { splitsA: number[], splitsB: number[], seed?: number, label?: 'area' | 'dims' | 'none' }`(기본 label `area`)와 기존 `a`, `b`. 엔진이 a×b 직사각형을 그 분할로 자른 조각들(`{id, w, h}`)을 만들고 seed로 섞어 왼쪽 "조각 상자"에 놓는다. 오른쪽 조립판은 `(splitsA.length+1) × (splitsB.length+1)` 슬롯(점선 칸, **크기·숫자 없음** — 처음엔 같은 크기, 조각이 놓이면 그 크기에 맞춰 늘어난다). Action `place-piece {id, col, row}`(끌어 놓기 또는 조각 선택 + 슬롯 누르기, 슬롯에 이미 있으면 맞바꿈), `unplace-piece {id}`. 조립 판정: 모든 슬롯이 차고, 같은 열 조각의 너비가 모두 같고 같은 행 조각의 높이가 모두 같으면 `assembled`. 조각 이름표는 label에 따라 넓이(예 600 — 문제에 주어진 재료) / "30×20" / 없음. 조각 회전은 없다. 조립이 끝나도 전체 곱·변 길이 합을 쓰지 않는다.
9. **Observation(새 모드):** tiling: `width`, `height`, `tileSize`, `fitsAll`(모든 방에서 남는 칸 0), `leftoverCells: number[]`(방별), `tilesUsed: number[]`, `recordedSizes`. decimal-area: `a`, `b`(소수 문자열), `product`(소수 문자열 — Observation에만), `overlapCells`, `unitSquares`. fraction-area: `a`, `b`, `product`(분수 문자열, 기약), `overlapCells`, `totalCells`. scaler: `prediction`, `multiplier`(문자열 또는 null), `result`(분수 문자열 또는 null), `tried`, `predictionFits`(예측이 실제 대소와 맞는지, 곱하는 수를 고르기 전에는 null). area-model 퍼즐: `puzzleAssembled`, `assembledDims: { a, b } | null`(조립됐을 때 열 너비 합·행 높이 합), `placedPieces`.
10. **Predicates(추가):** `tileSizeIs {value}`, `fitsAll`, `recordedSizesAre {values}`(집합 같음), `factorsFoundAre {values}`, `factorsAre {a, b, either?}`(Rational 비교), `overlapCellsIs {value}`, `productIs {value}`(Rational 비교 — `"0.18"`과 `"9/50"` 같음), `predictionIs {value}`, `multiplierIs {value}`, `triedAllBelowOne {count}`(1보다 작은 곱하는 수를 count개 이상 고름), `puzzleAssembled`, `assembledDimsAre {a, b, either?}`.
11. **이벤트(추가):** `area-changed {a, b, product}`(decimal-area·fraction-area에서 인수가 바뀔 때, 값은 문자열 — 실행기가 E03에 연결할 때 쓴다), `tile-changed {size, fitsAll}`. 기존 `partial-product-changed`·`value-changed`는 그대로.
12. **정답 노출 금지:** 곱·결과 길이·타일 개수·남는 칸 수·덮이는지 여부·조립한 곱셈식을 화면에 쓰지 않는다. 보여도 되는 숫자는 학생이 고른 값(타일 크기, 슬라이더 눈금, 칠한 칸 수는 `showCounts`일 때)과 주어진 재료(퍼즐 조각 넓이)뿐이다.
13. **입력·접근성:** Pointer Events만. 슬라이더 손잡이·조각·슬롯 터치 타깃 ≥ `targetSize`(SDK `minTouchRadius`). 모든 새 모드를 끌기 없이: 슬라이더는 −/+ 버튼과 방향키, 조각은 Tab 선택 + 방향키로 슬롯 고르기 + Enter, 칠하기는 조각 Tab + Space.

### 카드와 다르게 정한 것(이유)
- **decimal/fraction 설정 `a`·`b` 타입:** area-model은 기존처럼 숫자, decimal-area·fraction-area는 문자열(`"0.6"`, `"2/3"`)로 읽는다. Observation의 `a`·`b`도 모드에 따라 문자열/숫자가 된다. 카드 9번이 요구한 값 형식 때문이며, area-model의 기존 Observation은 그대로 숫자다.
- **decimal 기본 최댓값:** 카드대로 `maxA` 기본 `"1"`, `maxB` 기본 `"1"`. 각각 4·2에서 자른다.
- **tiling 안내 문구:** "남는 자리"라는 말이 정답(남는 칸 수)을 암시하지 않도록 "빈 자리"로 썼다.
- **puzzle 맞바꿈:** 상자에 있던 조각을 이미 놓인 슬롯에 놓으면 그 조각은 상자로 돌아가고, 놓인 조각을 다른 놓인 슬롯에 놓으면 두 조각이 자리를 맞바꾼다. 슬롯 격자 크기는 조각의 서로 다른 너비·높이 수로 정한다.
- **scaler 결과 숫자:** `showResult`는 "리본 길이 ○" 글자만 여닫는다. 아래 1m 눈금 자의 0…base 숫자는 원래 길이 재료라 항상 보인다.
- **fraction `layout`:** 설정을 읽어 `settings.layout`에 두지만 화면은 카드 기본대로 a=세로, b=가로로 그린다(가로/세로를 바꾸는 과제가 아직 없음).
- **decimal `grid`:** 10 고정. 설정 값은 받지 않는다.
