## 목표
T168 검수에서 크롬북 g6s1u5.A2.T1(응답 칸이 있는 두 칸 판)의 문제가 나왔다.
- distortion 막대그래프 영역이 최소 높이 200px로 눌린다.
- 그 아래 "기사 제목" 줄이 그래프 아래쪽을 덮어, 세로축 0 눈금과 가로축 이름(1반·2반)이 가려진다(스냅샷 `g6s1u5-a2-chromebook`).
- 이 과제는 "세로축 맨 아래 숫자"를 읽는 것이 핵심이라, 가려지면 학습이 안 된다.
- 아이패드(한 칸 판)와 전자칠판은 괜찮다.

## 구현 결정 (2026-11-19 Claude 작성 — 여기 적힌 대로 하고, 바꿔야 하면 메모에 이유를 적고 멈춰서 묻는다)
1. **원인부터 잰다.**
   - 크롬북 g6s1u5.A2.T1에서 `.wrap`, `.distControls`, `.distBody`, `.distBoard`, `.boardArea`, SVG, `.headline`의 크기·위치를 재어 메모에 적는다.
   - 겹침이 어디서 생기는지 찾는다. 짐작: `.distBody`·`.distBoard`가 `min-height: 0`이라 `.boardArea`(min-height 200)보다 작게 줄고, 넘친 그래프 위에 다음 형제인 `.headline`이 그려진다.
2. **겹치지 않게 한다.**
   - 어떤 판 크기에서도 형제 상자(조작 줄·그래프·제목 줄·체크리스트)가 서로 겹치지 않는다.
   - 공간이 모자라면 `.wrap`(이미 `overflow-y: auto`)이 세로로 스크롤한다.
   - 그래프 영역은 남는 높이를 받되, 그래프가 줄어드는 하한은 200px다.
3. **그래프를 덜 누른다.**
   - 크롬북 두 칸 판에서 그래프 높이가 200px보다 커질 수 있으면 키운다.
   - 방법은 둘 중 하나다:
     - 조작 줄을 한 줄로 촘촘히 한다(이미 쓰는 `.scaleRow` 간격 안에서).
     - 제목 카드 줄을 가로로 흘린다.
   - 단추 크기는 48px(저학년 64px) 아래로 줄이지 않는다.
   - 결과 높이를 메모에 적는다.
4. **바꾸지 않는 것:** Action·State·Observation·predicate의 뜻, 다른 모드(band-circle·line·bar 등)의 배치, 체크리스트 동작.
5. **테스트:**
   - graph-studio.spec.ts에 distortion 배치 E2E를 더한다. 3 뷰포트와, 응답 칸이 있는 두 칸 판을 흉내 낸 좁은 stage(폭 640 안팎, 높이 420)에서 확인한다.
     - 그래프 SVG 상자와 `.headline` 상자가 겹치지 않는다.
     - 세로축 0 눈금 글자와 가로축 범주 이름이 화면 안에서 보인다. 다른 요소에 덮이지 않았는지 `elementFromPoint`로 확인한다.
   - g6s1u5.spec.ts: 크롬북 A2.T1에서 같은 단언을 더한다.
   - 바뀐 스냅샷은 다시 찍고 직접 연다. 대상은 g6s1u5 `a2-*`, graph-studio distortion 관련이다. E18·g6s1u5 밖 스냅샷이 바뀌면 멈춘다.
