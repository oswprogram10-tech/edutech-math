**공통(T024 g5s1u4·data/content/g5s1u4.json을 본보기로 삼는다)**
1. **파일·형식:** `data/content/g2s2u2.json` 하나 + `tests/e2e/units/g2s2u2.spec.ts`. 스키마는 `src/core/runner/content-schema.ts`. 과제 ID는 `<활동ID>.T<n>`, `concepts`는 명세 개념 노드 ID(과제마다 1~2개). 설정 키는 스키마가 검사하지 않으므로 **엔진 types.ts에 있는 키만** 쓴다(명세 예시의 없는 키는 아래 과제별 결정대로 바꾼다).
2. **CPA:** 과제마다 `cpa`를 준다. 학생 화면 문구에 학년·단원 ID를 쓰지 않는다.
3. **정답 노출 금지:** 발문·힌트·선택지 이름·라벨에 그 과제의 정답 값을 쓰지 않는다. 힌트 문구는 `{a}`·`{b}`(hintVars)·`{student}`만 템플릿으로 쓴다.
4. **힌트:** 과제마다 ①(발문 `say`)·②(`show` 오버레이, 없으면 `say`만)·③(`backtrack`). 오개념 규칙(`when: {misconception}`)을 일반 규칙(`{"kind":"equals","path":"mode","value":"<모드>"}`)보다 앞에 둔다. 오버레이는 **이미 있는 것만** 쓴다(아래 과제별 결정). 발문은 docs/05 §4를 따르고 풀이 절차를 그대로 지시하지 않는다.
5. **오개념 감지:** 이 단원 코드는 모두 `diagnose`(감지 함수 있음)다. `diagnose`는 **응답 위젯 값(문자열)**만 읽고, `args` 값도 **문자열**로 쓴다(`{"a":"7"}`, 숫자 7 아님). 엔진 Observation 숫자(`value`, `partialSum`)는 감지되지 않는다. 명세 표의 코드마다 E2E에서 그 코드의 힌트 ① 문구가 뜨는 오답을 하나씩 넣는다.
6. **엔진·core 수정 금지:** 과제별 결정은 지금 엔진·실행기 기능만으로 만들 수 있게 정했다. 그래도 엔진 추가가 필요하면 **진행을 멈추고 메모로 묻는다**(같은 묶음의 다른 카드가 다른 엔진을 고치고 있다).
7. **E2E·화면:** 3개 뷰포트. 활동마다 테스트 하나(과제마다 대표 오답 → 힌트 ① → 고쳐서 통과), 활동마다 첫 화면 스크린샷, 크롬북·전자칠판에서 응답 칸과 '확인하기'가 첫 화면 안에 있는지, 오프라인에서 첫 활동이 열리는지(g5s1u4.spec.ts와 같은 구조·도우미).
8. **상태:** `data/units.json`의 `status`는 바꾸지 않는다. 명세와 다르게 만든 곳은 모두 카드 메모에 적는다.

**과제별**
9. **A1 배열판 분할(E04 `split`, `maxSplits:1`, `orientation:"either"`, `snapHints:[5]`, `showPartials:"color"`):**
   - T1(C) `rows:6, cols:7` "6×7을 5와 2로 나누어 세어 보세요" → `partialsAre {products:[30,12]}` + 응답 정수 "42". `diagnose`: `MC-MUL-SPLIT-PARTIAL-DROP {a:"6", parts:["5","2"]}`(30·12), `MC-MUL-ADD-CONFUSE {a:"6", b:"7"}`(13), `MC-MUL-FACT-NEIGHBOR {a:"6", b:"7"}`. ② SPLIT-PARTIAL-DROP → `known-fact`, ADD-CONFUSE·일반 → `row-count`. ③ 명세 표대로.
   - T2(P) `rows:7, cols:8` "아는 곱셈으로 나누어 7×8을 구하고 '기록하기'를 눌러 보세요" → `distinctSplitsAtLeast {count:1}` + 응답 "56". (`partialSumIs`만 쓰면 나누지 않아도 통과하므로 쓰지 않는다.) `diagnose` ADD-CONFUSE·FACT-NEIGHBOR `{a:"7", b:"8"}`.
   - T3(P) `rows:8, cols:9` "서로 다른 두 가지 방법으로 나누어 기록해 보세요" → `distinctSplitsAtLeast {count:2}` + 응답 "72". `diagnose` FACT-NEIGHBOR `{a:"8", b:"9"}`.
   - T4(P) **`rows:10, cols:6, allowExtend:true`**(E04 테스트 'allowExtend는 아래 한 줄을 빼는 조각으로 만든다'와 같은 설정) "10줄에서 한 줄을 빼서 9×6을 구해 보세요" → `partialsAre {products:[60,6]}` + 응답 "54". `diagnose` FACT-NEIGHBOR `{a:"9", b:"6"}`.
10. **A2 곱셈표(E04 `times-table`, `size:[9,9]`, `symmetryReveal:true`, `colorSameValue:true`):**
    - T1(P) **`prefill:"none"`**(명세의 `rows-2-5`는 4단 줄을 미리 채워 과제가 사라진다) "4단 줄을 채워 보세요" → `cellsMatch`로 (4,1)…(4,9) = 4…36. ② `row-count`, ③ `g2s2u2.table-step`.
    - T2(P) `prefill:"rows-2-5"` "4×7과 곱이 같은 다른 칸을 골라 보세요" → `selectedAre {cells:["7,4"]}`. ② `fold-diagonal`, ③ `g2s2u2.table-symmetry`.
    - T3(P) 같은 표 + 응답 `choice`(단일) "대각선으로 접으면 같은 수끼리 겹칠까요?" 예/아니요 → 예. 엔진에 접기 관찰값이 없으므로 접기는 판정하지 않는다. ② `fold-diagonal`.
    - T4(A, `showEngine:false`) 1×5, 0×5, 5×0 응답 정수 필드 3개 → "5", "0", "0". 필드마다 `diagnose` `MC-MUL-ZERO-ONE`(`{a:"1",b:"5"}`, `{a:"0",b:"5"}`, `{a:"5",b:"0"}`, `path`로 필드 지정). ②는 `say`만, ③ `g2s2u2.one-zero`.
    - T5(P) `prefill:"rows-2-5"` "곱이 24인 칸을 모두 골라 보세요" → `selectedAre {cells:["3,8","4,6","6,4","8,3"]}` + 응답 정수 "몇 칸을 골랐나요?" = "4"(`selectedAre`는 더 고른 칸을 막지 못해서 개수로 확인한다). ② `fold-diagonal`.

## 메모
- **엔진 추가 없음:** 명세의 과제를 지금 있는 predicate(`partialsAre`·`distinctSplitsAtLeast`·`cellsMatch`·`selectedAre`)와 오버레이(`known-fact`·`row-count`·`fold-diagonal`)만으로 만들었다. `src/core/`와 엔진 폴더는 고치지 않았다.
- **A2 T3(접기 질문):** 엔진 Observation에 접기 상태가 없어 구현 결정 10대로 응답 `choice`(예/아니요)로 확인한다. 접기 자체는 판정하지 않고 힌트 ②의 `fold-diagonal` 오버레이로만 보여 준다.
- **A2 T5(곱이 24인 칸):** `selectedAre`는 더 고른 칸(예: 24가 아닌 칸)을 막지 못하므로, 결정대로 응답 정수 "고른 칸 수"를 함께 받아 4인지 확인한다.
- **A1 T1 분할선:** `snapHints:[5]`라 `세로 분할선 놓기`를 누르면 5번째 자리에 놓인다. 분할선 `<g>`는 레이아웃 상자가 0이라 E2E에서 `toBeVisible()` 대신 `toHaveCount(1)`로 확인하고, 조각 라벨 30·12는 텍스트로 확인한다.
- **A1 T2·T3 기록:** 과제 판정은 `distinctSplitsAtLeast`라 E2E에서 `분할 기록하기`를 누른 뒤 기록 배지(`2가지 분할을 기록했어요.`)까지 확인한다. T3은 세로 분할을 기록·삭제한 뒤 가로 분할을 기록해 서로 다른 두 방법을 만든다.
- **E2E 칸 조작:** 곱셈표의 SVG `<g>` 칸은 WebKit에서 클릭 안정성 검사가 오래 걸릴 때가 있어, 칸에 포커스를 주고 Enter로 연다(엔진의 키보드 대체 조작). 선택 칸도 같은 방식으로 눌러 `aria-pressed`로 확인한다.
- **완료 기준의 '6단 완성'(9단 중 6단)은 이번 카드 과제로 다루지 않았다**(구현 결정 11). 반복 과제로 후속 카드에서 다룬다.
