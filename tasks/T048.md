## 구현 결정 (2026-11-04 Claude 작성 — 여기 적힌 대로 하고, 바꿔야 하면 메모에 이유를 적고 질문한다)
1. **폴더·모드:** `src/engines/E03-number-line/`만 고친다. `modes`는 기존 3개 뒤에 `skip-count`, `rounding`, `log-zoom`, `double` 순서로 붙인다(`NumberLineMode` 합집합, `DEFAULT_MAX`, `strings.instructions`, `modeOf`에 모두 추가). View.tsx가 이미 1185줄이므로 새 화면은 `views/SkipCountView.tsx`, `views/RoundingView.tsx`, `views/LogZoomView.tsx`, `views/DoubleView.tsx`로 나누고 View.tsx는 모드에 따라 고르기만 한다. reduce도 모드별 파일(`reduce-skip.ts` 등)로 나눈다. 기존 3개 모드의 동작·Observation·이벤트는 바꾸지 않는다.
2. **수:** 모든 값은 `Rational`. 상태에는 기존처럼 `Rational.toJSON()` 문자열로 둔다. 새 설정 키는 `number | string`을 받아 `String(value)` → 기존 `parseValue`로 읽는다(`0.1`처럼 정수가 아닌 number도 `String`을 거치면 된다). `"1e4"` 같은 지수 표기는 받지 않는다(무시하고 기본값) — 단원 명세 수정은 콘텐츠 카드 몫으로 메모에 남긴다. 올림·버림·반올림은 `ticks.ts`의 `floorRational`·`ceilRational`·`roundRational`(반올림 = 5 이상 올림)을 쓰고, `src/core/math`에는 손대지 않는다. 새 모드의 상태는 `skip`, `rounding`, `logZoom`, `double` 필드(다른 모드에서는 `null`)로 둔다.
3. **skip-count:** 설정 `min`(기본 0), `max`(기본 30), `start`(기본 min), `stepChoices`(기본 `[2,3,4,5]`), `step?`(있으면 고르기 버튼 없이 고정), `steps?`(여러 줄 — 줄마다 고정 step, g5s1u2용; 있으면 `stepChoices`·`step` 무시), `labels`(기존 all/partial/none), `showHopCount`(기본 **false**). 상태 `skip: { rows: { step: string | null, hops: string[] }[], start }`(hops = 뛴 뒤 도착 값들). Action `choose-step {row, step}`(hops를 비운다), `hop {row}`(마지막 도착 + step, max를 넘으면 무시), `unhop {row}`, `clear-hops {row}`. 툴바: "2씩"… 고르기 버튼, "한 번 뛰기", "되돌리기". 키보드: `J`/Space = 뛰기, Backspace = 되돌리기, 숫자 키 = step 고르기, 여러 줄이면 ↑/↓로 줄 고르기. 그림: 뛰기마다 기존 `JumpArrow` 호(라벨은 고른 step), 줄마다 다른 색 + 무늬(실선/점선 호). 기존 `place-point`(눈금 누르기·Enter)는 이 모드에서도 동작한다(g5s1u2 "공배수에 점 찍기"). 여러 줄이 겹치는 눈금을 엔진이 강조하지 않는다(그게 답이다).
4. **rounding:** 설정 `values`(값 목록, 1~3개, 예 `[389, 412]`) 또는 `value`(하나), `place`(어림할 자리 단위, 예 `10`, `100`, `"1"`, `"0.1"`), `methods`(기본 `["up","down","half-up"]`), `controls`(`"buttons"` 기본 / `"drag"`). 범위: 값마다 `lower = floor(v/place)·place`, `upper = lower + place`; 화면 구간은 모든 값의 `[min lower − place, max upper + place]`, 큰 눈금 = place(숫자 라벨), 작은 눈금 = place/10(라벨 없음). 상태 `rounding: { items: { value, marker: string | null, method: 'up'|'down'|'half-up'|null }[], selected: number }`. Action `round {item, method}`(그 방법으로 marker를 계산해 놓음 — 점이 원래 값에서 그 눈금으로 미끄러지는 애니메이션, `prefers-reduced-motion`이면 즉시), `move-marker {item, value}`(drag 모드: 큰 눈금으로만 스냅), `select-item {item}`, `clear-marker {item}`. drag 모드 키보드: 값 고르기(Tab/숫자 칩) → ←/→로 큰 눈금 한 칸씩 → Enter. 원래 값은 점 + 값 라벨(문제에 주어진 수라 보여도 된다), marker는 다른 모양(삼각 깃발) + 색. **결과 값을 따로 글자로 쓰지 않는다**(눈금 라벨로만 읽는다). `scenarios`·`showConsequence`는 받지만 무시하고 메모에 남긴다(문장은 콘텐츠·응답 위젯 몫).
5. **log-zoom:** 설정 `levels`(각 단계의 최댓값, 기본 `[10,100,1000,10000]`, 16자리까지 정수 문자열 허용 — `"10000000000000"`), `startLevel`(기본 0), `cards`(기존 키, `number | string` 허용), `snap`(`"minor"` 기본 = 단계 최댓값/100, `"major"` = /10), `labelStyle`(`"digits"` 기본 / `"korean"` = 만·억·조 단위 이름: 30000 → "3만", 200000000 → "2억", 끝자리 0이 아닌 수는 "2340만"처럼), `landmarks?: { value, label }[]`(콘텐츠가 직접 넣는 이정표 — 데이터 파일을 읽지 않는다), `start?`/`step?`(있으면 skip-count와 같은 "한 번 뛰기" 버튼과 호, 3번 결정과 같은 hops 상태). 범위는 늘 `[0, levels[level]]`. 상태 `logZoom: { level }` + 기존 points·cards. 줌아웃(− 버튼, 핀치 인, 휠 아래, 키 `-`) = level + 1, 줌인 = level − 1(맨 끝에서 무시). 단계가 바뀔 때 이전 단계 구간 `[0, 이전 최댓값]`을 줄 위 색 띠(빗금)로 남겨 "작아진 이전 구간"을 보여 준다. 큰 눈금 = 최댓값/10(라벨), 작은 눈금 = /100. 범위 밖으로 나간 점·카드는 지우지 않고 오른쪽 끝에 "→" 표시. 기존 decimal 줌(`zoom` Action)과 섞지 않는다 — 새 Action `log-zoom {level}`.
6. **double:** 설정 `top: { label, max? }`, `bottom: { label, max? }`, `anchors`(`[top, bottom]` 쌍 목록, 예 `[["2/3","1"]]`), `divisors`(기본 `[2,3]`), `multipliers`(기본 `[2,3]`), `labels`(`"expression"` 기본 / `"values"`). 두 줄의 x 비율은 첫 anchor의 top/bottom 비로 고정한다(대응 선이 늘 수직). 상태 `double: { pairs: { top, bottom, from: number | null, op: { kind: 'divide'|'multiply', factor: number } | null }[], selected }`. Action `select-pair {index}`, `scale-pair {kind, factor}`(고른 쌍의 위·아래를 같이 ÷/×해 새 쌍을 붙이고 그 쌍을 고름), `remove-pair`(마지막 쌍, anchor는 못 지움). 화면 구간은 `max(top.max, 모든 쌍의 top) × 1.1`까지 자동으로 늘린다(g6s2u1에서 top 1이 top.max 3/4보다 큰 문제 해결). 쌍마다 위아래를 잇는 수직선, 고른 쌍은 굵게. **라벨:** anchor는 값, 새로 만든 쌍은 기본 `"expression"` — 만든 과정을 식으로(`2/3 ÷ 2`, `1 ÷ 2`, 이어지면 `1 ÷ 2 × 3`) 써서 값(= 과제 답)을 보여 주지 않는다. `"values"`는 교사 시연용. 아래쪽에 누른 연산을 차례로 쌓는 띠(`÷ 2`, `× 3`)를 둔다 — 합친 결과(`× 3/2`)는 쓰지 않는다. `ops`·`goal`은 받지만 무시하고 메모에 남긴다.
7. **Observation(새 키, 모든 모드에 있고 해당 없으면 null):** skip-count: `skipRows: { step, hops, hopCount, landing }[]`, `step`·`hopCount`·`landing`(첫 줄). rounding: `rounding: { value, marker, method }[]`. log-zoom: `level`, `levelMax`, `levels`. double: `pairs: { top, bottom }[]`, `doubleOps: string[]`(예 `"divide:2"`). 값은 모두 Rational 문자열.
8. **Predicates(추가):** `landingIs {value, row?}`, `hopCountIs {count, row?}`, `stepIs {value, row?}`, `roundedTo {value, result, method?}`, `hasPointNear {value, within}`(log-zoom 과제 "1 눈금 안" 판정 — `|점 − value| ≤ within`, Rational 비교), `levelIs {level}`, `hasPair {top, bottom}`.
9. **이벤트(추가):** `hopped {row, step, count, landing}`, `rounded {item, value, result, method}`, `pair-added {top, bottom}`. 기존 `zoomed`는 log-zoom에서 `{level, tick}`(tick = 큰 눈금 간격)으로 낸다. skip-count·log-zoom 뛰기 뒤와 rounding marker가 바뀔 때 `value-changed {value}`(도착 값·marker)를 낸다.
10. **정답 노출 금지:** skip-count 뛴 횟수(기본), 여러 줄 겹치는 눈금, rounding 결과를 따로 쓴 글자, double 새 쌍의 값(기본), log-zoom에서 카드의 정답 위치를 화면에 쓰지 않는다. View 테스트로 확인한다.
11. **입력·접근성:** Pointer Events만. 버튼·점·marker 터치 타깃 ≥ `targetSize`(`minTouchRadius`). 모든 새 모드를 끌기 없이(버튼·키보드) 끝까지 할 수 있게. 색만으로 구분하지 않는다(줄·marker·쌍에 무늬·모양). 핀치·휠·버튼 세 가지 줌은 log-zoom에서도 동작한다(기존 `usePinch`·Ctrl+휠 코드 재사용).
12. **오버레이(힌트 ② 추가):** `two-ticks`(rounding: 값마다 lower·upper 두 큰 눈금만 진하게, 나머지 흐리게 — 어느 쪽인지 알려 주지 않는다, MC-ROUND-WRONG-PLACE), `pair-replay`(double: anchor에서 지금 쌍까지 만든 순서대로 화살표를 다시 그린다, 새 값 없음, MC-FRAC-DIV-INVERT-WRONG), `prev-band`(log-zoom: 이전 단계 구간 띠를 깜빡여 보여 준다).
13. **이번에 하지 않는 것(메모에 남김):** `range` 모드, 실행기 수준 `linkedViews`·`linkedNumberLine`(E02·E04·E15 연결), 랜드마크 데이터 파일, 시나리오 문장, g6s2 `goal: "reciprocal"` 판정 자동화.
14. **테스트:** reduce 단위 — skip 5씩 4번 → landing 20·hopCount 4, max 넘는 hop 무시, choose-step이 hops를 비움, steps [4,6] 두 줄 독립; rounding 243 place 10 → up 250·down 240·half-up 240, 245 half-up → 250, 4537 place 100 → 4500, 143.6 place 1 → 144, move-marker가 큰 눈금으로만 스냅; log-zoom level 0→3→3(끝에서 무시)→2, 16자리 levels, korean 라벨 30000 "3만"·200000000 "2억"·23400000 "2340만", hasPointNear; double anchor 2/3↔1에서 ÷2 → 1/3↔1/2, ×3 → 1↔3/2, 화면 구간 자동 확장, anchor는 remove-pair로 안 지워짐; `assertSerializable`; 이벤트 payload. View 테스트 — 기본 설정에서 skip hopCount 숫자 없음, rounding 결과 글자 없음, double 새 쌍 라벨이 식(값 아님), log-zoom 카드 정답 위치 없음. `tests/e2e/number-line.spec.ts`에 sandbox E2E 3개 뷰포트(`?config=` + 모드 선택): skip-count "5씩" + 키보드 J 4번 → landing 20, rounding 243 place 10 "올림" 버튼 → marker 250, log-zoom − 버튼 3번 → level 3 + 카드 2500 놓기, double ÷2 → ×3 → pairs에 1↔3/2.
