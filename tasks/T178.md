## 목표
E15에 `growth` 모드를 더한다. g2s2u6.A1 "3D 쌓기나무 성장 패턴 하이라이터"에 쓴다.
- 단계별 쌓기나무 모양(1·2·3단계 …)을 나란히 보여 준다. 각 단계에서 새로 늘어난 쌓기나무를 강조한다.
- 아래 표(단계 | 개수 | 늘어난 수)의 빈칸을 학생이 채운다.
- 4단계를 직접 쌓는 것은 E12 `cubes`가 맡는다. 콘텐츠가 실행기 `views`로 두 화면을 함께 띄운다(실행기는 이미 `views`·`links`를 지원한다). 이 카드는 E15만 만든다.

## 구현 결정 (2026-11-20 Claude 작성 — 여기 적힌 대로 하고, 바꿔야 하면 메모에 이유를 적고 멈춰서 묻는다)

### 1. 범위
- `PatternMode`에 `'growth'`를 더한다.
- 새 파일: `growth.ts`(순수 계산), `GrowthView.tsx`, `overlays/growth-split.tsx`
- 숫자 패드는 `CalcKeypad`를 재사용하거나 E15 안에서 작게 나눈다(같은 엔진 안이라 import 가능).
- 기존 세 모드의 동작·상태 모양은 바꾸지 않는다.
- `src/core/`, 다른 엔진, `data/`, `docs/`, `package.json`은 고치지 않는다.

### 2. 설정
```ts
interface GrowthConfig {
  mode: 'growth';
  shape: 'L' | 'stairs' | 'tower2';   // 기본 'L'
  stepsShown?: number;                 // 그림으로 보여 줄 단계(기본 3), 1~5
  highlightIncrement?: boolean;        // 기본 true
  table?: {
    upTo?: number;                     // 표 마지막 단계(기본 stepsShown + 2), stepsShown~8
    counts?: 'given' | 'blank';        // 보여 준 단계의 개수 칸(기본 'given')
    increments?: 'blank' | 'off';      // 늘어난 수 줄(기본 'blank')
  } | false;                           // false면 표 없음
  look?: 'cubes' | 'flat' | 'none';    // CPA: 입체 그림(C) / 색칸 그림(P) / 그림 없음(A, 표만)
}
```

### 3. 모양 (`growth.ts`)
- 각 모양은 단계 n의 쌓기나무 좌표 목록 `[x, y, z][]`를 만든다. 정수 좌표다. 개수는 n에 따라 정해진다.

  | 모양 | 단계 n의 쌓기나무 | 개수 |
  | --- | --- | --- |
  | `L` | 가로 x = 0…n−1 (y=0, z=0)과 세로 z = 1…n−1 (x=0, y=0) | 2n−1 (1, 3, 5, …) |
  | `stairs` | 열 i = 0…n−1에 높이 n−i | n(n+1)/2 |
  | `tower2` | 2열 높이 n | 2n |

- 늘어난 쌓기나무는 n단계 좌표에서 n−1단계 좌표를 뺀 것이다. 모양 정의가 앞 단계를 포함하도록 둔다. 단위 테스트로 확인한다.
- 개수는 정수라 number를 써도 된다(좌표·개수는 격자 인덱스, AGENTS 규칙 2 예외와 같다). 표 칸 입력은 문자열로 받아 정수로 비교한다.

### 4. 상태와 Action
- **상태:** `{ mode:'growth', settings, cells: Record<string,string>, active: string | null }`
  - 키는 `"<단계>.count"`·`"<단계>.inc"`다.
  - `inc` 칸은 단계 2부터 있다.
  - `count` 빈칸
    - `counts:'blank'`면 보여 준 단계의 count도 빈칸이다.
    - stepsShown 다음 단계의 count는 늘 빈칸이다.
- **Action:** `activate {cell}`, `type {key}`(0~9, 최대 3자리), `backspace`, `clear`, `move {dir}`(키보드 칸 이동)

### 5. 화면 (`GrowthView.tsx`)
- **보기 판 SVG** `data-testid="growth-canvas"`
  - 1~stepsShown 단계를 왼쪽에서 오른쪽으로 나란히 그린다. 단계 이름은 "1단계"다(학년 아님).
  - `look:'cubes'`: 등각 투영 쌓기나무(윗면·옆면 세 면 음영)
  - `look:'flat'`: 앞에서 본 정사각형 칸
  - `look:'none'`: 판 없이 표만
  - 쌓기나무 한 개는 화면 24px 이상이다. 넘치면 줄이지 말고 스크롤한다.
  - **highlightIncrement**
    - 늘어난 쌓기나무는 진한 색 + 굵은 윤곽 + 점 무늬(색만으로 구분 금지), 앞 단계에서 이어진 것은 옅은 색이다.
    - 늘어난 개수를 숫자 배지로 쓰지 않는다(과제 1의 답이다).
  - 쌓기나무에 `data-stage`·`data-new="true|false"`를 단다.
- **표** `data-testid="growth-table"` (HTML 또는 SVG)
  - 줄은 "단계", "개수", "늘어난 수"다.
  - 열은 1~upTo다.
  - 주어진 칸은 글자, 빈칸은 누를 수 있는 칸이다(targetSize 이상, `data-cell`).
  - 칸은 눌러서 고르고 숫자 패드로 입력한다. 키보드로는 방향키로 이동하고 숫자를 바로 입력한다.
- 엔진은 ✓/✕를 그리지 않는다.
- **레이아웃:** 보기 판은 `.boardArea`, 표·숫자 패드는 `.sideStack`이다. 판 맞춤 원칙은 T170·T175와 같다.
- **문구**는 `strings.ko.ts`에 둔다.

### 6. Observation과 predicate
- **Observation:** `shape`, `stepsShown`, `upTo`, `entries`(cells 그대로), `blanks`(빈칸 키 목록), `blanksCorrect`(모든 빈칸이 맞음), `misconceptions`
  - 정답 개수는 Observation에 넣지 않는다. 판정은 predicate 안에서 `growth.ts`로 계산한다.
- **Predicate**
  - `entryIs {cell, value}`: 이미 있는 이름이다. calc와 겹치지 않게 `growthEntryIs`로 한다.
  - `incrementsCorrect {}`: 모든 inc 빈칸이 맞다.
  - `countCorrect {stage}`
  - `blanksCorrect {}`
  - `hasMisconception {code}`: 기존 것을 재사용한다.
- **오개념 `MC-PATTERN-GROWTH-TOTAL`**
  - count 칸(stage ≥ 2)에 그 단계의 늘어난 수를 썼다(예: 4단계 개수 = 2).
  - count가 맞는 수와 같으면 걸지 않는다(`tower2` 1단계처럼 우연히 같을 때).
- 이벤트는 더하지 않는다(T175와 같다).

### 7. 오버레이 `growth-split` (`growth-canvas` 기준, GROWTH-TOTAL ②)
- 각 보여 준 단계에서 앞 단계 부분을 회색 덮개로, 새 쌓기나무를 굵은 테두리로 다시 그린다.
- 단계 아래에 그 단계 전체 개수 배지("모두 5개")를 단다. 보여 준 단계는 셀 수 있는 자료라 노출이 아니다.
- stepsShown 다음 단계는 그리지 않는다.

### 8. 테스트
- **단위**
  - `growth.ts`: 세 모양의 n=1·2·5 좌표 수, 앞 단계 포함, 늘어난 좌표
  - 표 빈칸 계산(counts given/blank, increments off)
  - predicate들
  - GROWTH-TOTAL(걸림, 안 걸림 두 경우)
  - reduce 불변·직렬화
- **View**
  - 정답 개수·늘어난 수 배지가 DOM에 없음
  - `look:'none'`이면 판 없음
- **E2E (`tests/e2e/pattern.spec.ts`에 growth 묶음, 3 뷰포트)**
  - inc 빈칸 2, 2 입력 → `incrementsCorrect`
  - 4단계 count에 2 → GROWTH-TOTAL
  - 키보드만으로 칸 이동·입력
  - `growth-split` 오버레이 1px 정렬
  - 크롬북·아이패드 판 스냅샷
  - `fit-canvas.spec.ts`의 E15 `modes`에 `'growth'`
- **E2E 범위:** `npx playwright test pattern fit-canvas overlay-alignment --workers=3 --reporter=line`

  - 새 파일: `growth.ts`(모양·빈칸·판정), `growth-layout.ts`(보기 판 논리 좌표·등각 면), `GrowthView.tsx`, `GrowthKeypad.tsx`, `overlays/growth-split.tsx`. 설정 정규화는 `settings.ts`의 `growthSettings`(잘못된 값은 기본값, 범위 밖 정수는 범위로 맞춤, error 판 없음).
  - 모든 모양이 y=0 평면이라 `flat`(앞에서 본 그림)이 등각 그림과 1:1이다. 1단계는 앞 단계가 없어 강조하지 않는다(data-new=false, 오버레이도 덮개·테두리 없음).
  - 표 DOM 순서는 줄 단위(개수 줄 → 늘어난 수 줄)다. 방향키는 같은 줄에서는 좌우의 다음 빈칸, 위·아래는 다른 줄의 같은 단계(없으면 가장 가까운 빈칸)로 옮긴다. 칸은 roving tabindex이고 초점이 들어오면 활성 칸이 된다.
  - Observation의 `entries`는 cells 그대로, 정답은 없다. 판정은 predicate(`incrementsCorrect`·`countCorrect`·`blanksCorrect`·`growthEntryIs`)가 `growth.ts`로 계산한다. 정답 개수가 count와 우연히 같은 모양은 현재 없어서(L·stairs·tower2 모두 2단계부터 개수 ≠ 늘어난 수) 그 분기는 코드 경계로만 둔다.
  - 판 맞춤: 쌓기나무 논리 폭 32, 최소 화면 24px(배율 0.75) 아래로는 줄이지 않고 `.boardArea[data-scroll]`로 스크롤. 단계 아래에 오버레이 배지용 빈 줄을 미리 비워 둔다.
  - `fit-canvas.spec.ts` E15 modes에 `growth`, `pattern.spec.ts`에 growth 묶음과 기준 이미지 2종(cubes L, flat stairs; 크롬북·아이패드)을 더했다. 기존 스냅샷은 다시 만들지 않았다.
