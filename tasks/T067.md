**g4s1u1 과제별**
1. **엔진 사실(이대로 쓴다):**
   - **E01 `big-number`:** `{"mode":"big-number","value":"52840000","slicer":"student"}`. 값은 문자열이고 16자리까지 쓴다.
     - 학생이 자른 대로 색·단위 이름표(만·억·조)가 붙는다. 처음에는 잘린 곳이 없다.
     - **`slicer:"auto"`는 미리 잘라 답을 보여 주니 쓰지 않는다.**
     - 역방향: `reverse:{spoken}`. 조·억·만·일 × 천·백·십·일 16칸 표 + 숫자 카드. `spoken`은 화면에 그려지지도, 읽히지도 않는다 — 들을 수는 발문에 쓴다. `spoken`에는 발문과 같은 수 읽기를 넣는다.
     - predicate: `cutsAre {positions}`, `cutsCorrect`, `builtIs {value}`, `selectedPlaceIs {exponent}`.
     - `tts` 키는 엔진이 무시하니 넣지 않는다. `place-chart`와 함께 쓰는 방식은 없다.
   - **E03 `log-zoom`:** `levels`(정수 문자열 배열, 12개까지), `startLevel`, `labelStyle`(`digits`/`korean`), `landmarks:[{value,label}]`(설정 안에 직접), 뛰어 세기 `start`·`step`.
     - predicate: `landingIs`, `hopCountIs`, `levelIs`.
     - 현재 단계 범위를 넘는 점프는 무시되니, 뛰어 세기 과제는 그 수가 들어가는 단계에서 시작한다.
     - `data/landmarks-ko.json`은 만들지 않는다. 이정표 값의 출처·기준 연도는 카드 메모에 적는다.
2. **A1 (E01 `big-number`).**
   - **T1 (P) 52840000:** `slicer:"student"` + 응답 `choice` 읽기 하나 고르기.
     - 선택지: "오천이백팔십사만" 정답 + "오십이만 팔천사백"·"오억 이천팔백사십만"·"오천이백팔십사억" 등.
     - 판정: `cutsCorrect` + 선택.
     - **MC-BIGNUM-GROUP3**(observation 코드 → `{misconception}` 금지): `any`(`cutsAre {positions:[3]}`, `cutsAre {positions:[3,6]}`) 규칙으로 L1·L2·L3. ② `four-digit-grid`(그리는지 확인).
   - **T2 (P) "이천삼십만 오" → 수:** 역방향.
     - 발문 예: "이천삼십만 오를 자릿값 표에 숫자 카드로 만들어요. 빈 자리에는 0을 놓아요."
     - 판정: `builtIs {value:"20300005"}`.
     - **MC-BIGNUM-ZERO-PLACE:** `diagnose`(경로 `built`, args `{expected:"20300005"}`).
     - `built`는 가운데 빈 칸이 있으면 null이다 — 그때는 일반 힌트가 나온다.
   - **T3 (P) 3528007140000에서 5가 나타내는 값:** `slicer:"student"` + 응답 `choice`("5억"·"50억"·"500억"·"5000억" 중).
     - 판정: 선택 "5000억". 자르기는 판정하지 않는다(도구로만).
     - 답이 12자리라 수 칸은 쓰지 않는다.
   - **T4 (A) 억이 10000개인 수:** 역방향.
     - 발문 예: "억이 10000개인 수를 자릿값 표에 만들어요."
     - 판정: `builtIs {value:"1000000000000"}`.
   - 완료 기준: 명세대로 4개 중 3개(T2 포함).
3. **A2 (E03 `log-zoom`).** `levels`는 10000부터 10배씩 10000000000000까지(10개).
   - **T1 (P) 234만에서 10만씩 5번:** `{"mode":"log-zoom","levels":[…],"startLevel":<10000000이 끝인 단계>,"start":"2340000","step":"100000","labelStyle":"korean"}` + 응답 `choice` "바뀌는 자리"(만·십만·백만).
     - 판정: `hopCountIs {count:5}` + `landingIs {value:"2840000"}` + 선택 "십만".
     - 실제 키·단계 번호는 엔진 코드로 맞춘다.
   - **T2 (P) 이정표 셋을 작은 순서로:** 같은 `levels`, `startLevel` 0, `landmarks`:
     - 서울 인구 약 940만(9400000)
     - 대한민국 인구 약 5100만(51000000)
     - 지구에서 태양까지 약 1억 5000만 km(150000000)
     - 값은 반올림한 어림값이다. 출처(통계청 주민등록 인구, 천문단위)와 기준 연도를 메모에 적는다.
     - 응답 `order` 이름 카드 셋. 판정: 순서 일치.
     - 학생이 줌아웃하며 이정표를 찾아보는 것이 활동이다(첫 화면에는 큰 이정표가 보이지 않는 단계로 시작).
   - **T3 (P) 4억 2천만 ○ 42억:** `showEngine:false`, 응답 `compare`(`left:"4억 2천만"`, `right:"42억"`). 판정: `<`.
     - **MC-BIGNUM-FIRST-DIGIT** 감지 함수는 첫 숫자가 같으면(4·4) 걸리지 않는다. 그래서 `{misconception}` 대신 `equals response.<id>.symbol ">"` 규칙으로 명세의 ①·②·③ 문구를 건다.
     - ②는 `say`만(오른쪽 정렬 겹치기 그림 없음).
   - **T4 (A) 7억 3500만 ○ 7억 5300만:** `showEngine:false`, `compare`. 판정: `<`.
   - 완료 기준: 명세대로 4개 중 3개.
4. **명세와 다른 곳(메모에 적는다):**
   - 수 읽기 TTS는 발문 스피커로.
   - 12~13자리 답은 고르기·자릿값 표로.
   - `landmarks-ko.json` 대신 설정 안 이정표.
   - "바뀌는 자리" 강조와 수직선 위 비교는 응답 칸으로.
   - `place-chart` 함께 쓰기 없음.
   - FIRST-DIGIT은 응답 규칙으로.

### 명세·카드와 다르게 한 곳
- **TTS:** 발문 스피커(앱 공통)로 읽는다. 콘텐츠에 `tts` 키를 넣지 않았다(엔진이 무시).
- **12~13자리 답:** 수 응답 칸 대신 고르기·자릿값 표(`builtIs`)로 판정한다.
- **이정표:** `data/landmarks-ko.json` 대신 E03 설정 안 `landmarks`에 직접 넣었다. 값은 카드에 제시된 반올림 어림값(서울 약 940만, 대한민국 약 5100만, 지구~태양 약 1억 5000만 km)이고, 출처는 통계청 주민등록 인구와 천문단위(1 AU ≈ 1.496억 km)이다. 카드에 기준 연도가 없어 화면에는 연도를 쓰지 않았고, 교사가 필요하면 설정에서 갱신한다.
- **"바뀌는 자리" 강조·수직선 위 비교:** 응답 고르기·부등호 위젯으로 대신했다.
- **`place-chart` 함께 쓰기 없음.**
- **MC-BIGNUM-FIRST-DIGIT:** 감지 함수가 4·4처럼 첫 숫자가 같으면 걸리지 않아 `{misconception}` 대신 `response.cmp.symbol`이 ">"·"="·null일 때의 규칙으로 ①·②·③을 걸었다.
- **T2 ②:** `four-digit-grid`는 역방향에서 `big.value`가 비어 있어 그리지 않는다. 그래서 T2 ②는 `say`만 쓰고, ② 오버레이 검사는 T1에서 했다.
- **T1 E2E:** 힌트 ② 뒤 자르기 틈을 키보드(Enter)로 다시 눌러 오버레이/클릭 안정성 문제를 피했다.
