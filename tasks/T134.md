## 목표
g6s2u3(공간과 입체) A1·A2에 필요한 2D 입력판을 E12 `cubes`에 더한다. 학생이 3D 모양을 보고 **위에서 본 모양에 수를 쓰고**, **층별 그림을 칠하고**, **투영(위·앞·옆에서 본 모양)을 예측해 칠하는** 것을 엔진 상태로 받아 predicate로 판정할 수 있게 한다. 3D 무대를 숨긴 2D 전용 화면(A 단계)도 지원한다.

투영 역추론(최소·최대 개수)과 보기 카드(가·나·다)는 T135에서 한다.

## 구현 결정 (2026-11-14 Claude 작성 — 여기 적힌 대로 하고, 바꿔야 하면 메모에 이유를 적고 멈춰서 묻는다)
**공통 규칙(T130 그대로):**
- 좌표 x 오른쪽, y 뒤(0 = 앞줄), z 위.
- 행렬 방향:
  - `top`/`heights`: 0행 = 뒷줄, 마지막 행 = 앞줄, 열 = x.
  - `front`: 0행 = 맨 위 층, 마지막 행 = 1층, 열 = x.
  - `side`(오른쪽에서 봄): 0행 = 맨 위 층, 열 0 = 앞줄(y=0) → 뒤.
  - 이 카드의 모든 새 격자(입력·칠하기·층별 그림)도 같은 방향을 쓴다. 층별 그림 한 장은 `top`과 같은 방향이다.
- 새 상태는 모두 JSON 직렬화 가능한 수 배열로 두고, Action → `reduce`로만 바꾼다.
- 엔진끼리 import 금지. `three`는 `three/` 폴더 안에서만 쓴다.

1. **설정 키**(`CubesConfig`에 더함, 모두 선택):
   - `numberGrid?: { mode: 'input' | 'drive' | 'given'; given?: number[][] }`
   - `layers?: { slider?: boolean; panel?: 'off' | 'live' | 'paint' | 'given'; given?: number[][][] }`
     - `given[k]`는 (k+1)층 그림이며 `top` 방향 0/1 행렬이다.
   - `paintViews?: ProjectionView[]`(칠하는 투영 판)
   - `stageHidden?: boolean`(3D·등각 무대를 그리지 않음)
   - `buildSettings`에서 정규화해 `CubesSettings`에 둔다.
   - 잘못된 값은 버린다. 행렬 크기가 격자와 다르면 그 키를 무시한다. 수는 0~maxHeight 정수로 자른다.
   - 기존 무시 키 `variant`·`layerSlider`·`bidirectional`은 그대로 무시한다(명세 예시 이름일 뿐이고 새 키로 대신한다).

2. **수 쓰기 격자(`numberGrid`)** — 패널 제목 "위에서 본 모양에 수 쓰기", test id `cubes-numbers`, 칸 `[data-num-cell="r,c"]`(행·열은 `top` 방향).
   - **`input`:** 학생이 칸마다 0~maxHeight 수를 쓴다. 상태 `numbers: number[][]`(처음 모두 0)이고 무대 쌓기나무와 독립이다.
     - 칸을 누르면 그 칸이 선택된다(`numberCursor`). 패널 아래 수 단추 줄 `0 … maxHeight`(48px)로 값을 넣는다.
     - 키보드: 패널에 포커스 → 방향키로 칸 이동, 숫자 키로 값, Backspace로 0.
     - Action `set-number {row, col, value}`, `move-number-cursor {to:[row,col]}`.
   - **`drive`:** `input`과 같은 입력이지만 값을 넣으면 그 기둥 높이가 그 값이 되게 쌓기나무를 더하거나 뺀다.
     - Action `set-height {x, y, h}`. 고정(locked) 쌓기나무보다 낮출 수 없고, `maxCubes`를 넘으면 무시한다.
     - 상태 `numbers`를 따로 두지 않는다. 화면 수는 현재 `heights`다.
     - `editable:false`면 무시한다.
   - **`given`:** `given` 행렬을 읽기 전용으로 보여 준다(칸 누르기 없음). 상태 변화가 없다.
   - 0인 칸은 빈칸으로 그린다(`input` 선택 칸만 "0"). 글자 18px 이상, 칸 48px 이상.

3. **층별 그림(`layers`)**
   - **`slider: true`:** 무대 옆 단추 묶음 "전체 · 1층 · 2층 … maxHeight층"(48px, test id `cubes-layer-btn-<k>`, 전체는 `cubes-layer-btn-all`).
     - 상태 `layerFocus: number | null`(1부터, null = 전체). Action `focus-layer {layer: number | null}`.
     - 고른 층 쌓기나무는 그대로 그리고, 다른 층은 반투명(불투명도 0.2, 등각·3D 모두)으로 그린다.
     - `layerFocus`가 있으면 `translucent` 단추보다 우선한다.
   - **`panel`:** 무대 아래(좁은 판) 또는 오른쪽 칸(넓은 판)에 층마다 작은 격자를 나란히 그린다. 제목 "1층", "2층" …, test id `cubes-layer-<k>`, 칸 `[data-layer-cell="k,r,c"]`, 칸 28px 이상. 층 수는 `maxHeight`.
     - **`live`:** 현재 쌓기나무로 각 층 칸을 칠해 보여 준다(읽기 전용, 답을 보여 주므로 P 단계 과제에서만 쓴다).
     - **`paint`:** 학생이 칸을 눌러 칠하기/지우기를 토글한다(칸 48px). 상태 `layerPaint: number[][][]`(maxHeight장, 0/1). Action `toggle-layer-cell {layer, row, col}`, `clear-layer-paint`. 키보드: 층 그림에 포커스 → 방향키·Enter 토글, PageUp/PageDown으로 층 이동. 무대 쌓기나무와 독립이다(칠해도 3D가 생기지 않는다 — 명세의 '칠하면 3D 생성'은 공중에 뜬 칠하기를 보여 줄 수 없어 하지 않는다).
     - **`given`:** `given` 그림을 읽기 전용으로 보여 준다(무대와 독립).
     - `slider`와 함께 쓰면 고른 층의 그림 테두리를 굵게 강조한다.

4. **투영 칠하기(`paintViews`)** — 보기마다 칠하는 격자 하나, 제목 "위에서 본 모양 그리기" / "앞에서 본 모양 그리기" / "오른쪽에서 본 모양 그리기", test id `cubes-paint-<view>`, 칸 `[data-paint-cell="view,r,c"]`(48px).
   - 크기: top = rows×cols, front = maxHeight×cols, side = maxHeight×rows. 행렬 방향은 공통 규칙대로다.
   - 상태 `painted: { top?: number[][]; front?: number[][]; side?: number[][] }`(0/1). Action `toggle-paint-cell {view, row, col}`, `clear-paint {view}`. 키보드는 층 그림과 같다.
   - 실시간 투영(`views`)과 같은 보기를 동시에 켜면 답이 보인다. 이런 설정이면 콘솔 경고를 내고 실시간 투영 쪽을 그리지 않는다.
   - 앞·옆 칠하기 격자 아래에 "1층" 쪽 바닥선과, 옆 격자에 "앞" 쪽 표시를 그린다(T130 `ProjectionGrid` front-label 방식).

5. **3D 숨기기(`stageHidden: true`)**: 무대(`cubes-stage`)와 렌더러 전환·시점·돌리기·반투명 단추를 그리지 않는다. 성능 감지도 하지 않는다. 쌓기·빼기 단추도 숨긴다(`editable`과 무관하게 무대가 없으므로). 패널(수 쓰기·층별·칠하기·과제 보기)만 남는다. Observation은 그대로 만든다.

6. **Observation 추가**(기존 키는 바꾸지 않는다):
   - `numbers`: `input`이면 학생 수 행렬, `drive`이면 `heights`와 같은 값, 없으면 키 없음
   - `layers`: 현재 쌓기나무의 층별 0/1 행렬 배열(maxHeight장, 항상)
   - `layerPaint`: `paint`일 때만
   - `painted`: `paintViews`가 있을 때만
   - `layerFocus`

7. **predicate 추가**(`events.ts`, 순수 함수, 단위 테스트 필수):
   - `numbersMatch {numbers?: number[][]}`: `numbers` args가 있으면 학생 수 = args이고, 없으면 학생 수 = 현재 `heights`다(3D를 보고 수 쓰기).
   - `numbersSum {sum: number}`: `input` 수의 합 = sum.
   - `layerPaintMatches {layer?: number}`: 칠한 층(1부터)이 실제 쌓기나무의 그 층과 칸 단위로 같다(평행이동 없음). layer가 없으면 모든 층이 같다.
   - `layerPaintFloating {against: 'paint' | 'cubes'}`: (k≥2)층에 칠한 칸 아래 (k-1)층이 비어 있으면 참이다. 아래층 기준은 `paint`면 칠한 아래층, `cubes`면 실제 쌓기나무 아래층이다(MC-LAYER-FLOATING).
   - `layersMatch {layers: number[][][]; shift?: boolean}`: 현재 쌓기나무의 층별 그림이 args와 같다. shift 기본 true면 x·y 평행이동을 허용하고 층은 그대로다.
   - `paintedMatches {view}`: 칠한 투영 = 현재 쌓기나무의 그 투영. 둘 다 전체 크기 격자에서 칸 단위로 비교하고 평행이동은 없다.
   - `paintedMirrored {view}`: 칠한 투영이 실제 투영을 좌우(열) 뒤집은 것과 같고 실제와는 다르다(MC-VIEW-SIDE-MIRROR).
   - `paintedShorter {view}`: front·side만 쓴다. 칠한 열 집합은 실제와 같고, 어떤 열은 칠한 높이가 실제보다 낮고, 높은 열은 없다(MC-VIEW-DEPTH-IGNORED).
8. **화면 배치:** 새 패널은 T133 순서에서 '과제 보기' 다음, 도구 막대 앞에 둔다(입력판이 판 안 스크롤 밑으로 밀리지 않게). 순서: 과제 보기 → 수 쓰기 → 층별 그림 → 투영 칠하기 → 도구 막대 …
   - T122·T131·T133 판 높이 규칙은 바꾸지 않는다.
   - 패널이 많아 넘치면 판 안 스크롤이 생길 수 있다. 샌드박스 E2E 설정마다 첫 화면에 들어오는지 메모에 적는다.
9. **문구:** 모든 새 문구는 `strings.ko.ts`에 둔다. 정답·규칙을 말하는 안내 문구는 쓰지 않는다. 패널 안내 한 줄은 이 셋만 쓴다.
   - "칸을 누르고 수를 골라요."
   - "칸을 눌러 칠하거나 지워요."
   - "층을 골라 그 층만 보아요."
10. **테스트:**
    - **단위:** reduce 새 Action(경계: 0, maxHeight, 고정 쌓기나무 아래로 낮추기, maxCubes 초과, `editable:false`), observe 새 키, predicate 7개(정답·대표 오답·mirror·floating 둘 다), 설정 정규화(크기 다른 행렬 무시).
    - **E2E** `tests/e2e/solid-3d-panels.spec.ts`(세 뷰포트, 샌드박스 `?stage=fit&config=`). 설정마다 첫 화면 측정과 키보드 조작을 하나씩 넣는다.
      - ① `numberGrid input` + 고정 쌓기나무
      - ② `drive`
      - ③ `layers slider+paint`
      - ④ `paintViews ["side"]` + `rotationLocked`
      - ⑤ `stageHidden` + `numberGrid given`
    - 기존 E12 E2E는 그대로 통과해야 한다.
