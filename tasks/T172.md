## 목표
E16 대응 관계(g4s1u6, g5s1u3)는 학생이 쓴 관계식이 대응표의 모든 쌍에서 성립하는지 판정해야 한다.
- 예: `□ = ○ × 4`, `□ - 1 = ○ × 3`
- 지금 `src/core/math`의 파서는 □ 하나만 받는다. ○와 `=`는 받지 못한다.

이 카드는 기존 `Ast`와 `parse`를 바꾸지 않고, 관계식 전용 파서와 판정 함수를 `src/core/math/relation.ts`에 더한다. E16 엔진(다음 카드)이 이것을 쓴다.

## 구현 결정 (2026-11-19 Claude 작성 — 여기 적힌 대로 하고, 바꿔야 하면 메모에 이유를 적고 멈춰서 묻는다)

### 1. 토큰
- `tokenize.ts`에 토큰 두 개를 더한다: `○`(U+25CB) → `{type:'circle'}`, `=` → `{type:'equals'}`.
- 기존 `parse()`는 이 둘을 만나면 지금처럼 `PARSE` 오류를 던진다(`parsePrimary`의 "예상하지 못한 기호", 최상위 끝 검사).
- 기존 `Ast` 유니온, `evaluate`, `display`, `render`, `equivalent`, `operation-order`는 고치지 않는다.
- `parse.test.ts`에 다음 두 경우를 더한다: `parse('○+1')`과 `parse('□=3')`이 `PARSE`를 던진다.

### 2. 관계식 AST와 파서 (`relation.ts`)
```ts
export type RelTerm =
  | { kind: 'number'; value: Rational; text: string }
  | { kind: 'var'; name: 'circle' | 'box' }
  | { kind: 'group'; expr: RelTerm }
  | { kind: 'binary'; op: BinaryOperator; left: RelTerm; right: RelTerm };
export interface Relation { left: RelTerm; right: RelTerm }
export function parseRelation(source: string): Relation; // 실패하면 MathError('PARSE', …, {position})
```
- 문법: `relation := expr '=' expr`, `expr`는 기존 parse와 같은 우선순위다(+ − < × ÷, 괄호).
  - 수: 자연수·소수·분수 리터럴이다(기존 토큰 규칙 그대로). 대분수는 받지 않는다.
  - `=`는 정확히 하나다. 없거나 둘 이상이면 PARSE다.
  - 비(`:`)는 PARSE다.
- 암시적 곱(`3○`, `○○`)은 받지 않는다(PARSE). 오류 위치(`position`)를 정확히 준다.
- `○`·`□`가 하나도 없는 식(`4 = 4`)도 파싱은 된다. 판정 함수가 처리한다.
- 공백은 무시한다. ASCII `* / -`도 받는다(기존 토큰 규칙).

### 3. 계산과 판정
- `evaluateTerm(term, env: { circle: Rational; box: Rational }): Rational`
  - 0으로 나누면 `MathError('DIV_BY_ZERO')`를 던진다.
- `relationHolds(rel, circle, box): boolean`
  - 좌변 값과 우변 값이 같은지 본다.
  - 0으로 나누기는 `false`다(throw 없음).
- `checkPairs(rel, pairs: readonly (readonly [Rational, Rational])[]): boolean[]`
  - 쌍은 `[○, □]`다. 각 쌍의 성립 여부를 돌려준다.
- `relationInfo(rel)`: `{ usesCircle, usesBox, circleCount, boxCount, boxOnly, solvedForBox }`
  - `boxOnly`: □만 있고 ○가 없다. "□ = □ + 4" 같은 이웃 항 규칙을 감지하는 데 쓴다.
  - `solvedForBox`: 한 변이 정확히 `□` 하나이고 다른 변에 □가 없다. "□ = ○ × 4" 모양이다.
- `sameOnDomain(a, b, domain: readonly Rational[]): boolean`
  - 각 ○ 값에서 두 관계식이 같은 □ 값 집합을 정하는지 본다.
  - 구현: 각 관계식을 □에 대해 푼다. □에 일차식인 경우만 다룬다.
    - 방법: 관계식 `L − R`을 □에 대한 일차식 `a·□ + b`(a, b는 ○를 대입해 정한 유리수)로 보고, `a ≠ 0`이면 □ = −b/a다.
    - □가 일차가 아니면(□×□, □가 나누는 수) `MathError('NONLINEAR')`를 던진다.
    - 값 하나로 정해지지 않는 ○가 있으면 false다(a = 0).
  - 같은 내용을 `solveBox(rel, circle): Rational | null`로도 내보낸다. a = 0이거나 0으로 나누면 null이다.
- `swappedHolds(rel, pairs)`: 각 쌍의 ○와 □를 바꿔 넣었을 때 모두 성립하는지 본다(MC-CORR-SWAP-VARS 감지용).
- 일차식 계산에는 기존 `evaluate.ts`의 Poly 도우미를 쓰지 않는다(그것은 □ 하나용이다). `relation.ts` 안에 작은 일차 다항식(□에 대한 계수, ○는 대입한 값) 계산을 둔다.
- 모든 값은 `Rational`이다. number는 쓰지 않는다.

### 4. 표시
- `formatRelation(rel): string`: 사람이 읽는 식이다. 유니코드 `+ − × ÷`, 기호 `○ □`, 연산자 앞뒤 한 칸 띄움, 괄호는 그대로 쓴다.
  - 예: `"□ = ○ × 4"`
  - E16 화면과 교사 기록이 쓴다.

### 6. 테스트 (`src/core/math/__tests__/relation.test.ts`, 경계값 필수)
- **파싱**
  - `□ = ○ × 4`, `□=○*4`(ASCII)
  - `□ - 1 = ○ × 3`
  - `(○ + 1) × 2 = □`
  - `□ = ○ ÷ 2`
  - `□ = 1/2 × ○`, `□ = 0.5 × ○`
- **PARSE 실패와 위치**
  - `+4`
  - `□ = □ + ` (끝)
  - `□ = ○ = 4` (둘)
  - `□ ○` (암시적 곱)
  - `3○`
  - `□ : ○`
  - 빈 문자열
- **checkPairs**
  - 의자 다리 `[[1,4],[2,8],[5,20]]`에서 `□ = ○ × 4`는 모두 참이다.
  - 같은 쌍에서 `□ = ○ + 3`은 첫 쌍만 참이다(ONE-PAIR).
  - 0 쌍 `[0,0]`
  - 큰 수 `[1000000, 4000000]`
  - 분수 쌍 `[1/2, 2]`
- **0으로 나누기**
  - `□ = 4 ÷ ○`에서 ○ = 0이면 false다.
  - `evaluateTerm`은 DIV_BY_ZERO를 던진다.
- **relationInfo:** `□ = □ + 4`는 `boxOnly`이고, `□ = ○ × 4`는 `solvedForBox`, `□ - 1 = ○ × 3`은 `solvedForBox`가 아니다.
- **sameOnDomain**
  - 1~20에서 `□ = ○ × 3 + 1`과 `□ − 1 = ○ × 3`이 같다.
  - `□ = ○ × 3 + 1`과 `□ = ○ × 3`은 다르다.
  - `□ × □ = ○`은 NONLINEAR를 던진다.
  - `0 × □ = ○`에서는 false다.
- **swappedHolds:** `○ = □ × 4`가 `[[1,4],[2,8]]`에서 참이다.
- **formatRelation:** ASCII 입력을 유니코드로 바꾸고, 괄호를 보존한다.
- **기존 테스트:** 바뀌지 않고 통과한다.
