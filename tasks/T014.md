## 구현 결정 (2026-11-03 Claude 작성 — 여기 적힌 대로 하고, 바꿔야 하면 메모에 이유를 적고 질문한다)
1. **폴더:** `src/engines/E07-column-calc/`, E05·E03과 같은 구조. 엔진 ID `E07`, modes 순서 `add`, `sub`, `decimal`. 확장 모드(`mul`, `div`, `estimate`)는 만들지 않는다. g4s2u3.A2 과제 5(어림 예/아니요)는 응답 위젯(T016) 몫이다.
2. **설정 키:** `a`, `b`(수 문자열, decimal은 `"3.5"`처럼), `op`(`add`/`sub` — decimal 모드에서 연산 지정), `magnetAlign`(`"C-P"`면 C·P 단계에서 자석 정렬, A 단계는 자석 없음; `true`/`false`도 받음), `padZeros`(`"optional"` / `"auto"` / `"off"`). `sub`에서 a < b면 설정 오류로 보고 a·b를 바꾸지 않는다(콘텐츠가 고친다).
3. **수 표현:** 자리 숫자는 문자열 한 글자(`"0"`~`"9"`), 값 계산은 `BigInt`·`Rational`. **소수를 number로 계산하지 않는다**(0.1+0.2 문제). 격자 열은 자릿값 지수(…, 1, 0, −1, −2 …)로 식별한다.
4. **격자:** 위에서부터 받아올림·받아내림 칸 줄 → a 줄 → b 줄(연산 기호) → 가로선 → 결과 줄. add·sub 모드는 두 수를 일의 자리 기준으로 처음부터 맞춰 놓는다. decimal 모드는 두 수 카드를 학생이 격자 위로 끌어 놓는다(`place` Action, 열 위치는 소수점이 놓인 열). 자석이 켜져 있으면 소수점 열에 붙고, 꺼져 있으면 놓은 자리 그대로다(오른쪽 끝 맞추기 실수가 가능해야 한다). 빈 자리 0 채우기는 `padZeros`에 따라 학생이 칸을 눌러 0을 넣거나(optional) 자동으로 채우거나(auto) 막는다(off).
5. **받아올림·받아내림 표기:** add는 열마다 위쪽 작은 칸에 받아올린 수(`carry`)를 쓴다. sub는 교과서 방식대로 열마다 두 표시가 있다. 윗수 숫자를 눌러 줄을 긋고 위 작은 칸에 고친 수(`regroup`)를 쓰는 것, 받는 열에 `10` 표시(`ten` 토글)를 붙이는 것이다. 모두 Action으로 기록하고 `carry-marked` 이벤트를 낸다.
6. **입력:** 칸을 누르면 숫자 키패드(0~9, 지우기). 키보드 숫자·Backspace·화살표. 다음 칸 자동 이동은 결과 줄 오른쪽 → 왼쪽(덧셈·뺄셈 모두). 입력 칸 하나 = Action 하나(`cell-entered` 이벤트). 칸은 `targetSize` 이상.
7. **정답 노출 금지:** 칸마다 기대값을 엔진 안에서 계산하지만 **화면에 맞음·틀림을 표시하지 않는다**(빨간 칸·초록 칸 금지). 기대값은 Observation 판정·진단에만 쓴다.
8. **Observation:** `mode`, `op`, `a`, `b`, `aligned`(소수점 열이 맞는지), `alignment`(`"point"` / `"right-edge"` / `"other"` / `null`), `complete`(결과 줄이 다 찼는지), `result`(학생 결과 줄의 값, Rational 문자열 — 빈칸이면 null), `resultRaw`(쓴 그대로 `"4.77"`), `carries`(열 지수 → 학생이 쓴 값), `regroups`, `wrongColumns`(틀린 결과 칸의 열 지수 목록), `errors: [{ column, code }]`, `misconceptions`(코드 중복 없음).
9. **오류 분류(순수 함수, `classify.ts`):** 틀린 결과 칸마다 다음 순서로 코드를 붙인다. ① `MC-DEC-ALIGN-RIGHT`: decimal에서 `alignment === "right-edge"`. ② `MC-SUB-SMALLER-FROM-LARGER`: sub에서 그 열 윗수 < 아랫수인데 학생 값 = |윗수 − 아랫수|. ③ `MC-PV-BORROW-NO-DECREMENT`: sub에서 아래 열에 받아내림을 해 주었는데 이 열을 원래 윗수로 계산한 값. ④ `MC-PV-NO-CARRY`: add에서 아래 열 합이 10 이상인데 받아올림 없이 계산한 값(또는 두 자리 합을 그대로 쓴 경우). 어느 것도 아니면 `"unknown"`. 이 엔진은 `src/core/math/diagnose.ts`를 바꾸지 않는다. 같은 코드가 엔진 Observation에 나오므로 콘텐츠는 힌트 `when`에 predicate `hasMisconception`을 쓴다.
10. **Predicates:** `resultIs`(args `{ value }`, 값 동치), `alignedByPoint`, `noErrors`, `hasMisconception`(args `{ code }`), `complete`.
11. **이벤트:** `cell-entered`, `carry-marked`, `aligned`(카드를 놓을 때 `{ alignment }`), `value-changed`(결과 줄이 다 찼을 때 `{ value }`, E05·E03과 같은 모양).
12. **CPA:** C는 열 머리에 자릿값 이름(일·소수 첫째·소수 둘째 …)과 자석, P는 자석만, A는 머리·자석 없음. 문구는 `strings.ko.ts`. 색 외에 테두리·줄긋기로 상태를 구분한다.
13. **오버레이(힌트 ②):** `place-value`(각 열에 자릿값 이름과 그 자리 숫자가 뜻하는 수를 보여 줌, 예: 0.5), `column-sum`(학생이 고른 열의 두 숫자와 받아온 수를 블록 그림으로). 결과 칸을 채우지 않는다.
14. **테스트:** classify 단위(코드마다 감지 예 + 정답은 감지 안 됨 + 모호한 예), reduce·observe(빈칸, 0 채우기, `12.08 + 0.9`, `5 − 1.36`처럼 자리 수가 다른 경우, 받아내림 연속), `assertSerializable`, `#/sandbox/E07` E2E(3개 뷰포트): decimal 자석 정렬 후 `3.5 + 1.27` 결과 입력 → `result` 4.77, 자석 끈 상태에서 오른쪽 끝 맞춤 → `MC-DEC-ALIGN-RIGHT`, 키보드만으로 한 문제.
