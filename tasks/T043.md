1. **폴더·모드:** `src/engines/E01-base-ten/`만 고친다. `modes`는 기존 5개 뒤에 `big-number`, `decimal`, `divide` 순서로 붙인다. 기존 모드의 동작·Observation·이벤트 모양은 바꾸지 않는다(소수 해석일 때만 아래 2번처럼 달라진다). View.tsx가 이미 1000줄이므로 big-number 화면은 `views/BigNumberView.tsx`, divide의 접시 부분은 `views/DividePlates.tsx`로 나눈다.
2. **소수 해석(`interpretation`):** 설정 `interpretation: 'whole' | 'decimal'`(기본 `whole`, `decimal` 모드는 항상 `decimal`)을 `settings`에 복사한다. 블록의 모양 값(`BlockValue` 1·10·100)은 그대로 두고 **해석만** 바꾼다: decimal에서 100(판) = 1, 10(막대) = 0.1, 1(낱개) = 0.01. decimal에서 1000 블록은 쓰지 않는다(`allowedBlocks` 기본 `[1,10,100]`, 1000이 들어오면 빼고, 100 블록은 더 묶지 않는다). `value.ts`에 `scaleOf(settings): Rational`(whole 1, decimal 1/100)과 `rationalValueOf(state): Rational`을 더하고, 값 계산은 이 함수를 거친다. **부동소수 금지:** 0.1·0.01을 number로 곱하거나 더하지 않는다.
   - Observation `value`: whole은 지금처럼 정수 number, decimal은 `Rational.toDecimalString()` 문자열(예 `"6.24"`, `"0.75"`, 0은 `"0"`).
   - `counts`: whole은 지금처럼 `{thousands, hundreds, tens, ones}`, decimal은 `{ones, tenths, hundredths}`(판·막대·낱개 수). `countsAre`는 두 키 묶음을 모두 받는다.
   - `valueIs {value}`: 인자와 Observation 값을 **둘 다 `Rational`로 바꿔** 비교한다(number면 `Rational.of`, 문자열이면 `Rational.parse`). 그래서 `{"value": "2.08"}`과 `{"value": 52}` 모두 된다.
   - 이벤트: decimal에서 `value-changed {value: "<소수 문자열>"}`, `grouped`·`broken`은 `{from, to, column}`의 from·to를 소수 문자열(`"0.01"`, `"0.1"`, `"1"`)로, `column`은 자릿값 지수(낱개 −2, 막대 −1, 판 0 — whole의 일 0·십 1·백 2와 같은 규칙을 음수로 늘린 것). whole의 이벤트 모양은 그대로다.
3. **시작 값:** `StartSpec`에 `value?: string`을 더한다(모든 모드). `"52"`·`"6.24"`를 해석에 맞는 **정규형 블록**으로 놓는다(decimal `"6.24"` → 판 6·막대 2·낱개 4). 기존 `ones/tens/...` 키와 함께 오면 `value`가 이긴다. 잘못된 문자열·음수·소수 셋째 자리 이상은 무시(빈 판).
4. **decimal 모드:** free와 같은 조작(놓기·옮기기·올가미 묶기·망치 풀기·10개 묶기 버튼)에 해석만 소수. 블록 상자 이름표는 `strings.ko.ts`의 "1", "0.1", "0.01"(블록 단위 이름이라 답이 아니다). 자릿값 표: `ChartName`에 `tenths`·`hundredths`를 더하고(열 지수 −1·−2, 기본 이름 "소수 첫째"·"소수 둘째"), decimal의 `chart`는 `["ones","tenths","hundredths"]` 같은 모양, 일과 소수 첫째 사이에 소수점을 그린다. `chartValue`도 decimal이면 소수 문자열.
5. **big-number 모드(블록 없음):** 설정 `value`(숫자 문자열 1~16자리, 맨 앞 0 금지 — 9999조까지라 number로 다루지 않는다. 모든 계산은 문자열·`bigint`), `slicer`(`"student"` 기본 / `"auto"` 처음부터 잘려 있음), `groupColors`(기본 `["gray","green","blue","purple"]` = 일·만·억·조), `expand`(boolean, 기본 true), `reverse?: { spoken: string }`(reverse가 있으면 숫자 띠를 그리지 않고 `value`는 생략한다 — 띠가 곧 답이다). 상태 `cuts: number[]`(오른쪽에서 센 자릿수 위치, 정렬·중복 없음), `expanded: number | null`(펼친 덩어리 index, 오른쪽부터 0), `selected: number | null`(고른 숫자의 자릿값 지수), `built: (number | null)[]`(reverse 칸, 16칸). Action `cut {position}`·`uncut {position}`(숫자 사이 틈을 누르거나 칼을 끌어 놓음, 아무 위치나 허용 — 틀린 위치도 그대로 보인다), `expand {group}`, `select-digit {position}`, `place-card {cell, digit}`·`clear-cell {cell}`(reverse). 그림: 잘린 덩어리마다 색 + **무늬**(일 없음·만 점·억 빗금·조 격자, 색만으로 구분 금지)와 단위 이름표(일·만·억·조)를 오른쪽 덩어리부터 붙인다. 펼치면 그 덩어리 네 숫자 위에 "천·백·십·일" 칸 이름. reverse: 위에 "조·억·만·일" 4묶음 × "천·백·십·일" 16칸 표, 아래 숫자 카드 0~9(무한 공급). `spoken` 문구는 화면에 쓰지 않는다(소리 듣기는 활동 발문 TTS가 한다 — 앱 TTS는 `src/app`에 있어 엔진이 쓰지 않는다. `tts` 설정은 받지만 무시하고 메모에 core 요청 여부를 적는다). **읽는 말(“오천이백팔십사만”)을 엔진이 만들어 보여 주거나 읽어 주지 않는다**(과제 답이다).
6. **divide 모드:** 설정 `dividend`(정수 또는 interpretation decimal이면 소수 문자열), `divisor`(2~9), `plates`(기본 divisor), `interpretation`, `rewindCheck`(boolean, 기본 false), `linkColumnCalc`·`autoHighlightSteps`는 받지만 엔진은 쓰지 않는다(연결은 실행기, 강조는 E07 몫). 시작: dividend를 정규형 블록으로 위쪽 "무더기"에 놓는다. 블록에 `plate?: number`를 더한다(없으면 무더기). Action `deal-block {id, plate}`(블록을 접시로 끌기, 또는 블록 선택 + 접시 누르기), `return-block {id}`, `deal-round {value}`(버튼 "○ 한 바퀴": 무더기에 그 블록이 접시 수 이상 있을 때 접시마다 하나씩 — 모자라면 비활성), `break {id}`(기존 망치 — **무더기에 있는 블록만** 풀린다), `rewind`(아래 7번). 접시에 놓인 블록은 접시 안에서 자릿값별로 줄 맞춰 그린다(좌표는 reduce가 정함). 접시별 값·몫·나머지를 숫자로 쓰지 않는다.
7. **되감기(`rewindCheck`):** `rewindCheck: true`면 "되감기" 버튼이 보인다. `rewind`는 모든 접시 블록을 무더기로 돌려 한 무더기로 모으고(묶지는 않는다) `log`에 `{kind:'rewind'}`를 남긴다(`BaseTenLogEntry.kind`에 `'rewind'` 추가, `from`은 선택 필드로). CSS로 블록이 무더기로 날아드는 연출(reduced-motion이면 즉시). 엔진 `receive`: 이벤트 `rewind-requested`를 받으면 `{type:'rewind'}`를 돌려준다(E07이 T047에서 이 이름으로 낸다). 검산식 채우기는 E07·응답 위젯 몫이다.
8. **E07 연결 이벤트(모양 고정 — T047이 받는다):** divide에서 상태가 바뀔 때마다 `divide-progress { columns: { column, perPlate, pile }[], equal, pileValue }`를 낸다. `columns`는 높은 자리부터, `column`은 2번의 자릿값 지수, `perPlate`는 그 자리 블록이 **모든 접시에 같은 수로** 놓였을 때 그 수(아니면 null), `pile`은 무더기에 남은 그 자리 블록 수, `equal`은 모든 접시의 값이 같은지, `pileValue`는 무더기 값(whole number / decimal 소수 문자열). 기존 `grouped`·`broken`·`value-changed`도 그대로 낸다(divide의 `value`는 무더기 + 접시 전체 값이라 풀기·나누기로 바뀌지 않는다).
9. **Observation(새 모드):** big-number: `mode`, `digits`(value 문자열), `cuts`, `cutsCorrect`(cuts가 4·8·12 … 중 자릿수보다 작은 것 전부와 정확히 같음), `expanded`, `selectedPlace`(지수 또는 null), `built`(reverse에서 맨 앞 빈칸을 뺀 숫자 문자열, 가운데 빈칸이 있으면 null), `builtHasGap`. divide: `value`, `plateValues: (number | string)[]`, `plateCounts`(접시별 counts), `equal`, `pileValue`, `pileCounts`, `breaks`, `log`, `rewound`(rewind 뒤 true, 이후 deal이 있으면 false). decimal: 2번 규칙의 `value`·`counts`·`chartValue` 외에는 free와 같다.
10. **Predicates(추가):** `cutsAre {positions}`, `cutsCorrect`, `builtIs {value}`(문자열 비교), `selectedPlaceIs {exponent}`, `platesEqual`, `plateValueIs {value}`(모든 접시가 그 값 — Rational 비교), `pileValueIs {value}`(나머지 — Rational 비교), `rewound`. 기존 `brokeAtLeast {from, count}`는 decimal에서 from을 모양 값(1·10·100)으로 받는다고 명시하고 테스트한다.
11. **정답 노출 금지:** 나타내는 수·접시별 값·몫·나머지·읽는 말을 화면에 숫자나 글로 쓰지 않는다. big-number의 덩어리 단위 이름표(일·만·억·조)와 칸 이름(천·백·십·일)은 이름이라 괜찮다. 실패 배지 등 기존 규칙은 그대로.

- **카드와 다르게 한 부분(이유 포함):**
  1. **big-number 자르기 위치:** `52840000`은 8자리라 오른쪽에서 센 틈이 4 하나뿐이다(`8`은 자릿수 밖). 카드 테스트 문구의 "4·8자리"는 네 자리씩 끊는 규칙(4의 배수)을 뜻하는 것으로 보고 E2E는 위치 4만 확인한다. 16자리 값 `1234567890123456`은 `[4,8,12]`로 단위 테스트했다.
  2. **decimal `start.value` 정규형 범위:** 정수 부분은 한 자리(0~9)만 받는다(판 10개 이상은 정규형이 아님). 소수 셋째 자리 이상·음수·형식 오류는 카드대로 빈 판. 맨 앞 0(`"06.2"`)은 정규화해 받는다.
  3. **decimal 기본 자릿값 표:** 설정에 `chart`/`columns`가 없으면 `[0,-1,-2]`(1·0.1·0.01)를 기본으로 보여 준다. 다른 모드는 기존처럼 표가 없으면 그리지 않는다.
  4. **divide `perPlate`:** 카드 문구대로 "그 자리 블록이 모든 접시에 같은 수"이면 무더기에 남은 블록이 있어도 그 수를 낸다(예: 십 5개 중 4개를 한 바퀴 돌린 뒤 `perPlate: 1`, `pile: 1`).
  5. **divide 입력:** 끌기·키보드 1~9 외에 "블록을 골라 둔 채 접시를 톡 누르기"도 지원한다(카드 6번의 두 번째 방법). 접시에 놓인 블록은 풀리지 않고, 무더기 블록만 풀린다.
  6. **big-number `groupColors`:** 기본 이름 `gray/green/blue/purple`을 색으로 매핑하고, 그 밖의 문자열은 CSS 색으로 그대로 쓴다. `expand:false`면 펼치기 버튼을 숨긴다.
  7. **reverse `built`:** 카드 9번대로 맨 앞 빈칸을 뺀 문자열이고, 중간 빈칸이 있으면 `null`. 16칸 표의 왼쪽(조)부터 채워도 문자열 비교라 값 자체는 학생이 만든 숫자열이다(자리 이름표만 안내).
  8. **설정 수용만 하고 쓰지 않음:** `linkColumnCalc`, `autoHighlightSteps`, `tts`는 타입에만 받고 엔진은 쓰지 않는다(카드 5·6·14번). `spoken`은 화면·TTS 어디에도 쓰지 않는다.
- **E07/T047로 넘기는 것:** `receive`는 `rewind-requested`만 `{type:'rewind'}`로 바꾼다(divide에서만). E07 자릿값 칸 입력으로 블록을 움직이는 `receive`와 검산식 채우기는 카드 14번대로 T047 몫. `divide-progress` 모양은 카드 8번 그대로 고정했다.
- **core 변경 요청:** 없음. 소수 값·비교는 `src/core/math`의 `Rational`만 썼고 상태에는 `bigint`를 넣지 않았다(문자열·number 배열). 새 오버레이 3개(`empty-plate`, `four-digit-grid`, `plate-levels`)는 엔진 폴더 안에만 두었다.
- **상태 메모:** `bigNumber`·`divide`는 모든 모드에서 null 허용 필드로 두어 JSON 직렬화·되감기·미러링 계약을 유지했다. 기존 5개 모드의 Observation 키·이벤트 payload는 그대로이고, E01 기존 테스트 54개도 통과한다.
