# 08. 코딩 에이전트와 일하는 방법

Claude(Claude Code), Codex, OpenCode 세 에이전트를 함께 쓰는 운영 규칙이다. 핵심은 **한 번에 한 작업 카드, 서로 다른 폴더, 다른 에이전트가 리뷰**다.

## 1. 처음 한 번 준비 (Windows)
1. Node.js LTS, Git, VS Code 설치. GitHub 계정에 비공개 저장소 `MathExplorer` 생성.
2. **저장소 위치:** 경로에 한글·공백이 있으면 일부 개발 도구가 오작동할 수 있다. 가능하면 `C:\dev\MathExplorer`처럼 영문 경로에 두고, 바탕화면의 `수학 에듀테크` 폴더에는 바로가기를 둔다. (지금 문서는 `수학 에듀테크\MathExplorer`에 있으니 그대로 옮기면 된다.)
3. 이 폴더를 저장소 첫 커밋으로 올린다.
4. 첫 작업: 에이전트에게 `tasks/T001.md를 수행해 줘`.

## 2. 세 에이전트가 읽는 파일
- **Codex, OpenCode:** 저장소 루트의 `AGENTS.md`를 자동으로 읽는다.
- **Claude Code:** `CLAUDE.md`를 읽는다. 이 저장소의 `CLAUDE.md`는 `AGENTS.md`를 따르라고만 적혀 있다 → 규칙은 `AGENTS.md` 한 곳에서만 고친다.

## 3. 작업 흐름

```
작업 카드 고르기 (tasks/Txxx.md, 상태 todo)
   ↓
에이전트 A에게 맡김: 새 브랜치 task/Txxx 에서 작업
   ↓
에이전트 A가 끝나면: 테스트 통과 + 카드의 '완료 확인' 체크 + PR(또는 브랜치) 
   ↓
에이전트 B에게 리뷰 요청 (A와 다른 에이전트)
   ↓
선생님이 직접 실행해서 확인 (npm run dev → 태블릿으로 접속)
   ↓
main에 합치기, 카드 상태 done
```

### 동시에 여러 에이전트를 돌릴 때
- **서로 다른 엔진 폴더**를 맡기면 동시에 돌려도 충돌이 거의 없다. 예: Codex는 `E05`, OpenCode는 `E03`.
- `src/core/`와 `data/units.json`은 **한 번에 한 에이전트만** 고친다. 엔진 작업 중 core 변경이 필요하면 에이전트가 직접 고치지 말고 작업 카드에 "core 변경 요청"을 적게 한다 → 선생님이 별도 카드로 처리.
- 각 에이전트는 별도 브랜치(가능하면 git worktree)에서 작업한다.

### 역할 나누기 (제안 — 써 보면서 바꿔도 된다)
| 작업 종류 | 맡길 에이전트 | 리뷰 |
| --- | --- | --- |
| core(수학 코어, SDK, 실행기, 지식 그래프) | 가장 신뢰하는 에이전트 하나로 고정 | 다른 에이전트 |
| 엔진 구현 | 세 에이전트가 나눠서 병렬 | 다른 에이전트 |
| 단원 콘텐츠 JSON(과제·힌트) | 아무나 — 명세를 옮기는 작업 | 선생님이 수학적으로 확인 |
| 테스트 보강·버그 수정 | 아무나 | — |

## 4. 에이전트에게 줄 말 (복사해서 사용)

**작업 시작**
```
tasks/T0xx.md 작업 카드를 수행해 줘.
AGENTS.md 규칙을 지키고, 카드의 '건드리지 말 것'에 있는 파일은 수정하지 마.
끝나면 npm test와 npm run test:e2e를 돌려서 통과한 결과를 보여 주고,
카드의 '완료 확인' 항목을 하나씩 체크한 결과를 알려 줘.
```

**리뷰 요청 (다른 에이전트에게)**
```
브랜치 task/T0xx 의 변경을 리뷰해 줘. 기준:
1) 작업 카드 tasks/T0xx 의 요구사항을 모두 만족하는가
2) AGENTS.md 규칙(엔진 간 import 금지, 부동소수 금지, 정답 노출 금지 등) 위반이 있는가
3) 테스트가 실제로 동작을 검증하는가(항상 통과하는 테스트는 아닌가)
4) 아이패드 Safari에서 문제가 될 API를 썼는가
수정은 하지 말고 문제 목록만 심각도 순으로 알려 줘.
```

**단원 콘텐츠 만들기**
```
docs/04-units/g5s1.md 의 g5s1u4 명세를 보고 data/content/g5s1u4.json 을 만들어 줘.
과제마다 E2E 테스트(정답 조작 통과, 대표 오답 → 힌트 ①)도 tests/e2e/units/g5s1u4.spec.ts 에 추가해 줘.
```

**명세가 이상할 때**
에이전트가 "명세대로는 구현이 어렵다"고 하면, 억지로 진행시키지 말고 이유를 들은 뒤 `docs/`를 먼저 고치게 한다. 명세와 코드가 어긋나기 시작하면 다음 에이전트가 헷갈린다.

## 5. 선생님만 할 수 있는 일
- 수학적으로 맞는지, 발문이 아이 눈높이인지 확인
- 실제 태블릿에서 손으로 조작해 보기(특히 1~2학년 터치)
- 단원 켜기 순서(내 수업 진도) 결정
- 학교 개인정보·소프트웨어 사용 절차 확인(`09-privacy-safety.md`)

## 6. 비용
- 세 에이전트의 구독·사용 요금은 앱 운영 예산(무료)과 별개다. 앱 자체는 정적 호스팅 + (2단계) Supabase 무료 플랜으로 운영비 0원을 목표로 한다.
