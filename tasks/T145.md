E12에 확장 모드 `surface-volume`을 더한다.
- **g6s1u6.A1 단계형 화면:**
  - 직육면체를 돌려 본다.

### 0. 명세와 다르게 하는 곳(정답 노출 금지)
- 명세의 "칠한 넓이가 누적"은 넓이 수를 화면에 보이는 것이다. 그렇게 하지 않는다.
  - 대신 칠한 면에 1cm 칸 격자를 그린다. 학생이 칸을 세거나 곱해서 넓이를 구하게 한다.
- A2 "겉넓이를 기록표에 모은다"의 겉넓이 수는 학생이 적는다. 엔진이 계산한 값은 관찰에만 둔다.
- 쌓기나무를 채울 때 "몇 개 쌓았어요" 같은 개수도 쓰지 않는다.
- 겉넓이 식·부피 식 입력(명세 ④·⑥ 단계)은 엔진이 아니라 콘텐츠의 응답 칸이 맡는다.
  - 설정 `steps`에 `surface-expr`·`volume-expr`가 있으면 받기만 하고 무시한다(경고 없음).
- docs는 Opus가 main에서 고친다.

### 1. 모드 유니온·파일
- `SolidMode`에 `'surface-volume'`을 더한다. 나누는 방식은 T142와 같다.
```
src/engines/E12-solid-3d/
  sv/geometry.ts   # 상자 면 넓이·전개도 배치·겉넓이·약수 조합(정수)
  sv/reduce.ts, sv/observe.ts, sv/predicates.ts
  views/SurfaceVolumeView.tsx, views/SvBoxStage.tsx, views/SvNetPaint.tsx, views/SvFillStage.tsx, views/SvBoxLog.tsx
  overlays/unpainted-blink.tsx, overlays/wrap-vs-fill.tsx, overlays/unit-zoom.tsx, overlays/wraps-compare.tsx
  __tests__/sv-geometry.test.ts, sv-engine.test.ts, sv-view.test.tsx
tests/e2e/solid-3d-sv.spec.ts
```
- 치수·넓이·부피는 정수다. 단위는 cm이고 1~10이다.

### 2. 설정 `SurfaceVolumeConfig`
| 키 | 형 | 기본 | 뜻 |
| --- | --- | --- | --- |
| `mode` | `'surface-volume'` | — | 필수 |
| `variant` | `'steps' \| 'fixed-volume'` | `'steps'` | |
| `solid` | `{w, d, h}` | `{4,3,2}` | 1~6 정수(steps). 정육면체는 세 값을 같게 준다 |
| `steps` | `('rotate'\|'unfold'\|'paint'\|'fill-voxels')[]` | 네 개 모두 | 단계 표시줄에 놓일 단계와 순서. `'unfold'`와 `'paint'`는 같은 전개도 화면이다. `'unfold'`만 있으면 칠하기 도구를 숨긴다 |
| `startStep` | 단계 이름 | `steps[0]` | |
| `layerFill` | boolean | true | "한 층 채우기" 단추 |
| `pairColors` | boolean | true | 칠할 때 마주 보는 면 쌍에 같은 색과 무늬를 제안한다(칠하기 단추 색만) |
| `volume` | 정수 2~64 | 24 | fixed-volume의 부피 |
| `log` | boolean | true | fixed-volume 기록표 |

- 받기만 하고 무시하는 키: `stage`, `fallback`, 그리고 `steps` 안의 `surface-expr`·`volume-expr`.
- 범위 밖 값은 자르고 `console.warn`한다.

### 3. 상자와 전개도 (`sv/geometry.ts`)
- 면 이름은 xray와 같다: `front`, `back`, `left`, `right`, `top`, `bottom`.
- 면 크기:
  - `front`/`back`: w×h
  - `left`/`right`: d×h
  - `top`/`bottom`: w×d
- 전개도는 십자형 고정 배치다(칸 좌표).
  - `front`를 가운데에 두고, 위에 `top`, 아래에 `bottom`, 그 아래에 `back`(뒤집힘)을 둔다.
  - 왼쪽에 `left`, 오른쪽에 `right`를 둔다.
  - 면마다 1cm 칸 격자를 그린다.
- `surfaceArea(w,d,h)`는 `2(wd+wh+dh)`, `volume(w,d,h)`는 `wdh`다.
- `boxesOfVolume(V)`: w ≤ d ≤ h인 정수 조합 목록이다(정렬). 예: 24 → 1×1×24, 1×2×12, 1×3×8, 1×4×6, 2×2×6, 2×3×4.
  - `minSurfaceBox(V)`는 겉넓이가 가장 작은 조합이다(같으면 목록 앞쪽).
- 기록에서 같은 상자인지는 세 수를 정렬해서 비교한다(2×3×4 = 4×3×2).

### 4. 상태·Action
```ts
SurfaceVolumeState = {
  mode: 'surface-volume'; settings;
  step: string;                                   // 지금 단계
  view: { yaw; pitch };                           // rotate 단계(T139 규칙)
  unfolded: boolean;                              // 전개도 화면에서 펼친 그림(true)인지 접힌 상자(false)인지
  painted: FaceId[];                              // 칠한 면(고정 순서)
  filled: [x, y, z][];                            // 채운 쌓기나무(정렬)
  layer: number;                                  // 지금 채우는 층(0부터)
  dims: [w, d, h];                                // fixed-volume에서 고른 상자
  logRows: { w; d; h; surface: number | null }[]; // fixed-volume 기록
}
```
| Action | 동작 |
| --- | --- |
| `{type:'go-step', step}` | `steps`에 있는 단계일 때만. 단계는 자유롭게 오갈 수 있다 |
| `set-view`·`rotate-view` | T139와 같다 |
| `{type:'toggle-unfold'}` | 전개도 단계에서만 |
| `{type:'paint-face', face}` | `paint` 단계이고 펼쳐 있을 때 칠하기와 지우기를 오간다 |
| `{type:'clear-paint'}` | |
| `{type:'place-cube', x, y}` | 지금 층의 빈 칸에. 아래층 같은 칸이 비어 있으면 무시한다(공중 금지) |
| `{type:'remove-cube', x, y}` | 지금 층의 칸에서. 위층 같은 칸이 차 있으면 무시한다 |
| `{type:'fill-layer'}` | `layerFill`일 때 지금 층을 모두 채운다. 아래층이 다 차 있어야 한다 |
| `{type:'set-layer', layer}` | 0..h−1 |
| `{type:'clear-cubes'}` | |
| `{type:'set-dims', w, d}` | fixed-volume에서 w가 V의 약수, d가 V/w의 약수일 때. h는 V/(w·d)이고 1..64다. 맞지 않으면 무시한다 |
| `{type:'add-log-row'}` | 지금 상자가 기록에 없을 때(정렬 비교) 빈 겉넓이로 더한다. 12줄까지 |
| `{type:'set-log-surface', row, value}` | 0~9999 정수 또는 null |
| `{type:'remove-log-row', row}` | |

- 상태는 JSON 직렬화가 되어야 한다.

### 5. 화면 `SurfaceVolumeView`
- **단계 표시줄**(steps):
  - 위쪽에 단계 칸을 둔다. 칸마다 번호와 짧은 이름을 쓴다(돌려 보기, 펼쳐 칠하기, 쌓기나무 채우기).
  - 칸을 누르면 그 단계로 간다. 지금 단계는 `aria-current="step"`과 굵은 테두리로 표시한다.
  - 칸 크기는 48px 이상이다.
- **rotate:**
  - `SvBoxStage`는 w×d×h 상자를 정사영으로 그린다. 투영은 `prism/geometry.ts`나 `xray/geometry.ts`의 함수를 import해서 쓰고, 그 파일은 고치지 않는다.
  - 면에 1cm 칸 격자를 옅게 그린다. 돌리기 단추와 끌기는 T139와 같다.
  - 모서리 길이 글자("4cm" 등)를 세 모서리에 붙인다. 치수는 문제 조건이라 정답 노출이 아니다.
- **unfold/paint:**
  - `SvNetPaint`는 3번 전개도를 그린다. "펼치기/접기" 단추를 둔다. 접으면 rotate 그림과 같은 상자, 펼치면 전개도다. 바뀔 때 400ms 애니메이션을 하고, `prefers-reduced-motion`이면 바로 바꾼다.
  - 칠하기 단계에서 면을 누르면 칠한다.
    - 칠한 면은 색과 빗금 무늬를 함께 쓴다.
    - `pairColors`면 마주 보는 쌍마다 색과 무늬가 같다(앞뒤 파랑 점, 좌우 주황 줄, 위아래 초록 격자).
    - 칠하지 않은 면은 흰 바탕에 격자만 있다.
  - 칠한 넓이 수는 쓰지 않는다.
- **fill-voxels (`SvFillStage`):**
  - w×d×h 투명 상자(점선 테두리)를 등각으로 그리고 채운 쌓기나무를 그린다. 그리기는 `IsoStage`와 같은 등각 규칙을 쓰되 이 모드 전용 컴포넌트로 만든다.
  - 지금 층의 바닥 칸(마름모)을 누르면 놓고, 놓인 칸을 누르면 뺀다.
  - 옆에 층 고르기(▲▼와 "1층"…)를 둔다. "한 층 채우기"·"모두 비우기" 단추를 둔다.
  - 개수는 쓰지 않는다.
- **fixed-volume:**
  - 왼쪽에 지금 상자를 1cm 쌓기나무로 쌓은 등각 그림을 그린다.
  - 오른쪽에 가로 고르기(V의 약수 단추들)와 세로 고르기(V/w의 약수 단추들)를 둔다. 높이는 계산되어 "높이 4cm"로 보인다. 치수는 학생이 고른 값이라 정답 노출이 아니다.
  - 아래에 기록표 `SvBoxLog`(T142 카운터 표와 같은 규칙)를 둔다.
    - 열: 가로 | 세로 | 높이 | 겉넓이(학생 입력) | ✕
    - "기록하기" 단추로 줄을 더한다. 맞음·틀림 표시는 없다.
- **배치:** T142와 같은 `.stageRow`/`.sideStack` 규칙을 쓰고 판에 `data-mode="surface-volume"`을 단다.
  - 크롬북 `?stage=fit`에서 각 단계의 무대, 주요 단추, 표 첫 줄이 `ratio:1`이어야 한다.
- **키보드:**
  - 1~4: 단계로 가기
  - Q/E/W/S: 돌리기
  - U: 펼치기·접기
  - 전개도 면과 바닥 칸: Tab + Enter
  - PageUp·PageDown: 층
  - L: 한 층 채우기
- **test id:** `sv-step-{step}`, `sv-box-stage`, `sv-unfold`, `sv-face-{id}`(`data-painted`), `sv-clear-paint`, `sv-fill-stage`, `sv-cell-{x}-{y}`, `sv-layer-up`/`down`, `sv-fill-layer`, `sv-clear-cubes`, `sv-w-{n}`, `sv-d-{n}`, `sv-log`, `sv-log-add`, `sv-log-cell-{i}`, `sv-log-remove-{i}`
- 문구는 `strings.ko.ts`의 `solid3dStrings.sv`에 둔다.

### 6. Observation(`surface-volume`)
```
mode:'surface-volume', variant, solid:{w,d,h}, step, unfolded,
painted:[...], paintedCount, paintedArea, allPainted, surfaceArea,          // 넓이 값은 판정용(화면에 안 씀)
cubeCount, fullLayers, complete, volume,
dims:[w,d,h], logRows:[{w,d,h,surface}], logDistinct, logCorrect:[bool], minSurfaceLogged
```
- `fullLayers`는 아래부터 가득 찬 층 수다.
- `complete`는 `cubeCount = w·d·h`일 때다.
- `minSurfaceLogged`는 `minSurfaceBox(V)`가 기록에 있고 그 줄의 겉넓이가 맞을 때다.

### 8. 오버레이(힌트 ②, `NetHelperBox` 상자, 숫자 결과를 쓰지 않음)
- **`unpainted-blink`** (MC-SURFACE-3-FACES):
  - 전개도를 작게 그리고, 칠하지 않은 면을 주황 테두리로 0.8초마다 깜빡인다.
  - `prefers-reduced-motion`이면 굵은 테두리로 고정한다.
  - 문구: "전개도에서 아직 세지 않은 면이 있을까요?"
- **`wrap-vs-fill`** (MC-VOLUME-SURFACE-CONFUSION):
  - 왼쪽에 포장지로 겉만 감싼 상자(면 테두리만, 빗금), 오른쪽에 쌓기나무로 속을 채운 상자를 그린다.
  - 문구: "상자를 감싸는 양일까요, 채우는 양일까요?"
- **`unit-zoom`** (MC-VOLUME-UNIT-CONVERT-100):
  - 세 칸을 그린다.
    - 1cm³ 쌓기나무 한 줄(1m 막대)
    - 그 줄을 쌓은 한 층(정사각형 판)
    - 층을 쌓은 큰 정육면체
  - 막대에는 "1m = 100cm" 길이 표시만 쓴다. 개수 결과는 쓰지 않는다.
  - 문구: "한 줄에 몇 개, 한 층에는 몇 줄, 몇 층일까요?"
- **`wraps-compare`** (MC-PERIMETER-AREA-SAME):
  - fixed-volume에서 1×1×V 상자와 `minSurfaceBox(V)` 상자의 전개도를 1cm 격자와 함께 나란히 그린다. 넓이 수는 쓰지 않는다.
  - 문구: "두 상자의 포장지 크기를 칸으로 비교해 볼까요?"
- 네 오버레이를 `index.ts`의 `overlays`에 등록하고 단위 테스트(그림/안 그림)를 둔다.

### 10. 덧붙임: 각기둥 전개도 카드만 보기 폭(T144 메모 엔진 수정 요청 1)
- `prismnet` 카드만 보기의 큰 카드 3장이 크롬북 두 칸 배치 판(약 637px)에서 한 줄에 들어가지 않는다. 카드 폭 207px × 3이 판 폭보다 넓어 '다' 카드가 아래 줄로 내려간다.
- 카드 3장 이하이면 판 폭에 맞춰 카드 칸 크기를 줄여 한 줄에 놓는다. 칸 크기는 `min(지금 값, (판 폭 − 간격) / 3에 맞는 값)`이다.
