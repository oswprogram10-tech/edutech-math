## 구현 결정 (2026-11-05 Claude 작성 — 여기 적힌 대로 하고, 바꿔야 하면 메모에 이유를 적고 질문한다)
1. **폴더·파일:** `src/engines/E07-column-calc/`만 고친다. 새 파일은 `grid-decimal.ts`(소수 곱셈의 자리 계산·결과 읽기·어림 비율 신호, 순수 함수), `classify-decimal.ts`, `views/ShiftDemo.tsx`(+ `ShiftDemo.module.css`), `views/EstimateBox.tsx`(소수 어림 입력 상자), `overlays/point-estimate.tsx`, `overlays/align-compare.tsx`. `View.tsx`는 `state.op === 'mul'`이면(모드가 `mul`이든 `decimal`이든) `MulView`를 고른다. 기존 add·sub·decimal(add/sub)·mul·estimate·div의 동작·Observation·이벤트는 바꾸지 않는다. 새 Observation 키는 소수 곱셈이 아니면 null이다.
2. **설정:** `{ "mode": "decimal", "op": "mul", "a": "2.4", "b": "1.3", "requireEstimate": true, "shiftDemo": { "value": "3.75", "ops": ["×10", "×100", "×0.1", "×0.01"] } }`(명세 예시 그대로). 아래에서 "소수 곱셈"은 `state.mode === 'decimal' && state.op === 'mul'`을 뜻한다.
   - a: 숫자(소수점 뺀) 1~4개, b: 1~3개, 각각 소수 자리 0~3. 둘 다 자연수여도 된다. 범위 밖이면 `DEFAULT_NUMBERS.decimalMul = { a: '2.4', b: '1.3' }`으로 고친다.
   - 곱셈 방식은 `carry`로 고정한다(`style`·`partial-products`·`debugSample`·`showZeroPlaceholder`는 소수 곱셈에서 무시).
   - 새 상태 필드: `resultPoint: number | null`, `requireEstimate: boolean`, `placeCards: boolean`, `shiftBase: string | null`(시프트 데모의 처음 값), `shiftOps: readonly ShiftOp[]`, `shiftExponent: number`, `shiftHistory: readonly ShiftOp[]`, `shiftHideGrid: boolean`. `ShiftOp = '×10' | '×100' | '×1000' | '×0.1' | '×0.01' | '×0.001'`을 types.ts에 둔다. 다른 모드에서는 null·false·빈 배열·0.
3. **격자 = 자연수 곱셈 격자:** 소수 곱셈의 격자는 소수점을 뺀 숫자열(`"24"`, `"13"`)을 자연수로 보고 T046 mul(`carry`)과 똑같이 만든다. `computeMulPlan`은 소수 곱셈일 때 `parseNumber(...).digits`를 정수로 쓰도록 넓힌다(지금은 소수 자리가 있으면 null을 돌려준다). 열은 **숫자열의 오른쪽부터 센 자리 번호**(0 = 맨 오른쪽 숫자)다. 부분곱 줄·받아올림·결과 줄·커서 순서는 T046 그대로다.
   - a·b는 오른쪽 끝을 맞춰 놓고, 각 수의 소수점은 그 수의 숫자 사이에 점 모양으로 그린다(칸이 아니다).
   - 결과 줄 칸은 열 0 … max(T046의 결과 줄 최고 열, aFrac + bFrac)까지 연다. 0.25 × 0.4처럼 앞에 0을 써야 하는 경우를 위해서다(열 0~3). 이 값은 문제의 두 수에서 나오며 정답이 아니다.
4. **결과 소수점 놓기:** Action `{ type: 'place-point', target: 'result', column: number | null }`. `column`은 결과 줄에서 **일의 자리가 되는 칸**이고, 점은 그 칸 오른쪽에 그린다. 0 … 결과 줄 최고 열만 받는다. null은 지우기다. 상태 `resultPoint`.
   - 화면: 결과 줄 바로 아래에 "점 놓기" 줄을 두고 결과 칸마다 점 버튼을 하나씩 둔다(칸 사이에 넣으면 48px 타깃이 안 나온다). 놓은 점은 결과 줄 칸 사이에 큰 점으로 그린다. 같은 버튼을 다시 누르면 지운다.
   - 키보드: 결과 칸이 선택된 상태에서 `.`을 누르면 그 칸 오른쪽에 점을 놓는다(이미 그 자리에 있으면 지운다).
   - `requireEstimate`이고 어림값을 아직 정하지 않았으면(`phase === 'estimate'`) `place-point`는 상태를 바꾸지 않는다. 점 버튼은 비활성으로 보이고 그 옆에 `strings.estimateFirst`("소수점을 놓기 전에 어림값을 먼저 써요")를 보인다.
   - **결과 읽기(`readDecimalResult` in grid-decimal.ts):** 결과 숫자는 T046처럼 가장 높은 채운 칸부터 열 0까지 읽는다(중간 빈칸이 있으면 미완성). 이 정수를 N, 점을 p라 하면 값 = N / 10^p다. p가 가장 높은 채운 칸보다 높으면 그 사이 칸(최고 채운 칸+1 … p)도 채워져 있어야 완성이다(0.100은 열 3에 0을 써야 한다). 점이 없으면 p = 0으로 읽는다.
   - **완성(`complete`):** 부분곱 줄 완성(T046 `rowsComplete`) + 결과 줄 완성 + (aFrac + bFrac = 0이거나 점을 놓음).
   - Observation: `result` = 완성일 때 값의 Rational 정규 문자열(3.12 → `"78/25"`), `resultRaw` = 칸 그대로 + 점 자리에 `.`, `resultPoint`, `pointPlaced: boolean`.
5. **requireEstimate(기본 false):** 켜면 `phase`가 `'estimate'`로 시작한다. 부분곱·결과 숫자 칸은 두 단계 모두에서 쓸 수 있고, 막는 것은 4번의 점 놓기뿐이다.
   - 어림 입력은 `views/EstimateBox.tsx`: 격자 위 작은 상자 + 키패드(0~9, `.`, 지우기, "정하기"). 기존 `enter-estimate {digit}`를 넓혀 소수 곱셈에서는 `'.'`도 받는다. 소수 곱셈 어림값 형식은 `^\d{1,4}(\.\d{1,3})?$`(점은 하나만). 기존 estimate 모드의 숫자 전용 규칙(`estimateDigits`)은 바꾸지 말고, 소수 곱셈용 `decimalEstimate(state): Rational | null`을 grid-decimal.ts에 따로 둔다.
   - `lock-estimate`는 어림값이 형식에 맞고 0보다 클 때만 `phase: 'calc'`로 바꾼다. `unlock-estimate`는 언제든 되고, 놓은 점은 그대로 둔다.
   - **신호등(소수 곱셈 전용, `decimalSignal`):** 완성 + 어림값을 정했을 때만 낸다. r = 결과 ÷ 어림값(Rational). 1/2 ≤ r ≤ 2면 `green`, 1/5 ≤ r ≤ 5(초록 제외)면 `yellow`, 그 밖(결과 0 포함)은 `red`. 소수점이 한 자리 틀리면(10배) 항상 빨강이 된다. 한계값은 설정으로 받지 않는다(`tolerance`는 소수 곱셈에서 무시). 화면은 기존 estimate의 신호등 모양(색 + 모양 + 글자)을 재사용한다.
   - Observation `phase`, `estimate`(학생이 쓴 문자열), `signal`. 이벤트 `estimate-locked`, `signal-changed`를 그대로 낸다. `estimateIs`는 소수 어림값도 Rational로 비교하도록 넓힌다(기존 정수 비교 결과는 그대로).
6. **shiftDemo(`{ value, ops, hideGrid? }`):** `views/ShiftDemo.tsx`. value는 숫자 6개 이하, 소수 자리 3 이하. ops는 `ShiftOp` 목록(모르는 값은 버린다).
   - 자릿값 기둥 8개(천·백·십·일 | 소수 첫째·둘째·셋째·넷째 — 3.75 × 0.01 = 0.0375까지 들어간다)를 고정해 그리고, 일과 소수 첫째 사이에 소수점을 고정 표시한다. value의 숫자들이 카드로 기둥에 꽂혀 있다.
   - ops마다 버튼("×10" 등). 누르면 Action `{ type: 'shift', op }` → `shiftExponent += k`(×10 = +1, ×100 = +2, ×1000 = +3, ×0.1 = −1 …), `shiftHistory`에 op를 붙인다. 숫자 카드가 기둥을 따라 미끄러진다(CSS transform transition, `prefers-reduced-motion`이면 즉시). **소수점은 움직이지 않는다.**
   - 숫자 카드가 기둥 8개 밖으로 나가게 되는 op는 버튼을 비활성으로 하고 reduce도 무시한다. "처음으로" 버튼 = Action `{ type: 'shift-reset' }`(exponent 0, history는 유지).
   - 빈 기둥에 0 카드를 자동으로 만들지 않는다(빈 기둥은 점선 칸). 값은 기둥 속 카드로만 보이고 별도의 숫자 글자("37.5")로 쓰지 않는다. aria-label은 기둥 이름과 그 안 카드 숫자만 읽는다.
   - CPA: C·P에서 보이고 A에서는 숨긴다. `hideGrid: true`면 곱셈 격자·어림 상자를 숨기고 시프트 데모만 보인다(명세 과제 1용).
   - Observation `shiftValue` = value × 10^exponent의 Rational 정규 문자열(데모가 없으면 null), `shiftHistory`. 이벤트 `shifted {op, value}`. Predicates `shiftValueIs {value}`(Rational 비교), `shiftUsed {op}`.
   - 데모는 결과를 보여 주는 조작 도구다. 예측 판정은 콘텐츠가 응답 위젯으로 **누르기 전에** 받는다(T071이 정한다). 이 내용을 카드 메모에 남긴다.
7. **placeCards(기본 false) — MC-DEC-MULT-ALIGN-POINT 관찰용:** false면 a·b가 오른쪽 끝을 맞춘 채 시작한다. true면 a는 놓인 채, b 카드는 놓이지 않은 채 시작하고, 학생이 기존 decimal의 `place {number:'b', pointColumn}` Action·끌기·키보드로 놓는다. 곱셈 정렬 판정은 새 함수 `mulAlignment(state)`로 한다(기존 `alignmentOf`는 add/sub용으로 그대로 둔다).
   - `'right-edge'`(두 수의 맨 오른쪽 숫자가 같은 열) = 바른 정렬, `'point'`(두 소수점이 같은 열이고 오른쪽 끝은 다름) = 오개념, `'other'`.
   - 바른 정렬 전에는 부분곱·결과 칸을 닫는다(누르면 아무 일 없음). `magnetAlign`은 소수 곱셈에서 오른쪽 끝 맞춤으로 끌어당긴다.
   - Observation `aligned`(= right-edge), `alignment`. `'point'`이면 오류 목록에 `MC-DEC-MULT-ALIGN-POINT`. 두 수의 소수 자리 수가 같으면 point와 right-edge가 같은 자리이므로 right-edge로 본다.
8. **오류 분류(`classify-decimal.ts`, `MisconceptionCode`에 `'MC-DEC-POINT-PLACEMENT' | 'MC-DEC-MULT-ALIGN-POINT'` 추가):** 순서대로 검사하고 모든 일치를 기록한다.
   - `MC-DEC-MULT-ALIGN-POINT`: 7번 조건.
   - 숫자 칸 오류는 기존 `classifyMul`을 숫자열 격자에 그대로 돌린다(코드도 그대로).
   - `MC-DEC-POINT-PLACEMENT`: 결과가 완성되었고, 결과 숫자 N(앞의 0 무시)이 숫자열 곱(a.digits × b.digits)과 같은데 p ≠ aFrac + bFrac. 오류의 열은 `resultPoint ?? 0`.
   - 기대 소수점 위치는 화면·Observation에 내보내지 않는다(misconceptions 코드만).
9. **오버레이(힌트 ②):**
   - `point-estimate`(MC-DEC-POINT-PLACEMENT): 작은 수직선에 학생 어림값과 학생 결과를 함께 찍고 둘 사이를 괄호로 잇는다. 눈금은 0과 두 값 중 큰 값의 1.2배까지. 어림값이 없으면 결과만 찍고 "어림값을 써 보면 비교할 수 있어요"를 보인다. 학생 값만 쓴다.
   - `align-compare`(MC-DEC-MULT-ALIGN-POINT): 두 정렬(소수점 맞춤 / 오른쪽 끝 맞춤)을 나란히 숫자 카드 배치 모양으로만 보인다. 결과값은 계산해 보이지 않는다.
10. **Observation 새 키(소수 곱셈이 아니면 null):** `resultPoint`, `pointPlaced`, `requireEstimate`, `shiftValue`, `shiftHistory`. 기존 `partials`·`expectedRowCount`·`rowsComplete`·`flaggedCells`·`style`도 소수 곱셈에서 mul처럼 채운다. `phase`·`estimate`·`signal`은 소수 곱셈에서도 채운다.
11. **Predicates 추가:** `pointPlaced`, `shiftValueIs {value}`, `shiftUsed {op}`. 기존 `resultIs`·`complete`·`noErrors`·`hasMisconception`·`signalIs`·`estimateIs`·`partialsAre`는 소수 곱셈에서도 동작해야 한다.
12. **이벤트 추가:** `point-placed {target, column}`, `shifted {op, value}`. index.ts `events` 목록에 넣는다.
13. **정답 노출 금지:** 곱·소수점 위치·소수 자리 수 합을 DOM 텍스트·aria-label·title·data-*에 쓰지 않는다. 안내 문구에 "소수 자리 수를 더해요" 같은 규칙을 쓰지 않는다. View 테스트: 2.4 × 1.3, 0.25 × 0.4 시작 화면에 `3.12`·`312`·`0.1`·`0.100`·`100`이 없음. 시프트 데모 3.75는 누르기 전 `37.5`·`375`·`0.375`가 없음.

16. **테스트:**
