**1. E07 틀린 칸 버튼은 debug 과제에서만**
- `state.hasDebugSample`(이미 `reduce.ts` 268줄 `baseState`에 있음, div·mul 공통)이 true일 때만 DivView·MulView의 표시 버튼 줄(`divStyles.footer` 안 버튼, `mulStyles.flagRow`)을 그린다. Div의 `footer`에 있는 되감기 버튼은 그대로 둔다.
- F 키 처리도 `hasDebugSample`일 때만 `toggleFlag`를 부른다. 아니면 그 키를 무시한다(다른 처리로 넘기지 않음).
- `reduce`의 `flag-cell` 처리와 `flaggedCell` 판정은 바꾸지 않는다(단위 테스트 그대로).
- `flagSkippedZero`(몫 칸 빈자리 표시, Div 446줄)는 다른 기능이니 건드리지 않는다.
- E2E(`tests/e2e/column-calc.spec.ts`에 추가): `#/sandbox/E07` 또는 단원 과제에서 ① 일반 나눗셈(g4s1u3.A1.T1)과 일반 곱셈(g4s1u3.A2.T1)에는 표시 버튼이 없고 F 키를 눌러도 `data-flagged="true"` 칸이 생기지 않는다. ② debug 과제(g4s1u3.A2.T3)에는 버튼이 있다.

**2. E04 오버레이를 `CanvasAlignedOverlay`로**
- `overlays/` 8개(fold-diagonal, known-fact, leftover-strip, missing-strip, overlap-count, ribbon-cut, row-count, slot-mismatch)의 바깥 `<svg …>`를 `CanvasAlignedOverlay`(`canvasSelector={'svg[data-testid="array-canvas"]'}`, `logicalWidth={LOGICAL_WIDTH}`, `logicalHeight={LOGICAL_HEIGHT}` — `types.ts`)로 바꾼다. 안의 도형 좌표는 그대로다. `<defs>`(빗금 pattern)는 `CanvasAlignedOverlay`의 children 안에 그대로 넣는다. `overlap-count`처럼 svg가 둘이면 둘 다 바꾼다.
- `View.module.css` `.canvas`의 `min-height`를 `160px`로 한다(T081과 같음).
- E2E(`tests/e2e/array-area.spec.ts`): 크롬북 뷰포트에서 g2s2u2의 `overlap-count`가 나오는 과제 하나와 g5s1u2.A1 T3(`leftover-strip`, 남는 칸이 생기는 크기를 기록한 상태)를 두 번 틀려 힌트 ②를 열고, 오버레이 svg와 `array-canvas`의 `getBoundingClientRect`가 2px 안에서 같은지 본다. `missing-strip`은 `#/sandbox/E04`처럼 오버레이를 직접 띄울 수 있는 곳이 있으면 같은 방식으로 보고, 없으면 단위 수준 확인만 하고 메모에 적는다.
- g3s2u1의 ② `say`를 `missing-strip`으로 되돌리는 일은 콘텐츠 변경이라 이 카드에서 하지 않는다(메모에 후속으로 적는다).

**3. E04 약수 선반을 HTML로**
- `shelf: true`이면 약수 선반을 svg 밖, 캔버스 오른쪽(가로 공간이 넉넉하면) 또는 아래에 HTML `<section data-testid="factor-shelf" aria-label="약수 선반">`으로 그린다. 제목 `S.shelf`, 비었을 때 `S.shelfEmpty`, 기록마다 `<li>`에 `S.shelfRecorded(rows, cols)`. 글자는 CSS px로 최소 16px(제목 18px).
- 기록마다 작은 점 그림은 넣어도 되고 빼도 된다. 넣으면 작은 인라인 svg(높이 32px 이하, `aria-hidden`)로 둔다.
- svg 안의 기존 선반(`<g data-testid="factor-shelf">`)은 지운다. 캔버스 오른쪽 790~960 자리가 비면 점 배열을 그 자리까지 넓히지 않아도 된다(배열 배치는 바꾸지 않는다).
- 터치 타깃은 없다(선반은 보기만). 기록 지우기는 지금처럼 실행기 `되돌리기`.
- E2E: 크롬북에서 g5s1u2.A1 T1에서 배열 하나를 기록한 뒤 `factor-shelf` 안 기록 글자의 computed `font-size`가 16px 이상이고, 선반이 화면 안(뷰포트 안)에 보인다. `tests/e2e/units/g5s1u2.spec.ts`가 svg 선반을 찾던 곳이 있으면 맞춘다.

**4. E03 log-zoom 확대 띠**
- `views/LogZoomView.tsx`에서, 뛰어 센 점이 하나 이상 있고 한 번 뛰기의 화면 폭(`|xOf(start + step) − xOf(start)|`)이 `MIN_STEP_LABEL_WIDTH`보다 작으면, 본 수직선 아래(논리 y 약 500~570, 눈금 이름표 `LINE_Y + 54`와 겹치지 않게)에 **확대 띠**를 그린다.
  - 띠의 범위는 `[start, start + n × step]`, n = max(10, 뛴 횟수). 값 계산은 모두 `Rational`.
  - 띠는 가는 수직선 하나, 양 끝 눈금, 그리고 step마다 작은 눈금이다. **이름표는 왼쪽 끝(시작 값)만** `logTickLabel(start, labelStyle)`로 쓴다. 중간 눈금과 오른쪽 끝에는 값을 쓰지 않는다(학생이 바뀌는 자리를 스스로 읽게 — 정답 노출 금지).
  - 학생이 뛴 호를 띠 위에도 같은 순서로 그리고, 호마다 step 이름표("10만")를 단다(본 수직선의 `log-hop-step-label`과 같은 문구·클래스).
  - 본 수직선의 띠 범위 구간과 띠 양 끝을 점선 두 개로 잇는다(확대 표시). 띠 왼쪽 위에 작은 제목 `numberLineStrings.logZoom.magnifyTitle = '확대해서 보기'`(새 문구, `strings.ko.ts`)를 둔다.
  - `data-testid="log-hop-magnifier"`를 띠 `<g>`에, 띠 안 호 이름표에는 `data-testid="log-hop-magnified-label"`.
  - 줌 단계를 바꿔 한 번 뛰기 폭이 28 이상이 되면 띠는 사라진다. 뛴 점이 없으면 그리지 않는다.
- 상태·Action·observe는 바꾸지 않는다(그리기만). 띠 범위 계산은 `log.ts`에 순수 함수(예: `magnifierRange(start, step, hopCount): { from: Rational; to: Rational } | null`)로 두고 `__tests__`에 단위 테스트: 234만·10만·5번 → 234만~334만, 뛴 횟수 12 → 234만~354만, step 폭이 충분하면 null(이 판단에 필요한 값은 인자로 받는다).
- E2E: g4s1u1.A2.T1에서 5번 뛰면 크롬북·아이패드에서 `log-hop-magnifier`가 보이고 그 안 이름표가 5개다. 띠 이름표 글자(`getBoundingClientRect().height`)가 크롬북에서 10px 이상이다. 띠가 사라지는 조건(한 번 뛰기 폭 ≥ 28)은 단위 테스트로 확인한다.

**5. E2E 시간 제한**
- `playwright.config.ts`:
  - `ipad` 프로젝트에 `timeout: 60_000`(다른 프로젝트는 기본 30초).
  - `workers: process.env.CI ? 2 : 6`(이 PC는 12코어, 기본값 6과 같지만 명시해서 늘어나지 않게).
  - 로컬 `retries`는 0 그대로(불안정한 테스트를 숨기지 않는다).
- 전체 E2E를 두 번 돌려 결과(통과·실패 수, 시간)를 둘 다 보고한다. 실패가 있으면 `--last-failed`로 다시 돌린 결과도 적는다.
