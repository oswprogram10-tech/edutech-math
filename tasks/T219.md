### 1. 공통
- 수 값은 Rational 문자열이다. 화면 좌표만 number.
- 새 코드는 `reduce-range.ts`, `range.ts`, `views/RangeView.tsx`, `views/range-story/`, 새 오버레이 파일에 둔다. 기존 파일은 모드 유니온·나누기·등록 줄과 `rounding`의 `scenario` 부분만 고친다. 기존 모드 동작·기준 이미지는 바꾸지 않는다(모드 상자 폭 때문에 도구 줄만 밀리면 다시 찍어도 된다, 메모에 적는다).
- 판은 기존 논리 1000×600, 선 `LINE_LEFT`~`LINE_RIGHT`를 그대로 쓴다. E2E에서 논리 높이를 가정하지 않는다.
- 샌드박스 모드 상자에 "수의 범위"를 더한다.

### 2. `range`
- **설정:** `{ mode:'range', min, max, unit, subdivisions?, story?:'rollercoaster'|'train'|'none', riders?:number[], maxBounds?:1|2, preset?:{ lower?:{value,closed}, upper?:{value,closed} }, readOnly?:boolean }`
  - `riders`는 0~10명, min~max 안의 정수. `story:'none'`이면 캐릭터·게이트를 그리지 않는다.
  - `maxBounds` 기본 1.
  - `preset`·`readOnly`: 게이트를 미리 만들어 두고 조작을 막는다(말로 쓰기 과제용).
- **조작**
  - 경계점 놓기: 수직선을 누르면 가까운 `unit` 눈금에 빈 동그라미 경계점이 생긴다. `maxBounds`개까지. 경계점을 끌어 옮길 수 있다.
  - 경계점을 누르면 속 찬 ↔ 빈 동그라미가 바뀐다. 조작 칸에도 경계점마다 [속 찬/빈 바꾸기] 단추.
  - 방향: 경계점이 하나면 조작 칸 [왼쪽으로]·[오른쪽으로] 단추(또는 경계점 옆 화살표 손잡이 끌기)로 굵은 구간 화살표를 그린다. 둘이면 두 점 사이 굵은 선이 자동이다.
  - [하나 지우기]·[처음으로].
  - [게이트 열기](`story`가 있을 때): 캐릭터가 왼쪽부터 한 명씩 게이트 앞으로 와서 구간 안이면 지나가고 밖이면 막혀 옆으로 비킨다(명당 400ms, reduced-motion이면 결과 한 번에). 캐릭터마다 "130cm" 같은 키 글을 단다(문제 자료라 보여도 된다).
  - 키보드: 수직선 초점에서 ←→로 커서를 `unit`씩 옮기고 Enter로 경계점 놓기, Space로 속 찬/빈 바꾸기. 나머지는 단추.
- **정답 노출 금지:** 목표 범위는 설정에 없다. 화면 글에 "이상·초과" 같은 말로 지금 상태를 풀어 쓰지 않는다(말로 쓰기 과제의 답이 됨).
- **Action:** `place-bound {value}`, `move-bound {index, value}`, `toggle-closed {index}`, `set-direction {dir:'left'|'right'}`, `remove-bound`, `open-gate`, `reset`
- **Observation:**
  - `mode:'range'`
  - `lower: {value, closed}|null`, `upper: {value, closed}|null`(경계 하나 + 오른쪽 → lower, 왼쪽 → upper, 둘 → 작은 쪽 lower)
  - `complete`(경계가 있고 방향이 정해짐)
  - `gateOpened`, `passed: number[]`, `blocked: number[]`(게이트를 연 뒤에만, 아니면 빈 배열)
  - `misconceptions: []`(MC-RANGE-BOUNDARY-INCLUSION은 콘텐츠가 `when`으로 건다)
- **Predicates:** `rangeIs {lower?, upper?}`(주지 않은 쪽은 null이어야 함), `gateOpened`, `complete`
- **오버레이 `boundary-rider`**(MC-RANGE-BOUNDARY-INCLUSION ②): `riders` 중 경계값과 같은 키의 캐릭터만 게이트 앞에 크게 그리고, **지금 학생 게이트로** 지나가는지 막히는지를 보인다(1초, reduced-motion이면 결과만). 경계값과 같은 rider가 없거나 경계가 없으면 그리지 않는다.

### 3. `rounding`의 `scenario`
- **설정 추가:** `scenario?:'bus-seats'|'candy-bags'|'height'`(값이 하나일 때만, 여러 값이면 설정 오류). 기존 `scenarios`(무시)는 그대로 둔다. `showConsequence` 기본 true.
- **장면**(수직선 아래, 방법을 고른 뒤): 전체 버스·봉지 수를 그리지 않는다(답 노출). 마지막 묶음만 그린다.
  - `bus-seats`(value 명, place 좌석 수): 올림이면 마지막 버스에 남은 학생 수만큼 앉고 빈 자리가 보인다("모두 탔어요"). 버림·반올림이 남은 학생을 못 태우면 정류장에 남은 학생 그림("못 탄 친구가 있어요").
  - `candy-bags`: 버림이면 봉지에 못 담고 남은 사탕 그림("남은 사탕"). 올림이면 덜 찬 마지막 봉지("다 차지 않은 봉지예요").
  - `height`: 장면 없음.
  - 나머지가 0이면 세 방법 모두 같은 결과 장면("딱 맞아요").
  - 결과 글은 고른 방법의 결과다. 어느 방법이 맞는지는 쓰지 않는다.
- **Observation 추가:** `scenario`, `consequence: 'all-seated'|'left-behind'|'partial-bag'|'leftover'|'exact'|null`
- **오버레이 `left-behind`**(MC-ROUND-CONTEXT-BLIND ②): `bus-seats`면 정류장에 남은 학생 그림을, `candy-bags`면 덜 찬 봉지 그림을 지금 방법과 상관없이 단독으로 보인다. 다른 scenario면 그리지 않는다.
- 기존 `two-ticks`(MC-ROUND-WRONG-PLACE ②)는 그대로 쓴다.

### 4. 테스트
- **단위**
  - range: 경계 놓기 눈금 맞춤, 속 찬/빈, 방향, 둘째 경계, lower/upper 정규화, `maxBounds` 넘기 거절, readOnly 거절, 게이트 통과(130 이상이면 130 통과·129 막힘, 130 초과면 130 막힘, 130 이상 150 미만이면 150 막힘)
  - rounding scenario: 243·10 버스 올림 all-seated, 버림·반올림 left-behind, 사탕 버림 leftover·올림 partial-bag, 240 exact, 여러 값 + scenario 설정 오류
  - JSON 왕복, predicates
  - View: range 시작 DOM에 "이상·이하·초과·미만" 글이 없다. 장면 DOM에 25·24 같은 전체 수가 없다.
  - 기존 E03 테스트 그대로 통과
- **E2E**(`number-line.spec.ts`에 더함, 3 뷰포트, 샌드박스)
  - range 누르기·끌기로 130 이상 만들고 게이트 열기, 두 경계 만들기
  - 키보드 경로 하나
  - rounding 버스 장면 둘(올림·버림)
  - 오버레이 둘 1px 정렬
  - 새 화면 스냅샷 × 크롬북·아이패드(range 게이트 연 뒤, rounding 버스)
- **E2E 범위:** `npx playwright test number-line fit-canvas overlay-alignment --workers=3 --reporter=line`

- **구현(Sonnet)**
  - 새 파일: `reduce-range.ts`, `scenario.ts`, `views/RangeView.tsx`, `views/range-story/`(geometry·Figures·RangeStory), `views/rounding-scene/`(Art·ResultScene), `overlays/boundary-rider.tsx`, `overlays/left-behind.tsx`. 기존 파일은 모드 유니온·등록·나누기·`rounding`의 scenario 부분만 고쳤다.
  - 공통 `hasMisconception {code}` predicate를 E03에 더했다(Observation `misconceptions` 목록을 봄). 목록은 range·scenario 있는 rounding에서만 `[]`로 나온다(T220이 `when`으로 채운다).
  - **T220 판정 경로(rounding):** 고른 방법은 `rounding.0.method`(`'up'|'down'|'half-up'`), 어림 결과는 `rounding.0.marker`, 상황 결과는 최상위 `consequence`(`'all-seated'|'left-behind'|'partial-bag'|'leftover'|'exact'|null`)와 `scenario`. `equals` 경로로 그대로 쓸 수 있다. scenario 없는 설정의 Observation에는 `scenario`·`consequence` 키가 없다(기존 Observation 그대로).
  - **range Observation:** `lower`/`upper`는 `{value, closed}|null`, `complete`, `gateOpened`, `passed`/`blocked`(키 정수 배열, 게이트를 연 뒤에만 채워짐). 범위를 바꾸면 게이트는 닫히고 결과가 비워진다. `rangeIs`는 `complete`가 거짓이면 거짓.
  - **설정 오류:** rounding에서 `scenario`와 `values` 2개 이상이면 `createInitialState`가 Error를 던진다(E07·E08 방식). `bus-seats`·`candy-bags`는 값이 자연수, `place`가 2~20 정수일 때만 받는다(그림 칸 때문). `height`는 장면 없음.
  - **판 높이:** range 판만 논리 1000×460(선 y 385)로 줄이고 CSS `aspect-ratio`를 인라인으로 맞췄다. 크롬북 1366×768·아이패드·전자칠판 모두 조작 칸 첫 줄이 첫 화면 안에 있다(E2E `expectControlsAboveFold`로 range·rounding scenario 확인, 모자람 0px). 오버레이 `boundary-rider`도 같은 460을 쓴다. 기존 모드의 판 높이·기준 이미지는 안 바꿨다. rounding은 600 그대로(scenario 장면은 수직선 아래 y 398~590).
  - E2E 좌표는 판 상자 너비/1000으로만 배율을 구하고 논리 높이를 쓰지 않는다. 기준 이미지는 판 상자(canvas)만 찍는다(크롬북·아이패드 각 2장).
  - `RoundingView` 조작 줄에 `data-testid="rounding-controls"`만 더했다(화면 변화 없음).
  - range 키(롤러코스터 캐릭터 라벨)는 문제 자료라 "130cm"로 보인다. 지금 상태를 풀어 쓰는 글은 없다(단위 테스트로 이상·이하·초과·미만 미포함 확인).
