2. **칠교·패턴 블록의 정확한 수 (`tangram/surd.ts`):**
   - 45° 회전은 √2, 패턴 블록의 정삼각형·30° 회전은 √3을 만든다. Rational만으로는 정확히 나타낼 수 없다. 오차 허용 판정은 쓰지 않는다.
   - 그래서 `a + b√d`(a, b는 `Rational`, d는 2 또는 3) 꼴의 수를 엔진 안에 둔다. `Surd = { readonly a: Rational; readonly b: Rational; readonly d: 2 | 3 }`.
   - 칠교 세트는 d = 2, 패턴 블록 세트는 d = 3이다. 한 세트 안의 모든 좌표·넓이는 이 꼴로 닫혀 있다(더하기·빼기·곱하기·나누기).
   - 함수: `sOf(a, b?, d)`, `sAdd`, `sSub`, `sMul`, `sDiv`(켤레 `a − b√d`를 곱해 나눈다), `sNeg`, `sSign(x): -1 | 0 | 1`, `sCompare`, `sEquals`, `sToNumber`(화면 좌표 전용), `sToJson(x): readonly [string, string]`, `sFromJson(json, d)`
   - `sSign`: a·b 부호가 같으면 그 부호다. 다르면 a²와 d·b²를 비교해 큰 쪽의 부호다(√d가 무리수라 둘이 같을 수 없다).
   - core가 아니라 엔진 안에 두는 이유: 카드가 core는 `geometry.ts` 함수 추가만 허용한다. Rational 두 개로 만든 정확한 수라서 절대 규칙 2(부동소수 금지)를 지킨다. 다른 엔진이 필요해지면 core로 옮기자고 메모에 적는다.
3. **칠교 기하 (`tangram/surd-geometry.ts`, `geometry.ts`의 알고리즘을 Surd로 옮긴다):**
   - `SPoint = { x: Surd; y: Surd }`, 상태에는 `SPointJson = readonly [readonly [string, string], readonly [string, string]]`
   - `sCross`, `sDot`, `sPolygonArea`, `sOrientation`, `sClipConvex`(Sutherland–Hodgman), `sConvexHull`, `sLocatePoint`
   - `sRotate(p, k, step)`: 원점 기준으로 k·step도 돌린다. cos·sin은 표로 둔다.
     - step 45(d = 2): 0, ±√2/2, ±1
     - step 30·60(d = 3): 0, ±1/2, ±√3/2, ±1
     - step 90은 두 세트 모두에서 된다.
   - 회전 행렬은 `(x, y) → (x·c − y·s, x·s + y·c)`다(y가 아래쪽이라 화면에서는 시계 방향).
4. **조각 세트 (`tangram/pieces.ts`, 기준 자세 꼭짓점, 격자 단위, y 아래쪽):**
   - `'tangram'`(d = 2, 4×4 정사각형을 이루는 7조각, 모두 정수 좌표):
     - `large-triangle` ×2: (0,0)(4,0)(2,2)
     - `medium-triangle`: (0,0)(2,0)(0,2)
     - `small-triangle` ×2: (0,0)(2,0)(1,1)
     - `square`: (1,0)(2,1)(1,2)(0,1)
     - `parallelogram`: (0,0)(2,0)(3,1)(1,1)
   - `'pattern-blocks'`(d = 3, 변 1, s = √3/2):
     - `triangle`: (0,0)(1,0)(1/2,−s)
     - `square`: (0,0)(1,0)(1,−1)(0,−1)
     - `rhombus`: (0,0)(1,0)(3/2,−s)(1/2,−s)
     - `thin-rhombus`: (0,0)(1,0)(1+s,−1/2)(s,−1/2)
     - `trapezoid`: (0,0)(2,0)(3/2,−s)(1/2,−s)
     - `hexagon`: (0,0)(1,0)(3/2,−s)(1,−2s)(0,−2s)(−1/2,−s)
   - 조각마다 `corners`(꼭짓점 수)를 둔다. 모든 조각은 볼록이다.
   - 조각의 화면 꼭짓점 = `at + R(rot·step)·F(flip)·기준 꼭짓점`이다. F는 x를 뒤집는다.
5. **실루엣 (`tangram/silhouettes.ts`, 인라인 데이터, 외부 자산 없음):**
   - 실루엣은 그 세트 조각의 정답 배치 목록 `{ kind, rot, flip, at }[]`으로 정의한다. 실루엣 다각형은 이 배치들의 합집합이고, 판정용 볼록 조각(part)도 이 배치들이다. 그래서 실루엣은 언제나 풀 수 있고 정확하다.
   - 만들 것:
     - 칠교: `square`(작은 세모 2개), `house`, `cat`, `boat`(뒤의 셋은 7조각을 모두 쓴다)
     - 패턴 블록: `house`(네모 2개 + 사다리꼴 지붕 등), `boat`
   - `square`는 아래처럼 고정한다(E2E가 쓴다). 실루엣 원점은 판 (2, 2)이다.
     - `{ kind: 'small-triangle', rot: 4, flip: false, at: (2,1) }`
     - `{ kind: 'small-triangle', rot: 0, flip: false, at: (0,1) }`
     - 합집합은 마름모꼴 정사각형 (1,0)(2,1)(1,2)(0,1)이다.
   - 나머지 실루엣의 정확한 배치는 구현자가 정한다. 단, 실루엣 하나는 원점에서 가로 15칸·세로 15칸 안에 들어가야 하고(쟁반 x 18과 겹치지 않게) 단위 테스트(13번)를 통과해야 한다.
   - `decor.tsx`: 실루엣마다 다 채웠을 때 덧그릴 인라인 SVG(창문·문, 눈·수염, 물결·돛 무늬 등)를 둔다. `data-testid="silhouette-picture"`.
   - 화면: 실루엣은 모든 part를 같은 진한 색으로 채우고, 같은 색 테두리를 둘러 틈을 숨긴다. `showPieceOutlines`면 part 테두리를 흰 점선으로 그린다.
6. **tangram 모드:**
   - **설정 (`TangramConfig`):**
     - `mode?: 'tangram'`
     - `pieceSet?: 'tangram' | 'pattern-blocks'`(기본 `tangram`)
     - `silhouette?: string`: 그 세트의 실루엣 id나 `'none'`. 없는 id면 그 세트의 `house`(기본값)다.
     - `pieces?: (string | { kind: string; rot?: number; flip?: boolean })[]`: 칠교 세트에서 판에 줄 조각과 처음 자세다. 없으면 7조각 모두 `rot: 0`이다. 패턴 블록은 무시하고 조각 더미를 준다.
     - `snapTolerancePx?: number`(기본 24, 8~48로 자름). 화면 px다.
     - `rotationStep?: number`: 칠교는 45·90(기본 45), 패턴 블록은 30·60·90(기본 30). 그 밖이면 기본값.
     - `showPieceOutlines?: boolean | 'first-task-only'`(기본 false). `'first-task-only'`는 엔진이 과제 순서를 모르므로 true로 본다. 콘텐츠가 과제마다 설정을 나눈다(메모에 적는다).
     - `allowFlip?: boolean`(기본 true)
     - `selectMode?: boolean`(기본 false): 조각 고르기 과제용. 켜면 끌기 대신 탭으로 고른다.
   - **판:** 28×18칸, 한 칸 40, 원점 화면 (40, 40). 실루엣 자리는 x 0~17, 조각 쟁반은 x 18~28(`tray.ts`가 조각마다 정수 `at`을 준다).
   - **상태 (`TangramState`):**
     - `mode: 'tangram'`
     - `pieces: { id; kind; rot: number; flip: boolean; at: SPointJson }[]`(`rot`은 step 단위 정수, 360/step로 나눈 나머지)
     - `selected: string[]`, `nextId`, `settings`(정규화 값과 `d`)
   - **Action:**
     - `place-piece { piece, at: SPointJson }`: 판 밖으로 나가면 무시한다.
     - `turn-piece { piece }`: 꼭짓점 평균을 중심으로 step만큼 돈다. 새 `at`은 정확히 계산한다(중심 c = at + R·F·c₀, 새 at = c − R′·F·c₀).
     - `flip-piece { piece }`: 꼭짓점 평균을 지나는 세로축으로 뒤집는다. `allowFlip`이 false면 무시한다.
     - `add-piece { kind, at }`, `remove-piece { piece }`: 패턴 블록만. 조각은 24개까지다.
     - `toggle-select { piece }`: `selectMode`일 때만.
   - **자석 스냅 (`tangram/snap.ts`의 `snapPiece(state, piece, rawAt: {x: number; y: number}, toleranceUnits: number): SPointJson`):**
     - 옮긴 조각 꼭짓점과, 실루엣 part 꼭짓점·다른 조각 꼭짓점의 정확한 차이로 만든 후보 중 `toleranceUnits` 안에서 가장 가까운 것을 고른다. 거리 비교만 `sToNumber`로 한다.
     - 없으면 rawAt을 1/8칸 Rational로 반올림한다(b = 0).
     - 포인터: `toleranceUnits = snapTolerancePx ÷ (화면 배율 × 40)`. 키보드: 0.3칸.
   - **조작:**
     - 조각을 끌어 놓으면 `snapPiece` 뒤 `place-piece`.
     - 두 번 탭(350ms 안, 움직임 없음, SDK `isTapGesture`)하면 `turn-piece`. 한 번 탭은 아무것도 하지 않는다(`selectMode`에서는 `toggle-select`).
     - "돌리기"·"뒤집기" 단추는 마지막으로 만진 조각(View 로컬)에 적용한다.
     - 패턴 블록은 쟁반 더미에서 끌어 내면 `add-piece`, 쟁반으로 끌어다 놓으면 `remove-piece`.
     - 단추 크기와 조각 터치 영역은 `targetSize`를 따른다. 조각마다 중심에 반지름 `minTouchRadius(targetSize)`인 보이지 않는 원을 더해, 작은 세모도 64px로 잡힌다.
   - **키보드:**
     - 조각은 `<g role="button" tabIndex={0} aria-label="조각 n">`이다. 이름에 모양 이름(세모·네모)을 넣지 않는다.
     - 방향키: 1/2칸 + 스냅(0.3칸)으로 `place-piece`
     - `R`: `turn-piece`, `F`: `flip-piece`, Enter/Space: `selectMode`에서 `toggle-select`
     - 패턴 블록 더미도 Tab으로 가고, Enter로 실루엣 원점 근처에 `add-piece`, Delete로 `remove-piece`
     - 조각 `<g>`에 `data-ax`·`data-ay`(at의 소수 근삿값, 소수 셋째 자리)와 `data-rot`를 단다(E2E용).
   - **완성 연출:** `silhouetteFilled`가 되면 `decor`를 덧그리고 조각 색을 그림 색으로 바꾼다. "다 채웠어요!" 상태 문구를 띄운다. reduced motion이면 바로 바꾼다.
7. **채움·겹침 판정 (정확 계산, `tangram/observe.ts`):**
   - 조각 넓이와 실루엣 넓이(part 넓이 합)는 Surd다.
   - 조각마다 `inside = Σ_part 넓이(sClipConvex(조각, part))`다.
   - 실루엣에 닿은 조각(inside > 0)끼리 하나라도 겹치면(clip 넓이 > 0) `overlap`이다.
   - 실루엣에 닿았지만 0 < inside < 조각 넓이면 `sticksOut`이다. 실루엣에 닿지 않은 조각(쟁반 등)은 판정에서 뺀다.
   - `filled`: 겹침 없음, 삐져나옴 없음, Σ inside = 실루엣 넓이.
   - `fillPercent`: `k/100 × 실루엣 넓이 ≤ Σ inside`인 가장 큰 정수 k(0~100). 겹치면 Σ inside가 커질 수 있으므로 100으로 자른다.
   - 외곽 `outline`: T106과 같은 방법(겹침 없음 + `sConvexHull` 넓이 = 조각 넓이 합)을 판의 모든 조각에 쓴다. `kind` 분류도 T106 `outline.ts`와 같은 규칙을 Surd로 한다. `base`·`width`·`height`는 null이다.
8. **circle-sectors 모드:**
   - **설정 (`CircleSectorsConfig`):**
     - `mode?: 'circle-sectors'`
     - `radius?: number | string`: `Rational.parse(String(value))`. 0보다 크고 100 이하. 기본 `"5"`.
     - `pi?: number | string`: 같은 방법으로 읽는다. 3 이상 4 이하. 기본 `"3.14"`. `"22/7"`도 된다.
     - `divisions?: number[]`: 4 이상 256 이하인 짝수, 오름차순. 기본 `[8, 16, 32, 64, 128, 256]`.
     - `manualUpTo?: number`(기본 8, 16을 넘으면 16)
     - `showDimensions?: boolean | 'lines' | 'named'`(기본 false): true와 `'lines'`는 가로·세로 표시선과 "가로"·"세로" 글자만 쓴다. `'named'`는 "원주의 반"·"반지름"을 쓴다.
   - **상태 (`CircleSectorsState`):**
     - `mode: 'circle-sectors'`, `level: number`(divisions 번호)
     - `slots: ({ sector: number; arcUp: boolean } | null)[]`: 길이 n, 손으로 붙이는 단계에서만 쓴다.
     - `autoArranged: boolean`
     - `arrangedDivisions: number[]`: 배열을 끝낸 등분 수(정렬, 중복 없음)
     - `settings`: `radius`·`pi`는 Rational 문자열로 둔다.
   - **Action:**
     - `set-level { level }`: `slots`를 비우고 `autoArranged = false`로 한다.
     - `place-sector { sector, slot, arcUp }`: n ≤ `manualUpTo`일 때만. 이미 놓은 조각이면 자리를 옮긴다. 다른 조각이 있는 칸이면 무시한다.
     - `unplace-sector { sector }`
     - `auto-arrange`: n > `manualUpTo`일 때만. `autoArranged = true`.
     - 배열이 끝나면(`arranged`, 9번) `arrangedDivisions`에 n을 더한다.
   - **그리기 (`circle-sectors/layout.ts`, 화면 계산만 number):**
     - 원은 왼쪽, 화면 중심 (230, 400), 반지름 150이다. `radius` 값은 그림 크기를 바꾸지 않는다.
     - 부채꼴 각 θ = 2π/n, 현 c = 2·150·sin(θ/2). 오른쪽 줄 시작 x0 = 440이다.
     - 칸 k의 중심 x = x0 + (k + 1)·c/2. `arcUp`이면 호가 위, 꼭짓점이 아래 기준선에 온다. 아니면 반대다. 엇갈리면 이웃 반지름이 정확히 맞닿는다.
     - 자동 배열은 원 자리에서 줄 자리로 옮겨 가는 CSS transform 1초다. reduced motion이면 바로 놓는다.
     - `showDimensions`: 줄 위쪽 호를 따라 가로 표시선, 왼쪽 끝 반지름에 세로 표시선을 그린다. 수 값은 쓰지 않는다.
   - **조작:**
     - n ≤ `manualUpTo`면 부채꼴을 원에서 끌어 줄 칸에 놓는다(가까운 칸에 스냅). 두 번 탭하면 들고 있는 방향(`arcUp`)이 바뀐다.
     - "더 잘게 나누기"·"덜 잘게 나누기" 단추와 `<input type="range" aria-label="나눈 조각 수">`로 `set-level`
     - n > `manualUpTo`면 "자동으로 붙이기" 단추로 `auto-arrange`
   - **키보드:**
     - 부채꼴은 `<path role="button" tabIndex={0} aria-label="조각 n">`이다(손으로 붙이는 단계만).
     - Enter로 집고, ←/→로 칸 커서를 옮기고(0번 칸부터 시작), `R`로 `arcUp`을 바꾸고, Enter로 `place-sector`. Esc는 취소, Delete는 `unplace-sector`.
     - 캔버스 svg에 `data-slot-cursor`(칸 번호)와 `data-held-arc-up`을 단다(E2E용).

### 카드와 다르게 정한 것 / 메모
- 실루엣 배치는 카드가 `square`만 고정했으므로 나머지는 구현자가 정했다. 모든 실루엣은 13번 테스트(정답 배치 채움·무겹침·넓이)를 통과한다. 칠교 `cat`은 7조각 전체를 쓰지만 hull 안에 빈 틈이 조금 있다(겹침 0, 넓이 16). 정답 배치 목록 자체는 화면에 쓰지 않는다.
- 카드 8번의 줄 좌표는 8등분만 해도 오른쪽이 1200을 넘는다(약 1358px). 판정·칸 계산은 카드 값을 그대로 쓰고, 그릴 때만 줄 그룹을 `rowScale`로 1160px 안에 맞춘다. 포인터는 `rowUnscale`로 되돌려 칸을 찾는다.
- circle-sectors 키보드는 카드 문구대로 Enter(집기) → 0번 칸에서 시작 → ←/→ → R → Enter다. 조각 k를 k번 칸에 놓는 E2E 흐름과 맞는다.
- 패턴 블록 더미는 판 위 조각과 별도 상태다. `add-piece`는 24개까지이고, 켠 `selectMode`에서만 `toggle-select`가 동작한다.
- 포인터 두 번 탭 시간은 `PointerEvent.timeStamp`로 잰다(`Date.now`는 React purity lint에 걸린다).
