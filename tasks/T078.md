1. **폴더·파일:** `src/engines/E07-column-calc/`만 고친다. 새 파일은 `grid-div-decimal.ts`(격자 수 만들기·소수 몫/나머지 읽기), `views/Magnifier.tsx`(+ css), 오버레이 4개. 나머지는 T047 파일(`grid-div.ts`, `classify-div.ts`, `views/DivView.tsx`, `reduce.ts`, `observe.ts`, `events.ts`)을 넓힌다. `decimal`이 false인 div(T047)의 동작·Observation 값은 그대로다(기존 테스트가 그대로 통과해야 한다).
2. **설정:** `{ "mode": "div", "decimal": true, "dividend": "6.24", "divisor": 3, "flagSkippedZero": true }`, `{ "mode": "div", "decimal": true, "dividend": "1.68", "divisor": "0.24", "magnifier": [10, 100], "allowOneSideScale": true }`(명세 예시 그대로). `{ "mode": "decimal", "op": "div", … }`도 같은 뜻으로 받는다(상태는 `mode: 'div'`, `decimal: true`).
   - dividend: 숫자(소수점 뺀) 1~5개, 소수 자리 0~3. divisor: 자연수 1~99, 또는 소수 자리 1~2이고 소수점을 뺀 값이 1~99인 소수(0.24, 1.3, 0.15, 0.4, 1.5). 범위 밖이면 `DEFAULT_NUMBERS.divDecimal = { a: '6.24', b: '3' }`.
   - `linkedBlocks`·`linkedNumberLine`은 이 카드에서 무시한다(러너 연결은 기존 receive만).
   - `rewindCheck`는 decimal에서 무시한다(false).
   - 새 상태 필드: `decimal: boolean`, `scaleA: number`, `scaleB: number`(0~3), `quotientPoint: number | null`, `extendLimit: number`, `magnifier: readonly number[]`(10·100·1000 중 설정값), `allowOneSideScale: boolean`, `oneSideTried: boolean`. 붙인 0은 기존 `aPads`(열 번호 목록)를 쓴다. decimal이 아니면 false·0·null·빈 배열.
3. **격자 수:** 격자의 나누어지는 수 G = dividend × 10^scaleA, 나누는 수 g = divisor × 10^scaleB(문자열 자리 옮기기로 만들고 number를 쓰지 않는다). 소수 ÷ 자연수면 scale은 0에 머문다.
   - 격자는 g가 자연수일 때만 열린다(scaleB ≥ divisor의 소수 자리 수). 닫혀 있으면 칸을 누를 수 없고 격자 위에 `strings.divisorNotWhole`("나누는 수에 소수점이 있으면 이 격자에서 나눌 수 없어요")을 보인다.
   - 격자 열은 G의 자릿값 지수다(일 = 0, 소수 첫째 = −1 …). `top` = G의 맨 윗열, `low` = −(G의 소수 자리 수) − (붙인 0의 개수). G에 소수 자리가 있거나 0을 붙였으면 피제수의 일의 자리 오른쪽에 소수점을 그린다.
   - **T047 계산을 low까지 넓힌다:** `grid-div.ts`의 열 반복(`column >= 0`)을 모두 `column >= low`로 바꾸고, 정수 계산은 I = G × 10^(−low)(붙인 0 포함)를 쓴다. 부분 피제수 P_0 = ⌊I / 10^(c₀ − low)⌋. decimal이 아니면 low = 0이라 T047과 같다. 단계·곱 줄·뺄셈 줄·내림 칸·커서·사다리·경고등·skippedZero 규칙은 T047 그대로이고 "열 0"을 "low"로 읽는다. 단, 마지막 단계의 내림 칸은 아래 5번을 따른다.
   - `scale` Action이 격자 수를 바꾸면 격자 칸(quotient·divProducts·divDiffs·estimateTries·aPads·quotientPoint·flagged·selected)을 모두 비운다.
4. **몫 소수점(decimal만):** T077의 Action을 넓혀 `{ type: 'place-point', target: 'quotient', column: number | null }`. column = 몫에서 일의 자리가 되는 칸(점은 그 칸 오른쪽). top … low만 받는다. 화면·키보드는 T077과 같다(몫 줄 아래 점 버튼 줄, 몫 칸 선택 + `.`).
   - **몫 읽기:** T047처럼 가장 높은 채운 칸부터 **가장 낮은 채운 칸**까지 빈칸을 빼고 숫자를 잇는다. 점이 있으면 열이 quotientPoint 이상인 숫자 뒤에 점을 넣는다(그런 숫자가 없으면 앞에 `0.`). 점이 없으면 이은 숫자를 정수로 읽는다. 예: 열 0 = 2, 열 −1 빈칸, 열 −2 = 8, 점 0 → `"2.8"`. 몫 값은 Rational이다.
   - Observation: `quotient` = Rational 정규 문자열(정수면 T047과 같은 `"13"`), `quotientRaw` = 칸 그대로(빈칸은 공백) + 점 자리에 `.`, `quotientPoint`.
5. **멈추는 곳과 완성:** decimal에서는 몫을 열 0 아래(소수 자리)에서 멈출 수 있다.
   - 마지막 단계의 몫 열 c가 0 이하이고 그 아래로 학생이 쓴 몫 0이 없으면 내림 칸을 만들지 않는다(거기서 멈춤). c > 0이면 T047처럼 적어도 열 0까지 내린다.
   - `divComplete`(decimal): 몫이 가장 높은 채운 칸부터 가장 낮은 채운 칸까지 빈칸이 없고, 가장 낮은 채운 칸 ≤ 0, 모든 단계의 곱·뺄셈 줄이 채워졌고, 마지막 뺄셈 줄이 있으며, 열 0 아래 몫 칸을 썼다면 몫 점을 놓았다. 맞았는지는 보지 않는다.
6. **나머지:** 마지막 뺄셈 줄 값 R, 그 줄의 가장 낮은 열 L이면 격자 단위 나머지 = R × 10^L, **원래 단위** 나머지 = R × 10^L / 10^scaleA.
   - Observation `remainder` = 원래 단위의 Rational 정규 문자열(7.4 ÷ 1.5를 74 ÷ 15로 풀면 14 → `"7/5"`), `remainderGrid` = 격자 단위(`"14"`). decimal이 아니면 `remainderGrid` = `remainder`(T047 값 그대로).
   - `remainderIs {value}`는 decimal에서 Rational로 비교한다(T047 정수 비교 결과는 그대로). Predicate `remainderGridIs {value}` 추가.
   - 나머지 경고등(`remainderAlarm`)은 격자 값끼리(뺀 결과 vs g) 비교한다.
7. **extendZeros(0~3, decimal 기본 2, 아니면 0):** 피제수 끝에 0을 붙여 계속 나눈다.
   - 기존 Action `pad-zero {number: 'a', column}`을 div decimal에서도 받는다. column = low − 1이고 붙인 개수 < extendLimit이면 붙이고, column = low이고 그 열이 붙인 0이면 떼어 낸다(그 열의 몫·곱·뺄셈 칸도 지운다). 그 밖은 무시.
   - 화면: 피제수 오른쪽 끝에 "0 붙이기" 버튼과(붙인 0이 있으면) "떼기" 버튼. 붙인 0은 점선 테두리 칸에 `0`으로 보인다. 키보드: 격자에 초점이 있을 때 `+` 붙이기, `-` 떼기.
   - 몫 칸은 붙인 열에도 연다.
   - Observation `extendedZeros`(붙인 개수).
8. **소수점 옮기기·확대경(소수 ÷ 소수):** Action `{ type: 'scale', side: 'both' | 'dividend' | 'divisor', to: number }`(0~3). `both`는 scaleA = scaleB = to. 한쪽만 바꾸면 `oneSideTried = true`.
   - **격자의 소수점 화살표(항상):** divisor에 소수 자리가 있으면 격자 위 두 수 옆에 각각 "소수점 오른쪽으로"·"되돌리기" 버튼(한쪽 `scale`)을 둔다. 원래 소수점 자리는 속이 빈 점으로 남기고 옮긴 자리까지 곡선 화살표를 그린다(교과서 표기). 키보드: 수 카드에 초점 + `→`/`←`.
   - **확대경(`magnifier: [10, 100]`, C·P에서만):** `views/Magnifier.tsx`. 버튼 "×10", "×100"(both, to = 1, 2)과 "처음으로"(to = 0). `allowOneSideScale`이면 "나누어지는 수만 ×10"·"나누는 수만 ×10"(한쪽 +1, 3을 넘지 않음)을 더한다. 지금 격자 수 두 개를 "168 ÷ 24"처럼 글자로 보이고, 그 아래 막대 두 개를 그린다: 나누어지는 수 막대는 고정 너비 W, 그 안에 나누는 수 길이(W × g / G, 화면 좌표만 number) 조각을 ⌊G / g⌋개(BigInt) 이어 그리고 남는 부분은 빗금으로 그린다. 조각은 최대 100개까지만 그린다. **조각 개수를 숫자로 쓰지 않는다**(학생이 센다). aria-label도 "나누는 수 막대가 나누어지는 수 막대에 몇 번 들어가는지 세어 보세요"처럼 개수 없이 쓴다.
   - Observation `scaleA`, `scaleB`, `scaledDividend`, `scaledDivisor`(Rational 정규 문자열), `gridOpen`, `oneSideTried`. Predicates `scaleIs {factor}`(scaleA = scaleB이고 10^scale = factor), `oneSideTried`.
   - 이벤트 `scaled {scaleA, scaleB}`.
9. **오류 분류(`classify-div.ts`, `MisconceptionCode`에 `'MC-DIV-NO-EXTEND-ZERO' | 'MC-DEC-DIV-SCALE-ONE-SIDE'` 추가, `MC-DEC-POINT-PLACEMENT`는 T077에서 추가됨):** T047 규칙을 low까지 넓힌 뒤 아래를 더한다. 학생 값과 문제의 수만으로 판정한다.
   - `MC-DIV-QUOTIENT-ZERO`: T047 (a)는 격자 정수 영역에서 비교한다(몫 숫자열이 정답 몫 숫자열에서 가운데 0을 뺀 것과 같음: 6.24 ÷ 3에서 "28"). (b)는 low까지 본다.
   - `MC-DEC-POINT-PLACEMENT`(몫): 열 0 아래 몫 칸을 썼는데 점이 없거나, quotientPoint ≠ 0.
   - `MC-DIV-NO-EXTEND-ZERO`: `divComplete`이고 원래 단위 나머지 ≠ 0이고 붙인 0 개수 < extendLimit.
   - `MC-DEC-DIV-SCALE-ONE-SIDE`: 격자가 열렸고 scaleA ≠ scaleB이고 몫 칸이 하나 이상 채워졌다(확대경에서 한쪽만 키워 보는 실험만으로는 기록하지 않는다).
10. **틀린 풀이(`debugSample.quotientRaw`):** decimal에서는 `quotientRaw`를 받는다. 몫 칸을 top부터 차례로 채우는 문자열이고 공백은 빈칸, `.`은 바로 앞 칸이 일의 자리라는 표시다(예: 6.24 ÷ 3, `"2. 8"` → 열 0 = 2, 점 0, 열 −1 빈칸, 열 −2 = 8). 그 몫으로 T047 8번처럼 단계 줄을 계산해 채운다(첫 단계 뒤 내림 칸이 열 −1·−2 두 칸이 되어 24를 내린 친구 풀이가 나온다). 칸 수가 top … low와 맞지 않으면 무시한다. 기존 `quotient` 키도 계속 받는다.
