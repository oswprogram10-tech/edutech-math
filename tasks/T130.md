1. **파일과 범위:**
   - 엔진 폴더는 `src/engines/E12-solid-3d/`이다. E09와 같은 구조로 만든다: `index.ts`, `types.ts`, `voxel.ts`(투영·정규화 계산, 순수 함수), `reduce.ts`, `observe.ts`, `events.ts`, `layout.ts`(등각 좌표·viewBox), `View.tsx`, `View.module.css`, `strings.ko.ts`, `views/CubesView.tsx`, `views/ProjectionGrid.tsx`, `overlays/`, `__tests__/`.
   - 엔진 ID는 `E12`, 이름은 "3D 입체"다. `modes`는 `['cubes']`이고 `layout`은 기본값(`fit`)이다.
   - `net-fold`·`shapes-sort`·`prism-pyramid`·`surface-volume`·`lathe`·`cross-section`·`xray`와 `cubes`의 `variant`(`top-numbers-layers`, `reconstruct`)는 만들지 않는다. 설정에 `variant`가 오면 무시한다.
   - `types.ts`의 Config·State·Action은 `mode`로 나뉘는 판별 유니온으로 둔다. 뒤 카드가 모드를 더할 수 있게 하기 위해서다.
   - **새 의존성을 넣지 않는다.** Three.js·WebGL·Canvas 2D를 쓰지 않고 SVG만 쓴다. `src/core/`는 고치지 않는다(필요하면 메모에 요청).
2. **좌표 (수학 값):**
   - 쌓기나무 하나는 정수 칸 `(x, y, z)`이다. x는 오른쪽(0 = 왼쪽 끝), y는 뒤쪽(0 = 맨 앞 줄), z는 위쪽(0 = 바닥 층)이다. 정수 격자 번호라 `number`를 허용한다(T100과 같음). 소수·분수는 생기지 않는다.
   - 격자 크기 `grid: [cols, rows]`는 x 칸 수·y 칸 수다(기본 [5, 5], 각 값 1~8로 자른다). `maxHeight`는 기본 5, 1~8로 자른다.
   - **쌓기 규칙(공중에 뜨지 않음):** 쌓기나무는 바닥이나 바로 아래 쌓기나무 위에만 놓인다. 그래서 칸 `(x, y)`마다 쌓인 높이 h가 있고, 그 칸의 쌓기나무는 z = 0 … h−1이다. 빼기는 그 칸의 맨 위 하나만 뺀다. 이 불변식은 `reduce`가 지키고 단위 테스트로 확인한다.
3. **설정 (`CubesConfig`):**
   - `mode: 'cubes'`
   - `grid`, `maxHeight`(위)
   - `maxCubes`(기본 `cols × rows × maxHeight`, 1 이상): 이 수에 이르면 더 쌓지 않고 상태 문구 "더 쌓을 수 없어요"를 띄운다.
   - `initial?: { at: [number, number, number]; color?: CubeColor; locked?: boolean }[]`: 처음부터 놓인 쌓기나무다. 같은 칸의 z가 0부터 빈틈없이 이어지지 않으면 그 칸의 공중에 뜬 것은 버린다(개발 모드 `console.warn`). `locked`인 쌓기나무는 학생이 뺄 수 없고, 그 위의 것은 뺄 수 있다.
   - `CubeColor = 'plain' | 'red' | 'blue' | 'yellow' | 'green'`. 학생이 놓는 쌓기나무는 `plain`이다. 색 쌓기나무에는 색과 함께 윗면 무늬(빨강 ●, 파랑 ▲, 노랑 ■, 초록 ◆)를 그린다(색만으로 구분 금지). `colorHints: false`면 `initial`의 색을 모두 `plain`으로 그린다(기본 `true`).
   - `views: ('top' | 'front' | 'side')[]`(기본 `['top', 'front', 'side']`): 실시간 투영 뷰로 보일 것. `[]`이면 투영 뷰를 그리지 않는다.
   - `sideDirection: 'right'`만 받는다(`'left'`가 오면 `'right'`로 취급하고 메모에 적는다).
   - `frontMarker`(기본 `true`): 바닥 앞쪽 가장자리에 "앞" 표시. 회전해도 바닥과 함께 돈다.
   - `translucentToggle`(기본 `true`): "반투명" 단추를 보인다.
   - `rotationLocked`(기본 `false`): 회전 단추를 숨기고 회전 Action을 무시한다.
   - `reference?: { cubes: [number, number, number][] }`: 과제가 보여 주는 **보기 모양**이다. 조작할 수 없는 작은 등각 그림으로 그린다. 이것은 과제 자료이지 학생 답이 아니다.
   - `referenceViews?: { top?: number[][]; front?: number[][]; side?: number[][] }`: 과제가 주는 **보기 투영**이다. 투영 뷰와 같은 모양의 작은 격자로 그린다. 행렬 규칙은 5번과 같다.
   - `fallback`, `variant`, `layerSlider`, `bidirectional`, `givenViews`, `challenge`, `verbalInstructions`, `targetFromStage`는 받기만 하고 무시한다(뒤 카드·단원 카드 몫). zod 스키마에서 모르는 키로 실패하지 않게 한다.
   - docs 예시의 `views` 객체 형식(`{ "top": "task-only", ... }`)은 이 카드에서 받지 않는다. 그 예시는 이 카드와 함께 배열 형식으로 고쳐 두었다(아래 메모).
4. **상태와 Action:**
   - **상태:** `{ mode: 'cubes', cubes: { x, y, z, color, locked }[], viewTurn: 0 | 1 | 2 | 3, translucent: boolean, tool: 'add' | 'remove', cursor: [number, number], focus: { view: 'top' | 'front' | 'side'; row: number; col: number } | null }`. `cubes`는 늘 (x, y, z) 사전순으로 정렬해 둔다(같은 모양이면 같은 JSON).
   - **Action:**
     - `add {x, y}`: 그 칸 맨 위에 `plain` 하나. 격자 밖, 높이가 `maxHeight`, 총수가 `maxCubes`면 상태를 그대로 돌려준다.
     - `remove {x, y}`: 그 칸 맨 위 하나. 비었거나 맨 위가 `locked`면 그대로.
     - `select-tool {tool}`, `move-cursor {to: [x, y]}`(격자 안으로 자름)
     - `turn {dir: 'left' | 'right'}`: `viewTurn`을 ±1(4로 나눈 나머지). `rotationLocked`면 그대로.
     - `set-translucent {on}`
     - `focus-cell {view, row, col} | null`: 투영 뷰 칸 강조(아래 7번)
     - `clear`: `locked`가 아닌 쌓기나무를 모두 뺀다. 이때 `locked` 아래가 비어 공중에 뜨는 일은 2번 규칙(맨 위부터만 빼기)상 생기지 않는다 — `locked` 위의 것만 빠진다.
   - `createInitialState(config)`는 `initial`을 정리해 넣고 `viewTurn: 0`, `translucent: false`, `tool: 'add'`, `cursor: [0, 0]`, `focus: null`이다.
5. **투영 행렬 규칙 (`voxel.ts`, docs/04-units/g6s2.md A2·A3 예시와 같음):**
   - `heightMap(cubes, grid)`: `rows × cols` 행렬. **행 0이 맨 뒤 줄(y = rows−1), 마지막 행이 맨 앞 줄(y = 0)**, 열 0이 x = 0이다. 값은 그 칸의 높이다. 위에서 내려다본 그림에서 앞이 아래쪽에 오게 하기 위해서다.
   - `topView`: `heightMap`과 같은 모양, 높이 > 0이면 1.
   - `frontView`: `maxHeight × cols`. **행 0이 맨 위 층(z = maxHeight−1), 마지막 행이 바닥 층(z = 0).** 열 x의 값은 그 열(모든 y) 가운데 가장 높은 기둥이 z 층에 닿으면 1.
   - `sideView`(오른쪽에서 본 모양): `maxHeight × rows`. 행 규칙은 `frontView`와 같다. **열 0이 맨 앞 줄(y = 0), 마지막 열이 맨 뒤 줄**이다. 오른쪽에 서서 왼쪽을 보면 앞쪽이 내 왼쪽에 오기 때문이다(MC-VIEW-SIDE-MIRROR의 기준).
   - **정규화 비교** `sameCells(a, b, shift)`: 두 행렬의 1인 칸을 (아래에서부터 행, 왼쪽에서부터 열) 집합으로 바꿔 비교한다. 행렬 크기가 달라도 된다(바닥·왼쪽 기준으로 맞춘다). `shift: true`면 열 방향(위에서 본 모양은 행·열 모두)으로 빈 줄을 밀어 최솟값을 0으로 맞춘 뒤 비교한다. 앞·옆 투영은 세로로 밀지 않는다(바닥은 고정).
   - `normalizeCubes(cubes, rotate)`: x·y 최솟값을 0으로 민 정렬 좌표 목록. `rotate: true`면 위에서 보아 90°씩 네 방향으로 돌린 것 가운데 사전순으로 가장 작은 것을 돌려준다.
   - `isConnected(cubes)`: 면으로 맞닿은 쌓기나무끼리 모두 이어져 있는가(0개·1개는 true).
   - **단위 테스트 (경계값을 꼭 넣는다):**
     - 0개, 1개, 꽉 찬 격자(`cols × rows × maxHeight`)
     - docs/04-units/g6s2.md A3 예시 세 투영을 동시에 만족하는 모양 하나를 손으로 만들어 세 투영이 그대로 나오는지
     - 옆 투영의 좌우: 앞 줄만 높은 모양에서 `sideView`의 왼쪽 열이 높다
     - 앞 투영이 앞뒤 기둥 중 높은 것을 보인다(낮은 앞 기둥 + 높은 뒤 기둥)
     - 같은 모양을 옮기거나 돌린 것의 `normalizeCubes` 일치, 거울상(L자 뒤집기)은 `rotate: true`여도 불일치
     - 네 번 돌리면 제자리, `rows ≠ cols`(예: [4, 2]) 격자 회전
6. **등각 무대 (`views/CubesView.tsx`, `layout.ts`):**
   - 무대는 SVG 하나다. `data-testid="cubes-canvas"`, `preserveAspectRatio` 기본(meet). viewBox는 `grid`·`maxHeight`로 정하고, 네 방향 회전 모두를 담는 상자로 잡아 돌려도 무대 크기가 변하지 않게 한다.
   - **회전:** `viewTurn = k`이면 평면 좌표 (x, y)를 위에서 보아 시계 반대 방향으로 90°씩 k번 돌린 (rx, ry)로 그린다(k가 홀수면 격자 크기가 [rows, cols]가 된다). 좌표 자체(상태·Observation)는 돌리지 않는다. 화면만 돈다.
   - **화면 좌표**(number 허용): 쌓기나무 한 변 s에 대해 `sx = (rx + ry) · (√3/2) · s`, `sy = ((rx − ry) / 2 − z) · s`(그 뒤 viewBox 원점으로 평행이동). 앞-오른쪽-위에서 본 모습이라 윗면·앞면·오른쪽 면이 보인다.
   - **그리는 순서(화가 알고리즘):** `rx − ry + z` 오름차순(멀리 있는 것 먼저). 같은 값끼리는 겹치지 않으므로 순서를 따지지 않는다. 단위 테스트로 작은 예(2×2×2)의 순서를 확인한다.
   - 면 셋은 밝기가 다른 같은 계열 색 + 검은 테두리다. 바닥 격자는 마름모 칸으로 그린다. "앞" 표시는 y = 0 쪽 가장자리 바깥에 글자와 화살표로 둔다.
   - **반투명(`translucent`):** 모든 면을 불투명도 0.35로 그리고 테두리를 실선으로 남겨 뒤·아래 쌓기나무가 비쳐 보이게 한다.
   - **누르기(Pointer Events):** 칸 `(x, y)`의 기둥 전체(바닥 마름모 + 그 칸 쌓기나무의 모든 면)가 한 누름 영역이다. 각 기둥을 `<g data-col="x,y">`로 묶는다. 누르고 8px 넘게 움직이지 않고 떼면 현재 `tool`의 Action(`add`·`remove`)을 보낸다. **600ms 넘게 누르고 있으면 `remove`**(명세의 '길게 누르면 제거')를 보내고, 뗄 때는 아무것도 보내지 않는다. 타이머는 `setTimeout`이고 `pointercancel`·`pointerleave`에서 지운다.
   - 기둥 누름 영역은 바닥 마름모의 화면 가로가 48px(저학년 64px) 이상이 되도록 s를 잡는다. 크롬북 샌드박스 기본 설정(5×5, 높이 5)에서 E2E로 확인한다(8번). 더 작아지면 키보드 조작이 대체 경로다.
   - **도구 줄:** "쌓기"/"빼기" 토글(`aria-pressed`), "왼쪽으로 돌리기"/"오른쪽으로 돌리기"(`rotationLocked`면 숨김), "반투명"(`translucentToggle`일 때), "모두 빼기". 버튼에 아이콘과 글자를 같이 쓴다.
   - **키보드** (무대 SVG에 `tabIndex=0`, `role="application"`, `aria-label`):
     - 방향키는 **화면 기준**으로 커서 칸을 옮긴다(돌린 상태에서도 ↑는 화면 위쪽 방향 칸). 회전 역변환으로 `move-cursor`를 만든다.
     - Enter·Space = `add`, Backspace·Delete = `remove`(커서 칸), `Q`/`E` = `turn left/right`, `T` = 반투명 토글.
     - 커서 칸은 바닥 마름모 굵은 점선 테두리 + 그 기둥 테두리 강조로 보인다.
     - `aria-live="polite"` 문구는 "가로 3번째, 앞에서 2번째 칸"과 "쌓았어요"/"뺐어요"/"더 쌓을 수 없어요"만 말한다. **칸 높이·전체 개수는 말하지 않는다**(개수 세기 과제의 답이 되기 때문).
7. **투영 뷰와 보기 그림 (`views/ProjectionGrid.tsx`):**
   - `views`에 있는 것마다 작은 SVG 격자 하나: `data-testid="cubes-view-top"` / `-front` / `-side`. 제목은 "위에서 본 모양", "앞에서 본 모양", "오른쪽 옆에서 본 모양". 위에서 본 모양 아래쪽에 "앞", 옆에서 본 모양 왼쪽 아래에 "앞"을 쓴다. **`data-testid`가 `-canvas`로 끝나면 안 된다**(판 맞춤 E2E가 첫 `-canvas` SVG를 무대로 본다).
   - 칸은 채움(진한 색) + 빗금으로 표시한다(색만으로 구분 금지). 칸 수만 그리고 숫자(높이·개수)는 쓰지 않는다.
   - 칸을 누르거나(키보드: 투영 뷰 SVG에 포커스 후 방향키 + Enter) `focus-cell`을 보내면, 무대에서 그 칸에 영향을 주는 쌓기나무(위: 그 기둥 전체 / 앞: 그 열 x·층 z의 모든 y / 옆: 그 줄 y·층 z의 모든 x)를 굵은 테두리로 강조한다. 같은 칸을 다시 누르면 `null`.
   - 투영 뷰는 학생이 쌓은 모양의 결과라 정답 노출이 아니다. 단원 콘텐츠가 투영을 맞히는 과제에서는 `views: []`로 끈다.
   - `reference`가 있으면 "보기" 제목의 작은 등각 그림(`data-testid="cubes-reference"`, 회전 없음)을, `referenceViews`가 있으면 "보기: 앞에서 본 모양" 같은 제목의 격자(`data-testid="cubes-reference-front"` 등)를 그린다.
8. **판 맞춤 (T122 규칙 그대로):**

    - 인자가 잘못되면(행렬이 아님 등) false를 돌려주고 throw하지 않는다.
12. **이벤트:** `cube-added {x, y, z, count}`, `cube-removed {x, y, z, count}`, `view-turned {viewTurn}`. 러너 이벤트에 `count`를 넣는 것은 화면 표시가 아니므로 괜찮다.
13. **오버레이 (힌트 ②, 학생이 만든 모양만 쓰고 목표 모양·정답을 그리지 않는다)** — 모두 `CanvasAlignedOverlay`에 selector `svg[data-testid="cubes-canvas"]`와 같은 viewBox를 넘겨 그린다:
    - `hidden-reveal`: 현재 방향에서 다른 쌓기나무에 완전히 가려진 쌓기나무만 점선 윤곽 + 빗금으로 그린다. MC-3D-HIDDEN-UNCOUNTED용이다. "가려짐" 판정은 화면 다각형 겹침이 아니라 정수 계산으로 한다: 돌린 좌표 (rx, ry, z)에서 보이는 세 면(윗면 +z, 앞면 −ry, 오른쪽 면 +rx) 쪽 이웃 칸 셋에 모두 쌓기나무가 있으면 가려진 것이다(떨어진 기둥에 가려지는 경우는 세지 않는다 — 덜 보여 줄 뿐 틀린 것을 보이지 않는다). 단위 테스트로 2×2×2 꽉 찬 덩어리에서 가려진 것이 1개(맨 뒤-왼쪽-아래)임을 확인한다.
    - `side-eye`: 무대 오른쪽(돌린 화면 기준이 아니라 상태 좌표의 +x 쪽)에 눈 그림과 왼쪽을 향한 화살표, 그리고 그 눈에서 볼 때 왼쪽이 "앞"임을 알리는 큰 "앞" 표시를 그린다. MC-VIEW-SIDE-MIRROR용이다. 투영을 그리지 않는다.
    - `row-lineup`: `args: { x: number }`. 학생 모양에서 열 x의 기둥들을 앞 줄부터 무대 옆에 나란히 세운 단면 막대로 그린다(높이는 학생이 쌓은 그대로). MC-VIEW-DEPTH-IGNORED용이다. `args`가 없거나 잘못되면 아무것도 그리지 않는다.

**2026-11-13 Antigravity(구현)**
- 회전 방향 정의: `turn { dir: 'right' }`는 위에서 보아 반시계 방향 회전(`viewTurn = (viewTurn + 1) % 4`)으로 화면 왼쪽 아래에 있던 `"앞"` 기준 가장자리가 오른쪽 아래로 이동하도록 했고, `dir: 'left'`는 `(viewTurn + 3) % 4`로 두었다.
- `sideDirection: 'left'` 입력은 명세에 따라 `'right'`로 정규화해 처리했다.
- `reduce(state, action)`가 `config` 인자를 받지 않는 `EngineDefinition` 계약을 따르기 위해, 정규화된 설정(`settings`, `focus`/`reference`/`referenceViews`는 `assertSerializable` 통과를 위해 `undefined` 대신 `null` 사용)을 `CubesState` 내부에 함께 저장했다.
- 키보드 방향키 이동은 현재 회전 상태(`viewTurn`)의 화면 기준 방향(`ArrowRight`/`ArrowLeft` → `±rx`, `ArrowUp`/`ArrowDown` → `±ry`)으로 1칸 옮긴 뒤 `unrotateCell`로 상태 좌표로 역변환해 `move-cursor`를 보낸다.
- `sameCells(a, b, shift = true, shiftRows = false)`는 `front`·`side`에서 바닥 기준이 흔들리지 않도록 기본 `shiftRows = false`로 두고, `projectionMatches`·`projectionsMatch`에서 `view === 'top'`일 때만 `shiftRows = true`를 넘긴다.
- `clear`는 각 `(x, y)` 기둥에서 가장 높은 `locked` 층 `highestLockedZ` 이하(`z <= highestLockedZ`)만 유지해 비정상 `initial` 입력에서도 공중에 뜬 쌓기나무가 남지 않게 보장했다.
- CSS 클래스 이름에 `canvas`가 들어가지 않도록 SVG 무대 클래스 이름은 `.stageSvg`로 두었다(T082/T122 규칙). 크롬북 E2E의 `[data-floor="0,0"]` 가로 48px 이상 검사는 샌드박스 개발 패널이 가로를 절반으로 줄이지 않는 `stage=fit` 학생 화면 기준으로 확인했다.
