## 목표
E17 분류기에 새 모드 `sort`와 `secret-rule`의 새 변형 `predict`를 더한다. g2s1u5와 g1s1u2.A1(T218)에 쓴다.
- `sort`: 카드를 상자에 넣어 분류하고, 상자별 개수를 센다. 기준을 먼저 고르거나(이름 붙은 상자), 상자에 학생이 아이콘 이름을 붙인다.
- `predict`: 컴퓨터의 비밀 기준으로 나뉜 예시를 보고, 새 카드가 어느 상자로 갈지 예측한 뒤 기준을 맞힌다.

### 1. 공통
- 기존 모드(venn·hierarchy·secret-rule twenty-questions) 동작은 바꾸지 않는다. 새 코드는 `sort/`, `secret-rule-predict/`, `decks/` 폴더에 둔다. 기존 파일은 유니온·모드 나누기·등록 줄만 고친다.
- 판 크기: `sort`와 `predict`는 논리 1000×700이다(기존 1000×1000은 그대로). 모드별 판 크기 함수를 두고, E2E에서 논리 높이를 가정하지 않는다.
- T199 세로 배치 CSS, Pointer Events + 키보드, 터치 타깃 48px(저학년 64px, `--touch-target`)을 따른다.
- 색만으로 정보를 전달하지 않는다: 단추 색마다 무늬를 다르게 한다(빨강 = 꽉 찬 칠, 파랑 = 빗금, 노랑 = 점무늬). 카드 aria-label에 색·모양·구멍 수(사물은 이름)를 쓴다. 보이는 정보라 노출 문제가 아니다.
- 샌드박스 모드 상자에 "분류하기"(sort)와 "비밀 기준 예측"(secret-rule predict)을 더한다. 도구 줄만 밀린 기준 이미지는 다시 찍어도 된다(메모에 적는다).
- **`src/core/` 수정 허용(이 한 곳만):** `misconceptions-w6.ts`에 `MC-SHAPE-BY-COLOR-SIZE`(label "색·크기로 모양을 묶음", units `['g1s1u2']`, backtrack `g1s1u2.shape-families`, detect `observation`)를 더한다. 레지스트리 테스트가 단원 집합 때문에 깨지면 그 테스트의 집합만 맞춘다.

### 3. `sort` 모드
- **설정:** `{ mode:'sort', deck:'buttons-12'|'classroom-objects-12', cards?:id[], criterionChoice?:Criterion[], bins?:1|2|3|4, binLabels?:'criterion-values'|'student-choice-icon'|'none', conveyor?:boolean, countTable?:'student'|'auto'|false, prefill?:Record<binId,id[]>, render?:'color'|'gray' }`
  - `cards` 기본은 묶음 전체, 순서는 주어진 순서다(컨베이어 순서). 없는 id는 설정 오류다.
  - `Criterion`: buttons는 `color`·`shape`·`holes`·`pretty`, objects는 `shapeFamily`·`color`·`size`.
  - `criterionChoice`가 있으면 `binLabels`는 `criterion-values`다. 기준을 고르면 상자가 그 값 개수만큼 생기고 값 이름(무늬 견본 포함)이 붙는다. `pretty`면 상자 둘 "예쁜 것"·"안 예쁜 것".
  - `student-choice-icon`: 상자 `bins`개(기본 3). 상자마다 아이콘 고르기 단추(objects: 상자 모양·둥근기둥·공 모양 아이콘, buttons: 색·모양·구멍 아이콘 값 목록). 고른 아이콘이 상자 이름이다.
  - `none`: 이름 없는 상자 `bins`개.
  - `prefill`: 시작할 때 상자에 미리 든 카드. `binId`는 `bin1`~`bin4`.
- **조작**
  - 기준 고르기(`criterionChoice`가 있을 때): 기준 아이콘 단추. 고르기 전에는 넣기를 거절한다. [기준 바꾸기]를 누르면 모든 카드가 판으로 돌아가고 기준을 다시 고른다(재분류).
  - 카드 넣기: 끌어서 상자에 놓기. 상자 밖에 놓으면 제자리. 상자에 든 카드를 다시 끌어 다른 상자나 판(트레이)으로 옮길 수 있다.
  - `conveyor:true`: 벨트에 카드가 하나씩 온다. 지금 카드를 넣어야 다음 카드가 온다(300ms 미끄러짐, reduced-motion이면 바로). `false`면 판 위 트레이에 모두 놓인다.
  - 개수표 `student`: 모든 카드를 넣으면 상자마다 −/+ 단추와 수 칸(0~20)이 생긴다. `auto`면 모든 카드를 넣은 뒤 상자마다 개수를 보인다.
  - 키보드: 카드(또는 벨트의 지금 카드)에 초점 → 숫자 1~4로 그 상자에 넣기, 0이나 Backspace로 트레이로. 상자 이름 아이콘·기준·개수 단추는 Enter/Space.
- **Action:** `choose-criterion {criterion}`, `change-criterion`, `move {card, to: binId|'tray'}`, `label-bin {bin, icon}`, `count {bin, value}`, `reset`
- **Observation:**
  - `mode:'sort'`, `deck`, `criterion: string|null`, `criterionHistory: string[]`
  - `bins: Record<binId, id[]>`, `binOf: Record<id, binId|null>`, `tray: id[]`, `allPlaced`
  - `binLabels: Record<binId, string|null>`
  - `pureBy: string[]`: 비어 있지 않은 모든 상자가 그 속성으로 한 값만 가지는 속성들(pretty 제외)
  - `mismatched: id[]`: 기준 이름 상자에서 상자 값과 다른 카드
  - `counts: Record<binId, number|null>`, `countsCorrect`
  - `removed: id[]`: `prefill`에 있던 카드 중 트레이로 꺼낸 것
  - `valueCounts: Record<string, number>`: 기준 값별 실제 개수(기준이 있을 때만, 화면에는 `countTable:'auto'`일 때만 그린다)
  - `misconceptions`
    - `MC-SORT-INCONSISTENT`: 카드 4장 이상을 넣었고, 카드 2장 이상인 상자 중 하나가 어떤 단일 속성으로도 한 값이 아닐 때
    - `MC-SHAPE-BY-COLOR-SIZE`(objects 묶음만): 카드 2장 이상인 상자 중 하나가 shapeFamily로는 섞였는데 color나 size로는 한 값일 때
    - `MC-COUNT-ONE-TO-ONE`: 학생이 넣은 개수 중 하나가 실제와 정확히 1 차이일 때
    - `MC-SHAPE-ORIENTATION`(objects 묶음만): shapeFamily가 같고 orientation이 다른 두 카드가 서로 다른 상자에 있을 때(트레이 제외)
- **Predicates:** `allPlaced`, `criterionIs {c}`, `pureBy {attribute}`(+ 상자 값이 서로 다름), `noMismatch`, `countsCorrect`, `labelsMatchBy {attribute}`(상자 이름 아이콘 = 그 상자 카드들의 값), `sameBin {a,b}`, `removedOnly {cards}`, `criterionChanged`(기록에 서로 다른 기준이 둘 이상)

### 4. `secret-rule` `predict` 변형
- **설정:** `{ mode:'secret-rule', variant:'predict', deck:'buttons-12', rule:{ attribute, value }, shownExamples?:number(기본 4), predictionsToGuess?:number(기본 3), guessOptions:{ attribute, value }[], seed?:number }`
  - `rule`은 `guessOptions` 안에 있어야 한다(설정 오류). `guessOptions`는 2~6개.
  - 예시 카드는 seed로 정한 고정 순서다. 예시에는 예·아니요가 하나 이상씩 들어가게 고른다.
- **화면:** 상자 둘 "예"·"아니요"에 예시 카드가 들어 있다. 위에 새 카드 하나. 예측 단추 [예 상자]·[아니요 상자](끌어서도 된다).
  - 예측하면 카드가 실제 상자로 옮겨지고 "맞았어요"/"다른 상자였어요"를 글로 보인다(게임 결과라 노출 아님).
  - 연속 정답 `streak`이 `predictionsToGuess`에 닿으면 기준 고르기 칸이 열린다(`guessOptions` 단추, "빨간색", "구멍 4개" 같은 이름). 틀리면 "카드를 더 보고 다시 골라요"를 보이고 다시 예측을 이어 간다(streak 0으로).
  - 카드가 다 떨어지면 예시가 아닌 카드를 seed 순서로 다시 낸다.
- **정답 노출 금지:** 비밀 기준(`rule`)은 DOM·aria·`data-` 어디에도 맞히기 전에는 없다.
- **Action:** `predict {bin:'yes'|'no'}`, `guess {attribute, value}`, `reset`(streak·예측만 처음으로)
- **Observation:** `mode`, `variant:'predict'`, `streak`, `predictions`, `correctPredictions`, `unlocked`, `guesses`(시도 수), `guessedRight`, `misconceptions: []`
- **Predicates:** `guessedRight`, `streakAtLeast {n}`

### 5. 오버레이 (`CanvasAlignedOverlay`, 판과 1px 정렬)
- `bin-attributes`(MC-SORT-INCONSISTENT ②): 상자마다 든 카드의 속성 아이콘 줄을 상자 옆에 늘어놓고, 그 상자 안에서 다른 값 아이콘에 굵은 테두리를 두른다.
- `two-friends`(MC-SORT-SUBJECTIVE ②): "친구 1", "친구 2" 작은 상자 그림 둘을 나란히 그린다. 같은 단추 4장(b01·b06·b10·b11 고정)이 서로 다르게 나뉜 고정 그림이다.
- `touch-dots`(MC-COUNT-ONE-TO-ONE ②): 상자 안 카드마다 짚는 점 하나를 차례로 찍는다(200ms 간격, reduced-motion이면 한 번에). **번호는 쓰지 않는다**(개수 정답 노출 방지, 명세의 "번호"를 바꾼 것 — 메모에 적는다).
- `gray-shapes`(MC-SHAPE-BY-COLOR-SIZE ②): 상자 안 카드 위에 같은 그림을 회색으로 덮어 생김새만 보이게 한다.
- `rotate-match`(MC-SHAPE-ORIENTATION ②): o-can-side가 판에 있으면 그 그림을 90° 돌려 o-can-up 자리에 겹치는 1초 애니메이션(reduced-motion이면 돌린 그림만). 없으면 그리지 않는다.

- E2E는 요소의 boundingBox로만 좌표를 잡고 논리 높이를 가정하지 않는다(64px 카드 검사만 판 상자 너비/1000을 배율로 쓴다).

**설정·동작에서 카드에 없던 것을 정한 곳**
- 샌드박스 모드 상자: `sort`, `predict` 두 줄을 더했다. `predict`는 secret-rule의 predict 변형이다(`{mode:'predict'}`와 `{variant:'predict'}` 모두 같은 변형). **상태의 `mode`는 'predict'**(기존 secret-rule 상태·reduce와 섞이지 않게)이고 **관찰의 `mode`는 'secret-rule', `variant`는 'predict'**(명세대로). fit-canvas의 모드 확인은 이 차이를 알도록 고쳤다.
- predict 설정에 `rule`·`guessOptions`를 둘 다 안 주면 기본 기준(빨강)과 색 3·모양 3 목록을 쓴다(샌드박스용). 하나라도 주면 둘 다 있어야 하고, rule이 guessOptions 안에 있어야 한다. 아니면 설정 오류.
- sort 설정 오류: 없는 묶음·카드 id·중복 카드·빈 카드 목록·묶음에 없는 기준(사물에 pretty 포함)·기준 고르기 없는 criterion-values·상자 수 1~4 밖·없는 prefill 카드/상자·**prefill + criterionChoice(상자가 기준을 고른 뒤에야 생기므로)**. predict 오류: rule이 guessOptions 밖·guessOptions 2~6 밖·shownExamples 2~8 밖·predictionsToGuess 1~12 밖·buttons-12 아닌 묶음. 오류면 학생 화면에는 "선생님께 알려 주세요"만 보이고 Action은 모두 무시한다.
- predict의 `reset`: streak·예측 수·맞힌 예측 수·잠금·예시/새 카드 순서를 처음으로 되돌리고 `guesses`와 `guessedRight`는 남긴다("streak·예측만"을 그대로 읽음). 화면에 reset 단추는 없다.
- predict에서 기준 맞히기 칸은 한 번 열리면(`unlocked`) 틀린 기준을 고르기 전까지 열려 있다(그 사이 틀린 예측으로 streak이 0이 돼도). 틀린 기준이면 streak 0·다시 잠김. 맞은 뒤에는 예측이 더 늘지 않는다. 카드 12장을 똑같이 가르는 기준이면 다른 옵션이어도 맞은 것으로 본다.
- predict 새 카드: 예시가 아닌 카드를 seed 순서로 돌아가며 낸다. 한 바퀴 뒤 다시 나오는 카드는 상자에서 꺼내어 새 카드로 낸다.
- `pureBy` predicate는 관찰의 새 필드 `pureDistinctBy`(상자 값이 서로 다른 pureBy)를 본다. 관찰 `pureBy`는 명세 그대로 "한 값만"이다. `labelsMatchBy`는 비어 있지 않은 모든 상자에 그 속성의 이름 아이콘이 있고 값이 그 상자 카드와 같으며, 상자끼리 값이 서로 달라야 참이다. `noMismatch`는 기준을 고른 뒤 넣은 카드가 1장 이상이고 mismatched가 비어 있을 때(pretty는 mismatched가 항상 비어 참).
- 상자 이름 아이콘은 `attribute:value` 문자열(`shapeFamily:box`, `color:red`, `holes:4`)이다. 사물은 shapeFamily 아이콘만(상자 모양·둥근기둥 모양·공 모양), 단추는 색·모양·구멍 아이콘 전부. 같은 아이콘을 다시 누르면 이름이 지워진다.
- 개수표 student: 칸은 number 입력과 [−][+]. 안 센 칸에서 −를 누르면 0, +를 누르면 1이 된다(빈 상자를 0으로 쓸 수 있게). 기준을 바꾸면 쓴 개수가 지워진다.
- `MC-SORT-INCONSISTENT`의 "어떤 단일 속성"은 묶음의 기준 속성(단추 color·shape·holes, 사물 shapeFamily·color·size, orientation 제외)이다.
- 새 이벤트: sort `card-placed`·`criterion-chosen`·`all-placed`, predict `predicted`·`rule-guessed`.
- `hasMisconception {code}` predicate는 **이미 있었고**(모든 모드의 관찰 `misconceptions`를 본다) 새로 만들지 않았다. sort·predict 관찰에도 그대로 작동한다(단위 테스트에 있음).
