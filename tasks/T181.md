## 목표
E15에 `gears` 모드를 더한다. g5s1u2.A2 "맞물려 도는 톱니바퀴"(최소공배수)에 쓴다.
- 톱니 수가 다른 두 바퀴가 맞물려 있다. 각 바퀴의 표시 톱니(빨강 + 무늬)가 처음에 맞닿아 있다.
- 한 칸씩 돌리면 두 표시가 언제 다시 맞닿는지 관찰한다.
- 아래 E03 `skip-count` 수직선과는 실행기 `links`로 잇는다.
  - E03은 이미 `value-changed {value}` 이벤트를 받아 그 위치에 연동 점을 그린다(`E03 events.ts receive`).
  - gears는 돌린 칸 수를 이 이벤트로 내보낸다. E03은 고치지 않는다.

### 2. 설정
```ts
interface GearsConfig {
  mode: 'gears';
  teethA?: number;      // 3~12, 기본 4
  teethB?: number;      // 3~12, 기본 6
  maxSteps?: number;    // 돌릴 수 있는 최대 칸(기본 60), 12~120
  predict?: boolean;    // 돌리기 전에 예측 입력(기본 false). true면 예측을 정하기 전에는 돌릴 수 없다
  showLaps?: boolean;   // 바퀴 수 표시(기본 true)
}
```

### 3. 상태와 Action
- **상태:** `{ mode:'gears', settings, steps: number, meetings: number[], predictionDraft: string, prediction: string | null }`
  - `steps`는 돌린 톱니 칸 수다(0 이상, 정수).
  - `meetings`는 지나간 맞닿은 칸 수다(오름차순, 0 제외).
- **Action**
  - `turn {by: 1 | -1}`: 범위 0~maxSteps로 자른다. 뒤로 돌려도 `meetings`는 지우지 않는다.
  - `turn-to {steps}`: 끌기용이다.
  - `reset`
  - `predict-type {key}`, `predict-backspace`, `predict-lock`: 정수 1~999이고, 한 번 정하면 바꿀 수 없다.
- 맞닿음은 `steps % teethA === 0 && steps % teethB === 0`이다. 정수 칸 수라 number를 써도 된다(격자 인덱스 예외).

### 4. 화면 (`GearsView.tsx`)
- **판 SVG** `data-testid="gears-canvas"`
  - 두 톱니바퀴를 옆으로 맞물리게 그린다. 톱니 하나 크기를 같게 해서 반지름이 톱니 수에 비례한다.
  - A는 시계 방향으로 한 칸에 360/teethA도, B는 반대 방향으로 360/teethB도 돈다.
  - 표시 톱니는 빨강 + 굵은 윤곽 + 점 무늬다(색만으로 구분 금지).
  - 두 표시가 맞닿은 순간(`steps > 0`이고 맞닿음)에는 맞닿은 곳에 별 모양 표시와 "다시 만났어요!" 글자를 쓴다. `aria-live`로 알린다.
  - 바퀴 가운데에 톱니 수를 쓴다.
- **돌리기**
  - "한 칸 돌리기" / "한 칸 되돌리기" 단추(targetSize 이상)
  - 바퀴를 끌어 돌리기(Pointer Events): 끈 각도를 A 기준 칸 수로 바꾼다.
  - 키보드: →/← 한 칸
  - 애니메이션은 한 칸 0.2초 이하이고, reduced-motion이면 바로 그린다.
- **기록 판**
  - "돌린 칸: n"
  - showLaps면 "A 바퀴: a번째 바퀴 b칸" 같은 표시
- **예측(`predict`)**
  - 숫자 패드와 "예측 정하기" 단추가 있다.
  - 정하기 전에는 돌리기 단추가 비활성이고, 이유 문구를 보여 준다.
  - 정한 예측은 판 위에 "내 예측: n"으로 남는다.
- **판 맞춤:** T170·T178 원칙과 같다. 줄이지 말고 스크롤한다. 문구는 `strings.ko.ts`에 둔다.

### 5. 이벤트
- `value-changed {value: String(steps)}`: steps가 바뀔 때마다 낸다(E03 연동용).
- `gears-met {steps}`: 새로 맞닿을 때 낸다.
- `EVENT_NAMES`에 둘을 더한다.

### 6. Observation과 predicate
- **Observation:** `teethA`, `teethB`, `steps`, `meetings`, `aligned`(지금 맞닿음), `prediction`, `misconceptions`
  - 최소공배수 값 자체는 넣지 않는다. `meetings`는 학생이 지나간 기록이라 괜찮다.
- **Predicate**
  - `metAtLeast {n}`: meetings 개수 ≥ n
  - `reachedSteps {n}`: 지금까지 최대 steps ≥ n. 상태에 `maxReached`를 둔다.
  - `predictionIs {value}`
  - `predictionLocked {}`
  - `hasMisconception {code}`
- **오개념 `MC-LCM-AS-PRODUCT`:** 예측이 teethA × teethB이고 그것이 최소공배수가 아니면 건다.

### 7. 오버레이 `meet-trail` (`gears-canvas` 기준, LCM-AS-PRODUCT ②)
- 판 아래 띠에 0부터 `max(prediction, steps)`까지 작은 두 줄 눈금을 그린다.
  - 윗줄은 teethA마다, 아랫줄은 teethB마다 점을 찍는다.
  - 두 줄이 겹치는 칸에 세로 강조 선과 무늬를 그린다.
- 예측이 없으면 `steps`까지만 그린다. 명세 ②가 "12 지점이 이미 겹쳐 빛남"이므로 겹침 표시는 허용한다.

### 8. 테스트
- **단위**
  - `gears.ts`: 맞닿음(4·6 → 12, 24), 6·9 → 18, 서로소 3·5 → 15, 같은 수 4·4 → 4
  - maxSteps 자르기, 되돌려도 meetings 유지
  - 예측 잠금 전 turn 무시
  - LCM-AS-PRODUCT(4·6에 24 걸림, 3·5에 15 안 걸림)
  - 이벤트 두 개
  - 직렬화
- **View:** 최소공배수 수가 시작 화면 DOM에 없음. 예측 모드에서 단추 비활성.
- **E2E (`tests/e2e/pattern.spec.ts`에 gears 묶음, 3 뷰포트)**

  - 키보드만으로 같은 흐름
  - 끌어 돌리기 한 번
  - 예측 24 → LCM-AS-PRODUCT, `meet-trail` 1px 정렬
  - 크롬북·아이패드 스냅샷

  - 샌드박스에서 E03과의 연동 확인은 콘텐츠 카드에서 한다.

## 메모

### 구현 메모 (T181, 소넷)
- 새 파일: `gears.ts`(맞닿음·reduce·오개념), `gears-layout.ts`(판 좌표·톱니 모양, View·오버레이 공용), `GearsView.tsx`, `overlays/meet-trail.tsx`. 기존 파일은 `types/reduce/observe/events/settings/index/View/strings/helpers/CSS`에 gears 분기만 더했다.
- 결정 보완
  - `maxReached`는 상태에 두고, `meetings`는 `maxReached`까지 새로 지나간 공배수를 더한다(끌어서 건너뛰어도 지나간 맞닿음을 센다). `reset`은 steps·maxReached·meetings를 비우고 예측은 그대로 둔다.
  - Observation 키: `teethA, teethB, steps, maxReached, meetings, aligned, prediction(숫자|null), misconceptions`. `aligned`는 0칸도 true(식 그대로). 화면의 별·글자는 `steps > 0`일 때만.
  - 이벤트 `value-changed {value: String(steps)}`는 steps가 바뀔 때마다(reset 포함), `gears-met {steps}`는 새로 지나간 공배수마다 낸다.
  - 바퀴 기하: 피치 60(논리), 왼쪽 바퀴 톱니는 맞닿는 곳(3시 방향)에 있고 오른쪽 바퀴는 그곳에 홈이 있어 톱니가 반 칸 비껴 있다. 표시 톱니(빨강+굵은 윤곽 4+점 무늬)는 처음에 맞닿는 곳 양옆에 놓인다. 왼쪽 시계 방향, 오른쪽 반대 방향.
  - 맞닿음 표시: 맞닿는 점에 작은 점, 바퀴 위에 별 모양 + 점선 + 글자 "다시 만났어요!"(SVG, aria-hidden) + 같은 뜻의 `aria-live` 문구(srOnly). 별을 맞닿는 곳 바로 위에 두면 표시 톱니를 가려 바퀴 위쪽으로 올렸다.
  - 판 맞춤: 톱니 한 칸(피치) 화면 32px(논리 60 → 배율 0.53) 아래로는 줄이지 않고 판 안에서 스크롤한다. 구현 결정 문서에는 값이 없어 growth의 24px(쌓기나무 한 변) 대신 이 값을 골랐다. 작은 바퀴(4·6)는 최대 2.5배까지 키운다.
  - 바퀴 수 표시 문구: "왼쪽 바퀴: a바퀴와 b칸"(완성한 바퀴 수 + 남은 칸). 명세 예시 "a번째 바퀴 b칸"은 12칸에서 "4번째 바퀴 0칸"처럼 헷갈려 바꿨다. 바퀴 이름은 A·B 대신 왼쪽·오른쪽(학생 화면).
  - 끌기: 바퀴 몸통을 누르고 돌리면 누른 바퀴 기준 각도 변화를 칸으로 바꿔 `turn-to`를 보낸다(왼쪽은 시계 방향, 오른쪽은 반대 방향이 앞).
  - meet-trail: 눈금은 `min(maxSteps, max(1, 예측, steps))`까지만 그린다(예측이 maxSteps보다 커도 판에 보이게). 숫자 라벨은 0과 끝 칸만, 겹침 칸 번호는 쓰지 않는다. 겹침은 세로 굵은 선 + 마름모.
- 알려 둘 것
  - 톱니 수 범위 3~12와 maxSteps 상한 120 사이에서 11·12처럼 최소공배수가 120을 넘는 짝(132)이 나온다. 콘텐츠 카드에서 그런 짝을 쓰지 않게 해야 한다.
  - 아이패드 세로 `stage=fit`처럼 판 높이가 좁은 화면은 판이 최소 크기(톱니 32px)까지 줄고 조작 묶음이 스크롤된다(growth와 같은 방식).
- 스냅샷: 새로 만든 것 4개(`pattern-gears`, `pattern-gears-predict`의 크롬북·아이패드). 기존 스냅샷은 다시 만들지 않았다.
