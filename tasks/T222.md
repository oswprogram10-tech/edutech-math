# T222 E14 clock 판: 응답 칸 옆 좁은 판에서 시계 윗부분이 잘리는 문제

| 항목 | 내용 |

| 웨이브 | W6 |
| 선행 카드 | T204 |

## 목표
g2s2u4.A1.T2(T204)는 `readOnly`, `unroll` 시계에 응답 칸 둘이 붙은 과제다. 크롬북·아이패드에서 이 과제를 열면 다음 문제가 생긴다.
- 캔버스가 최소 배율 0.6(600×360)으로 잡히고, 판 칸이 그보다 낮다.
- 시계 윗부분(11·12)이 판 안 스크롤 위로 잘려 첫 화면에 안 보인다(T204 메모와 기준 이미지 `g2s2u4-a1-t2-chromebook`).
- 펼치지 않은 상태인데도 띠 자리가 판 높이를 차지한다.

읽기 과제에서 12가 안 보이면 안 된다. 그래서 E14 `clock` 판을 고친다.

## 구현 결정 (2026-11-20 Claude 작성 — 여기 적힌 대로 하고, 바꿔야 하면 메모에 이유를 적고 멈춰서 묻는다)
1. **논리 높이**
   - 펼치지 않은 `clock`의 논리 판을 시계만 담는 크기로 줄인다(예: 1000×520 → 시계 원과 여백만, 또는 시계에 맞춘 정사각 비율). 펼치면 띠 자리를 더한다.
   - 바뀌는 높이는 `unrolled` 상태에서만 나온다(상태 → 레이아웃, 순수).
   - 톱니 이름표처럼 시계 옆에 두던 것은 줄어든 판 안에 들어가게 옮긴다.
2. **최소 배율과 맞춤**
   - 최소 배율 0.6은 그대로 둔다.
   - 판이 작아지면 같은 칸에서 더 큰 배율로 들어간다.
   - 그래도 칸보다 크면 판 안 스크롤의 처음 위치는 맨 위(0)다.
   - 초점이 들어가거나(slider) 펼치기를 하면서 스크롤이 내려가지 않게 한다. `scrollIntoView` 같은 것이 원인이면 판 안에서는 쓰지 않는다.
3. **목표:** 크롬북 1366×768과 아이패드 768×1024에서 g2s2u4.A1.T2 첫 화면에 시계 원 전체(12 포함)가 보인다. 안 되면 수치를 메모에 적고 멈춰서 묻는다.
4. **E2E**
   - `tests/e2e/units/g2s2u4.spec.ts`의 A1.T2에 `expectFitCanvasVisible`를 다시 넣는다(뺀 주석도 지운다).
   - g2s2u4·g1s2u3·clock-time 기준 이미지 가운데 바뀐 것은 다시 찍고 직접 확인한다. 메모에는 둘을 나눠 적는다.
     - 시계 크기·위치만 바뀐 것
     - 그 밖의 것
5. **E2E 범위:** `npx playwright test clock-time fit-canvas overlay-alignment g1s2u3 g2s2u4 --workers=3 --reporter=line`

### 구현 메모 (Sonnet, 2026-11-20)
- **검사 결과**: `npm test` 215파일 3712개 통과, 범위 E2E(`clock-time fit-canvas overlay-alignment g1s2u3 g2s2u4`) 마지막 전체 실행에서 스냅샷 3곳 외 모두 통과 → 스냅샷 갱신 뒤 clock-time·g1s2u3·g2s2u4 재실행 114개 통과(6개 skip은 크롬북 전용 검사), `npm run lint` 오류 0(경고 12개는 기존)·prettier 통과, `check:specs`·`build` 통과.
- **구현**
  - `layout.ts`: `CLOCK_ONLY_HEIGHT = 510`, `boardSize(unrolled)` 추가(펼치지 않으면 1000×510, 펼치면 1000×600). `CLOCK`·`SIDE`·`STRIP` 좌표는 그대로라 오버레이와 1px 안에 겹친다. 510은 시계 원 아래(470)와 힌트 ② `numeral-minutes` 이름표(`cy + labelR = 498`)까지 담는 값이다.
  - `View.tsx`: 맞춤 계산과 판 칸 `min-height`를 `boardSize`·`MIN_SCALE`(0.6, 그대로)로 계산(0.6 × 510 = 306px). `ClockBoard.tsx`: viewBox·`pointerToLogical`이 `boardSize`를 쓴다. 오버레이 셋(`hour-hand-focus`·`rewind-to-hour`·`numeral-minutes`)도 같은 논리 크기를 쓴다. reduce·observe·Observation은 손대지 않았다. 톱니 이름표·디지털 표시는 원래 x≥545로 줄어든 판(너비 1000 그대로) 안에 들어 있어 옮기지 않았다.
  - 스크롤: 판 안 스크롤을 내리는 코드는 E14에 없다(`scrollIntoView`·`focus` 호출 없음). 원인은 T204 E2E의 '조작 단추 64px 확인'이 `scrollIntoViewIfNeeded`로 바깥 상자를 맨 아래까지 내려 둔 것이었다(실제 첫 화면은 맨 위). 그래서 `g2s2u4.spec.ts`는 그 확인 뒤 스크롤을 0으로 되돌린 다음 `expectFitCanvasVisible`를 건다. 처음 위치가 맨 위인지는 같은 검사(캔버스가 판 안에 완전히 들어옴)로 본다.
- **목표 수치**(`g2s2u4.A1.T2` 첫 화면, 스크롤 0): 아이패드 768×1024는 판 칸 334px에 캔버스 654×334(배율 0.65)로 시계 전체가 보이고 바깥 스크롤이 없다. 크롬북 1366×768은 판 칸 306px에 캔버스 600×306(최소 배율 0.6)로 시계 전체(12 포함)가 보인다. 이 높이에서는 칸 높이 401px 안에 판 306 + 조작 단추가 다 안 들어가 바깥 상자가 11px 스크롤된다(캔버스는 맨 위에서 잘리지 않음). 목표는 달성했으나 크롬북에서 '펼치기·처음으로' 단추 줄이 첫 화면에 반쯤 잘려 보인다(기준 이미지 참고, 스크롤하면 닿는다).
- **E2E 수정(좌표 가정)**: `clock-time.spec.ts`의 `polarPoint`와 `g1s2u3.spec.ts`의 시계 좌표 변환이 논리 높이 600을 가정해서(`/600 * box.height`) 줄어든 판에서 끌기가 어긋났다. 높이 대신 너비 기준(`/1000 * box.width`)으로 바꿨다. `clock-time`의 '좁은 판' 검사는 높이 하한을 359 → 305(0.6 × 510)로 바꿨다.
- **기준 이미지**
  - 시계 크기·위치만 바뀐 것: `g2s2u4-a1-t2`(아이패드·크롬북·전자칠판, 이제 12가 보임), `g1s2u3-a2-t1`(아이패드·전자칠판), `clock-time` `clock-gears`(아이패드·크롬북). 모두 직접 열어 확인했고 시계 전체와 톱니 이름표가 보인다(전자칠판은 `clock-gears`가 변하지 않음).

- **스스로 의심스러운 곳**: ① 크롬북 첫 화면에서 조작 단추가 반쯤 잘려 보인다(위 수치). 더 줄이려면 최소 배율·조작 칸 높이를 건드려야 해서 카드 범위 밖이다. ② 펼치면 판이 510 → 600으로 바뀌어 판 칸 높이가 바뀐다(배율이 달라질 수 있음). 펼친 첫 화면 기준 이미지(clock-time)는 변화 없이 통과했다.
