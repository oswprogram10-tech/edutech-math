## 구현 결정 (2026-11-03 Claude 작성 — 여기 적힌 대로 하고, 바꿔야 하면 메모에 이유를 적고 질문한다)
1. **위치와 모양:** `src/core/runner/response/`(types.ts, reduce.ts, observe.ts, ResponseView.tsx, 위젯별 컴포넌트, strings.ko.ts, `__tests__/`). 응답은 엔진이 아니라 **실행기의 특별 슬롯 `response`**다. 엔진 레지스트리에 등록하지 않지만, 슬롯 기록이 그대로 쓰이도록 `createInitialState`·`reduce`(순수)·`observe`·`View`를 엔진과 같은 모양으로 만든다. 그래서 되돌리기·기록(`acted {slot:'response', ...}`)·재생(`replaySlots`)이 기존 구조로 동작한다. 슬롯 이름 `response`는 예약어(`views`에서 쓰면 스키마 오류).
2. **콘텐츠 스키마:** `ContentTask`에 `response?: ResponseSpec`, `showEngine?: boolean`(기본 true)을 더한다. `ResponseSpec = { fields: ResponseField[] }`, 필드마다 `id`(과제 안에서 유일)와 `kind`. 한 과제에 필드가 여럿일 수 있다(예: g3s1u6.A3 "4/10, 0.4"는 number 필드 2개). `response`가 있으면 `submit`은 `'button'`이어야 한다(zod refine). `showEngine:false`이면 엔진 패널을 그리지 않는다(A 단계 "식만" 과제). 엔진 상태는 그대로 만들어 판정·재생 일관성을 지킨다.
3. **필드 종류와 Observation**(판정 경로는 `response.<필드id>.<키>`):
   - `number` — 설정 `forms`(`integer`·`fraction`·`mixed`·`decimal` 중 허용할 것), `label?`. Observation `{ raw, value, form, valid, irreducible }`. `raw`는 학생이 쓴 표기 그대로 정규화(`"4/10"`, `"1 2/9"`, `"0.40"` — 끝자리 0과 약분 전 표기를 지운다면 오개념 판정이 불가능하므로 **절대 바꾸지 않는다**), `value`는 `Rational.toJSON()`(무효면 null), 분모 0·빈칸은 `valid:false`.
   - `choice` — `options: [{ id, label?, figure? }]`, `multiple: boolean`. Observation `{ selected: [id…] }`(id 오름차순).
   - `order` — `items: [{ id, label?, figure? }]`(콘텐츠에 적힌 순서가 처음 순서). Observation `{ order: [id…] }`.
   - `compare` — `left`, `right`(화면에 보일 수·식 문자열). Observation `{ symbol: '<' | '=' | '>' | null }`.
   - `sort` — `cards: [{ id, label }]`, `bins: [{ id, label }]`. Observation `{ bins: { [binId]: [cardId…] }, unsorted: [cardId…] }`(id 오름차순).
4. **판정:** 기존 `evaluateGoal`에 넘기는 Observation을 `{ ...판정 슬롯 Observation, response: 응답 Observation }`으로 합친다. predicate는 지금처럼 판정 슬롯 엔진의 것을 쓴다. 판정은 GoalSpec(`equals` 경로 값 비교, `all`/`any`)로만 한다 — 예: `{ kind:'equals', path:'response.ans.value', value:'6/5' }`는 `6/5`와 `1 1/5`를 모두 정답으로 받고, 표기까지 요구하면 `response.ans.raw`를 쓴다.
5. **수 입력 화면:** 화면 키패드(0~9, 분수 틀, 대분수 틀, 소수점, 지우기, 모두 지우기). 분수는 자연수·분자·분모 **칸이 따로 있는 틀**로 입력한다(문자열 파싱에 기대지 않는다). 허용 형식이 여럿이면 틀 바꾸기 버튼. 실제 키보드도 받는다(숫자, `/`, `.`, 스페이스, Backspace, Tab으로 칸 이동). iPad에서 OS 키보드가 뜨지 않게 `inputmode="none"` 또는 버튼 기반으로 만든다. 처음에는 **빈칸**이다(예시 값·자리 표시 숫자 금지).
6. **그림 선택지(`figure`):** `{ engine, mode, cpa, config }`이면 그 엔진 View를 **읽기 전용·작은 크기**로 그린다(`createInitialState(config)`, `readOnly`). 실행기가 불러올 엔진 목록에 figure 엔진도 넣는다 — `engineIdsOfContent(content)`를 `src/core/runner`에 만들고 `src/app/Runner.tsx`·`ActivityScreen.tsx`가 그것을 쓴다.
7. **조작:** 모든 변경은 Action 한 번(키패드 버튼 한 번 = Action 한 번). `order`는 위/아래 버튼 + 끌기, `sort`는 카드 탭 → 상자 탭 + 끌기(Pointer Events). 키보드만으로 모든 위젯을 끝까지 할 수 있어야 한다. 터치 타깃은 `targetSize` 이상, 선택 상태는 색 외에 체크 표시·테두리로도 구분.
8. **정답 노출 금지:** 제출 전에는 맞았는지 어떤 표시도 하지 않는다. 틀린 제출 뒤에도 어느 칸이 틀렸는지 표시하지 않는다(힌트는 T012). 선택지 순서는 콘텐츠 그대로(실행기가 섞지 않음 — 재생 결정성).
9. **문구:** 위젯 문구는 `response/strings.ko.ts`, 선택지·카드 이름은 콘텐츠 JSON.
10. **데모 콘텐츠:** `data/content/demo.json`에 활동 `demo.A3`(응답 위젯 맛보기)를 새로 추가한다. 과제마다 위젯 한 종류(number 분수, choice + E05 figure, order, compare, sort, `showEngine:false` 하나 포함). 기존 `demo.A1`·`demo.A2`는 바꾸지 않는다.
11. **테스트:** 위젯별 reduce·observe 단위 테스트(빈칸, 분모 0, 대분수, `0.40`의 raw 유지, 약분 전 표기 `4/10`), 스키마 테스트(`response` 있는데 `submit:'auto'` → 오류, `views`에 `response` 슬롯 → 오류), 합친 Observation 판정 테스트, `replaySlots`가 응답 슬롯을 재생하는 테스트, `assertSerializable`. E2E(3개 뷰포트): `#/activity/demo.A3`에서 위젯마다 틀린 제출 → 실패 문구만 나오고 정답 값이 DOM에 없음 → 고쳐서 통과, 되돌리기 한 번, 키보드만으로 분수 입력 1과제.
