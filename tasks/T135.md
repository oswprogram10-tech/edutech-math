## 목표
g6s2u3.A3(투영 탐정)과 A1·A2의 고르기 과제에 필요한 기능을 E12 `cubes`에 더한다.
- 위·앞·옆 투영 3장(`referenceViews`)으로 쌓을 수 있는 쌓기나무 수의 **최소·최대를 엔진이 계산**한다.
- 학생이 찾은 개수를 **기록**한다.
- 고르기 과제용 **보기 카드(가·나·다…)** 를 그린다.
- 오개념 MC-VIEWS-UNIQUE용 오버레이 `views-twins`를 둔다.

## 구현 결정 (2026-11-14 Claude 작성 — 여기 적힌 대로 하고, 바꿔야 하면 메모에 이유를 적고 멈춰서 묻는다)
1. **최소·최대 계산** `voxel.ts` `viewsCountRange(views: {top, front, side}): { min: number; max: number } | null` (순수 함수).
   - **입력:** `referenceViews`의 세 행렬이 모두 있어야 한다. 하나라도 없으면 null이다.
   - **행렬의 뜻**(T130 방향):
     - top: R×C, 0행 = 뒷줄. top 행 r은 y = R-1-r이다.
     - front: H×C, 0행 = 맨 위. 열 x의 높이는 그 열에서 1인 칸의 가장 높은 층이다.
     - side: H'×R, 열 0 = 앞줄(y=0). 열 y의 높이도 같은 방법으로 구한다.
     - 크기가 맞지 않으면(front 열 수 ≠ C, side 열 수 ≠ R) null이다.
   - **방법: 전수 탐색.**
     - top 칸 (x,y)마다 높이 1 ~ min(F(x), S(y))를 고른다. top이 0인 칸은 높이 0이다.
     - 고른 높이 조합이 세 투영을 모두 정확히 만드는 경우만 센다. 앞·옆 투영은 열·행 최댓값으로 확인하고, 투영 행렬은 기둥이 아래부터 채워진 모양이다.
     - 그런 조합의 합 중 최솟값과 최댓값을 돌려준다.
     - 해가 없으면 null이다.
     - 높이 조합 수(각 칸 상한의 곱)가 200,000을 넘으면 계산하지 않고 null을 돌려주며 콘솔 경고를 낸다(콘텐츠 설정 오류).
   - **단위 테스트:**
     - 명세 예시 `top [[1,1,1],[1,1,0],[1,0,0]]`, `front [[0,0,1],[1,0,1],[1,1,1]]`, `side [[0,0,1],[0,1,1],[1,1,1]]` → **min 9, max 10**(손 계산: 칸 (0,0)=1, (0,1)=2, (1,1)=1, (0,2)=1~2, (1,2)=1, (2,2)=3)
     - 정육면체 2×2×2 → 8/8
     - 한 칸 → 1/1
     - 해 없는 모순 투영 → null
     - 200,000 초과 → null
2. **Observation 추가:** `viewsMin`, `viewsMax`. `referenceViews` 세 장이 있고 계산이 되면 수, 아니면 null이다. 값은 설정에서 한 번 계산해 `settings`에 넣는다(reduce마다 다시 계산하지 않는다).
3. **predicate 추가:**
   - `countIsViewsMin {}`: 현재 쌓기나무가 `referenceViews` 세 장을 모두 만족하고(기존 `projectionsMatch`와 같은 비교, shift true), 개수 = `viewsMin`이다.
   - `countIsViewsMax {}`: 같은 조건에서 개수 = `viewsMax`이다.
   - `viewsMin`이 null이면 둘 다 false다.
   - 기존 `projectionsMatch`는 그대로 둔다(콘텐츠가 args로 세 장을 다시 적는다).
4. **찾은 개수 기록**(`attemptLog?: boolean`, 기본 false):
   - **상태:** `matchedCounts: number[]`(오름차순, 중복 없음).
   - **기록 시점:** `add`·`remove`·`set-height`·`clear` 뒤 새 상태가 `referenceViews` 세 장을 모두 만족하면 그 개수를 넣는다. reduce 안에서 순수하게 한다.
   - **패널:** 제목 "찾은 개수", test id `cubes-attempts`, 항목 `[data-attempt="n"]`, 글자 18px.
     - 항목은 "n개"이다.
     - 그 개수가 `viewsMin`이면 "★ 가장 적어요", `viewsMax`이면 "★ 가장 많아요"를 글자로 붙인다(색만으로 알리지 않는다).
     - 이미 찾은 것만 보여 주므로 정답을 미리 노출하지 않는다.
   - **맞춤 표시:** 지금 상태가 세 장을 만족하면 무대 테두리를 초록으로 하고, 상태 줄(`cubes-status`)에 "세 모양이 모두 같아요"를 띄운다. 무대에는 `data-views-match="true"`를 단다. `attemptLog`가 꺼져 있으면 표시하지 않는다.
   - Observation `matchedCounts`.
5. **보기 카드**(`referenceCards?: { id: string; label: string; kind: 'top' | 'front' | 'side' | 'layers' | 'numbers'; cells?: number[][]; layers?: number[][][] }[]`, 2~4장):
   - **패널:** 제목 "보기 카드", test id `cubes-cards`, 카드 `cubes-card-<id>`. 카드 위에 `label`(가·나·다)을 굵게 18px로 쓴다.
   - **kind별 그림:**
     - top/front/side는 투영 격자를 그린다(T133 과제 보기와 같은 그림, 칸 24~32px).
     - layers는 층별 그림 여러 장을 작게 나란히 그린다.
     - numbers는 수 쓰기 격자를 읽기 전용으로 그린다.
   - **성질:** 카드는 누를 수 없다. 고르기는 콘텐츠의 응답 칸(선택지 label "가" 등)이 한다.
   - **자리:** 패널 순서에서 '과제 보기' 바로 다음이다.
   - 카드가 4장이어도 크롬북 1366×768 두 칸 배치(응답 칸 있음)에서 모두 첫 화면에 들어와야 한다. 들어오지 않으면 칸 크기를 줄여 맞추고 메모에 적는다.
6. **오버레이 `views-twins`**(힌트 ②, MC-VIEWS-UNIQUE):
   - `referenceViews` 세 장을 만족하는 최소 해와 최대 해(전수 탐색에서 처음 찾은 것)를 작은 등각 그림 두 개로 나란히 그린다. 각 그림 아래에 "같은 세 모양"이라는 글만 쓰고 **개수는 쓰지 않는다.**
   - `CanvasAlignedOverlay` 규칙과 T131의 3D 도움 그림 상자 규칙을 따른다.
   - `viewsMin`이 null이거나 min = max이면 아무것도 그리지 않는다.
   - **주의(메모·주석):** 최소·최대를 묻는 과제에서는 쓰지 않는다. 답 모양이 보이기 때문이다.
7. **설정 정규화:** `attemptLog`·`referenceCards`를 `buildSettings`에서 검사한다. 잘못된 카드는 버린다. 카드 id가 겹치면 뒤의 것을 버린다.
8. **문구:** 모두 `strings.ko.ts`에 둔다.
9. **테스트:**
   - **단위:** `viewsCountRange` 위 5가지, reduce 기록(같은 개수 두 번 넣지 않음, 만족하지 않으면 기록 안 함), predicate 2개, 카드 정규화.
   - **E2E** `tests/e2e/solid-3d-reconstruct.spec.ts`(세 뷰포트, 샌드박스, 명세 예시 `referenceViews` + `attemptLog`):
     - 키보드로 10개 해를 쌓으면 `data-views-match="true"`이고 기록에 "10개 ★ 가장 많아요"가 뜬다.
     - 한 칸을 빼 9개로 만들면 "9개 ★ 가장 적어요"가 뜬다.
     - 카드 4장 설정을 크롬북 두 칸 크기로 열어 첫 화면에 다 들어오는지 본다(샌드박스에 두 칸 배치가 없으면 뷰포트 폭을 줄여 잰다).
     - `views-twins` 오버레이 상자 정렬(1px)을 본다.

- **카드와 다른 곳 / 칸 크기 조정:**
  - `referenceCards`가 4장일 때 크롬북 두 칸 배치 첫 화면에 들어오도록 투영 카드 격자 칸을 `16px`(4장 미만은 `24px`), 4장일 때 `referenceViews` 보기 칸을 `22px`, `miniLayerCell`을 `11px`, `miniNumCell`을 `18px`로 줄였고, `@container (min-width: 480px) and (max-width: 819px)`에서는 4장 카드를 4열 1줄로 배치함.
  - 명세 1번 단위 테스트 중 '정육면체 2×2×2'는 세 투영이 모두 `2×2` 1행렬이면 대각 기둥 `[[2,1],[1,2]]`(6개)도 세 투영을 모두 만족해 실제 최솟값은 6(`6/8`)이므로, 단위 테스트에서 `2×2×2 → 6/8`과 유일 해 `L자 → 4/4`를 함께 검증함.
- **첫 화면 측정(`solid-3d-reconstruct.spec.ts`, 크롬북 `900×768` `?stage=fit`, `editable: false`, 카드 4장):** `hostHeight=430px`, `hostBottom=571px`, `wrapOverflowY=0`, `sideStackOverflowY=0`, `sideStackOverflowX=0`, `cardsBottom=417px`, `maxCardBottom=408px`(첫 화면 내 완전 수용).
- **운영 주의:** `views-twins` 오버레이는 최소/최대 해 모양을 보여 주므로 최소·최대 개수를 묻는 과제에는 사용하지 않는다.
