## 구현 결정 (2026-11-04 Claude 작성 — 여기 적힌 대로 하고, 바꿔야 하면 메모에 이유를 적고 질문한다)
1. **폴더·모드:** `src/engines/E02-counters/`만 고친다. `modes`는 기존 4개 뒤에 `rekenrek`, `pairing`, `share`, `measure-out` 순서로 붙인다. `bubble-pairs`·`bridge`는 모드가 아니라 **part-whole의 `variant`**다(`variant?: 'plates' | 'bubble-pairs' | 'bridge'`, 기본 `plates`). 상태는 `mode: 'part-whole'`을 유지하고 `variant`로 구분하는 별도 타입(`BubblePairsState`, `BridgeState`)을 `CountersState` 합집합에 더한다. `inferMode`: `variant`가 있으면 part-whole. View.tsx가 이미 1200줄이므로 새 화면은 `views/RekenrekView.tsx`, `views/PairingView.tsx`, `views/ShareView.tsx`, `views/MeasureOutView.tsx`, `views/BubblePairsView.tsx`, `views/BridgeView.tsx`로 나누고 View.tsx는 모드·변형에 따라 고르기만 한다. reduce도 모드별 파일(`reduce-rekenrek.ts` 등)로 나눠도 된다. 기존 4개 모드의 동작·Observation은 바꾸지 않는다.
2. **수:** 개수·길이는 모두 0 이상의 정수(number). `Rational`은 쓰지 않는다. 무작위가 필요하면(방울 배치) createInitialState에서 `seed`(기본 1)로 한 번만 정한다.
3. **rekenrek:** 설정 `rows`(1~10, 기본 2), `perRow`(10 고정 — 다른 값은 10으로 고친다), `colorBreak`(기본 5), `skipBy`(누르는 단위 버튼 목록, 기본 `[1]`, 예 `[1,2,5,10]`), `showNumeral`(`never` 기본). 상태 `left: number[]`(줄마다 왼쪽으로 민 구슬 수), `history: number[]`(밀기·되밀기 뒤마다의 전체 합). Action `push {row, count}`(그 줄 오른쪽 구슬을 count개 왼쪽으로, 남은 수보다 많으면 남은 만큼), `pull {row, count}`(반대). 조작: 오른쪽에 있는 구슬을 누르거나 왼쪽으로 끌면 **그 구슬과 그보다 왼쪽에 있는 오른쪽 구슬이 함께** 밀린다(실제 셈판처럼). 줄 옆에 `skipBy` 버튼("+1", "+2", "+5", "+10" — 10은 한 줄 통째로)과 "−1" 버튼. 키보드: 줄 포커스 + `←`(skipBy 첫 값만큼 밀기)·`→`(되밀기), 숫자키 1·2·5·0(=10). 구슬 색: 한 줄의 1~5번과 6~10번을 색 + 무늬(속 찬 원 / 가운데 점 원)로 구분한다.
4. **pairing:** 설정 `count`(1~20), `predictFirst`(기본 true), `labels`(두 문구, 기본 `strings.ko.ts`의 `["짝수","홀수"]`), `icon`(`child` 기본 — `icons.tsx`에 인라인 SVG 아이 그림 추가 / `dot`이면 점 2열). 상태 `phase: 'predict' | 'ready' | 'paired'`, `prediction: 0 | 1 | null`(labels 순서). `predictFirst`면 `predict` 단계에서 두 라벨 버튼만 보이고(`predict {choice}`), 고른 뒤 "짝 만들기" 버튼(`make-pairs`)이 열린다. `make-pairs`는 앞에서부터 (0,1), (2,3) … 순서로 짝을 짓는 **결정적** 연출(CSS로 한 쌍씩 차례로, `prefers-reduced-motion`이면 즉시). 남은 1명 옆에 깃발 그림. 짝을 지은 뒤 "짝수/홀수" 글자나 개수를 화면에 쓰지 않는다(깃발만). "다시" 버튼(`reset-pairs`)은 `ready`로 돌리고 prediction은 지우지 않는다.
5. **share(등분제):** 설정 `total`, `groups`(접시 수 2~6), `icon`(기본 `candy`), `showNumeral`. 상태는 개수만: `pile`(아직 안 나눈 수), `plates: number[]`, `rounds`(한 바퀴 버튼 횟수). Action `deal {plate}`(무더기에서 한 개 → 접시; 무더기의 셈돌을 끌어 접시에 놓거나, 접시를 눌러도 같음), `take-back {plate}`(접시에서 한 개 → 무더기), `deal-round`("한 바퀴씩 나누기": 무더기가 접시 수 이상일 때만 모든 접시에 하나씩 — 모자라면 버튼 비활성, 남은 셈돌은 무더기에 그대로 보인다). Observation 키는 part-whole과 같은 `plates`를 써서 기존 `platesAre`를 그대로 쓴다.
6. **measure-out(포함제):** 설정 `total`, `groupSize`(고정) 또는 `groupSizeChoices`(학생이 먼저 고름), `showRemainder`(기본 true), `sentenceTemplate`(예 `"{size}씩 {groups}묶음"`), `icon`(기본 `strawberry`), `showNumeral`. 셈돌마다 `{id, x, y, bag: number | null}`(x·y는 seed로 흩어 놓은 논리 좌표 정수). Action `choose-size {size}`(choices가 있을 때 — 바꾸면 모든 봉지를 푼다), `bag {ids}`(SDK `useLasso`로 감싼 셈돌; 봉지에 안 든 셈돌만 세어 **정확히 groupSize개면** 새 봉지, 아니면 셈돌은 그대로이고 `lastAttempt {count, ok:false}` — E01 올가미와 같은 방식, 실패 배지는 학생이 감싼 개수), `bag-next`("○개 덜어 내기" 버튼: 안 든 셈돌 중 앞에서부터 groupSize개 — 올가미 대체), `unbag {bag}`. 봉지는 새로 생길 때마다 아래 줄에 차례로 놓인다(접시 수 자동 증가). 남은 셈돌이 groupSize보다 적으면 `showRemainder`일 때 "남은 것" 칸으로 모아 점선 테두리(개수는 쓰지 않는다). `sentenceTemplate` 문장은 `showNumeral: "always"`일 때만 보인다(봉지 수가 곧 답이므로).
7. **part-whole `bubble-pairs`:** 설정 `target`(기본 10), `bubbles`(1~9 수 목록), `pickUpTo`(2 기본 / 3 — "세 방울로 10"), `showSumOnMiss`(기본 true), `face`(`"numeral"` 기본 / `"dots"` — P 단계 방울 안 점), `seed`. `timer`는 받지만 무시한다(시간 제한 없음). 방울은 seed로 정한 자리에 놓이고 CSS로 살짝 떠 있는 연출만(물리 없음, reduced-motion이면 정지). 상태 `bubbles: {id, value, popped}[]`, `selected: string[]`, `lastMiss: {ids, sum} | null`, `pops: number[][]`, `streak`, `bestStreak`, `misses`. Action `pick {id}` / `unpick {id}`(방울을 누르기, 또는 한 방울을 다른 방울에 끌어 부딪히면 두 방울 `pick`). reduce가 판정: 고른 합 == target → 그 방울들 popped, `pops`에 값 목록, streak+1. 고른 합 > target이거나 고른 수가 `pickUpTo`에 닿았는데 합 ≠ target → `lastMiss`, 선택 해제, streak 0, misses+1. View는 `lastMiss`가 바뀌면 1.5초 동안 방울이 튕기고 `showSumOnMiss`면 **학생이 고른 방울의 합**을 보여 준다(반례 — 목표 짝을 알려 주지 않는다).
8. **part-whole `bridge`:** 설정 `gap`(2~20), `rods`(고를 수 있는 막대 길이 목록, 1~9, 각 길이는 여러 번 써도 됨), `maxRods`(기본 2), `preset`(처음 놓인 막대 길이 목록, 예 `[9]`·`[9,7]`), `presetLocked`(기본 false — 과제 4 "하나 바꾸기"는 preset을 뺄 수 있어야 한다), `tenMarker`(boolean), `noText`(boolean — 화면 글자 없이 그림·아이콘만, aria-label은 유지), `face`(`"cells"` 기본: 막대에 칸이 보임 / `"numeral"`: 막대 위 숫자만, 칸 숨김). 상태 `placed: number[]`(왼쪽 둑부터 놓은 순서), `recorded: number[][]`(정렬한 길이 목록, 중복 제거). Action `place-rod {length}`(maxRods 초과면 무시), `remove-rod {index}`, `record-bridge`(합 == gap일 때만 쌓는다). 그림: 틈은 gap칸 길이, 막대는 왼쪽 둑부터 이어 놓고, 합이 모자라면 틈이 그대로 보이고 넘치면 막대가 오른쪽 둑 위로 튀어나온다. `tenMarker`: 10칸 자리에 세로 표시선, 10을 넘은 칸은 색 + 빗금. 합 == gap이면 캐릭터가 건너는 CSS 연출(학생이 만든 상태의 결과 표시). 막대 길이 숫자(`face:"numeral"`)는 주어진 재료라 써도 되지만 **틈 길이 숫자와 합은 쓰지 않는다**.
9. **Observation(새 모드):** rekenrek: `rows: number[]`, `total`, `history`, `reached: number[]`(처음 도달한 순서의 서로 다른 합), `fullRowPushes`(한 번에 10개 민 횟수), `moves`. pairing: `phase`, `prediction`(라벨 index 또는 null), `paired`, `pairs`·`leftover`(paired 뒤에만 값, 아니면 null). share: `plates`, `pile`, `equal`(모든 접시 같음), `rounds`, `total`. measure-out: `groupSize`(null 가능), `bags`, `loose`, `total`, `lastAttempt`. bubble-pairs: `pops`, `popCount`, `allPopsHitTarget`, `streak`, `bestStreak`, `misses`, `remaining: number[]`. bridge: `placed`, `sum`, `gap`, `fits`, `recorded`, `distinctBridges`.
10. **Predicates(추가):** `historyIncludesInOrder {values}`(history에 values가 이 순서로 나타남 — "10, 20, 30 … 50"), `reachedAll {values}`, `predictionIs {choice}`, `pairedDone`, `pileIs {value}`, `allPlatesEqual`, `bagsIs {value}`, `looseIs {value}`, `groupSizeIs {value}`, `popsAtLeast {count}`, `poppedWith {size}`(그 개수 방울로 터뜨린 적 있음), `streakAtLeast {count}`, `bridgeFits`, `placedInclude {length}`, `distinctBridgesAtLeast {count}`. 기존 `totalIs`·`platesAre`는 새 모드에서도 같은 뜻으로 동작한다.
11. **이벤트(추가):** rekenrek은 기존 `value-changed {value}`(total). `bubble-popped {values}`, `bagged {size, bags}`. share·pairing·bridge는 새 이벤트 없음.
12. **정답 노출 금지:** 개수·합·봉지 수·짝 수·남은 수는 `showNumeral:"always"`가 아니면 숫자로 쓰지 않는다. 예외는 학생이 고른 방울의 합(빗나감 반례)과 주어진 재료의 숫자(방울 숫자, `face:"numeral"` 막대 길이)뿐이다. 단원 명세 g1s2u4의 힌트 ② "10이 되는 두 수에 같은 색 테두리"는 정답 짝을 알려 주므로 **만들지 않는다**(메모에 docs 수정 제안으로 남긴다).
13. **오버레이(힌트 ② 추가):** `plate-bars`(share: 접시별 개수를 높이 막대로 나란히 — 숫자 없이, MC-DIV-UNEQUAL-SHARE), `pair-march`(pairing: 짝짓기 연출을 다시 보이고 남은 1명 강조, MC-ODD-EVEN-SIZE), `bubble-frame`(bubble-pairs: 지금 고른 방울의 수만큼 텐프레임에 점을 찍고 빈칸을 점선 동그라미로 — 짝 방울은 가리키지 않는다, MC-MAKE10-PAIR), `ten-gap`(bridge: 10칸 표시선까지 남은 빈칸을 점선 동그라미로, MC-MAKE10-SPLIT), `bead-groups`(rekenrek: 민 구슬을 5개·10개 묶음 윤곽으로). 기존 `count-ones`는 share·measure-out에서도 동작하게 한다.
14. **입력·접근성:** Pointer Events만. 구슬·방울·막대·접시·버튼 터치 타깃 ≥ `targetSize`(1~2학년 단원이므로 E2E 한 번은 64로). 모든 새 모드를 끌기 없이 버튼·키보드로 끝낼 수 있어야 한다: rekenrek 버튼, share는 접시 누르기·한 바퀴 버튼, measure-out은 `bag-next`, bubble-pairs는 Tab+Enter로 pick, bridge는 막대 버튼 + Delete로 빼기.

- **구현 결정과 다르게 한 것:**
  1. `groups` 설정 타입을 `readonly number[] | number`로 넓혔다. 기존 part-whole은 접시별 개수 배열, share는 접시 수(number)로 같은 키를 쓴다. 기존 part-whole 동작은 그대로이고 `inferMode`는 number일 때 share로 본다.
  2. bridge `rods`에 같은 길이를 여러 번 적으면 **각각 별개의 막대**로 센다(놓으면 하나씩 소모). `preset`도 같은 막대를 소모한다.
  3. bubble-pairs 배치는 상태에 좌표를 두지 않고 index로 결정한다. `seed`는 방울 목록의 순서를 섞는 데만 쓴다(상태 JSON 유지).
  4. bubble-pairs는 고른 합이 목표를 넘으면 `pickUpTo`에 닿기 전이라도 바로 빗나감으로 처리한다(수가 더 커지면 정답이 될 수 없으므로).
  5. rekenrek `perRow`는 카드대로 10으로 고정하고 다른 값은 무시한다. `colorBreak`는 1~9로 자른다.
- **docs 수정 제안:** g1s2u4 힌트 ②의 "10이 되는 두 수에 같은 색 테두리"는 정답 짝을 알려 주므로 만들지 않았다. `docs/04-units/g1s2.md`의 해당 힌트를 `bubble-frame` 오버레이(지금 고른 수만큼만 텐프레임에 표시)로 바꾸기를 제안한다.
- **core 요청:** g3s1u3.A1의 왼쪽 share·오른쪽 measure-out 나란히 놓기와 `showEquation:"after-both"`는 실행기 두 슬롯이 필요해 이번 카드에서 하지 않았다. `after-submit`·`afterReveal`도 여전히 core 신호가 필요하다. measure-out 올가미는 기존 SDK `useLasso`·`selectInside`만 써서 core 변경은 없었다.
- 효과음·입자 연출은 넣지 않았다. bubble·bridge는 `value-changed`를 내지 않고 `bubble-popped`·`bagged`만 새로 낸다.
