### 1. `docs/03-engines.md`
- 엔진 20개 절마다 "필수 모드"·"확장 모드" 줄을 실제 `modes`와 맞춘다.
  - 구현된 모드는 그대로 두고, 구현 안 된 모드에는 끝에 "(미구현)"을 붙인다. 지우지는 않는다.
  - 구현됐는데 문서에 없는 모드·변형은 확장 모드 줄에 더한다(예: E13 `estimate`·`map-route`·`capacity`·`weight`, `length`의 `roll-circle`, E14 `time-calc`, E17 `sort`·`secret-rule` `predict`, E03 `range`, E06 `compare`).
- E20 `proportion-grid`: "(미구현 — 같은 격자 저울 그림을 E06 `proportion`으로 만들었다, T196·T198)"로 고친다.
- 부록 "단원 명세에서 나온 엔진 확장 요청" 표에 맨 끝 칸 "상태"를 더한다. 구현됐으면 카드 번호(예: "T211"), 아니면 "미구현"을 쓴다. 카드 번호는 `tasks/README.md`·카드 파일을 `grep`해서 찾고, 못 찾으면 "확인 필요"로 둔다(추측 금지).

### 2. `docs/00-handoff.md`
- "진행 상황" 절 제목의 날짜를 오늘(2026-11-20) 기준으로 바꾼다.
- 기존 긴 글은 지우지 않는다. 절 맨 앞에 **"W4~W6 요약"** 글머리 6~12줄을 새로 넣는다.
  - 웨이브마다: 구현한 엔진·모드, 콘텐츠를 넣은 단원, 운영 방식(W5부터 Opus 기획·검수 + 소넷 구현 `card-implementer`, 카드마다 작업 폴더, 웨이브 끝에만 전체 E2E·푸시·CI)
  - 시범 운영 메모(README 병합 메모의 "시범 운영 메모"·"알려진 문제"를 한 줄씩 모은 것, 10줄 이내)
  - "71개 단원 콘텐츠가 모두 들어갔으나 units.json status를 done으로 바꾸는 것은 운영자가 학생 입장에서 끝까지 해 본 뒤(DoD 6)"
- 사실은 README 병합 메모와 카드 메모에서만 가져온다. 거기 없는 숫자(테스트 수 등)는 쓰지 않는다.
