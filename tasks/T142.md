## 목표
E12에 확장 모드 `prism-pyramid`를 더한다(g6s1u2.A1 「수직 엘리베이터 vs 한 점 수렴」).
- 학생은 밑면 정다각형의 변의 수 n(3~8)을 고르고, "밀어 올리기" 손잡이로 각기둥을 만든다. "한 점으로 모으기" 손잡이를 쓰면 각뿔이 된다.
- 입체는 돌려 볼 수 있고, 엑스레이로 숨은 모서리를 비춰 볼 수 있다. 면·모서리·꼭짓점을 눌러 표시하며 센다.
- 카운터 표에는 만든 입체가 한 줄씩 쌓인다. **면·모서리·꼭짓점 수는 학생이 직접 적는다.**
- 엔진은 개수를 화면에 쓰지 않는다. 절대 규칙 3번 때문이다(아래 0번).

이 카드가 끝나면 g6s1u2.A1 콘텐츠를 쓸 수 있다. A2(각기둥 전개도)는 T143이 맡는다.

### 0. 명세와 다르게 하는 곳
- 명세의 "구성 요소(n+2, 2n, 3n) 자동 카운터"는 정답을 화면에 보여 준다. AGENTS.md 절대 규칙 3번에 걸린다.
- 그래서 카운터 표는 엔진이 줄(입체 종류와 n)만 만들고, 수는 학생이 적는다.
- 표에 맞음·틀림 표시는 하지 않는다. 판정은 Observation과 GoalSpec이 한다.
- docs/04-units/g6s1.md는 Opus가 main에서 고친다. 이 카드에서는 docs를 건드리지 않는다.

- `SolidMode`에 `'prism-pyramid'`를 더한다.

### 3. 입체와 요소 이름 `prism/geometry.ts`
- **밑면:** 정n각형이다(n 3~8). 외접원 반지름은 1이다. 꼭짓점 `b{i}`는 `(cos(−90°+360°·i/n), sin(…), 0)`이고 i는 0..n−1이다.
  - 첫 꼭짓점이 앞쪽(y가 음수 쪽)을 향하게 놓는다. 그래야 기본 시점에서 앞에 변이나 꼭짓점이 보인다. 실제 각도는 구현하면서 보기 좋게 맞춘다.
- **높이:** 단계 h(0~4)에 0.5를 곱한 값이다. 그림 크기는 배율로 맞춘다.
- **각기둥**(`top:'flat'`, h ≥ 1): 윗면 꼭짓점 `t{i}` = `b{i}` + (0, 0, 높이)
  - 면: `bottom`, `top`, 옆면 `s{i}`(b_i, b_{i+1}, t_{i+1}, t_i)
  - 모서리: 밑면 `eb{i}`(b_i–b_{i+1}), 윗면 `et{i}`, 옆 `el{i}`(b_i–t_i)
  - 참 개수: 면 n+2, 모서리 3n, 꼭짓점 2n
- **각뿔**(`top:'apex'`, h ≥ 1): 꼭짓점 `apex` = (0, 0, 높이)
  - 면: `bottom`, 옆면 `s{i}`(b_i, b_{i+1}, apex)
  - 모서리: `eb{i}`, `el{i}`(b_i–apex)
  - 참 개수: 면 n+1, 모서리 2n, 꼭짓점 n+1
- **h = 0:** 밑면만 있는 평면도형이다(`kind:'base'`). 표시 도구와 카운터 표 '적기'를 막는다.
- **요소 순서(고정):**
  - 면: `bottom`, (`top`), `s0..`
  - 모서리: `eb0..`, (`et0..`), `el0..`
  - 꼭짓점: `b0..`, (`t0..` 또는 `apex`)
  - 키보드 Tab 순서와 테스트가 이 순서를 쓴다.
- **눕힌 입체**(`orientation:'lying'`): 입체 전체를 x축으로 −90° 돌려 그린다. 그러면 밑면이 앞과 뒤를 본다.
  - 요소 이름은 그대로다. `bottom`·`top`이 밑면 두 개다.
  - 각뿔도 눕힐 수 있다.
- **정사영·보이는 면·숨은 모서리·배율:** T139 4번 규칙을 그대로 쓴다.
  - 시점 yaw·pitch, 15° 단위, 정규화
  - 숨은 모서리는 붙은 두 면이 모두 안 보이는 모서리, 숨은 꼭짓점은 붙은 면이 모두 안 보이는 꼭짓점이다.
  - 면 법선은 바깥쪽이다.
  - 배율은 높이 4단계·n=8 입체의 외접 구(경계 상자 대각선)를 기준으로 한 번 정한다. **n·높이·시점이 바뀌어도 배율은 바뀌지 않게 한다**(밀어 올리면 커지는 것이 보이게).
- `trueCounts(kind, n)` → `{faces, edges, vertices}`. `kind`가 `'base'`면 null이다.

### 4. 설정 `PrismConfig`
| 키 | 형 | 기본 | 뜻 |
| --- | --- | --- | --- |
| `mode` | `'prism-pyramid'` | — | 필수 |

- 범위 밖 값은 자르고 `console.warn`한다.

### 5. 상태·Action
`PrismState`:
```ts
{
  mode: 'prism-pyramid';
  settings: PrismSettings;            // 4번을 정규화한 값
  sides: number;                      // 3~8
  height: number;                     // 0~4
  top: 'flat' | 'apex';
  view: { yaw: number; pitch: number };
  xray: boolean; xrayUsed: boolean;
  tool: 'face' | 'edge' | 'vertex' | null;
  marked: { faces: string[]; edges: string[]; vertices: string[] };   // 3번 순서로 정렬
  apexPlayed: boolean;                // 'apex'로 한 번이라도 바꿨으면 true
  table: PrismTableRow[];             // 추가한 순서
}
PrismTableRow = { kind: 'prism' | 'pyramid'; n: number; faces: number | null; edges: number | null; vertices: number | null }
```
| Action | 동작 |
| --- | --- |
| `{type:'set-sides', n}` | n이 범위 안이고 고정이 아닐 때. 표시(`marked`)는 비운다 |
| `{type:'set-height', h}` | `extrude` 손잡이가 있을 때 0~4. h가 0이 되면 표시를 비운다 |
| `{type:'set-top', top}` | `apex` 손잡이가 있을 때. 바뀌면 표시를 비우고, `'apex'`가 되면 `apexPlayed=true` |
| `{type:'set-view'}`·`{type:'rotate-view'}`·`{type:'toggle-xray'}`·`{type:'set-tool'}` | T139와 같다 |
| `{type:'toggle-mark', kind, id}` | 지금 입체에 있는 id일 때만. h=0이면 무시한다 |
| `{type:'clear-marks'}` | 표시를 모두 지운다 |
| `{type:'add-table-row'}` | `counterTable`이고 kind가 prism이나 pyramid일 때, 지금 (kind, n) 줄을 빈 수로 더한다. 같은 (kind, n) 줄이 이미 있으면 무시한다. 줄은 최대 12개 |
| `{type:'set-table-cell', row, col, value}` | `col`은 `'faces'\|'edges'\|'vertices'`, `value`는 0~99 정수 또는 null |
| `{type:'remove-table-row', row}` | 줄을 뺀다 |

- 상태는 JSON 직렬화가 되어야 한다.
- 끄는 중인 손잡이 위치와 모으기 애니메이션 진행도는 화면 지역 상태다.

### 6. 화면 `PrismView`
- **배치:** T139 xray와 같은 `.stageRow`/`.sideStack` 규칙을 쓰고 판에 `data-mode="prism-pyramid"`를 단다.
  - 왼쪽(넓은 칸): `PrismStage`
  - 오른쪽: 위에서부터 n 고르기, 손잡이 두 개, 표시 도구 막대, 카운터 표
  - sideStack 폭은 xray와 같다(`min(42%, 320px)`, `min-width 220px`). 표가 길면 sideStack 안에서 스크롤해도 된다. 판 전체가 넘치면 안 된다.
- **`PrismStage`(SVG):** T139 `XrayStage`와 같은 규칙을 쓴다.
  - 면 그리기, 엑스레이, 끌어 돌리기, 돌리기 단추, 표시 도구, 표시 모양, 누르는 범위를 그대로 따른다.
  - 공통으로 뺄 수 있는 함수(투영, 깊이순 정렬)는 xray 쪽 코드를 고치지 말고 `prism/geometry.ts`에 따로 둔다. xray 동작 회귀를 막기 위해서다.
- **n 고르기:** "밑면의 변" − / + 단추(48px 이상)와 가운데 작은 정다각형 그림을 둔다. 수는 "변 5개"처럼 쓴다. n은 학생이 고른 값이라 정답 노출이 아니다.
- **손잡이 두 개:**
  - "밀어 올리기": 세로 트랙과 손잡이. 5칸(0~4)이고 Pointer Events로 끌어 가장 가까운 칸에 맞춘다.
  - "한 점으로 모으기": 두 칸 스위치("그대로" / "한 점으로").
  - 둘 다 `role="slider"` 또는 `aria-pressed` 단추로 만들고, 키보드로 쓸 수 있어야 한다. 손잡이 크기는 48px 이상이다.
  - 모으기를 바꾸면 윗면 꼭짓점들이 한 점으로 모이는(또는 펴지는) 300ms 애니메이션을 그린다. `prefers-reduced-motion`이면 바로 바꾼다.
- **이름 표시:** 무대 위에 "오각기둥"·"육각뿔" 같은 입체 이름을 쓴다.
  - n 3~8 이름은 `strings.ko.ts`의 표로 둔다(삼각~팔각).
  - h=0이면 "오각형"처럼 밑면 이름을 쓴다.
  - 이름은 개수가 아니라 정답 노출이 아니다. 단, 설정 `showName`(4번)으로 콘텐츠가 끌 수 있게 한다.
- **개수를 쓰지 않는다.** 표시한 개수, "다 찾았어요", 참 개수를 어디에도 쓰지 않는다.
- **카운터 표 `PrismCounterTable`(`counterTable`일 때):**
  - 열: 입체 이름 | 면 | 모서리 | 꼭짓점 | 줄 빼기(✕)
  - "표에 적기" 단추를 누르면 지금 입체 줄이 더해진다. h=0이거나 같은 줄이 이미 있으면 단추를 막는다.
  - 칸은 `inputmode="numeric"` 입력이다. 숫자 2자리까지 받고, 비우면 null이다.
  - 입력은 핵심 개념 입력이라 큰 글씨를 쓴다. 칸 높이 48px 이상.
  - 맞음·틀림이나 색 표시는 하지 않는다.
- **키보드:**
  - 무대 Q/E/W/S/X는 T139와 같다.
  - `[`·`]`: n −/+
  - PageUp·PageDown: 밀어 올리기 한 칸 위/아래
  - A: 모으기 바꾸기
  - 요소 Tab + Enter·Space로 표시
- **test id:**
  - 무대·요소: `prism-stage`, `prism-face-{id}`, `prism-edge-{id}`, `prism-vertex-{id}`(`data-hidden`, `data-marked`)
  - 도구: `prism-tool-{face|edge|vertex}`, `prism-toggle-xray`, `prism-turn-left`/`right`, `prism-tilt-up`/`down`, `prism-clear-marks`
  - 손잡이: `prism-sides-dec`/`inc`, `prism-extrude`(손잡이 요소, `aria-valuenow`), `prism-apex`
  - 표: `prism-table`, `prism-table-add`, `prism-row-{i}`, `prism-cell-{i}-{faces|edges|vertices}`, `prism-row-remove-{i}`
  - 이름: `prism-name`
- **문구:** 모두 `strings.ko.ts`(`solid3dStrings.prism`)에 둔다.

### 7. Observation(`prism-pyramid`)
```
mode:'prism-pyramid', sides, height, top, kind:'base'|'prism'|'pyramid', orientation,
view:{yaw,pitch}, xray, xrayUsed, apexPlayed,
visibleFaces:[...],
marked:{faces,edges,vertices}, markedCount:{face,edge,vertex},
trueCount:{face,edge,vertex} | null,      // 엔진 계산값(화면에는 쓰지 않음, 판정용)
table:[{kind,n,faces,edges,vertices}, ...],
tableCorrect:[boolean, ...]               // 줄마다 세 칸이 모두 참 개수와 같으면 true
```
- 다른 모드 전용 키는 넣지 않는다. 그래서 다른 모드 predicate는 이 관찰에서 false가 되고, 그 반대도 마찬가지다(테스트).

### 8. predicate(잘못된 인자는 false)
| 이름 | 인자 | 참 조건 |
| --- | --- | --- |
| `solidIs` | `{kind, n?}` | 지금 kind가 같고, n이 있으면 sides도 같다 |
| `markedCountIs` | `{kind, n}` | xray와 같은 이름이고, 관찰의 `markedCount`로 판정한다. 이미 있는 xray predicate가 `mode`를 보고 나누도록 고친다. xray 동작은 그대로다 |
| `allMarked` | `{kind}` | 같은 방식. 지금 입체의 그 종류를 모두 표시 |
| `tableRowIs` | `{kind, n, faces?, edges?, vertices?}` | (kind, n) 줄이 있고, 주어진 칸이 모두 그 값 |
| `tableRowCorrect` | `{kind, n}` | 그 줄의 `tableCorrect`가 true |
| `tableCorrectAtLeast` | `{count}` | 맞는 줄 수 ≥ count |
| `apexPlayedIs` | `{value}` | `apexPlayed === value` |
| `markedBasesOk` | — | 표시한 면이 정확히 밑면 두 개(각기둥: `bottom`·`top`), 각뿔이면 `bottom` 하나 |

- 오개념 감지 예:
  - MC-PYRAMID-AS-PRISM-COUNT: `tableRowIs {kind:'pyramid', n:6, vertices:12}`
  - MC-PRISM-BASE-ORIENTATION: `orientation:'lying'`에서 `markedBasesOk`가 아님
  - 콘텐츠 카드가 이렇게 쓸 수 있게 해 둔다.

### 9. 이벤트
`sides-changed {n}`, `height-changed {h}`, `top-changed {top}`, `table-row-added {kind,n}`, `table-cell-set {row,col}`을 `EVENT_NAMES`에 더한다. view·xray·mark 이벤트는 xray와 같은 이름을 쓴다.

### 10. 힌트 ② 오버레이

- **카드와 다르게 한 곳(이유):**
  1. 밑면 시작 각도: 카드는 "첫 꼭짓점 `b0`이 앞(−90°)". 구현은 `−90° − 180°/n`부터 시작해 옆면 `s0`이 늘 정면을 보게 했다(n=4면 정사각형이 축에 맞게 서고, 기본 시점에서 앞 옆면이 평평하게 보임). 요소 이름·순서·참 개수는 카드와 같다. 카드가 "실제 각도는 보기 좋게 맞춘다"고 허용한 범위로 봤다.
  2. `set-height`: cubes에 이미 `{type:'set-height', x, y, h}`가 있어 이름이 겹친다. 유니온에서 `action.x`가 안 좁혀져 cubes reduce에 `if (!('x' in action)) return state;` 한 줄(타입 좁히기)을 더했다. prism reduce는 반대로 `x`가 있는 모양을 거른다. cubes 동작은 그대로(전체 테스트·E2E 통과).

  4. 모으기 애니메이션 중에는 표시 누르기를 막는다(300ms). `matchMedia`가 없으면(jsdom) 애니메이션 없이 바로 바꾼다.
