3. **skip-count:** 설정 `min`(기본 0), `max`(기본 30), `start`(기본 min), `stepChoices`(기본 `[2,3,4,5]`), `step?`(있으면 고르기 버튼 없이 고정), `steps?`(여러 줄 — 줄마다 고정 step, g5s1u2용; 있으면 `stepChoices`·`step` 무시), `labels`(기존 all/partial/none), `showHopCount`(기본 **false**). 상태 `skip: { rows: { step: string | null, hops: string[] }[], start }`(hops = 뛴 뒤 도착 값들). Action `choose-step {row, step}`(hops를 비운다), `hop {row}`(마지막 도착 + step, max를 넘으면 무시), `unhop {row}`, `clear-hops {row}`. 툴바: "2씩"… 고르기 버튼, "한 번 뛰기", "되돌리기". 키보드: `J`/Space = 뛰기, Backspace = 되돌리기, 숫자 키 = step 고르기, 여러 줄이면 ↑/↓로 줄 고르기. 그림: 뛰기마다 기존 `JumpArrow` 호(라벨은 고른 step), 줄마다 다른 색 + 무늬(실선/점선 호). 기존 `place-point`(눈금 누르기·Enter)는 이 모드에서도 동작한다(g5s1u2 "공배수에 점 찍기"). 여러 줄이 겹치는 눈금을 엔진이 강조하지 않는다(그게 답이다).
4. **rounding:** 설정 `values`(값 목록, 1~3개, 예 `[389, 412]`) 또는 `value`(하나), `place`(어림할 자리 단위, 예 `10`, `100`, `"1"`, `"0.1"`), `methods`(기본 `["up","down","half-up"]`), `controls`(`"buttons"` 기본 / `"drag"`). 범위: 값마다 `lower = floor(v/place)·place`, `upper = lower + place`; 화면 구간은 모든 값의 `[min lower − place, max upper + place]`, 큰 눈금 = place(숫자 라벨), 작은 눈금 = place/10(라벨 없음). 상태 `rounding: { items: { value, marker: string | null, method: 'up'|'down'|'half-up'|null }[], selected: number }`. Action `round {item, method}`(그 방법으로 marker를 계산해 놓음 — 점이 원래 값에서 그 눈금으로 미끄러지는 애니메이션, `prefers-reduced-motion`이면 즉시), `move-marker {item, value}`(drag 모드: 큰 눈금으로만 스냅), `select-item {item}`, `clear-marker {item}`. drag 모드 키보드: 값 고르기(Tab/숫자 칩) → ←/→로 큰 눈금 한 칸씩 → Enter. 원래 값은 점 + 값 라벨(문제에 주어진 수라 보여도 된다), marker는 다른 모양(삼각 깃발) + 색. **결과 값을 따로 글자로 쓰지 않는다**(눈금 라벨로만 읽는다). `scenarios`·`showConsequence`는 받지만 무시하고 메모에 남긴다(문장은 콘텐츠·응답 위젯 몫).
5. **log-zoom:** 설정 `levels`(각 단계의 최댓값, 기본 `[10,100,1000,10000]`, 16자리까지 정수 문자열 허용 — `"10000000000000"`), `startLevel`(기본 0), `cards`(기존 키, `number | string` 허용), `snap`(`"minor"` 기본 = 단계 최댓값/100, `"major"` = /10), `labelStyle`(`"digits"` 기본 / `"korean"` = 만·억·조 단위 이름: 30000 → "3만", 200000000 → "2억", 끝자리 0이 아닌 수는 "2340만"처럼), `landmarks?: { value, label }[]`(콘텐츠가 직접 넣는 이정표 — 데이터 파일을 읽지 않는다), `start?`/`step?`(있으면 skip-count와 같은 "한 번 뛰기" 버튼과 호, 3번 결정과 같은 hops 상태). 범위는 늘 `[0, levels[level]]`. 상태 `logZoom: { level }` + 기존 points·cards. 줌아웃(− 버튼, 핀치 인, 휠 아래, 키 `-`) = level + 1, 줌인 = level − 1(맨 끝에서 무시). 단계가 바뀔 때 이전 단계 구간 `[0, 이전 최댓값]`을 줄 위 색 띠(빗금)로 남겨 "작아진 이전 구간"을 보여 준다. 큰 눈금 = 최댓값/10(라벨), 작은 눈금 = /100. 범위 밖으로 나간 점·카드는 지우지 않고 오른쪽 끝에 "→" 표시. 기존 decimal 줌(`zoom` Action)과 섞지 않는다 — 새 Action `log-zoom {level}`.
6. **double:** 설정 `top: { label, max? }`, `bottom: { label, max? }`, `anchors`(`[top, bottom]` 쌍 목록, 예 `[["2/3","1"]]`), `divisors`(기본 `[2,3]`), `multipliers`(기본 `[2,3]`), `labels`(`"expression"` 기본 / `"values"`). 두 줄의 x 비율은 첫 anchor의 top/bottom 비로 고정한다(대응 선이 늘 수직). 상태 `double: { pairs: { top, bottom, from: number | null, op: { kind: 'divide'|'multiply', factor: number } | null }[], selected }`. Action `select-pair {index}`, `scale-pair {kind, factor}`(고른 쌍의 위·아래를 같이 ÷/×해 새 쌍을 붙이고 그 쌍을 고름), `remove-pair`(마지막 쌍, anchor는 못 지움). 화면 구간은 `max(top.max, 모든 쌍의 top) × 1.1`까지 자동으로 늘린다(g6s2u1에서 top 1이 top.max 3/4보다 큰 문제 해결). 쌍마다 위아래를 잇는 수직선, 고른 쌍은 굵게. **라벨:** anchor는 값, 새로 만든 쌍은 기본 `"expression"` — 만든 과정을 식으로(`2/3 ÷ 2`, `1 ÷ 2`, 이어지면 `1 ÷ 2 × 3`) 써서 값(= 과제 답)을 보여 주지 않는다. `"values"`는 교사 시연용. 아래쪽에 누른 연산을 차례로 쌓는 띠(`÷ 2`, `× 3`)를 둔다 — 합친 결과(`× 3/2`)는 쓰지 않는다. `ops`·`goal`은 받지만 무시하고 메모에 남긴다.

## 메모

### 구현 결과
- `skip-count`: `min`/`max`/`start`/`stepChoices`/`step`/`steps`/`showHopCount`를 읽고, 줄마다 `step`·`hops`를 따로 둔다. `choose-step`은 그 줄의 `hops`를 비우고, `hop`은 마지막 도착 + step이 `max`를 넘으면 무시한다. `unhop`·`clear-hops`도 있다. 화면은 줄마다 색과 호 무늬(실선/점선)를 달리하고, 기본값에서는 뛴 횟수를 쓰지 않는다(`showHopCount: true`일 때만 표시). 여러 줄에서 겹치는 눈금에 점을 찍지 않는다.
- `rounding`: 값마다 `lower`/`upper` 큰 눈금을 계산해 화면 구간을 `[min lower − place, max upper + place]`로 잡는다. `place`는 `state.unit`(작은 눈금 = place/10)에서 `× 10`으로 복원한다. `round`·`move-marker`·`select-item`·`clear-marker`를 구현했고, drag 모드는 큰 눈금에만 스냅한다. 원래 값은 점+라벨, 결과는 삼각 깃발 모양+색으로만 보여 주고 결과 글자는 쓰지 않는다.
- `log-zoom`: `levels`(16자리 정수까지), `startLevel`, `cards`, `snap`(minor/major), `labelStyle`(digits/korean), `landmarks`, `start`/`step` 뛰어 세기를 구현했다. 단계 이동은 새 Action `log-zoom`으로만 하고, 이전 단계 구간은 빗금 띠로 남긴다. 범위 밖 점·카드는 지우지 않고 오른쪽 끝에 `→`로 표시한다. −/＋ 버튼, 핀치, 휠, 키보드 `-`/`+`를 모두 연결했다.
- `double`: anchor는 값 라벨, 새 쌍은 기본적으로 만든 식(`2/3 ÷ 2`, `1 ÷ 2 × 3`)으로 표시해 답을 노출하지 않는다. `labels: "values"`는 교사 시연용으로만 값 라벨을 쓴다. `scale-pair`는 위·아래를 같은 ÷/×로 바꿔 새 쌍을 붙이고, `remove-pair`는 마지막으로 만든 쌍만 지우며 anchor는 남긴다. 화면 구간은 `max(top.max, 모든 top) × 1.1`로 자동 확장한다. 연산 띠에는 누른 `÷ 2`, `× 3`만 쌓고 합친 결과는 쓰지 않는다.
- 공통: 새 상태는 `skip`/`rounding`/`logZoom`/`double`(해당 없으면 null)이고 모두 `Rational.toJSON()` 문자열 또는 JSON 값이다. Observation에 `skipRows`·`step`·`hopCount`·`landing`·`rounding`·`level`·`levelMax`·`levels`·`pairs`·`doubleOps`를 더했다. Predicate는 `landingIs`·`hopCountIs`·`stepIs`·`roundedTo`·`hasPointNear`·`levelIs`·`hasPair`를 등록했다. 오버레이는 `two-ticks`·`pair-replay`·`prev-band`를 등록했다. 기존 3개 모드(integer/fraction/decimal)의 상태·Observation·이벤트·화면은 그대로 두었고, `View.tsx`는 모드 선택만 한다.

### 카드와 다르게 한 점과 이유
1. `logZoom` 상태에 `levels`를, `double` 상태에 `topMax`를 더 넣었다. `observe(state)`는 설정을 받지 않으므로 단계별 최댓값과 화면 확장 기준을 상태에서 읽어야 했고, 둘 다 `Rational` 문자열이라 직렬화에도 문제가 없다.
2. `ticks.tickStep`을 정리해 `integer`와 새 모드 4개가 `unit`을 눈금 간격으로 쓰게 했다. `fraction`(subdivisions로 나눔)·`decimal`(10^level로 나눔) 분기는 기존과 같아 기존 3개 모드 동작은 바뀌지 않는다.
3. `snap` 설정 타입을 기존 `'tick'`에 `'minor'`·`'major'`를 더해 넓혔다. 기존 콘텐츠의 `"tick"`을 깨지 않으면서 log-zoom은 `'tick'`/기본값을 minor로 읽는다.
4. `min`/`max`/`unit`/`cards`를 `number | string`으로 넓혔다. 카드의 콘텐츠 예시가 `"min": 0`, `"place": 10`처럼 숫자를 쓰므로 새 모드만 숫자를 받게 하면 예시가 동작하지 않는다. 기존 3개 모드는 `configRational`로 읽어 문자열 설정 결과를 그대로 유지한다.
5. `round` 이벤트는 방법만 바뀌어 marker가 같아도 `rounded`를 내고, `value-changed`는 marker가 실제로 바뀔 때만 낸다. 학생이 같은 자리에서 방법을 바꿔 보는 것도 관찰할 수 있게 하려는 선택이다.
6. `place-card`에서 log-zoom 카드 값이 `max`보다 크면 화면 위치 대신 카드 자체 값을 상태에 둔다. 카드 5번의 "범위 밖 카드는 지우지 않고 →로 표시"를 구현하려면 원래 값이 필요하다.
7. `hasPointNear`는 점뿐 아니라 꽂힌 카드 값도 센다. log-zoom 과제에서 카드로 답하는 경우를 놓치지 않기 위해서다.
8. `scale-pair`는 `pair-added`만 내고 `value-changed`를 내지 않는다(카드 9번 그대로). 새 쌍의 값을 다른 엔진에 흘리면 정답이 노출될 수 있어 의도적으로 막았다.
9. `double`의 `factor`는 카드대로 `number`이고 양의 정수만 받는다. 상태·Observation에는 `"divide:2"` 같은 문자열로만 남긴다. 지나치게 큰 factor(1000 초과)는 화면이 감당하지 못해 무시한다.
10. `labels` 설정 키를 `'all' | 'partial' | 'none' | 'expression' | 'values'`로 넓혀 double의 라벨 방식을 기존 키로 받는다. 새 키를 만들지 않아 콘텐츠 설정이 단순해진다.
