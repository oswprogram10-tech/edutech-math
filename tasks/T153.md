## 목표
크롬북·전자칠판에서 응답 칸과 E12 판이 두 칸으로 놓일 때(판 폭 560~940px), `lathe`·`cylinder-net` 옆 패널(`sideStack`)의 조작 줄이 칸보다 넓어져 왼쪽·오른쪽이 잘린다. 잘린 왼쪽은 스크롤로도 닿지 않는다(T152 검수에서 발견).
- g6s2u6.A2.T1·T2(크롬북·전자칠판): 굴리기 줄(`cn-roll-step`·되돌리기·`cn-roll-full`·처음으로)의 왼쪽 단추가 약 49px 잘리고, 오른쪽 '처음으로'도 잘린다.
- g6s2u6.A1.T4~T6(크롬북): 레이저 단추 왼쪽이 약 13px 잘리고, 단면 패널(`ltSection`)이 칸 오른쪽 끝을 넘는다.
모든 조작이 잘리지 않고 손이 닿게 한다.

## 먼저 읽을 문서
- `src/engines/E12-solid-3d/View.module.css` 2020~2240줄(lathe·cylinder-net 전용 스타일)과 `.sideStack > *` 규칙(296줄 부근)
- `src/engines/E12-solid-3d/views/LatheView.tsx`, `views/CylinderNetView.tsx`
- `tests/e2e/units/g6s2u6.spec.ts`의 첫 화면 기준(`fit`/`reachable` 표)과 굴리기 우회(키보드로 굴림)
- tasks/T152.md 메모(측정값 표)

## 원인 (Claude 확인)
- `.wrap[data-mode='lathe'] .ltSide`와 `.wrap[data-mode='cylinder-net'] .sideStack`은 `flex-direction: row; flex-wrap: wrap; justify-content: center`이다.
- 그런데 공통 규칙 `.sideStack > * { flex: 0 0 auto }` 때문에 자식(`cnBtnRow`, `ltCutRow`)이 줄어들지 않고 내용 폭(한 줄)으로 놓인다.
  - `cnBtnRow`는 안에 `flex-wrap: wrap`이 있어도 바깥 너비가 max-content라 줄바꿈하지 않는다.
  - `ltCutRow`는 줄바꿈이 없다.
- 넘친 자식이 가운데 정렬되면 왼쪽으로 삐져나가고, overflow 스크롤은 왼쪽 넘침에 닿지 못한다.

## 구현 결정 (2026-11-18 Claude 작성 — 여기 적힌 대로 하고, 바꿔야 하면 메모에 이유를 적고 멈춰서 묻는다)
1. **CSS만 고친다.** 모드 전용 선택자(`.wrap[data-mode='lathe']`, `.wrap[data-mode='cylinder-net']`)로만 고친다. 다른 모드와 공통 `.sideStack` 규칙은 바꾸지 않는다.
2. 두 모드의 옆 패널 직계 자식에 `flex: 0 1 auto; max-width: 100%; min-width: 0`을 준다. 줄어들 수 있게 해 안쪽 `flex-wrap`이 동작하게 한다.
3. 두 모드 옆 패널의 `justify-content: center`를 `justify-content: safe center`로 바꾼다. 넘쳐도 왼쪽이 잘리지 않게 하기 위해서다. 아이패드 Safari 17 이상이 지원한다. 미지원 브라우저는 선언 전체를 무시하므로, 바로 앞 줄에 `justify-content: flex-start`를 둔다.
4. `ltCutRow`에 `flex-wrap: wrap`을 준다. 폭이 모자라면 단면 패널이 레이저 단추·높이 막대 아래 줄로 내려간다. 단면 패널 폭 150px는 그대로 둔다.
5. JSX는 바꾸지 않는다. CSS로 해결이 안 되면 멈추고 이유를 보고한다.
6. **확인 기준:** 아래 E2E로 잰다.
   - 크롬북(1366×768)·전자칠판·아이패드 뷰포트에서 g6s2u6.A1.T4·T5·T6·A2.T1·T2를 연다.
   - 옆 패널 안 모든 단추와 단면 패널이 다음을 만족해야 한다.
     - `boundingBox().x >= sideStack 왼쪽 - 1`, 오른쪽 끝은 `<= sideStack 오른쪽 + 1`
     - 필요하면 `scrollIntoViewIfNeeded()` 뒤 화면 안에 들어올 것
   - A1.T4~T6은 레이저 켠 상태로 잰다.
7. **g6s2u6.spec.ts 갱신**
   - 굴리기 키보드 우회를 단추 클릭(`cn-roll-step`, `cn-roll-full`, 처음으로)으로 바꾼다.
   - 첫 화면 기준표에서 잘림 때문에 `reachable`로 둔 항목은 실제로 `fit`이 되면 `fit`으로 고친다. 높이 때문에 `reachable`인 항목(A2.T4 응답 6칸 등)은 그대로 둔다. 바꾼 항목은 메모에 표로 적는다.
   - 레이저·단면 패널도 `reachable` 검사에 넣는다.
8. **스냅샷:** 바뀐 기준 이미지(g6s2u6 A1·A2 크롬북·전자칠판, solid-3d-lathe·cylnet 샌드박스)는 다시 찍고 직접 열어 확인한다. 바뀌지 않아야 할 다른 E12 모드 스냅샷이 바뀌면 멈추고 보고한다.
9. **새 E2E:** `tests/e2e/solid-3d-lathe.spec.ts`·`solid-3d-cylnet.spec.ts`의 `?stage=fit` 샌드박스는 비율 1이라 이 문제를 못 잡는다. 실행기 두 칸 배치는 g6s2u6.spec.ts에서 잰다(6번). 엔진 spec은 고치지 않아도 된다.
10. **멈춤 조건:** 크롬북 두 칸 배치 무대(`lt-stage`, `cn-roll-stage`) 높이가 200px 미만이 되면 멈추고 측정값을 보고한다.
