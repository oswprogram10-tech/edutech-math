1. **파일·형식:** `data/content/g5s1u5.json` 하나. 콘텐츠 스키마를 따르고 `views`/`links`, `response`, `showEngine`, `hints`, `hintVars`, `diagnose`를 쓴다. 과제 ID는 `<활동ID>.T<n>`, `concepts`는 명세의 개념 노드 ID(과제마다 1~2개).
2. **CPA:** 활동 안에서 C → P → A 순서. A 과제는 `showEngine:false` + 응답 위젯이 기본(E07·E08처럼 엔진이 곧 답 입력인 과제는 엔진을 보인다). 학생 화면 문구에 학년·단원 ID를 쓰지 않는다.
3. **정답 노출 금지:** E05는 `showValue`를 켜지 않는다(add-sub의 '결과', mixed의 변환 표기, decimal-grid의 '값 = 0.47'은 답이다). E03에서 점 찍기·카드 꽂기·점프가 판정인 과제는 `"labels": "partial"`. 발문·힌트·선택지 이름에 그 과제의 정답 값을 쓰지 않는다. E08 `debugSamples`의 틀린 풀이는 문제 자체이므로 그대로 보여도 된다.
4. **힌트:** 과제마다 ①·②·③. 발문은 docs/05 §4(학생이 만든 것을 언급, "어떻게/왜/몇" 질문, 정답 수치 금지)를 따르고, 풀이 절차를 통째로 지시하는 문장, 정답을 거의 말해 주는 문장("6개와 7개 중…"), 오개념을 부추기는 문장을 쓰지 않는다. 오개념 규칙(`when`)을 일반 규칙보다 앞에 두고, **오답 하나에만 걸린 규칙만 두지 말고 단계마다 일반 규칙도 둔다**. ②는 쓸 수 있는 오버레이가 있으면 쓴다(E07 `place-value`·`column-sum`, E08 `bar-check`, E05 `grid-reveal`·`size-compare`, E03 `distance-from-zero`·`same-point` — 단 `same-point`에 정답 값을 넣지 않는다). 없으면 2단계 질문 발문으로 둔다.
5. **오개념 감지:** 명세 표의 코드는 모두 `src/core/math/diagnose.ts`에 감지기가 있다. 응답 값으로 감지할 때는 `diagnose`, E07·E08 엔진이 찾은 코드는 predicate `hasMisconception`(args `{ code }`)을 힌트 `when`에 쓴다. 감지기가 맞는 답에도 걸리는지 확인한다(T024 메모의 `MC-COMMON-DENOM-ONLY-PRODUCT` 사례). 명세 표의 코드마다 이 단원 과제에서 감지되는 테스트를 하나씩 둔다. 이 단원 과제로 만들 수 없는 코드는 메모에 적는다.
6. **엔진·core 수정 금지(카드에 따로 허용한 것만 예외):** 아래 과제별 결정은 지금 엔진·실행기 기능만으로 만들 수 있게 정했다. 그래도 필요하면 **진행을 멈추고 메모로 묻는다**(같은 묶음의 세 카드가 같은 엔진 파일을 동시에 고치면 병합 충돌이 난다).
7. **다른 단원 E2E:** `tests/e2e/star-map.spec.ts`와 `tests/e2e/response.spec.ts`는 이 카드에서 고치지 않는다(T022만 예외 — 그 카드 참고). 이 단원 콘텐츠 때문에 깨지면 메모에 적는다.
8. **E2E·화면:** `tests/e2e/units/g5s1u5.spec.ts`(3개 뷰포트) — 과제마다 정답 조작 → 통과, 대표 오답 → 힌트 ①(정답 값은 DOM에 없음), 활동마다 첫 화면 스크린샷, 크롬북·전자칠판에서 응답 칸(또는 엔진 입력)과 '확인하기'가 첫 화면 안에 있는지, 오프라인에서 첫 활동이 열리는지.

    - 명세 A1의 `overlay-slicer` 조작은 add-sub의 겹치기로 대신한다.
11. **A2(E08 `fraction-steps`·`lines`):**
    - 과제 1~3은 `start`만 두고, 판정은 `allLinesEquivalent` + `finalValueIs` + 과제 1은 `finalIrreducible`, 과제 2는 `finalIsMixed`(대분수로 정리)다.

    - 과제 5 "어림 후 계산"은 `choice`(1보다 클까/작을까)와 E08 줄 풀이를 한 과제에 둔다. 문제는 결과가 1보다 큰 덧셈 하나로 정하고, 판정은 어림 선택이 맞음 + 최종 값이다(명세의 '일관성 기록'은 이렇게 좁힌다).
    - 오개념 힌트는 `hasMisconception`(`MC-FRAC-ADD-DENOM`, `MC-FRAC-ADD-NO-CONVERT-NUM`, `MC-FRAC-BORROW-AS-TEN`, `MC-SUB-SMALLER-FROM-LARGER`)과 `MC-FRAC-NO-SIMPLIFY`(최종 줄 값은 맞지만 기약이 아님 → `finalIrreducible` false를 `when`으로)다.
12. **A3(E05 `mixed`, a·b·op 문제형):**
    - 과제 1 "막대 하나 쪼개기"는 `{ "mode":"mixed","op":"-","a":"3 1/6","b":"1 3/4","breakWhole":true,"commonGrid":12 }`이고, 판정은 Observation `pieceValue` "14/12" + `naturalPart` 2다.
    - 과제 2 "빼기 완성"은 같은 설정이고, 판정은 응답 대분수 1 5/12(값 비교)다. 엔진의 합치기 결과는 `showValue` none이라 보이지 않는다.
    - 과제 3 "4 − 2 2/5"는 응답 값 8/5(1 3/5)이고, `diagnose` `MC-FRAC-WHOLE-MINUS`를 건다.

## 메모
- **A2 T5 범위 축소(카드 11번 허용):** 명세의 '어림과 계산의 일관성 기록'을 `5/6 + 3/4` 한 문제로 좁혔다. 학생은 '1보다 크다/작다/같다'를 먼저 고르고, 같은 과제에서 E08 줄 풀이로 `19/12`를 확인한다. 판정은 어림 선택 + `allEquivalent` + `finalValueIs`다. 여러 문제의 일관성을 따로 기록하지는 않는다.
- **A2 T4 `debugSamples` 표기:** 카드 11번의 `["1/2 + 1/3", "= 2/5"]` 대신 `["1/2 + 1/3", "2/5"]`을 썼다. E08은 `debugSamples`를 식으로 파싱해 줄을 만들고 화면에서 줄 사이에 `=`를 따로 그리므로, 앞의 `=`는 식에 넣지 않는다.
- **오개념 힌트 방식:** E08이 Observation의 `misconceptions`에서 찾는 코드(`MC-FRAC-ADD-NO-CONVERT-NUM`, `MC-FRAC-BORROW-AS-TEN`, `MC-SUB-SMALLER-FROM-LARGER`)는 `when`에 predicate `hasMisconception`(args `{ code }`)을 썼다. 실행기가 콘텐츠 `diagnose`를 돌리는 것은 `{ "misconception": ... }` 지름길을 쓸 때뿐이라, E08 과제에는 지름길을 쓰지 않았다. E05 응답 과제(A1 T1 `MC-FRAC-ADD-DENOM`, A3 T3 `MC-FRAC-WHOLE-MINUS`)는 `diagnose` + 지름길을 쓴다.

- **오개념 코드 커버:** 명세 표의 다섯 코드가 모두 E2E에서 감지된다 — A1 T1 `MC-FRAC-ADD-DENOM`, A2 T1 `MC-FRAC-NO-SIMPLIFY`(최종 줄이 기약이 아님), A2 T2 `MC-FRAC-ADD-NO-CONVERT-NUM`, A2 T3 `MC-FRAC-BORROW-AS-TEN`·`MC-SUB-SMALLER-FROM-LARGER`. 이 단원 과제로 만들 수 없는 코드는 없어 T023처럼 메모에 남길 예외가 없다.
