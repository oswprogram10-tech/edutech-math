## 구현 결정 (2026-11-18 Claude 작성 — 여기 적힌 대로 하고, 바꿔야 하면 메모에 이유를 적고 멈춰서 묻는다)
1. **자료는 설정 안에 직접 둔다.**
   - 명세의 `"datasetPicker": "data/datasets/g4-bar/*.json"`(파일 묶음)은 쓰지 않는다. 대신 설정 키 `datasets`를 둔다:
     `datasets?: { id: string, title: string, data: Record<string, number>, valueLabel?: string, categoryAxisTitle?: string, valueAxisTitle?: string, source?: string }[]`
   - 콘텐츠 JSON 한 파일에 다 들어가므로 새 폴더나 불러오기가 필요 없다.
   - 명세 문서의 이 부분은 콘텐츠 카드가 고친다. 이 카드에서는 docs를 건드리지 않는다.
   - `source`는 자료 출처 글이다. 있으면 그래프 아래에 작은 글씨(최소 글자 크기)로 "자료: …"라고 보인다.
2. **화면:**
   - `datasets`가 있으면 그래프 위에 `role="radiogroup"` 단추 줄을 둔다. 단추 글자는 `title`이다.
   - 처음에는 아무 묶음도 고르지 않은 상태다. 표와 그래프 자리에 "자료를 하나 골라요" 안내만 보인다.
   - 고르면 그 묶음의 `data`·축 제목·`valueLabel`이 T155의 같은 키 대신 쓰인다. 나머지 설정(`graph`, `graphType`, `scale`, `orientation` 등)은 그대로다.
   - 다른 묶음으로 바꾸면 학생 그래프(`bars`·`marks`)와 학생 표를 비운다. 되돌리기는 실행기의 되돌리기로 한다.
3. **상태·Action·Observation:**
   - 상태: `datasetId: string | null`
   - Action: `pick-dataset {id}`(목록에 있는 id만)
   - Observation 추가: `datasetId`. 고른 뒤에는 기존 키(`table`, `graphValues`, `graphMatchesData` 등)가 고른 묶음의 `data` 기준이 된다. 고르지 않았으면 범주가 없는 상태다.
   - Predicate 추가: `datasetPicked`
   - 묶음 사이 비교 predicate는 만들지 않는다. 콘텐츠는 응답 칸과 `graphMatches`로 판정한다.
4. **테스트:**
   - 단위: 고르기 전 범주 없음, 고르면 data가 바뀜, 바꾸면 학생 그래프가 비워짐, 없는 id 무시, 직렬화
   - View: 단추 줄과 안내 글, `source` 글
   - E2E(graph-studio, 3 뷰포트): 묶음을 고르고 막대를 그려 `graphMatches`가 맞는지 본다. 크롬북 두 칸 폭(660×420)에서 단추 줄이 잘리지 않는다. 스냅샷은 한 장(크롬북, 고른 뒤)이다.
5. **글자:** 안내 글과 `source` 글은 T158 최소 글자 크기를 따른다. 문구는 strings.ko.ts에 둔다.
