## 구현 결정 (2026-11-03 Claude 작성 — 여기 적힌 대로 하고, 바꿔야 하면 메모에 이유를 적고 질문한다)
1. **폴더:** `src/engines/E08-step-solver/`. 엔진 ID `E08`. modes 순서는 `lines`, `fraction-steps`, `debug`다. `order-tree`는 W1 단원에 쓰이지 않아(g5s1u1, W2 이후) 이 카드에서 만들지 않는다.
2. **줄 표현:** 각 줄은 **토큰 배열**로 상태에 둔다(JSON). 토큰 종류는 수(자연수), 분수 틀 `{n, d}`, 대분수 틀 `{w, n, d}`, 소수, 연산 `+ − × ÷`, 괄호, `□`이다. 판정할 때 토큰을 `src/core/math`가 읽는 식(AST 또는 파서 문자열)으로 바꾼다. 문자열을 손으로 파싱하지 않는다. 줄 앞의 `=`는 화면 표시일 뿐 식에 넣지 않는다. 학생이 쓴 표기(약분 전, 대분수)는 그대로 둔다.
3. **입력:** 수식 키패드에는 숫자, 분수 틀, 대분수 틀, 소수점, `+ − × ÷`, `( )`, `□`, 지우기, 줄 추가, 줄 삭제가 있다. 설정 `keypad`로 보이는 키를 고른다(명세의 `"digits"`, `"fraction"`, `"mixed"`, `"+"`, `"-"`, `"="` 등). 틀 안에서 칸 이동은 탭 또는 키보드 Tab·화살표로 한다. 자유 텍스트 입력은 받지 않는다. 키 하나 = Action 하나. iPad에서 OS 키보드가 뜨지 않게 한다(T016 수 입력과 같은 방식).
4. **설정 키:** `start`(첫 줄, 고정·수정 불가 — 예: `"3 1/4 - 1 3/4"`), `keypad`, `checkEachLine`(기본 true), `stepLabels`(이름표 목록), `allowFreeOrder`, `diagnose`(기본 true), `problem`(`start`의 별칭), `debugSamples: [{ lines: [...] }]`(debug 모드의 가상 친구 풀이). 이 문자열들은 콘텐츠가 주는 문제이므로 파서로 읽어도 된다.
5. **줄 판정:** 줄 i(i ≥ 1)마다 줄 i−1과 값이 같은지 `src/core/math`의 `equivalent`/`evaluate`로 본다(Rational, number 금지). 화면에는 줄 옆에 ✓ 또는 빨간 테두리 + ✗ 기호를 보여 준다(`checkEachLine`이 true일 때, 색 외에 기호로도). **이것은 이전 줄과 같은지만 알려 주는 것이지 정답 값을 보여 주는 것이 아니다**(명세 g4s2u1.A3·g5s1u5.A2). 미완성 줄이나 `□`가 있는 줄은 판정하지 않는다(중립 표시).
6. **오개념 진단과 반례:** 깨진 줄이 생기면 그 앞 줄이 `a ± b` 꼴(두 항)일 때 `src/core/math/diagnose.ts`의 감지 함수에 a, b, op, 학생 줄의 값·표기를 넘겨 코드를 찾는다. 최소 `MC-FRAC-ADD-DENOM`, `MC-FRAC-ADD-DENOM-HALF`, `MC-FRAC-ADD-NO-CONVERT-NUM`, `MC-FRAC-BORROW-AS-TEN`, `MC-FRAC-WHOLE-MINUS`(모두 diagnose.ts에 이미 있음)를 다룬다. diagnose.ts에 없는 감지(예: 대분수의 분수 부분을 거꾸로 빼는 `MC-SUB-SMALLER-FROM-LARGER`)는 **엔진 안에 두지 말고 메모로 요청**한다. 코드가 찾아지면 그 줄 아래 반례 상자를 띄운다. 문장은 학생 줄의 수만 쓴다(예: "2/5보다 작아졌네요? 무언가를 더했는데요?"). 그림은 이전 줄 값과 학생 줄 값 두 막대다. **정답 값은 문장·그림 어디에도 넣지 않는다.** 콘텐츠의 `cpa`가 A면 그림 없이 문장만 보여 준다.
7. **fraction-steps:** 줄마다 이름표 칸이 있다. 학생이 `stepLabels` 중에서 골라 붙이거나 바꾼다(`allowFreeOrder`가 true면 순서 자유). 이름표는 판정에 쓰지 않고 Observation에만 남긴다.
8. **debug:** `debugSamples`의 풀이 한 개를 읽기 전용 줄로 보여 준다(여러 개면 순서대로, 설정 `sample` 인덱스로 고정 가능). 학생이 틀린 줄을 고르고(`select-line`), 그 줄 아래에 고친 줄을 키패드로 쓴다. **어느 줄이 틀렸는지 미리 표시하지 않는다**(✓/✗는 학생이 고친 줄에만).
9. **Observation:** `mode`, `lines: [{ expr, value, valid, equivalentToPrev, label }]`(expr는 정규화된 식 문자열, value는 Rational 문자열 또는 null), `firstBrokenLine`(없으면 null), `allEquivalent`, `finalValue`, `finalRaw`, `finalIrreducible`, `finalIsMixed`, `lineCount`, `misconceptions: [{ line, code }]`. debug는 `selectedLine`, `fixedValue`를 더한다.
10. **Predicates:** `allLinesEquivalent`, `finalValueIs`(args `{ value }`, 값 동치), `finalIrreducible`, `lineCountAtLeast`(args `{ n }`), `selectedLineIs`(args `{ line }`), `hasMisconception`(args `{ code }`), `differentExpressions`(g4s2u1.A3 과제 5 "서로 다른 식 2가지": 학생 줄들 중 값이 args `value`인 서로 다른 식이 `count`개 이상).
11. **이벤트:** `line-added`, `line-checked`(`{ line, equivalent }`), `misconception-found`(`{ line, code }`), `value-changed`(마지막 줄 값 `{ value }`).
12. **오버레이(힌트 ②) `bar-check`:** 학생이 고른 줄(기본은 첫 깨진 줄)과 그 앞 줄의 값을 같은 기준 막대 두 개로 그린다. 정답 막대는 그리지 않는다.
13. **CPA·크기·문구:** P는 반례에 그림을 넣고, A는 문장만 넣는다(명세). 터치 타깃은 `targetSize` 이상이다. 문구는 `strings.ko.ts`에 둔다.
14. **테스트:** 단위 테스트로 다음을 확인한다. 토큰→식 변환(분수·대분수·괄호), 줄 판정, `1/2+1/3` → `2/5` 줄이 `firstBrokenLine` + `MC-FRAC-ADD-DENOM`, `3 1/4 − 1 3/4 = 2 2/4` 진단, 미완성 줄 중립, debug 선택·고치기, `assertSerializable`. 그리고 `#/sandbox/E08` E2E를 3개 뷰포트에서 돌린다. 키패드로 `3/8 + 4/8` → `= 7/8` 두 줄 작성 → 모두 ✓, `1/2 + 1/3` → `= 2/5` → ✗와 반례 상자(정답 5/6 텍스트 없음), debug에서 틀린 줄을 고르고 고치기.
