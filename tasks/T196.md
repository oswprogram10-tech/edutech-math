## 목표
E06 양팔저울(T187)에 `proportion` 모드를 더한다.
- 비례식 `a : b = c : d`의 외항 a, d는 직사각형 격자(a×d칸)로 왼쪽 접시에, 내항 b, c는 직사각형 격자(b×c칸)로 오른쪽 접시에 올린다. 넓이가 같으면 수평이다.
- □가 있으면 슬라이더로 □ 값을 바꿔 수평을 찾는다.
- 카드 여러 장 가운데 하나를 골라 저울에 올릴 수 있다.

이 모드는 g6s2u4.A1(T198)에 쓴다. 명세의 E20 `proportion-grid`는 같은 그림이라 만들지 않는다(T198에서 명세를 고친다).

## 구현 결정 (2026-11-20 Claude 작성 — 여기 적힌 대로 하고, 바꿔야 하면 메모에 이유를 적고 멈춰서 묻는다)

### 1. 설정
```ts
interface ProportionConfig {
  mode: 'proportion';
  equation?: string;              // "3 : 5 = □ : 20" — 네 항, □는 0개 또는 1개
  cards?: string[];               // □ 없는 비례식 후보 2~4장("2 : 3 = 4 : 6", "2 : 3 = 3 : 4" …). equation과 함께 쓰지 않음
  unknownSlider?: { min: number; max: number };  // 기본 {min:1, max:20}
  look?: 'scale' | 'grid' | 'symbols';           // C 저울+격자 / P 격자 두 개 나란히(저울 없음, =/≠) / A 식만, 기본 'scale'
  pairSelect?: boolean;           // 기본 false: true면 학생이 네 항 중 두 개를 골라 왼쪽 직사각형을 만든다
}
```
- 항은 1~30의 정수만 받는다. 0·소수·분수는 설정 오류다(소수·분수 비 간단히 하기는 콘텐츠 응답 과제가 맡는다).
- `equation`과 `cards`가 둘 다 있거나 둘 다 없으면 설정 오류다. 샌드박스 기본은 `"3 : 5 = □ : 20"`이다.
- **설정에 □의 정답을 두지 않는다.** 기울기는 학생이 놓은 값으로만 계산한다.

### 2. 상태·Action (기존 equation 상태와 분리된 모드별 상태)
- **상태:** `terms: (string|null)[]`(□ 자리는 null), `boxIndex: number|null`, `tryValue`, `tries`, `cardIndex: number|null`, `pair: [number, number] | null`(pairSelect)
- **Action**
  - `try {value}`: 슬라이더 값, 정수, 범위 안
  - `select-card {index}`
  - `pick-pair {indices:[i,j]}`: 서로 다른 두 항
  - `reset`
- `cards` 모드에서 처음에는 저울이 비어 있다. "카드를 골라 저울에 올려 보세요"를 띄운다.

### 3. 계산·Observation
- **왼쪽 넓이**
  - pairSelect가 아니면 외항 곱 a×d다.
  - pairSelect이면 고른 두 항의 곱이다.
- **오른쪽 넓이:** 나머지 두 항의 곱이다.
- □ 값을 모르면 tilt는 `'unknown'`이다.
- **Observation**
  - `mode:'proportion'`
  - `terms: (string|null)[]`(□는 넣어 본 값, 없으면 null)
  - `boxIndex`, `tryValue`, `tries`
  - `leftArea`·`rightArea: string|null`, `balanced`, `tilt`
  - `boxValue`(balanced일 때 tryValue)
  - `cardIndex`, `isProportion: boolean|null`(올린 카드의 외항 곱 = 내항 곱)
  - `pair`, `pairing: 'extremes-means' | 'other' | null`
  - `misconceptions`
- **MC-RATIO-ADDITIVE**
  - □ 자리별로 '차를 보존한' 값을 계산한다. 넣어 본 값 가운데 이 값과 같고 수평이 안 되는 것이 있으면 기록한다.
    - c 자리: a + (d − b)
    - d 자리: b + (c − a)
    - a 자리: c − (d − b)
    - b 자리: d − (c − a)
  - 예: 3 : 5 = □ : 20에서 18
- **MC-PROPORTION-CROSS-WRONG:** pairSelect에서 고른 짝이 외항 짝({0,3})도 내항 짝({1,2})도 아니면 기록한다.
- **Predicates**
  - 기존 E06 predicate는 이 모드에서도 같은 뜻이 되게 한다(`balanced`, `boxValueIs`, `triesAtMost`, `hasMisconception`).
  - 새 predicate: `isProportion`, `cardIs {index}`, `pairingCorrect`(외항 짝 또는 내항 짝)

### 4. 화면
- **위쪽 식 줄:** 네 항을 글자로 쓴다. □는 넣어 본 값이 있으면 그 값과 "□" 표시를 쓴다.
  - 외항은 둥근 괄호 모양 위 표시와 "바깥쪽", 내항은 아래 표시와 "안쪽"을 단다.
  - 이 표시는 늘 보이는 것이 아니라 오버레이 `cross-brackets`가 그린다.
- **접시 위 격자**
  - 가로 = 첫째 수, 세로 = 둘째 수 칸이다.
  - 같은 칸 크기로 두 접시를 맞춘다. 가장 큰 변이 접시 폭에 맞고, 칸 하나는 최소 4논리px다.
  - 격자 아래에 "가로 a칸 × 세로 b칸"과 "모두 n칸"을 쓴다. □ 쪽은 넣어 본 뒤에만 쓴다.
- **기울기:** E06 equation의 기울기 함수와 결과 글을 그대로 쓴다(넓이 비교).
- **look**
  - `grid`: 저울 없이 두 격자를 나란히 두고 사이에 =/≠를 둔다.
  - `symbols`: 식 줄과 "외항의 곱 ○ 내항의 곱" 줄만 둔다. ○는 =/≠ 기호다.
- **조작**
  - 슬라이더(□, Pointer Events)와 −/+ 단추를 둔다. 키보드 ←→도 쓴다.
  - 카드 단추를 둔다(카드 식 글자 그대로).
  - pairSelect이면 항 단추 넷을 두고, 둘을 고르면 왼쪽 격자가 만들어진다.
  - [처음으로]를 둔다.
- 판 맞춤·48px·색만으로 전달 금지는 E06 기존 방식을 따른다.

### 5. 오버레이
- **`big-tilt`:** 이 모드에서도 그린다. 마지막으로 넣은 값으로 크게 기운 그림자 저울과 두 넓이 글을 그린다.
- **`cross-brackets`**(CROSS-WRONG ②): 식 줄 위에 외항 짝을 잇는 위 괄호와 "바깥쪽", 내항 짝을 잇는 아래 괄호와 "안쪽"을 그린다. 두 괄호는 선 모양(실선·점선)으로도 구별한다.
- **`area-diff`**(일반 ②)
  - 두 격자를 왼쪽 아래 모서리에 맞춰 겹친 그림을 판 가운데에 그린다.
  - 한쪽에만 있는 칸은 빗금으로 그린다. 숫자는 쓰지 않는다.
  - 넓이를 모르면 그리지 않는다.

### 6. 등록과 테스트
- `modes`에 `proportion`을 더하고, fit-canvas ENGINES의 E06 modes에도 더한다.
- **기존 equation 동작·그림은 바뀌면 안 된다.**
  - 모드 이름 `proportion`이 `equation`보다 길다. 그래서 샌드박스 모드 상자가 넓어져 equation 기준 이미지의 도구 줄이 몇 px 밀릴 수 있다(T174·T190과 같은 일).
  - 차이 이미지에서 다른 곳이 도구 줄뿐이면, 그 equation 기준 이미지만 `--update-snapshots`로 다시 찍는다. 다시 찍은 사실과 확인 결과를 메모에 적는다(Opus 허락).
  - 엔진 그림이 달라졌으면 멈추고 묻는다.
- **단위**
  - 3 : 5 = □ : 20: 12 → balanced, 18 → MC-RATIO-ADDITIVE, 11 → tilt
  - □ 자리 넷 각각의 '차 보존' 값
  - cards
    - "2 : 3 = 4 : 6" → isProportion true
    - "2 : 3 = 3 : 4" → false, 기울어짐
  - pairSelect
    - {0,3} → pairingCorrect
    - {0,2} → CROSS-WRONG
  - 설정 오류(0, 소수, □ 2개, equation·cards 둘 다)
  - 경계값: 슬라이더 min·max
  - JSON 왕복
- **E2E**(`tests/e2e/balance.spec.ts`에 추가, 3 뷰포트)
  - 슬라이더·키보드로 수평
  - 카드 고르기
  - pairSelect
  - 오버레이 셋 1px 정렬
  - look 셋 첫 화면 스냅샷
  - 크롬북 좁은 판
- **E2E 범위:** `npx playwright test balance fit-canvas overlay-alignment g2s1u3 --workers=3 --reporter=line`

## 메모

### 구현 메모 (Sonnet, T196)
- **구조:** equation 파일(`types.ts`·`reduce.ts`·`observe.ts`·`Board.tsx`·`Controls.tsx`)은 그대로 두고 `proportion/`(types·settings·read·reduce·observe·layout·result·Board·View)을 새로 만들었다. 합친 타입은 `unions.ts`, 모드 전환은 `engine.ts`(`createState`·`reduceState`·`observeState`, 설정에 `mode:'proportion'`이 아니면 equation), `View.tsx`는 상태의 `mode`로 `EquationView`/`ProportionView`를 고르는 얇은 껍데기. 판 맞춤 계산은 `fit.ts`로 뺐다(`MIN_SCALE` 재내보냄). 기존 equation 동작·Observation 이름·그림은 바뀌지 않는다(`layout.ts`는 `tiltDegreesOf(left,right)`만 추가하고 `tiltDegrees`가 그걸 부른다, 결과 같음).
- **카드와 모순 하나:** "equation·cards 둘 다 없으면 설정 오류"인데 샌드박스 기본이 `3 : 5 = □ : 20`이라 둘 다 없음 = 기본 식으로 했다. 둘 다 있을 때만 오류.
- **슬라이더 상한 45(카드에 없는 결정):** 칸 최소 4논리px를 지키려고 `unknownSlider.max ≤ 45`(1 ≤ min ≤ max)로 막았다. 항은 1~30이라 가장 큰 변이 45칸 이하 → 저울 접시 칸(가로 260×세로 180)에서 칸이 4px 이상. 칸 크기는 4~36px로 묶었다(작은 항이 접시를 가득 채우지 않게).
- **Action 값 형식:** `try {value}`는 equation처럼 정수 문자열("12"). 슬라이더는 끄는 동안 지역 값만 바꾸고 놓을 때·−/+·←→·Home/End에서만 `try`를 보낸다(`tries`가 부풀지 않는다). □를 아직 안 넣었으면 어느 쪽 한 칸 움직임도 첫 값(min)부터 시작한다.
- **빈 저울:** 카드를 고르기 전(`cards` 모드)에는 `terms: []`, Observation `terms: []`·`tilt:'unknown'`·`isProportion:null`. pairSelect에서 짝을 고르기 전에도 두 접시가 비고 `leftArea`·`rightArea`는 null. □를 포함한 짝은 □를 넣기 전까지 그 접시 격자 대신 "?" 상자를 그린다.
- **`isProportion`:** 짝 선택과 무관하게 외항의 곱 = 내항의 곱(네 항이 다 정해졌을 때). `balanced`·`boxValue`·`leftArea`/`rightArea`는 pairSelect의 짝을 따른다(카드대로 `boxValue`=balanced일 때 tryValue).
- **MC-PROPORTION-CROSS-WRONG:** 지금 고른 `pair`로만 판단(고친 뒤 사라진다). MC-RATIO-ADDITIVE는 `tries` 기록으로 판단(고쳐도 남는다, MC-EQUAL-ANSWER와 같은 방식). 차 보존 값이 비례식도 되면(2 : 2 = □ : 2의 2) 기록하지 않는다.
- **화면:** 식 줄(y=98)에 네 항, □는 굵은 테두리 상자(넣은 값이 있으면 그 값). 결과 글은 y=32. 격자 밑에 "가로 a칸 × 세로 b칸"·"모두 n칸"(□ 쪽은 넣어 본 뒤에만). look `grid`·`symbols`에도 식 줄과 `balance-sign`(=/≠/?)이 있다. 괄호·"바깥쪽/안쪽"은 오버레이 `cross-brackets`에만 있다(바깥쪽 실선·안쪽 점선, 값 없음). `area-diff`는 판 가운데 패널에 왼쪽 아래 모서리를 맞춘 겹친 그림(왼쪽만 ／ 빗금·오른쪽만 ＼ 빗금, 숫자 없음), `big-tilt`는 마지막으로 넣은 값의 두 넓이와 ≠. `match-bars`는 proportion에서 그리지 않는다.
- **키보드:** ←→(↑↓)는 슬라이더에 초점이 있을 때만 쓴다(wrap 전체에서 가로채지 않음).
- **스냅샷:** 새 기준 이미지 8장(`balance-proportion-{scale,grid,symbols,scale-tilt}` × 크롬북·아이패드, 직접 열어 확인). **다시 찍은 equation 기준 이미지 8장**(`balance-{scale,bars,symbols,scale-tilt}` × 크롬북·아이패드): 모드 상자가 `proportion` 글자 때문에 넓어져 도구 줄 단추만 오른쪽으로 밀렸다. 차이 이미지를 열어 보니 엔진 그림·조작 칸은 그대로고 도구 줄만 달랐다(카드 허락 범위). g2s1u3 기준 이미지는 안 바뀌었다(통과).
- **범위 밖 요청:** 없음.
