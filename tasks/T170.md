### 1. 파일과 범위
- 엔진 폴더는 `src/engines/E15-pattern/`이다. 엔진 ID는 `E15`, 이름은 "규칙·패턴", `modes`는 `['sequence', 'hundred-chart']`다.
- 파일:
  - `index.ts`, `types.ts`(모드별 판별 유니온), `strings.ko.ts`
  - `tokens.tsx`: 토큰 그림
  - `pattern.ts`: 반복 단위·이어 가기·오개념 판정, 순수 함수
  - `chart.ts`: 배열표 좌표·가린 칸, 순수 함수

### 2. 토큰
- 토큰은 문자열 ID다. 아래 기본 토큰은 `tokens.tsx`의 SVG 그림으로 그린다. 이모지·글꼴에 기대지 않는다.
  - 모양: `circle`, `triangle`, `square`, `star`, `heart`
  - 과일: `apple`, `banana`, `grape`, `strawberry`
  - 몸짓: `clap`(박수), `jump`(점프), `hands-up`(만세). 사람 막대 그림이다.
- 기본 토큰이 아닌 문자열(예: `"1"`, `"ㄱ"`)은 그 글자를 큰 글씨로 쓴 글자 카드다.
- **색만으로 구분하지 않는다.** 모양·과일은 윤곽이 서로 다르다. `look: 'color'`일 때만 색을 칠한다.
- 카드 한 변은 `targetSize`(48 / 저학년 64) 이상이다. 칸 안 그림은 카드의 70%다.
- 화면 낭독용 이름은 `strings.ko.ts`에 둔다(동그라미, 세모, 네모, 별, 하트, 사과, 바나나, 포도, 딸기, 박수, 점프, 만세). 글자 카드는 그 글자를 읽는다.

### 3. `sequence` 설정
```ts
interface SequenceConfig {
  mode: 'sequence';
  variant?: 'extend' | 'translate'; // 기본 'extend'
  items: string[];          // 팔레트 토큰(순서대로 그린다)
  given?: string[];         // 앞에 주어진 칸(기본 [])
  blanks: number;           // 학생이 채울 칸 수(1~16)
  givenDisplay?: 'show' | 'sound-only'; // 기본 'show'
  look?: 'color' | 'plain' | 'symbol';  // CPA, 기본 'color'
  symbols?: Record<string, string>;     // look 'symbol'일 때 토큰 → 글자(예: circle → "ㄱ")
  mapping?: { sound?: 'pentatonic' | 'none'; motion?: boolean }; // 기본 { sound: 'pentatonic', motion: false }
  notes?: Record<string, number>;       // 토큰 → 음 번호(0 = 도). 없으면 items 순서로 도·미·솔·라·높은 도·높은 레
  // translate 전용
  source?: string[];        // 보내는 무늬 한 번(반복 단위)
  repeat?: number;          // source 반복 횟수(기본 2, 1~6)
  targetAlphabet?: string[];// 받는 암호에 쓸 토큰(이것이 팔레트가 된다)
}
```
- `audio: 'web-audio'` 같은 모르는 키는 받기만 하고 무시한다. 스키마가 모르는 키로 실패하지 않게 한다.
- **`extend`:** 트랙은 `given` 칸 다음에 `blanks`개 빈칸이다. `given: []`, `blanks: 8`이면 "내 규칙 만들기"다(빈칸 8개를 자유롭게 채움).
- **`givenDisplay: 'sound-only'`:** 주어진 칸을 "?" 카드(스피커 그림)로 그린다. 토큰은 DOM에 없다(`data-token` 속성도 없음). ▶로 소리만 들을 수 있다.
- **`translate`:** 두 줄이다.
  - 윗줄 '보내는 무늬'는 `source`를 `repeat`번 이은 주어진 칸이다(`givenDisplay` 규칙을 따른다).
  - 아랫줄 '받는 암호'는 같은 길이의 빈칸이다. 팔레트는 `targetAlphabet`이다.
  - 이때 `items`, `given`, `blanks`는 무시한다.
  - `source`에 글자 토큰(`"3"`, `"1"`)을 주고 `targetAlphabet`에 모양을 주면 "숫자 암호 → 모양" 과제가 된다.
- **설정이 잘못된 경우**(개발 모드 `console.warn`, throw 없음):
  - `given`이 비어 있지 않은데 반복 단위가 없으면(4번 `coreOf`가 null) 그대로 그린다.
  - `items`에 없는 토큰이 `given`에 있어도 그린다.

### 4. 반복 단위와 판정 (`pattern.ts`, 순수 함수)
- **`coreOf(seq, minRepeats = 2)`**
  - `seq`가 길이 p인 단위로 처음부터 되풀이되는 가장 작은 p를 찾는다. 조건은 모든 i ≥ p에서 `seq[i] === seq[i-p]`이고 `seq.length >= p * minRepeats`다.
  - 반환값은 `seq.slice(0, p)`다. 그런 p가 없으면 `null`이다(빈 배열도 `null`).
  - 끝이 단위 중간에서 끊겨도 된다(○△○△○의 단위는 ○△).
- **`continuation(given, n)`:** `coreOf(given)`로 다음 n칸을 이어 간 배열이다. 단위가 없으면 `null`이다.
- **`sameCycle(a, b)`:** 두 단위가 회전으로 같은가(○○□ ≡ ○□○)다. `coreIs`의 `rotate` 옵션이 쓴다.
- **오개념 판정(`patternMisconceptions(given, filled)`):** 빈칸을 모두 채웠고 `filled`가 `continuation`과 다를 때만 본다.
  - `MC-PATTERN-LAST-ONLY`: 채운 칸이 모두 `given`의 마지막 토큰과 같다.
  - `MC-PATTERN-CORE`: LAST-ONLY가 아니면서, 2 ≤ L ≤ min(4, given 길이)인 L 가운데 다음을 만족하는 것이 있다.
    - L이 실제 단위 길이와 다르다.
    - `filled`가 `given`의 끝 L칸(`given.slice(-L)`)을 단위로 이어 간 것이거나, 앞 L칸(`given.slice(0, L)`)을 단위로 처음부터 되풀이했을 때 그 자리의 토큰과 같다.
    - 예: ○○△○○△ 뒤에 ○△○.
  - `given`이 비었거나 단위가 없으면 아무것도 감지하지 않는다.
- **`translate` 대응(`translatePairs(source, target)`):** 같은 자리의 (보내는 토큰, 받는 토큰) 쌍을 모은다.
  - `consistent`: 한 보내는 토큰이 늘 한 받는 토큰이고, 다른 보내는 토큰은 다른 받는 토큰이다(일대일). 빈칸이 있으면 `false`다.
  - `MC-PATTERN-TRANSLATE`: 채운 칸만 볼 때 한 보내는 토큰에 받는 토큰이 둘 이상 붙었거나, 두 보내는 토큰이 같은 받는 토큰을 받았다. 빈칸이 남아도 감지한다.
- **단위 테스트(경계값):**
  - `coreOf`
    - 빈 배열
    - 길이 1
    - ○○○○: p는 1
    - ○△○△○: ○△
    - ○○△○○△: ○○△
    - ○△□○△: `minRepeats` 2에서 null
    - `minRepeats` 1이면 늘 자기 자신 이하의 단위가 있다
  - `continuation`: 끝이 단위 중간일 때 이어지는 위치가 맞다.
  - 오개념
    - LAST-ONLY: ○△○△○ 뒤 ○○○
    - CORE: ○○△○○△ 뒤 ○△○
    - 정답이면 둘 다 아님
    - 빈칸이 남으면 아무것도 감지하지 않음
  - `translate`
    - 일대일 성립
    - 한 사과에 1과 3
    - 사과와 바나나가 모두 1
    - 빈칸 있음

### 5. `sequence` 상태와 Action
- **상태:**
  ```ts
  {
    mode: 'sequence',
    settings,           // 정규화된 설정
    slots: (string|null)[], // 학생 빈칸, 길이 = blanks(또는 translate 길이)
    cursor: number,     // 선택된 빈칸 번호
    sent: boolean,      // translate의 '보내기'
  }
  ```
  - `settings`는 T130 메모처럼 상태 안에 둔다. `reduce`가 config를 받지 않기 때문이다.
  - `null` 대신 `undefined`를 쓰지 않는다(`assertSerializable`).
- **Action:**
  - `place {slot, token}`: 그 빈칸에 토큰을 놓는다.
    - 팔레트에 없는 토큰이나 범위 밖이면 상태를 그대로 둔다.
    - 놓은 뒤 `cursor`는 다음 빈칸(없으면 그대로)이다.
  - `clear-slot {slot}`
  - `move-cursor {slot}`: 범위 안으로 자른다.
  - `clear-all`
  - `send`: translate일 때 `sent: true`. 다른 Action은 모두 `sent`를 `false`로 되돌린다.
- **재생은 상태가 아니다.** ▶ 재생 중 강조, 소리, 동작은 View의 로컬 상태와 타이머다. 상태·Observation에 넣지 않는다.

### 6. `sequence` 화면 (`SequenceView.tsx`)
- **트랙**
  - 한 줄로 그린다: 주어진 칸 → 빈칸. 좁으면 줄을 바꾼다(가로 스크롤 없음).
  - 주어진 칸은 회색 바탕과 테두리이고 누를 수 없다. 빈칸은 점선 테두리다.
  - 선택된 빈칸은 굵은 테두리와 아래 ▲ 표시다.
  - `data-testid`
    - 주어진 칸: `pattern-given-<i>`
    - 빈칸: `pattern-slot-<i>`
    - 토큰이 보이는 칸에는 `data-token`을 단다. `sound-only`의 주어진 칸에는 달지 않는다.
- **팔레트(`pattern-palette`)**
  - 토큰 카드 단추들이다. 누르면 `cursor` 빈칸에 `place`한다.
  - 빈칸을 누르면 `move-cursor`한다. 채운 빈칸을 다시 누르면 `clear-slot`이다.
  - 팔레트 카드에서 빈칸으로 끌어 놓기도 된다(Pointer Events, 8px 넘게 움직이면 끌기).
  - 소리가 켜져 있으면 팔레트 카드를 누를 때 그 음을 짧게 낸다.
- **도구 줄**
  - "▶ 들어 보기": 주어진 칸 + 채운 빈칸을 차례로 재생한다. 한 칸 500ms, 빈칸에서 멈춘다.
  - "모두 지우기"
  - translate일 때 "보내기"
- **재생**
  - 재생하는 칸에 강조 테두리를 그린다.
  - `mapping.sound !== 'none'`이고 오디오를 쓸 수 있으면 그 토큰의 음을 낸다.
  - `mapping.motion`이면 트랙 옆 캐릭터(막대 사람 SVG)가 토큰 순서(items 0·1·2)에 따라 박수·점프·만세 자세를 한다. 그 밖의 토큰은 박수다.
  - `prefers-reduced-motion`이면 자세만 바꾸고 움직이지 않는다.
- **오디오(`audio.ts`)**
  - `AudioContext`(또는 `webkitAudioContext`)가 있을 때만 쓴다. 첫 사용자 동작(▶·팔레트 누름)에서 만들고 `resume()`한다(iPad Safari 자동재생 제한).
  - 음은 사인파 0.35초, 짧은 감쇠다. 음 번호 n의 주파수는 도(261.63Hz)에서 장음계 오음(도·레·미·솔·라)을 따른다. 옥타브를 넘으면 2배다. 주파수는 화면 값이 아니라 소리 값이므로 number를 써도 된다.
  - 오디오를 못 쓰면 ▶은 강조와 동작만 하고, 도구 줄에 "소리를 낼 수 없어요"를 띄운다.
  - `sound-only` 칸은 이때 각 "?" 카드 안에 음 높이 막대(높이 = 음 번호)를 그린다. 이것이 대체 화면이다.
  - jsdom·Playwright에서는 오디오가 없거나 조용하다. 테스트는 소리 자체가 아니라 강조 순서를 본다.
- **translate:** 윗줄(보내는 무늬)과 아랫줄(받는 암호) 사이에 같은 자리끼리 잇는 옅은 세로선을 그린다.
  - "보내기"를 누르면(`sent`) 셋째 줄 '되돌린 무늬'를 그린다.
  - 되돌리는 규칙: 학생 암호의 각 받는 토큰을 그 받는 토큰이 **처음** 나온 자리의 보내는 토큰으로 바꾼다.
  - 원래 무늬와 다른 칸에는 ✕와 빗금을 그린다(학생 자료로 만든 결과다).
- **키보드**
  - 트랙에 `tabIndex=0`이다.
  - ←/→: 빈칸 이동
  - 숫자 1~9: 팔레트 n번째 토큰 놓기
  - Backspace·Delete: 지우기
  - P: 재생
  - `aria-live`: "3번째 칸에 세모"만 말한다. 맞고 틀림은 말하지 않는다.
- **CPA `look`**
  - `color`: 색 그림
  - `plain`: 회색 윤곽 그림
  - `symbol`: `symbols`의 글자 카드로 그린다(없는 토큰은 그림 그대로)

### 7. `sequence` Observation과 predicate
- **Observation**
  - `mode`, `variant`
  - `given`: `sound-only`여도 Observation에는 넣는다. 판정용이고 화면에 그리지 않는다.
  - `slots`, `filled`(채운 수), `complete`
  - `sequence`: given + slots, 빈칸은 `null`
  - `expected`: `continuation`. 판정 전용이고 View는 쓰지 않는다.
  - `continuesGiven`: complete이고 `expected`와 같다.
  - `core`: complete일 때 `coreOf(학생 slots)`. extend에서 given이 비었을 때 "내 규칙"용이다. given이 있으면 `coreOf(given + slots)`.
  - `misconceptions`: 정렬된 코드 목록
  - translate일 때 추가: `pairs`, `consistent`, `sent`, `restoredMatches`(되돌린 무늬 = 원래 무늬)
- **Predicate**(인자가 잘못되면 false, throw 없음)
  - `blanksAre {tokens}`
  - `continuesGiven {}`
  - `coreIs {core, rotate?: boolean}`: 학생 slots의 단위가 `core`와 같다. `rotate`면 `sameCycle`. 기본 false.
  - `hasRepeat {minCoreLength?: number, minRepeats?: number}`: 학생 slots가 complete이고, `coreOf(slots, minRepeats)`가 있으며, 그 길이가 `minCoreLength` 이상이다. 기본은 2, 2다. ○○○○는 단위 길이 1이라 기본값에서 false다.
  - `translateConsistent {}`
  - `restoredMatches {}`
  - `hasMisconception {code}`
- **이벤트:** `token-placed {slot, token}`, `slot-cleared {slot}`, `pattern-played {}`, `code-sent {consistent}`

### 8. `hundred-chart` 설정
```ts
interface ChartConfig {
  mode: 'hundred-chart';
  range?: [number, number];   // 기본 [1, 100]. 시작은 10으로 나눈 나머지가 1 또는 0, 칸 수는 10의 배수, 최대 200칸
  hidden?: number[] | 'cross' | { random: number; seed?: number; within?: [number, number] };
  center?: number;            // 'cross'의 가운데(가린다). 위·아래·왼·오른 칸은 보이고 나머지 칸은 view에 따름
  view?: 'full' | 'cross-only' | 'row' | 'column'; // 기본 'full'
  focus?: number;             // view 'row'·'column'일 때 기준 칸
  select?: boolean;           // 칸 고르기(기본 false)
  paint?: boolean;            // 칠하기(기본 false)
  prepainted?: number[];      // 처음부터 칠해진 칸(학생이 지울 수 없음)
  revealOnAnswer?: boolean;   // 받기만 하고 무시(맞고 틀림을 엔진이 보이지 않는다)
}
```
- 칸 값은 정수 칸 번호라 `number`를 허용한다(T130 격자 번호와 같은 근거). 학생 입력은 숫자 문자열로 저장하고 비교 때 정수로 바꾼다.
- `hidden`
  - `'cross'`: `center` 하나만 가린다.
  - `view: 'cross-only'`: 가운데와 위·아래·왼·오른 넷만 그리고 나머지 칸은 그리지 않는다(빈 자리).
  - `row`·`column`: `focus` 칸이 있는 가로줄·세로줄만 그린다.
  - `{random: n}`: `range`(또는 `within`) 안에서 n칸을 고른다.
    - E17 `random.ts`의 시드 난수를 쓴다. `seed`가 없으면 `createInitialState`에서 한 번 정해 상태에 저장한다(되감기·미러링에서 같은 칸).
    - 가로·세로로 맞닿은 두 칸은 함께 가리지 않는다.

### 9. `hundred-chart` 상태·Action·화면
- **상태:** `{ mode: 'hundred-chart', settings, hidden: number[], entries: Record<string, string>, selected: number | null, painted: number[], active: number | null }`
  - `entries`의 키는 칸 번호 문자열이다.
  - `painted`는 정렬하고 `prepainted`를 포함한다.
- **Action**
  - `activate {cell}`: 가린 칸만, 입력할 칸 고르기
  - `type-digit {digit}`: `active` 칸 입력 끝에 붙인다. 최대 3자리다.
  - `backspace`
  - `clear-entry`
  - `select-cell {cell}`: `select`일 때
  - `toggle-paint {cell}`: `paint`일 때. `prepainted`·가린 칸은 무시한다.
- **화면 (`ChartView.tsx`)**
  - 10열 격자 SVG 하나다. `data-testid="chart-canvas"`, 칸은 `data-cell="<번호>"`다.
  - 보이는 칸은 숫자를 쓴다. 가린 칸은 나뭇잎 그림 + "?"다. 입력이 있으면 나뭇잎 위에 그 수를 쓴다.
  - 입력한 칸이 맞는지 틀린지는 표시하지 않는다(`revealOnAnswer` 무시).
  - `active` 칸은 굵은 테두리다. 고른 칸은 굵은 테두리 + 모서리 점이다.
  - 칠한 칸은 채움 + 점무늬다(색만으로 구분 금지). `prepainted`는 같은 그림이고 자물쇠 표시가 없다.
  - 칸 한 변은 판에 맞춰 크게 그리되 `targetSize` 이상이다. 100칸 전체가 판에 안 들어가면 SVG 높이를 칸 크기에 맞추고 판 안에서 세로 스크롤한다(T163 `ScrollBoard` 방식을 참고하되 E18을 import하지 않는다).
  - 크롬북·아이패드 판에서 10×10의 칸 한 변을 E2E로 재어 메모에 적는다.
- **숫자 패드**
  - 가린 칸이 있을 때 판 옆(좁으면 아래)에 0~9, 지우기, "다 썼어요"(active 해제) 단추를 둔다. 단추는 `targetSize` 이상이다.
  - 물리 키보드 숫자·Backspace도 받는다.
- **키보드:** 격자에 `tabIndex=0`이다.
  - 방향키: 커서 칸 이동(+1, +10)
  - Enter: 가린 칸이면 activate, select면 고르기, paint면 칠하기
  - `aria-live`: "46번 칸"·"칠했어요"만 말한다.
  - 가린 칸은 "가려진 칸"이라고 말하고 그 수를 말하지 않는다.

### 10. `hundred-chart` Observation과 predicate
- **Observation**
  - `mode`, `hidden`
  - `entries`: 칸 번호 → 정수 또는 null
  - `entriesComplete`
  - `entriesCorrect`: 모든 가린 칸의 입력 = 칸 번호
  - `selected`, `painted`(학생이 칠한 것 + prepainted, 정렬)
  - `misconceptions`
- **오개념:** `MC-CHART-ROW-COL`. 어떤 가린 칸의 입력이 칸 번호와 다르고, 바로 위나 아래 칸 수에서 ±1이면(예: 33 아래 칸에 34) 넣는다.
  - 레지스트리는 `diagnose`이지만 엔진도 Observation으로 낸다. 콘텐츠가 둘 중 하나를 고른다.
- **Predicate**
  - `entriesCorrect {}`
  - `entryIs {cell, value}`
  - `selectedIs {value}`
  - `paintedIs {values}`: 정확히 같은 집합
  - `paintedMultiples {of, upTo, from?}`: painted = {from(기본 of)부터 of씩 ≤ upTo}
  - `hasMisconception {code}`
- **이벤트:** `cell-entered {cell}`, `cell-selected {cell}`, `cell-painted {cell, on}`

### 11. 오버레이 (힌트 ②)
- 학생 자료나 과제가 준 자료로만 그리고, 정답 토큰·정답 수를 쓰지 않는다.
- 모두 `CanvasAlignedOverlay`를 쓴다.
  - sequence: 트랙 SVG(`data-testid="pattern-track"`)에 맞춘다. 트랙을 SVG로 그리거나, 트랙 상자를 selector로 쓴다.
  - chart: `chart-canvas`에 맞춘다.
- **`core-boxes`** (MC-PATTERN-CORE)
  - 주어진 칸에 실제 반복 단위마다 번호 붙은 점선 상자를 씌운다.
  - 빈칸 쪽에도 같은 길이의 빈 상자 틀을 이어 그린다(토큰 없음).
  - 학생 칸 가운데 바로 앞 상자의 같은 자리 토큰과 다른 칸에 ✕ 표시를 한다.
- **`replay-break`** (MC-PATTERN-LAST-ONLY)
  - 학생 칸 가운데 `expected`와 처음 다른 칸에 물결 표시와 "여기서 리듬이 바뀌어요"를 그린다.
  - "▶ 다시 듣기" 단추가 그 칸까지 재생한다.
- **`mapping-card`** (MC-PATTERN-TRANSLATE)
  - 학생이 채운 칸에서 보내는 토큰마다 처음 붙인 받는 토큰을 "🍎 = 1" 모양 카드로 나열한다(그림 토큰).
  - 같은 보내는 토큰에 다른 받는 토큰이 붙은 칸은 트랙에 ✕로 표시한다.
- **`ten-step`** (MC-CHART-ROW-COL)
  - 오개념이 난 가린 칸의 바로 위 칸 수를 10 막대와 낱개 점으로 칸 옆에 그린다.
  - 그 아래에 "10 막대 1개 더"를 화살표로 그린다. 아래 칸 수 자체는 쓰지 않는다.
  - `args: {cell}`가 없으면 Observation에서 첫 오개념 칸을 쓴다.
