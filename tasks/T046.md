## 구현 결정 (2026-11-04 Claude 작성 — 여기 적힌 대로 하고, 바꿔야 하면 메모에 이유를 적고 질문한다)
1. **폴더·모드:** `src/engines/E07-column-calc/`만 고친다(예외는 10번의 데모 콘텐츠). `modes`는 기존 3개 뒤에 `mul`, `estimate` 순서로 붙인다(`ColumnMode`, `DEFAULT_NUMBERS`, `strings.instructions`에 추가). View.tsx(561줄)는 모드에 따라 고르기만 하고, 새 화면은 `views/MulView.tsx`, `views/EstimateView.tsx`로 둔다. 곱셈 계산은 `grid-mul.ts`, 곱셈 오류 분류는 `classify-mul.ts`로 나눈다. 기존 add·sub·decimal의 동작·Observation·이벤트는 바꾸지 않는다. T047이 `div`와 `divide-progress` 받기를 더하므로 `receive`는 이벤트 이름별 함수 표(`receivers: Record<string, (state, payload, config) => Action | null>`)로 만든다.
2. **설정 값:** `a`, `b`는 `number | string` 모두 받는다(`String()` 뒤 기존 `parseNumber`) — 단원 명세 예시가 number다. 곱셈은 자연수만(a 1~4자리, b 1~2자리). 범위 밖이면 `DEFAULT_NUMBERS.mul`(`46`×`5`)로 고치고 메모 없이 진행. 수는 문자열 자리 단위로 다루고, 소수가 필요한 곳은 `Rational`(이 카드에는 없음).
3. **mul 격자:** 설정 `style: 'carry' | 'partial-products'`(기본 `carry`, 단원 명세의 `"two-rows"`는 `carry`의 다른 이름으로 받는다), `showZeroPlaceholder: boolean`(기본 true), `debugSample?: { rows: string[], sum: string }`.
   - `carry` + b 한 자리: a, b 아래 결과 줄 하나(기존 `result` 행) + 위쪽 올림 줄(기존 `carries`, 열 키 = 받는 열). 213×4 → 852.
   - `carry` + b 두 자리(= "two-rows"): b의 자리마다 부분곱 줄 하나(46×27 → 322, 920), 그 위에 줄마다 올림 칸, 아래 합 줄(`result`). 둘째 줄 일의 자리(열 0)는 `showZeroPlaceholder`가 true면 흐린 "0"이 미리 채워진 점선 칸(수정 불가), false면 학생이 0을 쓰거나 비워 둬도 된다(빈칸 = 0으로 읽음, 그 열 외에는 빈칸 = 미완성).
   - `partial-products`(b 한 자리 전용, 두 자리면 `carry`로): a의 0이 아닌 자리마다 부분곱 줄(46×5 → 30, 200), 아래 합 줄. 줄 순서는 낮은 자리부터.
   - 상태: `partials: Record<string, string>[]`(줄 index → 열 → 숫자), `partialCarries: Record<string, string>[]`, 합은 기존 `result`, 기존 `carries`는 b 한 자리 carry에서만. `CellRef`에 `index?: number`를 더하고 `EditableRow`에 `'partial' | 'partial-carry'`를 더한다. `enter`·`select`가 index를 받는다. 키보드 자동 진행: 한 줄 안에서 오른쪽→왼쪽, 줄 끝에서 다음 줄 오른쪽 끝.
   - `debugSample`: rows·sum을 미리 채운 "틀린 풀이"를 보여 주고(수정 가능), 새 Action `flag-cell {row, index?, column}`으로 학생이 틀린 칸을 표시한다(다시 누르면 해제). Observation `flaggedCells`.
4. **곱셈 오류 분류(`classify-mul.ts`, 기존 `MisconceptionCode`에 추가):** 판정은 학생이 쓴 줄 값과 기대값의 비교로만. 순서대로 검사하고 첫 일치만 기록한다.
   - `MC-MUL-PARTIAL-SHIFT`: 둘째 이후 부분곱 줄 값이 기대값/10^k(자리 밀기 안 함)과 같다. 예 46×27에서 둘째 줄 92.
   - `MC-MUL-PARTIAL-MISSING`: 합 줄 값이 부분곱 하나와 같거나, 부분곱 하나를 뺀 합과 같다.
   - `MC-MUL-CARRY-ADD-BEFORE`: 어떤 열 숫자가 `((a의 그 자리 + 받은 올림) × b의 자리) mod 10`과 같고 기대 숫자와 다르다.
   - `MC-PV-NO-CARRY`: 어떤 열 숫자가 받은 올림을 더하지 않은 `(a자리 × b자리) mod 10`, 또는 올림 없이 `a자리 × b자리` 두 자리를 그대로 쓴 값과 같다(27×3=61의 6). 기존 코드 재사용.
   - `MC-MUL-NO-PLACE-VALUE`: 결과 값이 자리마다 곱을 자릿값 없이 더한 값과 같다(4×23 → 8+12=20).
   - 덤: 뺄셈 `MC-PV-BORROW-ACROSS-ZERO`도 여기서 함께 더한다(`classify.ts`) — 위 숫자가 0인 열을 거쳐 받아내림했는데 그 열 결과가 기대값 +1(0을 9로 줄이지 않고 10으로 씀)이면. 우선순위는 기존 ④ 뒤.
5. **estimate:** 설정 `op: 'add' | 'sub' | 'mul'`, `a`, `b`, `roundTo`(10·100·1000), `tolerance: { green, yellow }`(어림값과 학생 결과의 차이 한계, 기본 `{ green: roundTo, yellow: roundTo*2 }`), `sample?: string`(미리 채운 틀린 결과 — "다시 확인" 과제용), `style`(mul일 때 3번).
   - 단계 `phase: 'estimate' | 'calc'`. 처음엔 어림값 칸(최대 6자리, 같은 키패드)만 열리고 "어림값 정하기"(`lock-estimate`)를 누르면 잠기고 격자가 열린다. 어림값을 고치려면 "어림값 다시"(`unlock-estimate`, 격자 입력은 지우지 않음).
   - 격자는 op에 따라 기존 add·sub 격자 또는 3번 mul 격자를 그대로 쓴다(코드 공유, 새 격자 만들지 않음).
   - 결과가 완성되면 신호등: `|어림값 − 학생 결과| ≤ green` 초록, `≤ yellow` 노랑, 그 밖 빨강. **학생이 쓴 결과와 비교하므로 정답을 드러내지 않는다.** 색 + 모양(●·▲·■) + 말("가까워요"·"조금 멀어요"·"많이 멀어요")로 보이고 숫자 차이는 쓰지 않는다.
   - `sample`이 있으면 결과 줄이 미리 채워진 채 시작하고 신호등이 바로 보인다. "다시 확인" 버튼(`recheck`)을 누르면 `rechecked: true`가 되고 결과 줄을 지워 다시 풀게 한다.
   - `roundTo`로 엔진이 어림값을 계산해 보여 주지 않는다. Observation에만 `estimateIsMultiple`(어림값이 roundTo의 배수인지)을 둔다.
   - 단원 명세의 `estimateBar`(g4s1u3 나눗셈 배수 사다리)는 T047 몫이다. 이 카드에서 만들지 않는다.
6. **receive(연결):** 설정 `linkMarks: 'auto' | 'hint'`(기본 `hint`). `receive`는 cpa를 모르므로 C 단계 자동 기록은 콘텐츠가 `linkMarks: "auto"`로 정한다.
   - E01 `grouped {from, to, column}`(add 격자): `auto`면 `carries[column+1]`에 "1"을 쓴다(이미 있으면 그대로). `hint`면 그 칸을 강조만 한다(상태 `linkHighlights: string[]`, 키 `"carry:1"` 꼴, 다음 입력 때 지움).
   - E01 `broken {from, to, column}`(sub 격자): `auto`면 `crosses`에 column, `regroups[column]` = (그 열의 지금 위 숫자 − 1, 위 숫자는 regroup이 있으면 그것, 없으면 원래 숫자, 그 열에 ten 표시가 있으면 +10 — 403−158에서 0 → 9), `tens`에 column−1을 표시한다. `hint`면 그 세 칸을 강조만.
   - E04 `partial-product-changed {parts}`(mul 격자): 부분곱 줄 중 **기대값이 |product|와 같은 줄**에 그 part의 `colorIndex`를 칠한다. payload의 a·b 방향은 쓰지 않는다(E04 area-model의 a·b가 뒤바뀌어 있어 값으로만 맞춘다). 색은 E04 `PARTIAL_PALETTE`의 값을 복사해 `strings`가 아닌 `palette.ts`에 두고 import하지 않는다. 줄 왼쪽에 같은 무늬 띠를 붙여 색만으로 구분하지 않는다. 상태 `rowColors: Record<string, number>`.
   - 받은 이벤트는 새 Action `link-mark {...}`·`link-colors {...}`로 바꿔 돌려준다(receive는 Action을 돌려줄 뿐이다). 해당 없는 모드면 `null`.
7. **Observation(새 키, 해당 없으면 null):** mul: `style`, `partials: string[]`(줄 값, 빈 줄은 null), `expectedRowCount`(줄 수만 — 줄 값은 넣지 않는다), `rowsComplete`, `flaggedCells`, `rowColors`. estimate: `phase`, `estimate`, `estimateIsMultiple`, `signal: 'green' | 'yellow' | 'red' | null`, `rechecked`. 기존 `result`·`complete`·`errors`·`misconceptions`는 mul·estimate에서도 채운다.
8. **Predicates(추가):** `partialsAre {values}`(줄 값 목록이 같음), `signalIs {value}`, `estimateIs {value}`, `flaggedCell {row, index?, column}`, `linkMarked {kind, column}`.
9. **이벤트(추가):** `estimate-locked {estimate}`, `signal-changed {signal}`. 기존 `cell-entered`는 index를 payload에 더하고, `value-changed`는 mul 합 줄이 완성될 때도 낸다.
10. **데모 콘텐츠(이 카드에 한해 `data/content/demo.json` 수정 허용 — 새 활동을 덧붙이기만, 기존 A1~A3 수정 금지):** `demo.A4` "블록과 세로셈" — views E01 `add-sub`(왼쪽) + E07 `add`(오른쪽, `linkMarks: "auto"`), links `grouped`·`broken` E01→E07, 과제 1개 38+25 `resultIs 63`. `demo.A5` "넓이와 곱셈" — views E07 `mul`(`style: "partial-products"`, 46×5, 채점 슬롯) + E04 `area-model`, link `partial-product-changed` E04→E07, 과제 1개 `resultIs 230`. 힌트는 기존 레지스트리에 있는 코드만 쓰거나 생략. `tests/e2e/runner.spec.ts`의 "과제 3 / 8" 같은 기존 단언이 깨지면 새 활동이 기존 흐름에 끼어든 것이니 고친다(기존 단언을 바꾸지 말 것).
11. **정답 노출 금지:** 부분곱 줄 값·합·어림값의 기대값을 화면에 쓰지 않는다. 신호등은 학생 결과 기준. `linkMarks: "auto"`는 학생이 블록으로 한 조작을 옮겨 적는 것이라 허용. View 테스트로 확인한다(mul 46×27·estimate 389+412 설정에서 1242·801·322·920·800이 DOM에 없음).
