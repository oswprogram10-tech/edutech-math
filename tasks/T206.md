## 목표
E06 양팔저울에 `compare` 모드를 더한다.
- 사물 그림을 양쪽 접시에 끌어 놓으면 저울이 무거운 쪽으로 기운다(결정적 애니메이션).
- 저울을 몇 번 썼는지 센다.
- 크기와 무게가 반대인 물건으로 "크면 무겁다"를 깨뜨린다.

이 모드는 g1s1u4.A2(T207)에 쓴다. `equation`·`proportion`은 바꾸지 않는다.

## 구현 결정 (2026-11-20 Claude 작성 — 여기 적힌 대로 하고, 바꿔야 하면 메모에 이유를 적고 멈춰서 묻는다)

### 1. 파일
- 코드는 `src/engines/E06-balance/compare/`에 둔다. `proportion/`과 같은 구성이다.
- `unions.ts`·`engine.ts`·`index.ts`·`settings`(모드 구분)는 `compare`를 더하는 줄만 고친다.
- equation·proportion 파일은 건드리지 않는다.
- 판 맞춤과 T199 세로 배치 CSS는 E06 기존 방식을 그대로 쓴다.

### 2. 설정
```
{ mode:'compare',
  items: [{ id, kind, weight, visualSize? }],
  showValues?: boolean,
  maxPerPan?: number }
```
- **`items`:** 2~4개다.
  - `kind`는 사물 그림 종류다: `apple | feather | balloon | stone | sponge | iron-ball | book | eraser`
  - `weight`는 정수 1~20이다.
  - `visualSize`는 `small | medium | large`이고, 기본은 kind별 기본 크기다. 큰 스펀지는 `large`, 작은 쇠공은 `small`로 콘텐츠가 정한다.
- **`showValues`:** 기본 false다. true일 때만 물건 아래에 무게 숫자를 쓴다. 1학년 과제는 쓰지 않는다.
- **`maxPerPan`:** 기본 1이다. 한 접시에 올릴 수 있는 물건 수다.
- 물건 이름 글은 `strings.ko.ts`에 둔다(사과, 깃털, 풍선, 돌, 스펀지, 쇠공, 책, 지우개).

### 3. 조작
- 판 아래 선반에 물건들을 놓는다. 물건을 끌어 왼쪽·오른쪽 접시에 놓고, 접시의 물건을 끌어 선반으로 되돌린다.
- **키보드:** 선반의 물건을 고르고 L(왼쪽)·R(오른쪽)·Backspace(선반으로)를 누른다. 같은 일을 하는 조작 칸 단추도 둔다.
- **Action:** `place {id, pan:'left'|'right'|'shelf'}`, `reset`
  - 접시가 가득 차면(`maxPerPan`) 거절한다.
  - 같은 자리로 옮기면 거절한다.
- **저울 기울기:** 양쪽 무게 합을 비교한다.
  - 기울기 각도는 equation과 같은 규칙(결정적, 최대 각)을 쓴다.
  - 한쪽만 비었으면 물건이 있는 쪽으로 기운다.
- **결과 글:** "왼쪽이 더 무거워요", "오른쪽이 더 무거워요", "수평이에요". 결과 글은 학생이 올린 상태의 결과라 보여 줘도 된다.
- **비교 수 세기:** 양쪽 접시에 물건이 하나 이상씩 있는 상태가 새로 만들어질 때마다 `weighings`가 1 오른다.
  - "새로"의 기준은 (왼쪽 집합, 오른쪽 집합)의 조합이다.
  - 전에 센 조합과 같으면 세지 않는다.

### 4. Observation과 predicates
- **Observation:**
  - `mode`, `left: string[]`, `right: string[]`
  - `tilt: 'left'|'right'|'level'`, `balanced`
  - `weighings: number`
  - `pairsCompared: string[]`: "a|b" 형식이고, 사전 순으로 정렬한 한 물건씩 비교한 쌍이다.
  - `heaviest: string`, `orderHeavyFirst: string[]`: 모든 items 기준이고, 무게가 같으면 id 순이다.
  - `misconceptions: []`
- **Predicates:**
  - `onPans {left?, right?}`: 집합이 같은지 본다.
  - `bothPansUsed`, `balanced`
  - `weighingsAtLeast {n}`
  - `compared {a, b}`: 한 번이라도 a와 b를 서로 반대 접시에 하나씩 올렸는지 본다.
- **판정 방식:** 엔진은 "무거운 것 고르기"를 하지 않는다. 고르기·순서는 콘텐츠 응답(choice·order)이 맡는다.

### 5. 오버레이
- **`size-vs-weight`**(MC-SIZE-IS-WEIGHT ②)
  - 저울에 올린 두 물건 옆에 두 줄을 그린다.
    - "크기" 막대: visualSize 상대 길이
    - "무게" 막대: 지금 저울 결과 방향만. 무거운 쪽 막대를 길게, 같으면 같게 그린다.
  - 숫자는 쓰지 않는다.
  - 두 접시에 물건이 하나씩 없으면 그리지 않는다.
- `big-tilt`는 compare에서도 쓸 수 있으면 그대로 등록해 쓴다. equation 전용 계산이면 compare에서는 그리지 않는다. 어느 쪽인지 메모에 적는다.

### 6. 테스트
- **샌드박스 모드 상자에 "무게 비교"를 더한다.** 모드 상자 폭이 바뀌어 E06 기준 이미지에서 도구 줄만 밀리면 다시 찍어도 된다(메모에 적는다).
- **샌드박스 기본:** sponge(2, large)·iron-ball(9, small)·apple(3)이다.
- **단위**
  - 놓기·거절, 기울기, weighings 세기(같은 조합 다시 세지 않음)
  - compared, orderHeavyFirst에서 같은 무게
  - JSON 왕복, predicates
  - View: `showValues:false`이면 시작 화면 DOM·aria·data-에 weight 숫자가 없다.
- **E2E**(`tests/e2e/balance.spec.ts`에 compare 묶음, 3 뷰포트, 샌드박스)
  - 끌어 놓기
  - 키보드 L·R
  - 세 물건 두 번 비교
  - `size-vs-weight` 1px 정렬
  - 첫 화면 스냅샷 × 크롬북·아이패드
- **E2E 범위:** `npx playwright test balance fit-canvas overlay-alignment --workers=3 --reporter=line`

### 구현 메모 (Sonnet, 2026-11-20)
- **구조**: `src/engines/E06-balance/compare/`에 `types·settings·reduce(읽기 포함)·observe·events(emit·predicates)·layout·Art(물건 그림 8종)·Board·View·strings.ko·compare.module.css`와 `overlays/size-vs-weight.tsx`·`overlays/guard.tsx`. 기존 파일은 모드를 나누는 줄만 고쳤다: `unions.ts`(타입 합침), `engine.ts`(compare 분기 3줄), `View.tsx`(compare 분기), `index.ts`(modes·predicates 합치기·emit 분배·오버레이 등록), `events.ts`(compare면 빈 배열 한 줄), `overlays/match-bars.tsx`(`mode === 'proportion'` → `!== 'equation'`)·`overlays/big-tilt.tsx`(compare이면 null 한 줄). 이 둘은 `build`(tsc -b)가 compare 상태 타입을 좁히라고 해서 고쳤다. 기존 `__tests__/engine.test.ts`는 modes 배열과 오버레이 이름 목록에 `compare`·`size-vs-weight`를 더했다. `tests/e2e/fit-canvas.spec.ts` E06 모드 목록에도 `compare`를 더했다.
- **오버레이**: `size-vs-weight`는 카드대로(크기 막대 = visualSize 상대 길이 small 1·medium 2·large 3, 무게 막대 = 저울 방향만, 숫자 없음). 한 접시에 여럿이면 크기는 합친 상대 길이. **`big-tilt`는 equation 전용 계산(tries·□)이라 compare에서 그리지 않는다.** `match-bars`·`cross-brackets`·`area-diff`도 마찬가지로 `guard.tsx`의 `skipInCompare`로 감싸 compare에서는 안 그린다(기존 오버레이 이름·동작은 그대로). 샌드박스의 [힌트 겹쳐 보기] 단추는 첫 오버레이(`big-tilt`)를 켜므로 compare에서는 `?overlay=size-vs-weight`로 연다.
- **카드에 없는 결정**
  - `maxPerPan`은 1~4 정수, `weight` 정수 1~20, `items` 2~4개, id는 `[A-Za-z0-9_-]{1,24}`(조합 이름 구분자와 겹치지 않게). 어긋나면 설정 오류(오류 문구만 보임). 설정에 `items`가 없으면(mode만이든 다른 키가 있든) 샌드박스 기본 스펀지(2, large)·쇠공(9, small)·사과(3). kind별 기본 크기: apple·feather·stone·sponge·book = medium, balloon = large, iron-ball·eraser = small.
  - 양쪽이 모두 비면 `tilt:'level'`이지만 `balanced:false`(양쪽에 물건이 있고 합이 같을 때만 true). 결과 글은 "물건을 접시에 올려 보세요"(카드 3문구 밖의 추가 문구).
  - `pairsCompared`·`compared`는 양쪽 접시에 정확히 하나씩일 때만 쌍을 기록한다(여럿이 올라 있을 때는 안 기록). `[처음으로]`는 접시만 비우고 `weighings`·쌍 기록은 지우지 않는다(proportion의 tries와 같은 방식).
  - 좌우를 바꾼 조합((a|b)와 (b|a))은 서로 다른 조합이라 각각 센다. 오른쪽에 같은 물건을 한 접시에서 다른 접시로 직접 옮기는 것도 가능(`place`).
  - 한 접시에 여러 개(`maxPerPan` ≥ 3)면 접시 위 물건 그림을 줄인다(`panScale`). 물건 그림 한 변(논리): small 52·medium 74·large 96. 눌러 잡는 영역은 최소 80(0.6배에서 48px 안팎).
  - 선택(고른 물건)은 View 지역 상태이고 Action이 아니다. 물건에 초점이 가거나 누르면 고른다. 조작 칸 단추 셋(왼쪽·오른쪽·선반으로)이 고른 물건을 옮긴다. 키보드 L·R·Backspace(Delete도)는 고른 물건에 적용되고 wrap 전체에서 듣는다. 끌기는 8px 넘게 움직여야 끌기이고, 놓은 자리가 논리 y ≥ 476이면 선반, 아니면 x < 500이면 왼쪽·아니면 오른쪽 접시다. 끄는 동안 좌표는 지역 상태이고 놓을 때 `place` 하나만 보낸다.
  - 샌드박스 모드 상자에는 모드 이름 그대로 `compare`가 나온다(다른 엔진 모드도 영어 이름이다).
- **정답 노출**: `showValues:false`이면 무게 숫자가 DOM·aria·data-에 없는 것을 단위 테스트로 확인했다(시작 화면, 기울어진 뒤, 샌드박스 기본, 오버레이 텍스트에 숫자 없음). `data-target-size`(조작 칸 크기)만 제외했다. 위치 좌표는 `data-`에 두지 않았다. `showValues:true`일 때만 물건 아래에 무게(선반은 "이름 무게", 접시는 숫자)를 쓴다.
- **E2E**(`balance.spec.ts` compare 묶음 11개 × 뷰포트): 끌어 놓기(판 상자 너비로만 배율 계산, 논리 높이 가정 없음), 가득 찬 접시 거절 글, 키보드 L·R·Backspace(옮긴 뒤에도 초점 유지), 조작 칸 단추·[처음으로], 세 물건 두 번 비교(weighings 2, 같은 조합 다시 안 셈, pairsCompared·orderHeavyFirst), `size-vs-weight` 1px 정렬·막대 길이 방향·숫자 없음·접시가 비면 안 그림, 터치 타깃 48/64.
