## 목표
새 엔진 E16 `function-machine`을 만든다. 이 카드의 모드는 셋이다.
- `black-box`: 수를 넣으면 숨은 규칙의 결과가 나오고 대응표에 쌓인다. 학생은 관계식을 써서 시험한다.
- `table`: 대응표의 빈칸을 채우고 관계식을 쓴다.
- `covary`: 슬라이더로 ○를 바꾸면 그림과 □가 함께 변하고 대응표가 채워진다.

g4s1u6.A1(블랙박스)과 g5s1u3.A1(공변 슬라이더·대응표)을 이 세 모드로 만들 수 있어야 한다. `rule-shooter`(g5s1u3.A2)는 다음 카드 몫이다.

### 1. 파일과 범위
- 엔진 폴더는 `src/engines/E16-function-machine/`이다. ID는 `E16`, 이름은 "대응 관계", `modes`는 `['black-box', 'table', 'covary']`다.
- 파일:
  - `index.ts`, `types.ts`(모드별 판별 유니온), `settings.ts`, `strings.ko.ts`
  - `relation-check.ts`(코어 relation 위의 엔진 판정과 오개념, 순수 함수)
  - `reduce.ts`, `observe.ts`, `events.ts`
  - `Keypad.tsx`(수·식 키패드), `RelationTable.tsx`(대응표 SVG)
  - `BlackBoxView.tsx`, `TableView.tsx`, `CovaryView.tsx`, `scenes.tsx`(그림 장면), `View.tsx`, `View.module.css`
  - `overlays/`, `__tests__/`
- 수학 값은 모두 `Rational`이다. 상태에는 Rational 문자열(`"4"`, `"1/2"`)로 둔다. 슬라이더 위치·화면 좌표만 number다.
- `src/core/`, 다른 엔진, `data/`, `docs/`, `package.json`은 고치지 않는다.

### 2. 공통 설정
```ts
interface CommonConfig {
  rule: string;              // 숨은(또는 장면의) 규칙, 예 "□ = ○ × 4". parseRelation이 되고 solvedForBox여야 한다
  xLabel?: string;           // 표 첫 줄 이름(기본 "○"), 예 "의자 수"
  yLabel?: string;           // 기본 "□", 예 "다리 수"
  ruleInput?: boolean;       // 관계식 입력 칸(기본 true)
  domain?: [number, number]; // 정수 ○ 범위(기본 [0, 20]), 판정 sameOnDomain에 쓴다
}
```
- `rule`이 파싱되지 않거나 `solvedForBox`가 아니면 개발 모드 `console.warn`을 띄우고, 빈 판("설정 오류")을 그린다. throw하지 않는다.
- 명세 예시의 `"x*3"` 꼴은 받지 않는다. 단원 콘텐츠 카드가 명세를 `"□ = ○ × 3"` 꼴로 고친다.

### 3. 키패드 (`Keypad.tsx`)
- 두 종류다.
  - **수 키패드:** 0~9, 지우기(⌫), "다 썼어요"
  - **식 키패드:** 수 키 + ○ □ + − × ÷ ( ) =, ⌫, "모두 지우기", "규칙 시험하기"
- 모든 단추는 `targetSize` 이상이다. 물리 키보드 입력도 받는다.
  - 숫자
  - `o`/`O` → ○, `b`/`B` → □
  - `+ - * / ( ) =`
  - Backspace
  - Enter → 시험
- 식 입력 칸은 쓴 그대로(유니코드 기호) 보이고, 커서는 끝에만 있다.
- 시험할 때 `parseRelation`이 실패하면 입력 칸 아래에 "식을 다시 확인해 볼까요?"와 오류 위치 밑줄을 보인다. 오류 문구에 정답을 쓰지 않는다.

### 4. 대응표 (`RelationTable.tsx`, 오버레이 기준 SVG)
- 가로 대응표(첫 행 ○, 둘째 행 □, 열 = 쌍)를 SVG 하나로 그린다. 교과서 표 모양이다. `data-testid="relation-canvas"`, 열마다 `data-col="<i>"`다.
- 칸은 수를 쓰거나, 학생이 채울 빈칸이다. 빈칸을 누르면 수 키패드 입력 대상이 된다.
- 관계식을 시험하면 각 열 아래에 ✓/✕ 표시를 한다. 그림 기호와 색을 같이 쓴다(색만으로 구분 금지).
  - 이것은 학생 식을 학생이 본 쌍에 넣은 결과라 정답 노출이 아니다.
  - 식을 고치면 표시는 사라진다.
- 열이 많아 칸이 targetSize보다 작아지면 판 안에서 가로 스크롤한다. 칸은 targetSize 이상이고 글자는 화면 14px 이상이다.

### 5. `black-box`
- **설정:** `inputRange?: [number, number]`(기본 `domain`), `maxTrials?: number`(없으면 무제한), `avoidForm?: string`(아래 `ruleFormDiffers`용, 판정에만 쓰고 화면에 보이지 않음)
- **화면**
  - 상자 그림(입구 ○, 출구 □)이 있다. 학생이 수 키패드로 ○를 쓰고 "넣기"를 누르면 짧은 애니메이션 뒤 □가 출구에 나온다.
  - 그 쌍은 대응표 끝에 열로 더해진다. 같은 ○를 다시 넣으면 열을 더하지 않고 그 열을 강조한다.
  - `prefers-reduced-motion`이면 애니메이션 없이 바로 나온다.
  - `maxTrials`에 이르면 "넣기"를 끄고 "넣을 수 있는 횟수를 다 썼어요"를 보인다. 시도 횟수 표시는 "넣은 횟수 2 / 3" 꼴이다(점수 아님).
  - 범위 밖 수는 "0부터 20까지의 수를 넣어요"(범위 문구)로 막는다.
  - 결과가 정수가 아니면 분수로 보인다.
- **상태:** `{ mode, settings, draft: string, trials: [x, y][] (Rational 문자열), ruleText: string, tested: null | { text, ok: boolean, holds: boolean[] }, ruleHistory: string[], target: 'input' | 'rule' }`
  - `ruleHistory`: 시험한 식(파싱된 것만) `formatRelation` 문자열, 최근 10개
- **Action:** `type {target, key}`, `backspace {target}`, `clear {target}`, `insert-input`(draft → trial), `test-rule`, `focus {target}`

### 6. `table`
- **설정:** `rows: { x: string | null; y: string | null }[]`
  - 둘 중 하나만 `null`이면 그 칸이 학생 빈칸이다. 둘 다 값이면 주어진 칸이다.
  - 값은 Rational 문자열이다.
- **빈칸 정답:** □ 빈칸은 `solveBox(rule, x)`다. ○ 빈칸은 `domain` 정수 가운데 `solveBox(rule, ○) = y`인 것이다(없으면 설정 오류 경고).
  - 정답은 Observation(`cellsCorrect`)에만 두고 화면에 그리지 않는다.
- **상태:** `{ mode, settings, cells: Record<string, string>, active: string | null, ruleText, tested, ruleHistory, target }`
  - `cells` 키는 `"<col>.x"`·`"<col>.y"`다.
- **Action:** 5번과 같은 입력 Action + `activate {cell}`

### 7. `covary`
- **설정:** `scene: 'chairs-legs' | 'triangles-sticks' | 'dots'`, `x: { min, max }`(정수), `blankRows?: number[]`(○ 값), `look?: 'picture' | 'dots' | 'none'`(CPA, 기본 `picture`)
- **장면 (`scenes.tsx`)**: ○ 값에 따라 그린다.
  - `chairs-legs`: 의자 ○개, 다리가 보인다.
  - `triangles-sticks`: 이쑤시개로 이은 삼각형 ○개.
  - `dots`: ○줄의 점.
  - 그림의 개수는 `rule`과 맞아야 한다. 장면이 rule과 맞는지는 단위 테스트로 본다(chairs-legs ↔ `□ = ○ × 4`, triangles-sticks ↔ `□ = ○ × 2 + 1`).
  - `look: 'dots'`면 그림 대신 점·막대, `'none'`이면 장면을 그리지 않는다(표와 식만).
- **슬라이더**
  - 손잡이 48px 이상, ←/→/Home/End를 받는다.
  - 슬라이더를 움직여 ○가 바뀌면 그 ○ 열이 표에 더해진다(○ 오름차순, 이미 있으면 그대로).
  - `blankRows`에 있는 ○ 열의 □ 칸은 빈칸(학생 입력)이고, 그 ○에서는 장면 아래 □ 수 글자를 쓰지 않는다. 그림은 그대로 그린다(구체물 단계에서 세어 볼 수 있음).
  - 그 밖의 열은 □가 자동으로 채워지고, 장면 아래에 "○ = 3, □ = 12"를 쓴다.
- **상태:** `{ mode, settings, x: string, visited: string[], cells, active, ruleText, tested, ruleHistory, target }`
- **Action:** `set-x {x}` + 6번 Action

### 8. Observation
- **공통**
  - `mode`
  - `pairs`: 표에 보이는 완성된 쌍. 학생이 채운 칸 포함, 빈칸은 제외. `[x, y]` Rational 문자열.
  - `ruleText`, `ruleValid`, `ruleFormatted`, `ruleInfo`(relationInfo)
  - `holdsAll`: 시험한 식이 `pairs` 모두에서 성립하고 `pairs` ≥ 2
  - `holdsCount`
  - `matchesHidden`: `sameOnDomain(학생 식, rule, domain 정수)`. NONLINEAR는 false다.
  - `ruleHistory`
  - `misconceptions`
- **모드별**
  - black-box: `trials`, `trialCount`
  - table·covary: `cells`, `cellsComplete`, `cellsCorrect`
  - covary: `x`, `visited`
- **오개념(`relation-check.ts`)**: 마지막 `test-rule` 기준이다.
  - `MC-PATTERN-ONE-PAIR`: 식이 유효하고, `pairs` ≥ 2이며, 성립하는 쌍이 1개 이상이지만 전부는 아니다.
  - `MC-CORR-SWAP-VARS`: 식이 `holdsAll`이 아니고, `swappedHolds(식, pairs)`이며, `pairs` ≥ 2다.
  - `MC-PATTERN-RECURSIVE-ONLY`: 다음 둘 중 하나다.
    - 식이 `boxOnly`다(□ = □ + 4).
    - 식이 파싱되지 않고, 입력이 `+`·`−`로 시작하며 `=`가 없다("+4").
  - `MC-FUNC-ADD-ONLY`
    - 조건: 숨은 `rule`의 □ 쪽 식에 ○ 곱셈이 있다(○의 계수 ≠ 1). 그리고 `ruleHistory`의 마지막 두 식이 모두 `□ = ○ + c`·`□ = ○ − c` 꼴(○ 계수 1)이다.
    - 계수는 `solveBox`로 ○ = 0, 1을 넣어 차이로 구한다.

### 9. Predicate (인자가 잘못되면 false)
- `holdsAll {minPairs?: number}`(기본 2)
- `matchesHidden {}`
- `ruleSolvedForBox {}`
- `ruleFormDiffers {from: string}`: 식이 `matchesHidden`이고, `formatRelation`이 `from`을 파싱해 포맷한 것과 다르다.
- `trialsAtMost {n}`
- `cellsCorrect {}`
- `cellIs {col, which: 'x' | 'y', value}`

`trial-added {x, y}`, `rule-tested {valid, holdsAll}`, `cell-entered {cell}`, `x-changed {x}`

### 11. 오버레이 (힌트 ②, `relation-canvas`에 맞춘다)
- 학생 자료·과제 자료로만 그리고, 숨은 규칙이나 빈칸 정답을 쓰지 않는다.
- **`fail-cols`** (ONE-PAIR): 학생 식이 성립하지 않는 열에 굵은 빨간 테두리와 빗금을 그리고, "이 줄에서는 맞지 않아요"를 쓴다.
- **`diff-arrows`** (ADD-ONLY)
  - 표에서 ○가 1씩 커지는 이웃 열 쌍마다 ○ 행 위에 "+1", □ 행 아래에 "+k"(실제 □ 차이) 화살표를 그린다.
  - 이웃 쌍이 없으면 ○ 차이가 가장 작은 쌍을 쓴다.
  - 표에 있는 수끼리의 차이라 정답 노출이 아니다.
- **`long-chain`** (RECURSIVE-ONLY)
  - `args: {x}`(기본 100)
  - 표 오른쪽에 "+k, +k, +k, … (x번)" 사슬을 그린다. 처음 몇 개만 그리고 "… 97번 더"로 줄인다. k는 학생 표의 이웃 차이다.
  - □ 값은 쓰지 않는다.
- **`swap-check`** (SWAP-VARS)
  - 표 첫 열의 ○ 값을 학생 식에 ○로 넣어 `solveBox`로 나온 □를 "○ = 2일 때 내 식의 □ = 1/2"로 쓴다.
  - 그 열의 실제 □와 나란히 둔다.
  - 장면이 `chairs-legs`면 다리 반 개 그림을 덧붙인다.

### 13. 테스트
- **단위**
  - `relation-check` 오개념 네 개의 참·거짓 경계
    - ONE-PAIR는 pairs 1개일 때 아님
    - SWAP는 holdsAll일 때 아님
    - ADD-ONLY는 숨은 규칙이 덧셈이면 아님, 식 하나만 시험했으면 아님
  - 빈칸 정답(○ 빈칸 역산, 분수 결과)
  - `maxTrials`, 같은 ○ 재입력, `covary` 방문 정렬
  - `assertSerializable`, `reduce`가 입력을 바꾸지 않음
  - predicate 참·거짓
- **View**
  - `blankRows` ○에서 장면 아래 □ 글자가 없음
  - table 빈칸 DOM에 정답 수 없음
  - 숨은 규칙 문자열이 DOM에 없음
  - 학년·점수 없음
- **E2E (`tests/e2e/function-machine.spec.ts`, 3 뷰포트, 샌드박스)**
  - black-box `□ = ○ × 3`: 키패드로 1·2·5 넣기 → 표 3열 → `□ = ○ + 2` 시험(ONE-PAIR, ✕ 열 둘) → `□ = ○ × 3` 시험(holdsAll, matchesHidden)
  - 키보드만으로 같은 흐름
  - SWAP: `○ = □ × 3`을 시험
  - RECURSIVE: `+3` 입력 후 시험
  - ADD-ONLY: 덧셈식 두 번 시험
  - table: ○ 빈칸·□ 빈칸 채우기 → `cellsCorrect`
  - covary chairs-legs: 슬라이더 키보드로 5까지 → 5열 □ 빈칸, 장면 아래 글자 없음 → 20 입력 → `cellsCorrect`
  - 오버레이 4개가 그려지고 `relation-canvas`와 1px 안
  - 터치 타깃: 키패드 단추·표 칸·슬라이더 손잡이 ≥ 48(64 설정 ≥ 64)
- **스냅샷:** black-box(3쌍 넣은 뒤)·covary 첫 화면, 크롬북·아이패드. 직접 열어 확인한다.
- **E2E 범위:** `npx playwright test function-machine fit-canvas overlay-alignment --workers=3 --reporter=line`만 돌린다.

- **측정값(stage=fit, 크롬북 1366×768):** 첫 `-canvas` 캔버스(상자·장면·표) 짧은 변 black-box 426, covary 395, table 426(표 배율 1.5). 보드(1920×1080)는 491~516. 손잡이·키패드·표 칸은 48 설정에서 48/52/66 이상, 64 설정에서 64/71/66 이상(표 칸은 80×64 고정이라 두 설정 모두 64 이상).
- **카드와 다르게 한 것**
  - `rule`을 쓰지 않으면(샌드박스·fit 검사) 모드·장면별 기본 규칙(`□ = ○ × 3`, chairs-legs `× 4`, triangles-sticks `× 2 + 1`, dots `× 5`)과 table 기본 표를 쓴다. `rule`을 썼는데 읽히지 않거나 solvedForBox가 아니면 카드대로 설정 오류 빈 판(경고)이다.
  - `Tested`는 `{ text, ok, errorAt }`이고 `holds` 배열을 상태에 두지 않는다. ✓/✕와 holdsAll은 현재 표에서 그때그때 계산한다(칸을 고쳐도 표시가 낡지 않게). 표시는 입력식이 시험한 식과 같을 때만 보이고, 오개념·오버레이는 식을 고쳐도 다음 시험 전까지 유지한다.
  - `covary`의 `cells` 키는 열 번호가 아니라 `"<○ 값>.y"`다(슬라이더로 열이 끼어들어 번호가 밀리므로).
  - black-box 상태에 `lastX`(강조 열)와 `notice`('range'|'no-output'|'limit')를 더했다. 같은 ○ 재입력은 열을 더하지 않고 강조만 한다.
  - 대응표 칸은 targetSize와 무관하게 80×64(논리 px)로 고정했다. 오버레이 props에 targetSize가 없어 표 좌표가 targetSize에 따라 달라지면 오버레이가 어긋나기 때문이다. table 모드는 배율 ≥ targetSize/64일 때까지 줄이고, 그보다 좁으면 판 안에서 스크롤한다.
  - 표 SVG는 위(오버레이 문구)·□ 줄 아래(차이 화살표)·✓/✕ 띠·아랫띠(사슬·설명)를 항상 둔다. 그래서 `long-chain` 사슬은 "표 오른쪽"이 아니라 표 아랫띠에 그린다(오버레이가 표 SVG와 같은 상자여야 하므로). 오버레이가 없을 때는 아랫쪽이 비어 보인다.
  - 표 칸 분수 답: 숫자 키패드에는 `/` 단추가 없다(카드 목록대로). 물리 키보드 `/`는 표 칸에서 받는다(`1/2`). 터치만으로는 분수 빈칸을 못 채우므로 분수 답이 나오는 활동은 콘텐츠 카드에서 정해야 한다.
  - 식 입력은 공백을 받지 않는다(`□=○×3`처럼 쓰이고 `formatRelation`으로 보기 좋게 바뀐다).
  - 첫 `-canvas`로 fit 검사가 재는 것은 상자(`machine-canvas`)·장면(`scene-canvas`)이고 오버레이 기준은 `relation-canvas`다. table 모드는 표가 판에 있어 `relation-canvas`가 곧 첫 캔버스다.
  - 물리 키보드로 처리한 키는 `stopPropagation`한다(샌드박스의 `+`/`=` 확대·되돌리기 단축키와 겹치지 않게).
- **fit-canvas ENGINES:** E16 세 모드 모두 넣었다. 빼야 하는 모드 없음.
